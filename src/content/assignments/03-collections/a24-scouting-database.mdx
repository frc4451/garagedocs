## Scenario

Use an ArrayList to hold a changing collection of scouting entries. Add, remove, search, filter, and sort the entries through methods on ScoutingDatabase.

The six seeded teams are deterministic practice fixtures for this program. Do
not treat their names, drivetrains, or scores as current competition scouting
data.

Return an unmodifiable view from all() so callers can read the list without adding or removing entries through that view.

## What To Build

**`TeamEntry`**: a record holding `teamNumber`, `teamName`, `drivetrain`, `avgPoints`
and `climbsHigh`, with a compact constructor that validates: team number 1 to 99999,
name not blank, `drivetrain` one of `TANK` / `MECANUM` / `SWERVE` / `OTHER`, `avgPoints`
not negative. `pickScore()` is `avgPoints`, plus 25 when the team climbs high.

**`ScoutingDatabase`**: one `ArrayList<TeamEntry>` field and nothing else:

## A Live View

Returning the internal list directly would let callers change the database without
using its methods. The record constructor still validates newly created entries,
but a caller could clear the database or insert null through the exposed list.
`Collections.unmodifiableList(entries)` provides a read-through wrapper whose
mutation operations throw `UnsupportedOperationException`.

It is a *view*, not a snapshot: later additions through `add` show up in a view
somebody already holds. This assignment deliberately requires that live
behavior. `List.copyOf(entries)` would instead make an unmodifiable snapshot,
which would not change when the database changes. Unmodifiable describes the list
operations; it does not freeze arbitrary mutable objects stored in a list.

## Optional And Predicate Bridge

`findByTeamNumber` always returns an `Optional<TeamEntry>`. Start with
`Optional.empty()`, return `Optional.of(entry)` when the loop finds the matching
team, and never return `null`. The supplied CLI then uses `map` to turn a found
entry into display text and `orElse` to supply the missing case.

`Predicate<TeamEntry>` is a yes-or-no test passed into `filter`. For each entry,
call `test.test(entry)` and append only accepted entries to a fresh result list.
Then `filterByDrivetrain` can pass a drivetrain lambda to that same method, and
the `h` command can pass a different lambda without duplicating the loop.
