### Scenario

A ring buffer holds the most recent N values and drops the rest. It is the smoothing
primitive behind almost every filter you will write: the last five voltage readings, the
last twenty vision frames, the last second of odometry.

None of that code cares what kind of value it holds. Written generically, one class
serves all of it: a `RingBuffer<Double>` for voltages, a `RingBuffer<VisionResult>` for
vision, a `RingBuffer<Pose2d>` for odometry. That is where generics stop being syntax
you tolerate and start being the reason you wrote a class at all.

both ways, then does the whole thing again with a `RingBuffer<String>` because a
generic class that only ever gets used at one type has not proved anything.

### Stretch goals

- Add `T get(int indexFromOldest)`: O(1) random access with a bounds check. You already
  have the arithmetic; this is about what to throw when the index is out of range.
- Add a bounded type parameter: `class SortableRing<T extends Comparable<T>> extends
  RingBuffer<T>` with a `T max()`. The `extends Comparable<T>` bound is precisely what
  lets you call `compareTo` inside it.
- Implement `Iterable<T>` on `RingBuffer` itself so `for (T t : buffer)` works without
  calling a method first. Then document which direction you chose, because the caller
  cannot see it.
