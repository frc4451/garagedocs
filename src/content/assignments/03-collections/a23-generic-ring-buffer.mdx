## Scenario

Store the most recent N values in a fixed-size array. When the buffer fills, replace the oldest value and advance its index.

Use a type parameter so the same RingBuffer class holds Double values, Strings, or records. The buffer stores history; averaging or filtering that history is a separate operation.

Keep that separation in your design: `RingBuffer<T>` stores and orders values.
It cannot average an arbitrary `T`, and no averaging method belongs in the
required class.

## Iterable And Iterator

`oldestFirst()` and `newestFirst()` return an `Iterable<T>`, an object that can
create an iterator each time a for-each loop starts. They do not return one
already-used `Iterator<T>`. Each call to `iterator()` therefore needs fresh
position state, so two loops can walk the same buffer independently.

An iterator has two different promises. `hasNext()` reports whether another
value exists, and `next()` returns it. After the iterator is exhausted,
`next()` must throw `NoSuchElementException`; returning `null` would confuse an
exhausted iterator with a buffer that actually stores `null`.

## Stretch Goals

Finish and grade the required version first. Make a copy of the two source
files in a separate `stretch/` folder for any goal below, and compile that copy
separately. The required browser output should continue to come from the
original files.

- Add `T get(int indexFromOldest)`: O(1) random access with a bounds check. You already
  have the arithmetic; this is about what to throw when the index is out of range.
- Add a bounded type parameter: `public class SortableRing<T extends Comparable<T>> extends
  RingBuffer<T>` with a `public T max()`. Give it a public constructor that accepts
  capacity and calls `super(capacity)`. The `extends Comparable<T>` bound is precisely what
  lets you call `compareTo` inside it.
- Implement `Iterable<T>` on `RingBuffer` itself so `for (T t : buffer)` works without
  calling a method first. Then document which direction you chose, because the caller
  cannot see it.
