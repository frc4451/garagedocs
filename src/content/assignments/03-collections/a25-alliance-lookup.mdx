## Scenario

Use a map to look up a team number, a drivetrain group, or a match outcome.
`HashMap.get` and `HashMap.put` have expected constant-time performance when
hashes distribute keys well. Walking a map or producing a list of results still
takes time proportional to the entries visited, and `HashMap` promises no
iteration order.

The teams and outcomes seeded in `main` are deterministic practice fixtures.
They are not current event data or official match results.

Use a record containing match number and alliance as the outcome key. Its generated equals and hashCode methods let equivalent keys find the same entry.

## Keys, Results, And Indexes

`MatchKey` owns alliance normalization. Check the supplied text without regard
to case, reject anything other than red or blue, and assign one of the canonical
strings `"RED"` or `"BLUE"` to the record component. That makes separately
constructed keys equal and gives them equal generated hash codes.

`getTeam` and `outcomeFor` return an `Optional` because absence is a normal
lookup result. `teamsWith` returns an empty list for an unknown drivetrain and
an unmodifiable result for a known one, so callers cannot alter it or reach the
private list of team numbers. `countByDrivetrain` similarly returns a fresh map
rather than a private field.

The supplied fixture adds each team number once. This assignment does
not define what should happen if `addTeam` receives the same team number again;
a replacement in the primary map could otherwise leave stale or duplicate team
numbers in the drivetrain index. Implement the stated append behavior for the
unique fixture. If you extend the program to edit existing teams, decide how to
update both indexes together and add a separate test for that behavior.

## Stretch Goals

Finish and grade the required version first. Copy the five source files into a
separate `stretch/` folder before trying a goal below, then compile that copy.
Keep the required files and their printed output unchanged.

- Swap `teamsByNumber` for a `LinkedHashMap` and compare the iteration order against the
  `HashMap` version. Then decide whether your `main` was relying on an order it was never
