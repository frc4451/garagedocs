### Scenario

Use a map to look up a team number, a drivetrain group, or a match outcome. HashMap offers expected constant-time lookup with well-distributed hashes; producing a list of results still takes time proportional to that list.

Use a record containing match number and alliance as the outcome key. Its generated equals and hashCode methods let equivalent keys find the same entry.

### What to build

**`MatchKey`**: a record of `matchNumber` and `alliance`, whose compact constructor
requires the alliance to be `RED` or `BLUE` in any case, and stores it upper case.

**`MatchOutcome`**: a record of `score` and `won`.

<RulesBox title="Hints" items={[
  "<strong>Why a record is the right shape for a key.</strong> A map finds an entry by hashing the key first and only then comparing. If two keys are <code>equals</code> but hash differently, the second one lands in a different bucket and <code>get</code> returns <code>null</code> for a key that <em>matches</em>. Records derive both from the same components, so they cannot disagree. Write the class by hand with only <code>equals</code> overridden and watch the lookup fail.   "<strong>Normalise in the compact constructor, not at the call site.</strong> If <code>MatchKey</code> upper-cases the alliance on the way in, then <code>outcomeFor(3, \"red\")</code> and <code>outcomeFor(3, \"RED\")</code> build equal keys and find the same value. ### Stretch goals

- Swap `teamsByNumber` for a `LinkedHashMap` and compare the iteration order against the
  `HashMap` version. Then decide whether your `main` was relying on an order it was never
  promised.
- Add a `TreeMap` summary of total score by alliance colour. `TreeMap` sorts by the key's
  natural ordering, which for `String` means you get the sorted output for free.
- Rewrite `countByDrivetrain` with `Collectors.groupingBy` and `Collectors.counting`, then
  put the two versions side by side and pick one. [A26](/java/assignments/a26-stream-filter)
  is that argument at length.
