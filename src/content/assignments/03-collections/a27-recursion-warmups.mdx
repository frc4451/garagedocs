**Cites:** [Recursion](/java/java-algo-recursion), [Searching](/java/java-algo-searching), [Memoization](/java/java-algo-memoization).
**Difficulty:** medium. **Estimated time:** 90 minutes.

### Scenario

You will not reach for recursion every day in robot code. You will reach for the
*thinking shape* constantly: tree traversal, divide and conquer, backtracking, anything
where the problem contains a smaller copy of itself.

These five methods are each short enough to fit on a sticky note. That is deliberate.
The work is not the code — it is getting the two-rule structure into your hands so that
the next time you meet a problem shaped like this, you recognise it.

No loops in any of the bodies. `main`'s test driver is allowed them; the methods are not.

### Halving the exponent

`powerSlow` makes one recursive call per unit of exponent. `powerFast` uses the
identity:

```java
base^exp = (base * base)^(exp / 2)   // when exp is even
         = base * base^(exp - 1)     // when exp is odd
```

Every even step halves the remaining exponent, so the depth goes from O(n) to O(log n).
Increment `slowCalls` and `fastCalls` at the top of the two methods; `main` prints both
counts for `2.0^10` so you can see the difference rather than take it on trust.

### Stretch goals

- Add `fib(int n)` the naive way and time `fib(35)`. Then add `fibMemo` backed by a
  `HashMap<Integer, Long>` and time it again. The gap between O(2ⁿ) and O(n) is not a
  number you forget once you have watched it.
- Add a recursive maze solver over a `boolean[][]`: mark visited, recurse on the
  neighbours, unmark on the way out when a branch fails. That unmarking is what makes it
  backtracking rather than flood fill.
- Rewrite `reverse` so it does not call `substring`. Each `substring` copies, which
  quietly makes the whole thing O(n²) — pass an index instead and compare.
