## What To Build

Copy your `Robot.java` and tester from A11 into this assignment’s folder, preserving
the A11 submission. Then open the **copied** `Robot.java` in the A12 folder and
document that copy. Leave the completed A11 files unchanged.

An **invariant** is a rule the object keeps true after construction and after its methods finish, such as keeping speed within the accepted range.

**The class itself**: a Javadoc block above `public class Robot` with a one-sentence
summary, a short paragraph (2–4 sentences) on the invariants it maintains, an
`@author` tag, and `@since` with the date or season.

**Every public constructor**: a one-sentence summary, `@param` for each parameter
describing what a valid value looks like, and `@throws IllegalArgumentException`
saying exactly when it fires.

**Every public method**: a summary, `@param` for each parameter, `@return` describing
the result (omit for `void`), and `@throws` for anything it can produce.

Use `{@code ...}` for names and literals, and `{@link ...}` to cross-reference.

## Read A Javadoc Block

This unrelated example shows the parts of a constructor comment without supplying
the wording for `Robot`. It is a schematic excerpt, so the `...` body is a
placeholder and the snippet is not meant to compile.

```java norun
/**
 * Creates a practice timer with a positive duration.
 *
 * <p>The timer begins stopped. Call {@link #start()} when the activity begins.
 *
 * @param durationSeconds planned duration; must be greater than {@code 0}
 * @throws IllegalArgumentException if {@code durationSeconds} is not positive
 */
public PracticeTimer(int durationSeconds) { ... }
```

Write the `Robot` documentation in your own words from its actual behavior and the
A11 requirements. The generated page should tell a caller what is accepted without
revealing how each method is implemented.

## Generate And Read It

Generate only the class whose documentation this assignment grades. Including an
undocumented tester would produce warnings that have nothing to do with the
`Robot` API.

Save the copied source files. Use [Java Setup's terminal steps](/java/fundamentals/java-setup#compile-and-run) to open a terminal in `assignments/a12-document-the-robot-class/`, then run:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
javadoc -Xdoclint:all -d docs Robot.java
Get-Item docs/index.html | Select-Object FullName
```

</CodeTab>
<CodeTab label="Terminal">

```bash
javadoc -Xdoclint:all -d docs Robot.java
ls "$PWD/docs/index.html"
```

</CodeTab>
</CodeTabs>

Use the printed path to find `docs/index.html` in File Explorer or Finder, then
double-click it to open it in a browser and read your own class as a stranger would.
This step is not optional: most weak Javadoc looks fine in the source and falls apart
on the rendered page, where the summary line stands alone.

## Stretch Goals

- Add `{@link}` cross-references between `Robot` and the setters that enforce the same
  ranges, then check that the links resolve in the generated HTML.
- Write the class-level paragraph as if for somebody who will *subclass* `Robot`. Describe what callers can rely on and what remains free to change.
