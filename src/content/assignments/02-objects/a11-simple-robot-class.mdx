## Scenario

Create a Robot class that stores four values, checks their allowed ranges, and provides methods to read or update them. Its limits are exercise requirements, not robot inspection rules.

## What To Build

Create `Robot` with four `private` fields: `name`, `teamNumber`, `maxSpeedMps`, and `weightLbs`. Add these constructors and methods:

- A four-argument constructor that **validates every parameter** before storing it
- A two-argument constructor `Robot(String, int)` that **chains** to the first with
  `this(...)` and defaults of `0.0` and `0`. Do not copy the validation into it
- Getters for all four fields
- Setters for `maxSpeedMps` and `weightLbs` only: `name` and `teamNumber` are set
  once, at construction. Both setters validate
- `toString()` reading exactly
  `Robot[name=Titan, team=1234, maxSpeed=4.5 m/s, weight=120 lb]`
- `equals(Object)` comparing **`name` and `teamNumber` only**. Two robots with the
  same name and number are equal even if their speeds differ

`double` has a special value named `NaN` ("not a number"). A check such as
`speed < 0.0 || speed > 30.0` misses it because every ordered comparison with
`NaN` is false. Treat `Double.NaN` as bad input too. `Double.isNaN(maxSpeedMps)`
checks that case directly, in both the constructor and the setter.

## Build Locally

The editor tab is named `RobotTester`, which is the class containing `main`. For
the repository version, create these two files in the assignment folder:

- `Robot.java` contains `public class Robot` and all of its fields. Mark the
  constructors, getters, setters, `toString`, `equals`, and `hashCode` public.
- `RobotTester.java` contains `public class RobotTester` and the supplied `main`
  and `rejects` methods.

Java requires each public top-level class to be in a file with the same name.
Save both files. Open the assignment folder's terminal as shown in [Compile And Run](/java/fundamentals/java-setup#compile-and-run), then compile both files and run the class that contains `main`. Keep any import needed by `Robot`, such as `java.util.Objects`, at the top of `Robot.java`.

The two constructors are an overload: they share the name `Robot` and have
different parameter lists. A call to `this(...)` invokes another constructor on
the same new object. Put it first in this constructor so the code works in the
browser's Java 17 runner as well as locally. A `final` field may be assigned by a constructor and cannot be assigned
again afterward, so `name` and `teamNumber` can be final while speed and weight
remain changeable through their setters.

## Equality Methods

Every Java class inherits methods from `Object`. **Overriding** means providing your own version with the same method signature. Write `public boolean equals(Object other)` and `public int hashCode()`; `@Override` above each method lets the compiler check that you are overriding an existing method. `toString()` is another inherited method you override to return your chosen description.

An `Object` parameter can receive a reference to a `Robot`, a `String`, or another class, so check its type before reading Robot fields. In Java 17, `other instanceof Robot robot` both tests the type and gives you the name `robot` for that object when the test succeeds. The test is false for `null`. Compare names using `String.equals` and team numbers using `==`. An unrelated class is never equal under this assignment's rule.

A **hash code** is an integer used by collections to organize objects for lookup. You can import `java.util.Objects` and use `Objects.hash(...)` to combine the same fields you compare in `equals`. For example, a different class identified by `label` and `number` could call `Objects.hash(label, number)`. Do not include mutable values that your equality rule ignores. Read [Objects.hash](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Objects.html#hash(java.lang.Object...)) for the helper's contract.

You do not need subclasses for this assignment. If you extend `Robot` later, review the equality contract before adding new fields to the comparison.

## Stretch Goals

Finish and save the required version first. Try these in a copy so changed methods
or extra output cannot interfere with the required checks.

- Add a `public static Robot fromString(String)` that parses your own `toString` output back
  into a `Robot`, and check that a round trip returns an equal object.
- Make `Robot` immutable: drop both setters and add `withMaxSpeedMps(double)` that
  returns a *new* `Robot`. Decide which version you would rather maintain.
