### Scenario

Almost every confusing bug a new Java programmer writes comes from one misunderstanding:
believing a variable *holds* an object. It holds a reference to one. Two variables can
name the same object; passing one to a method hands over a copy of the reference, not
of the object.

This assignment is not about writing code. It is about **being wrong on paper first**,
which is the only reliable way to find out what you expect Java to do.

### How to work through it

For each of the five experiments:

1. **Predict** what every print will produce, *before running*. Write it in the
   `// PREDICTION:` comment already in the starter
2. **Run** it
3. **Reconcile.** If the result differs from your prediction, add `// SURPRISE: I expected X, got Y, because Z.` If it matches, explain why in one sentence.
   `// Confirmed.`

You turn in the file with the predictions and explanations still in it. A file with
only correct output and no comments scores zero on the section that matters.

### Stretch goals

- Add a sixth experiment with a `String`: compare two identical literals with `==`, then
  two strings built at run time with `new String("Titan")`. Explain why the answers
  differ, and why the first one is a trap rather than a feature.
- Add a seventh with an array of `Robot`. Predict what a fresh `Robot[5]` contains, then
  what happens when you call a method on element 0.
