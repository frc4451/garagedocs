### Scenario

Write three subclasses that respond to the same performStep method. A loop can call that method on each Subsystem reference, and Java selects the implementation for its object.

These classes update console state only. They are a model for learning inheritance, not WPILib subsystems or motor-control code.

### What to build

`Subsystem` is written for you: a `protected final name`, an `enabled` flag with
`enable()`/`disable()`, a `toString()`, and one `abstract String performStep()`.

Implement three subclasses. Each calls `super(name)`, marks `performStep` with
`@Override`, and keeps its own state `private`:

after tick 4 re-enables it and disables the drivetrain, so you can watch state and
polymorphism interact.

### Stretch goals

- Add a `Climber` that refuses to run before tick 100, and add it to the array without
  touching the loop. Adding it to the array changes setup; the loop body should stay unchanged.
- Give `Subsystem` a `periodicCount` that increments on every `performStep`, without
  letting any subclass forget to bump it. That is what the template-method pattern is for.
