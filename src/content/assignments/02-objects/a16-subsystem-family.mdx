## Scenario

Write three subclasses that respond to the same performStep method. A loop can call that method on each Subsystem reference, and Java selects the implementation for its object.

These classes update console state only. They are a model for learning inheritance, not WPILib subsystems or motor-control code.

## What To Build

This assignment continues the class work from [A14: Robot and Battery
Composition](/java/assignments/a14-robot-and-battery-composition). There, one
object held another. Here, three classes *extend* one parent and inherit its name,
enabled state, and finished methods. Read [Inheritance](/java/fundamentals/java-inheritance)
before starting. The Badge 1 route places A16 after that lesson; this page explains
the abstract-method and array pieces needed to finish the assignment.

`Subsystem` is written for you: a `protected final name`, an `enabled` flag with
`enable()`/`disable()`, a `toString()`, and one `abstract String performStep()`.

Implement three subclasses. Each calls `super(name)`, marks `performStep` with
`@Override`, and keeps its own state `private`:

## Build Locally

Create `Subsystem.java`, `Drivetrain.java`, `Intake.java`, `Shooter.java`, and
`RobotLoop.java` in the assignment folder. Put the matching top-level type in each
file and declare each class `public`. Make each subclass constructor `public` too.
The browser combines them into one file, so its helper classes remain
package-private and only `RobotLoop` is public.

Add `import java.util.Locale;` above `Drivetrain`. Format its line with
`String.format(Locale.ROOT, ...)` so the automated check still sees decimal points
on a computer whose default locale uses decimal commas. In the browser, place the
import above every class.

## Follow One Tick

`Subsystem` is abstract, so it describes shared state but cannot be constructed by
itself. Its `performStep` declaration ends with a semicolon because each concrete
subclass must supply the body. In every subclass, store the constructor arguments
in private fields after `super(name)`, then implement the public method marked
`@Override`.

The array's declared type is `Subsystem[]`, but each element still refers to its
real object. On tick 1, `s.performStep()` therefore runs the drivetrain, intake,
or shooter body for that element. That runtime choice is polymorphism. You do not
need a type test or cast in the loop.

For the shooter, first remember the old RPM. Then change `currentRPM` toward
`targetRPM` by no more than 500 and format `old -> new`. Handle both directions,
including a target below the current value. Do the disabled check before changing
any subclass state.

## Stretch Goals

Finish and save the required version first. Try stretch work in a copy so added
state or output cannot interfere with the five-tick checks.

- Add a `Climber` that refuses to run before tick 100, and add it to the array without
  touching the loop. Adding it to the array changes setup; the loop body should stay unchanged.
- Give `Subsystem` a `periodicCount` that increments on every `performStep`, without
  letting any subclass forget to bump it. That is what the template-method pattern is for.
