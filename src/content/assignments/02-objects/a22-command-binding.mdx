### Scenario

`controller.a().onTrue(shooter.spinUp())` is the line every command-based tutorial opens
with, and it hides something worth understanding: the button is not a value that got
read once. It is a **question**, stored, and asked again fifty times a second.

That is what a `BooleanSupplier` is for. Build the small version and the WPILib one
stops being magic.

`main` presses the button across five ticks — released, held, held, released, held — so
the rising edge happens **twice**. Getting `onTrue` to fire exactly twice, and
`whileTrue` three times, is the assignment.

<RulesBox title="Hints" items={[
  "<strong>A rising edge needs memory.</strong> \"Is it true now?\" cannot tell a press from a hold. Store the previous value per hook and fire when <code>now &amp;&amp; !previous</code>.   "<strong>A <code>Runnable</code> is a stored action, not a result.</strong> Registering it runs nothing; the scheduler decides when. If your output appears during registration instead of during a tick, you called the action rather than storing it."

### Stretch goals

- Add `onFalse` for the falling edge, and `toggleOnTrue` that flips a boolean each press.
  Between them they cover almost every binding a driver asks for.
- Add `Button and(Button other)` returning a button true only when both are — and note
  that you can build it out of the two suppliers without touching the scheduler at all.
