### Scenario

Tuning constants live in a file so you can change them without recompiling. That
convenience cuts both ways: the file is also where a typo turns into a robot that
drives at 850% power because somebody wrote `8.5` instead of `0.85`.

The fix is to refuse bad values **once, at the edge**, where the file becomes objects.
After that boundary, the rest of the code can stop asking.

### Input format

```text
# comments start with #
maxDriveSpeed = 0.85
maxAccel = 2.5
intakeRPM = 1800
shooterTargetRPM = 4500
climberEnabled = true
teamNumber = 1234
```

Order does not matter. Blank lines and `#` lines are ignored. Whitespace around the
`=` is allowed.

### What to build

**`Config`** with six `private final` fields, validated in the constructor. A bad value
throws `IllegalArgumentException` **naming the key and the value**:

<ContentTable
  headers={["Key", "Valid range"]}
  rows={[
    ["<code>maxDriveSpeed</code>", "0.0 to 1.0"],
    ["<code>maxAccel</code>", "greater than 0.0"],
    ["<code>intakeRPM</code>", "0 to 6000"],
    ["<code>shooterTargetRPM</code>", "0 to 6000"],
    ["<code>climberEnabled</code>", "<code>true</code> or <code>false</code>, case-insensitive"],
    ["<code>teamNumber</code>", "greater than 0"]
  ]}
/>

**`ConfigLoader.load(String path)`** opens the file with try-with-resources, skips
blanks and comments, splits each line on the first `=`, then builds a `Config`. A
missing key, an unparseable number and an out-of-range value all throw
`IllegalArgumentException`. A missing *file* throws `IOException`: a different kind of
problem, and callers will want to tell them apart.

### Stretch goals

- Collect *every* problem in the file and throw once with all of them listed, instead of
  stopping at the first. Far kinder at 11pm before a competition.
- Add `saveTo(String path)` writing the config back out in the same format, and confirm
  a load-save-load round trip is stable.
