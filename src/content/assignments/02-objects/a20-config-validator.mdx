## Scenario

Read a text configuration file and validate each value before creating a Config object. Report the key that failed so a user knows what to correct.

The ranges below are exercise requirements. Validation checks those ranges; it does not prove that a configuration is suitable for a physical robot.

## Input Format

```text
# comments start with #
maxDriveSpeed = 0.85
maxAccel = 2.5
intakeRPM = 1800
shooterTargetRPM = 4500
climberEnabled = true
teamNumber = 1234
```

Order does not matter. Blank lines and `#` lines are ignored. Whitespace around the
`=` is allowed.

## What To Build

**`Config`** with six `private final` fields, validated in the constructor. A bad value
throws `IllegalArgumentException` **naming the key and the value**:

    ["<code>shooterTargetRPM</code>", "0 to 6000"],
    ["<code>climberEnabled</code>", "<code>true</code> or <code>false</code>, case-insensitive"],
    ["<code>teamNumber</code>", "greater than 0"]

/>

**`ConfigLoader.load(String path)`** opens the file with try-with-resources, skips
blanks and comments, splits each line on the first `=`, then builds a `Config`. A
missing key, an unparseable number and an out-of-range value all throw
`IllegalArgumentException`. A missing *file* throws `IOException`: a different kind of
problem, and callers will want to tell them apart.

## Concepts Before Coding

The earlier Try/Catch lesson introduces handlers and `finally`, but this assignment
adds two file-specific ideas. `IOException` is a checked exception, so `load` must
either catch it or declare `throws IOException`; keep the supplied declaration so
the caller can distinguish a file problem from bad configuration text.

`BufferedReader.readLine()` returns one line without its line-ending characters. It
returns `null` only after the reader reaches the end of the file. That is why a file
loop reads a line, handles it, and stops when the next result is `null`.
Try-with-resources closes the reader when execution leaves the `try` block, whether
the block finishes normally or an exception leaves it early.

The `Map<String, String>` is a temporary lookup table: each parsed key goes into the
map with its text value, and the constructor arguments are read back by key after
the file ends. Unlike the counting examples in Sets and Maps, there is no useful
default for a missing configuration key. Check for every required key and throw an
`IllegalArgumentException` that names it before parsing or constructing `Config`.

## Build Locally

Create `Config.java` and move the complete `Config` class into it. Declare the class
and its constructor `public`, and keep its six fields `private final`. Save the
public `ConfigLoader` class, including the unchanged supplied `main`, `dataDir`, and
test helpers, in `ConfigLoader.java`. Declare the `load` method `public static` in
the local two-file version so other code can use the loader.

Run these commands from `assignments/a20-config-validator/`:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
javac Config.java ConfigLoader.java
java -Duser.language=en -Duser.country=US ConfigLoader
```

</CodeTab>
<CodeTab label="Terminal">

```bash
javac Config.java ConfigLoader.java
java -Duser.language=en -Duser.country=US ConfigLoader
```

</CodeTab>

The language and country options keep the decimal point in `Config.toString`
consistent with the expected output on computers that normally print decimal
commas.

In the browser, `dataDir()` chooses `/files` when available. In a local run, it
tries the operating system's temporary directory and then the current folder. The
supplied `main` creates and rewrites `constants.txt` in that chosen directory, so
do not point it at a configuration you want to keep. Later, when your own program
calls `load("robot-config.txt")`, that relative path refers to the folder from which
you launched `java`. No robot hardware is involved in either workflow.

For booleans, first accept only text equal to `"true"` or `"false"` while ignoring
case. Then call `Boolean.parseBoolean`. That API returns `true` only for text equal
to `"true"` while ignoring case; every other string becomes `false`, including a
misspelling.

Manually test the inclusive numeric boundaries `maxDriveSpeed = 0.0`,
`maxDriveSpeed = 1.0`, and both RPM values at 0 and 6000. Also test a line without
`=` and confirm the message identifies that line. For an out-of-range value, read
the exception message and confirm it includes both the key and the rejected value.
In the required comment about the ranges, state that they are supplied exercise
limits. Do not present them as current robot rules or hardware limits.

First save a passing copy of the required version. Try each stretch goal in a
separate copy so new file output or diagnostics cannot interfere with the required
checks.

- Collect *every* problem in the file and throw once with all of them listed, instead of
