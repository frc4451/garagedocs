## Scenario

Use records to group related values. Java supplies component accessors, equals, hashCode, and toString. Add validation and methods for the behavior the assignment needs.

The examples store a vision result and a position setpoint. Records can have methods; choose them when their named components describe the value you want to represent.

## What To Build

**`VisionResult`**: a record with `timestampMs`, `xMeters`, `yMeters`,
`areaSqPixels` and `confidence`, implementing `Comparable<VisionResult>`:

- A **compact constructor** rejecting a negative `timestampMs`, a `confidence` outside
  `[0.0, 1.0]`, and a negative `areaSqPixels`
- `compareTo` ordering by `timestampMs` ascending
- `public static int recent(VisionResult[] results, long maxAgeMs, long now)` counting the
  results no more than `maxAgeMs` older than `now`

**`Setpoint`**: a record with `name`, `valueMeters` and `toleranceMeters`:

- A compact constructor that **trims the name**, rejects blank, and rejects a negative
  tolerance
- `public boolean isReached(double currentMeters)`: true when `currentMeters` is within
  `toleranceMeters` of `valueMeters`

## Compact Constructors

A compact constructor uses the record name with **no parameter list**. This
complete, separate `Main.java` example prints `Practice Bot`. Save it in a separate
practice folder and use [Compile And Run](/java/fundamentals/java-setup#compile-and-run)
to try it; keep the assignment's `RecordsTester.java` unchanged while exploring:

```java
public class Main {
    public record Label(String text) {
        public Label {
            if (text == null || text.trim().isEmpty()) {
                throw new IllegalArgumentException("text must not be blank");
            }
            text = text.trim();
        }
    }

    public static void main(String[] args) {
        Label label = new Label("  Practice Bot  ");
        System.out.println(label.text());
    }
}
```

The compact constructor can normalize its parameters before the
fields are assigned, so whatever the parameters hold at the end is what the record
keeps. That is how a record validates and normalises without repeating the component parameter list and field assignments.

The starter keeps `VisionResult` and `Setpoint` package-private because all three
top-level types share one browser source file. Keep those declarations as supplied.
Declare each compact constructor `public`. Also declare `recent` and `isReached`
`public`; `compareTo` is already public because it implements the public
`Comparable` method.

For the manual boundary check, create a temporary `Setpoint` whose target is `1.0`
and tolerance is `0.125`. Confirm that `isReached(0.875)` and `isReached(1.125)` are
both true, while `isReached(1.25)` is false. These fractions are exact in binary,
so rounding does not obscure the inclusive boundary. Decimal values such as
`0.05` can introduce tiny rounding differences when you subtract them; see
[Floating-Point Calculations](/java/fundamentals/java-calculations).
Remove the temporary calls before your final submission.
