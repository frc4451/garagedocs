### Scenario

Use records to group related values. Java supplies component accessors, equals, hashCode, and toString. Add validation and methods for the behavior the assignment needs.

The examples store a vision result and a position setpoint. Records can have methods; choose them when their named components describe the value you want to represent.

### What to build

**`VisionResult`**: a record with `timestampMs`, `xMeters`, `yMeters`,
`areaSqPixels` and `confidence`, implementing `Comparable<VisionResult>`:

- A **compact constructor** rejecting a negative `timestampMs`, a `confidence` outside
  `[0.0, 1.0]`, and a negative `areaSqPixels`
- `compareTo` ordering by `timestampMs` ascending
- `static int recent(VisionResult[] results, long maxAgeMs, long now)` counting the
  results no more than `maxAgeMs` older than `now`

**`Setpoint`**: a record with `name`, `valueMeters` and `toleranceMeters`:

- A compact constructor that **trims the name**, rejects blank, and rejects a negative
  tolerance
- `boolean isReached(double currentMeters)`: true when `currentMeters` is within
  `toleranceMeters` of `valueMeters`

### The compact constructor

A compact constructor uses the record name with **no parameter list**:

```java
record Setpoint(String name, double valueMeters, double toleranceMeters) {
    Setpoint {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException("name must not be blank");
        }
        name = name.trim();   // assigning the component normalises what gets stored
    }
}
```

The compact constructor can normalize its parameters before the
fields are assigned, so whatever the parameters hold at the end is what the record
keeps. That is how a record validates and normalises without repeating the component parameter list and field assignments.
