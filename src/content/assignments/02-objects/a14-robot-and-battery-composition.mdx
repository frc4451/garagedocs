## Scenario

Give a Robot a Battery field. This is composition: one object holds a reference to another.

The Battery in this exercise is an immutable object holding a serial number and a
voltage measurement. Two Robot objects can share that data. It does not model
physically sharing one battery between two robots or changing a battery during use.

## What To Build

**`Battery`** with `private final` `serial` and `restingVoltage`, a validating
constructor (`serial` not blank; `restingVoltage` between `0.0` and `14.0`), getters,
and `toString()` reading `Battery[serial=ABC123, restingV=12.50]`.

There are **no setters**. Once a `Battery` exists, its values are locked.

Reject `Double.NaN` as an invalid voltage too. As in A11, comparisons such as
`voltage < 0.0 || voltage > 14.0` do not catch `NaN`; use
`Double.isNaN(restingVoltage)` for that special value.

**`Robot`** gains a `private final Battery` field:

- The long constructor takes a `Battery` as a fifth parameter and rejects `null`
- `getBattery()` lets callers read it
- **No `setBattery`**: the field is `final`
- `toString()` includes the battery
- The two-argument constructor supplies a default battery of your choosing

The default is exercise data, not a real reading. Choose a valid placeholder
serial and a voltage in the accepted range, and explain those two choices in the
required comment. Keep the same values every run so the output is predictable.

## Build Locally

Create `Battery.java`, `Robot.java`, and `RobotPlusBatteryTester.java` in the same
assignment folder. Each file contains the matching `public` top-level class. The
browser starter instead keeps all three types in one file, so only
`RobotPlusBatteryTester`, the class containing `main`, is public there.

`Battery.java` also needs `import java.util.Locale;` above the class so its
formatted decimal is stable on computers whose default locale uses a comma.
Mark both local classes, their constructors, and their getters public. Mark the
Robot setters and both `toString` methods public as well. In the browser file,
`Battery` and `Robot` cannot be public top-level classes because Java permits only
one public top-level class per source file.

## Stretch Goals

Finish and save the required version first. Try these in a copy so added methods or
output cannot interfere with the required checks.

- Add `Robot withBattery(Battery)` returning a *new* `Robot` that shares everything else
  but carries the new battery. That is how immutable types handle change.
- Add a `BatteryLog` holding a `Battery[]` and a method returning the freshest one.
  Decide whether the log should copy the array it is handed, and write down why.
