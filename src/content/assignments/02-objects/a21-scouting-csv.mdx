## Scenario

Write scouting entries to a CSV file, then read them back without changing their values. Notes can contain commas or quotes, so the reader must distinguish field separators from characters inside a quoted field.

The supplied team numbers, names, notes, and scores are exercise data. Do not use
them as current facts about real teams.

Support one record per line in this exercise. Report a malformed row and continue reading valid rows.

CSV means comma-separated values. A CSV row is plain text whose fields are separated by commas. Quotation marks let
a comma belong to a field instead of separating fields. For example, the notes
value `fast, "steady"` is written as `"fast, ""steady"""`: the outer quotes protect
the comma, and each quote inside the value is doubled. Those extra marks belong to
the file format; reading the row must restore the original notes value.

Before starting, review [A20: Config Validator](/java/assignments/a20-config-validator)
for the file-reading pattern. A21 uses the same try-with-resources structure so the
reader closes at the end of the block. `readLine()` returns `null` at end of file,
which ends the loop. Both public methods declare `throws IOException`, so file
failures can travel to the caller instead of being mistaken for malformed CSV rows.

## What To Build

**`TeamEntry`** holding `teamNumber`, `teamName`, `drivetrain`, `avgPoints`,
`climbsHigh` and `notes`. Validate in the constructor: `avgPoints` not negative, and
`drivetrain` one of `TANK`, `MECANUM`, `SWERVE`, `OTHER`.

**`CsvIO`** with two static methods:

```java norun
public static void writeAll(String path, TeamEntry[] entries) throws IOException;
public static TeamEntry[] readAll(String path) throws IOException;
```

These are method signatures showing the required names, parameters, return types,
and checked exception. The semicolons mean they are not implementations. Write
each method with braces in `CsvIO`.

**Writing**: open with try-with-resources, write the header
`teamNumber,teamName,drivetrain,avgPoints,climbsHigh,notes`, then one line per entry.
**Escape `notes`** when it contains a comma or a quote: wrap it in `"..."` and double
any internal `"`. For the required samples, only notes contains commas or quotes. Assume the other text fields contain neither, and that no field contains a newline. Supporting general CSV input requires handling these cases in every text field.

If you use `PrintWriter` as the starter's file-writing helper does, remember that
its writing methods record errors instead of throwing `IOException`. Call
`checkError()` after writing, before leaving the resource block, and throw an
`IOException` if it reports a failure. Try-with-resources still closes the writer.
The supplied sample checks do not simulate disk-write failures.

**Reading**: skip the header, parse each line honouring those quotes, and when a line
is malformed, **print a warning and skip it** rather than abandoning the load.
Each valid data row must produce exactly six fields. Preserve an empty final field,
such as the notes in `1234,Titan,SWERVE,55,true,`, rather than losing it. Treat a
row with an unclosed quoted field as malformed. When checking whether a quote is
doubled, verify that a next character exists before reading it.

## Browser Files And Local Files

The Run button writes and reads a real file in the browser runner's virtual file
system. The starter's `dataDir()` chooses `/files` when it is available, then the
Java temporary directory, then the current directory. The file operations are
real, but this storage is separate from your computer and practice repository.
Running the checks does not save `scouting.csv` or your Java source to the
repository, and the browser file may disappear after the runner session.

For the repository version, create these three source files in
`assignments/a21-scouting-csv/`:

- `TeamEntry.java` contains `public class TeamEntry`.
- `CsvIO.java` contains `public class CsvIO`.
- `RoundTripDemo.java` contains `public class RoundTripDemo` and `main`.

Make all three classes, the `TeamEntry` constructor, and the methods named in this
assignment `public` in the local files. Put the required `import` statements above
the class that uses them. Keep all three files in the same folder and omit a
`package` line.
The browser combines them into one editor, where Java permits only
`RoundTripDemo` to be a public top-level class. Copy your completed browser work

## What The Checks Cover

The automated checks inspect the starter program's console output: four rows must
survive, commas and quotes in notes must survive, all fields must match, and the
two valid rows must remain after malformed rows are skipped. They do not inspect
whether you used try-with-resources, separated escaping and parsing into helper
methods, kept the catch around one row, wrote the required comments, or copied the
source into your repository. Check those rubric items yourself. This is a file
simulation exercise; it does not need a robot or other hardware.

## Stretch Goals

- Handle a newline *inside* a quoted field, which real CSV permits. This changes the
  shape of the reader because you can no longer assume one row is one line.
- Add `appendAll` that adds rows to an existing file without rewriting it, and work out
  what has to be true about the header for that to be safe. Try stretch work in a
  copy after the required checks pass so it cannot break your graded version.
