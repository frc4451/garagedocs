## Scenario

For this exercise, use a fictional 150-second timeline: 15 seconds of autonomous followed by teleop, with the final 30 seconds labeled endgame. These are exercise constants, not current-season rules.

Implement the same phase decision with an if/else chain and a switch expression. Compare both results at every boundary.

## Read The Supplied Main

The starter's `main` is already complete. `int[] times = { ... };` creates an array of test
times. The `for (int t : times)` loop runs once for each value and stores the current value
in `t`. Each pass calls both phase methods and prints their answers on the same line. Leave
that code unchanged; your work belongs in the three method bodies and in any bucket helper
you add directly inside the class.

A method declaration names its return type before its name. Both phase methods therefore
must reach a `return` that supplies a `String`. For the switch version, first reduce the
range question to a few exact bucket values with a separate helper, then switch on that
single bucket. Declare any helper you add with explicit visibility, such as
`private static int ...`. A Java `switch` does not accept conditions such as
`case seconds < 15`; its case labels match values.

An arrow-form switch expression returns one value. Its shape is:

```java norun
return switch (bucket) {
    case SOME_BUCKET -> "some result";
    default -> "fallback result";
};
```

This partial pattern shows the syntax only. Choose your own bucket names or values and map
all exercise phases yourself. The semicolon after the closing brace belongs to the return
statement.

## Requirements

- Both phase methods return the same value for every input. That is the point of printing
  them side by side
- No bare numbers scattered through the branches; name the boundaries
- The `switch` version uses the arrow form, not fall-through `case` labels with `break`
