**Topic:** methods, arrays, linear interpolation, simple sorting.
**Cites:** [Arrays](/java/java-arrays), [Methods](/java/java-methods), [Sorting](/java/java-algo-sorting).
**Difficulty:** medium. **Estimated time:** 90 minutes.

### Scenario

You spend an afternoon on the practice field firing from measured distances and writing down
the RPM that scored. Now you have six data points and a shooter that needs a number for
every distance in between. A lookup table with interpolation is how most teams solve this,
and it is worth writing once by hand before you reach for a library.

This is the closest thing in Track 1 to a real subsystem helper.

### What to build

A single file `ShooterLookup.java` with these `public static` methods:

```java
public static double[][] readSamples(Scanner in, int n);
public static void       sortSamples(double[][] samples);
public static int        upperIndex(double[][] samples, double distance);
public static double     interpolate(double[][] samples, double distance);
public static void       printSamples(double[][] samples);
public static double     rpmFor(double[][] samples, double distance);
```

`main` reads `n` (at least 2), fills a `double[n][2]` where column 0 is distance and column
1 is RPM, sorts by distance ascending, prints the sorted table, then loops: read a distance,
print its RPM, stop on a negative distance.

### Behaviour of `rpmFor`

<ContentTable
  headers={["Distance", "Result"]}
  rows={[

    ["At or above the last sample", "The last RPM, and print <code>(clamped at max)</code>"],
    ["Anywhere in between", "Interpolate between the two nearest samples"]
  ]}
/>

Print results as `RPM = 3150.00`, and the sorted table as `1.00 m -> 2200.00 rpm`.

Worked example: samples at 1.0 m / 2200 rpm, 2.0 m / 2800 rpm, 3.0 m / 3500 rpm, 4.0 m /
4100 rpm. A query at 2.5 m sits halfway between the second and third samples, so the answer
is 3150.00.

### Requirements

- Sort with a sort you write yourself. Insertion sort is plenty at this size
- `rpmFor` decides which of the three cases applies; `interpolate` only ever handles the
  in-between case
- The table is printed after sorting, so the user can check the data went in correctly

### Stretch goals

- Replace the linear scan in `upperIndex` with a binary search and confirm it gives identical
  answers on every query. See [Finding a boundary](/java/java-algo-searching#finding-a-boundary).
- Reject a table with two samples at the same distance, since interpolating between them
  divides by zero. Decide whether to refuse the input or drop the duplicate.
