**Difficulty:** beginner. **Estimated time:** 30–45 minutes.

### Scenario

You will keep every Practice assignment in one GitHub repository. Each assignment gets
its own folder, while the repository's `README.md` records what you have finished and
your self-score. Your reviewer can use one link to inspect your current work and commit
history throughout the track.

Complete this setup before A01. You need Git, Java 25, a verified GitHub account, and VS Code.
If any of those are missing, use the cited setup pages before continuing.

### What to build

Create a GitHub repository named `garagedocs-practice`. Public and private repositories
both work. Follow your team's privacy policy. If the repository is private, grant your
mentor or reviewer access before you submit it.

Clone the repository to your computer and create this starting structure:

```text
garagedocs-practice/
├── .gitignore
├── README.md
└── assignments/
    └── a00-practice-repository-setup/
        └── README.md
```

Do not put passwords, access tokens, private keys, robot credentials, or Driver Station
logs in this repository.

### Create the repository

1. Sign in to GitHub and create a repository named `garagedocs-practice`.
2. Add a `README.md` when GitHub asks whether to initialize the repository.
3. Copy the repository's URL from its **Code** menu.
4. Replace `repository-url` below with that URL and run the commands.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git clone repository-url
cd garagedocs-practice
git status
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git clone repository-url
cd garagedocs-practice
git status
```

</CodeTab>
</CodeTabs>

`git status` should name the repository's default branch and report a clean working tree.
If cloning fails, read the error before changing anything. Authentication failures and
missing repository access require different fixes.

### Add the shared files

Create `.gitignore` in the repository root with these entries:

```text
# Java compiler and build output
*.class
out/
build/

# Editor and operating-system files
.DS_Store
Thumbs.db
```

You may commit a `.vscode` folder later if it contains settings the reviewer needs. Check
every file before committing it and keep machine-specific or private settings out.

### Commit and submit A00

Review and publish the setup files:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git status
git diff
git add .gitignore README.md assignments/a00-practice-repository-setup/README.md
git diff --staged
git commit -m "Complete A00: Set up practice repository"
git push
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git status
git diff
git add .gitignore README.md assignments/a00-practice-repository-setup/README.md
git diff --staged
git commit -m "Complete A00: Set up practice repository"
git push
```

</CodeTab>
</CodeTabs>

Open the repository on GitHub after the push. Confirm that all three files appear and
that the newest commit has the message shown above. Send the repository URL to your
reviewer. For a private repository, ask the reviewer to confirm access.

### Workflow for A01 through A28

Use the same repository for the rest of Practice:

1. Pull before starting if you work on more than one computer.
2. Create the assignment folder named on its GarageDocs page.
3. Keep that assignment's source files, input files, and notes in its folder.
4. Run the program and complete the self-grading rubric.
5. Update the root `README.md` with the status, self-score, and folder link.
6. Review `git status`, `git diff`, and `git diff --staged`.
7. Commit with `Complete AXX: Assignment name` and push.
8. Open GitHub and confirm the commit and files are visible.

The in-page editor remains useful for quick checks. Your GitHub repository is the
submission record, so copy the completed work into its assignment folder and run it
locally before marking the assignment complete.

### Completion check

A00 is complete when:

- The repository opens on GitHub
- The root `README.md` identifies the student and contains the submission table
- `.gitignore` excludes Java build output
- The A00 folder records the setup details
- The reviewer can open the repository
- The setup commit is visible on GitHub
