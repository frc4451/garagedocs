**Cites:** [Create a GitHub Account](/tools/creating-your-github-account), [Install Git](/tools/installing-git), [Java Setup](/java/fundamentals/java-setup), [VS Code: Tour](/tools/vscode-tour), [Local Git Workflow](/tools/local-git-workflow),

[GitHub Remotes](/tools/github-remotes).
**Difficulty:** beginner. **Estimated time:** 30–45 minutes.

## Scenario

You will keep every Practice assignment in one GitHub repository. Each assignment gets
its own folder, while the repository's `README.md` records what you have finished and
your self-score. Your reviewer can use one link to inspect your current work and commit
history throughout the track.

Complete this setup before A01. You need Git, Java 25, a verified GitHub account, and VS Code.
Git is the program that records changes on your computer. GitHub is the website that stores
a remote copy and lets your reviewer see it. If any requirement is missing, follow
[Create a GitHub Account](/tools/creating-your-github-account) and
[Install Git](/tools/installing-git), then complete [Java Setup](/java/fundamentals/java-setup).
Java Setup includes VS Code installation. Use
[VS Code: Tour](/tools/vscode-tour#open-the-folder-not-the-file) if you need help opening the
correct folder. Open PowerShell on Windows or Terminal
on macOS or Linux, run `git --version` and `java --version`, and ask a mentor for help if either
command says it is not recognized or not found.

## What To Build

Create a GitHub repository named `<yourname>Badge01`, replacing `<yourname>` with your
first name (for example `AlexBadge01`). Public and private repositories both work. Follow
your team's privacy policy. If the repository is private, grant your mentor or reviewer
access before you submit it.

Badge 1 students create this repository locally and push it to GitHub in
[Step 3: Git](/badges/badge-1-git), rows 3.2 to 3.6. A **local repository** is the project
folder on your computer. The **GitHub repository** is the remote copy on the website. A
**clone** is a new local copy made from the GitHub repository.

Your finished repository will have this starting structure:

```text
<yourname>Badge01/
├── .gitignore
├── README.md
└── assignments/
    └── a00-practice-repository-setup/
        └── README.md
```

Do not put passwords, access tokens, private keys, robot credentials, or Driver Station
logs in this repository.

## Choose Your Starting Point

<RulesBox title="Use One Local Copy">

- If the repository is already on this computer, open that existing folder. Do not clone it again.
- If the repository exists on GitHub but is not on this computer, clone it by following the next section.
- If it exists in neither place and you are completing Badge 1, finish rows 3.2 through 3.6 in
  [Step 3: Git](/badges/badge-1-git), then return here. Those rows create the repository locally
  and publish it to GitHub.
- If you are completing A00 outside the Badge 1 sequence, create it on GitHub and clone it by
  following the next section.

</RulesBox>

If you already have a local copy, select **File → Open Folder** in VS Code and choose the
repository folder. Select **Terminal → New Terminal**, run `git status`, and confirm that Git
reports a branch instead of saying the folder is not a repository. Then continue to
[Add The Shared Files](#add-the-shared-files).

In every case, continue only when one local repository folder is open in VS Code and the same
repository is visible in your GitHub account.

## Create Or Clone From GitHub

Use this section when the repository is not on this computer. If it already exists on GitHub,
skip steps 1 and 2. If you already have a local copy, continue to
[Add The Shared Files](#add-the-shared-files).

1. Sign in to GitHub and create a repository named `<yourname>Badge01`.
2. Add a `README.md` when GitHub asks whether to initialize the repository.
3. Copy the repository's URL from its **Code** menu.
4. Choose a parent folder for your projects, outside any existing repository. Open that folder
   with **File → Open Folder** in VS Code, then select **Terminal → New Terminal**.
   Cloning will create the repository folder inside this parent folder. Paste the repository URL between the quote
   marks on the first line below. The example folder name uses `AlexBadge01`; replace it with
   your actual repository name. Do not type angle brackets around your name.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
$RepositoryUrl = "PASTE THE REPOSITORY URL HERE"
git clone $RepositoryUrl
cd AlexBadge01
git status
git remote -v
```

</CodeTab>
<CodeTab label="Terminal">

```bash
repository_url="PASTE THE REPOSITORY URL HERE"
git clone "$repository_url"
cd AlexBadge01
git status
git remote -v
```

</CodeTab>
</CodeTabs>

Cloning creates a new folder and connects it to the GitHub repository. It is only appropriate
when that repository is not already cloned on this computer. `git status` should name the
repository's default branch and report a clean working tree.
`git remote -v` should show the GitHub URL you copied, usually beside the name `origin`.
If cloning fails, read the error before changing anything. Authentication failures and
missing repository access require different fixes.

After the clone succeeds, select **File → Open Folder** in VS Code and open the newly created
repository folder, such as `AlexBadge01`. Confirm that its name appears at the top of the
Explorer before creating files. The earlier `cd` command changed the terminal's folder; it did
not change the folder displayed in the VS Code Explorer.

## Add The Shared Files

Create `.gitignore` in the repository root with these entries:

```text
# Java compiler and build output
*.class
out/
build/

# Editor and operating-system files
.DS_Store
Thumbs.db
```

You may commit a `.vscode` folder later if it contains settings the reviewer needs. Check
every file before committing it and keep machine-specific or private settings out.

## Give The Reviewer Access

If the repository is public, send its URL to your reviewer. If it is private, open the
repository on GitHub, select **Settings**, open the access section for collaborators, and add
the reviewer's exact GitHub username. GitHub may ask you to confirm your password. The reviewer
must accept the invitation before they can open the private repository. Never ask for or share
passwords, authentication codes, access tokens, recovery codes, or private keys.

## Commit And Submit A00

Before publishing, check that the three setup files contain your information and that your
reviewer can access the GitHub repository. Change A00’s status in the root README from
`Not started` to `Complete`, then save the file. The completion check below is your final
confirmation after publishing.

Before running the commands, confirm that the terminal prompt shows your practice repository
folder. `git status` lists changed and new files. `git diff` shows unstaged changes to tracked
files, so a brand-new file may appear only in `git status`. `git add` selects the three named
files for the next commit, and `git diff --staged` shows exactly what that commit will record.
The final `git push` sends the commit to GitHub.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git status
git diff
git add .gitignore README.md assignments/a00-practice-repository-setup/README.md
git diff --staged
git commit -m "Complete A00: Set up practice repository"
git push
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git status
git diff
git add .gitignore README.md assignments/a00-practice-repository-setup/README.md
git diff --staged
git commit -m "Complete A00: Set up practice repository"
git push
```

</CodeTab>
</CodeTabs>

Open the repository on GitHub after the push. Confirm that all three files appear and
that the newest commit has the message shown above. Send the repository URL to your
reviewer. For a private repository, ask the reviewer to confirm access.

## Workflow For A01 Through A28

Use the same repository for the rest of Practice:

1. Pull before starting if you work on more than one computer.
2. Create the assignment folder named on its GarageDocs page.
3. Keep that assignment's source files, input files, and notes in its folder.
4. Run the program and complete the self-grading rubric.
5. Update the root `README.md` with the status, self-score, and folder link.
6. Review `git status` and `git diff`.
7. Stage the selected assignment files and the root `README.md` with `git add`, using their
   explicit file paths. Then review exactly what is staged with `git diff --staged`.
8. Commit with `Complete AXX: Assignment name` and push.
9. Open GitHub and confirm the commit and files are visible.

The in-page editor remains useful for quick checks. Your GitHub repository is the
submission record, so copy the completed work into its assignment folder and run it
locally before marking the assignment complete.

## Completion Check

After the push, confirm all of these items:

- The repository opens on GitHub
- The root `README.md` identifies the student and contains the submission table
- `.gitignore` excludes Java build output
- The A00 folder records the setup details
- The reviewer can open the repository

- The A00 row in the root `README.md` says `Complete`
- The setup commit is visible on GitHub

These checks confirm the repository structure and published files. They do not judge the
quality or correctness of later assignment programs.
