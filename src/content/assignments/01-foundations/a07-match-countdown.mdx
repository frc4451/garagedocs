## Scenario

Print the entire fictional timeline from A05. The text bar and percentage help you check the first second, phase boundaries, and final second. The program prints the timeline immediately; it does not wait a real second per line.

## What To Build

A single file `MatchCountdown.java`. No user input for the timeline itself. Print **151
lines**, one for each `t = 0` through `t = 150`:

```text
t=  0  AUTO     [                                ]   0%
t=  1  AUTO     [                                ]   0%
t= 15  TELEOP   [###                             ]  10%
t= 75  TELEOP   [################                ]  50%
t=120  ENDGAME  [#########################       ]  80%
t=150  OVER     [################################] 100%
```

After all 151 lines, prompt `Run again? (y/n):` and replay on `y`. Use a `do-while` for the
outer replay loop.

This is a simulated countdown: `t` is a loop counter, and each line is printed as fast as
the computer can produce it. Do not add `Thread.sleep` or any other delay. A real-time
program needs a clock and must account for scheduling delays, which is outside this
exercise.

## Replay Loop

A `do-while` runs its body once before it checks the condition. That matches this program
because the first timeline must print before there is an answer to test. Use this partial
structure inside `main`; fill in the timeline and prompt where the comments say:

```java norun
String answer;
do {
    // A for loop prints t = 0 through t = 150 here.
    System.out.println("Run again? (y/n):");
    if (in.hasNextLine()) {
        answer = in.nextLine().trim();
    } else {
        answer = "n";
    }
} while (answer.equalsIgnoreCase("y"));
```

The semicolon after the closing `while (...)` is required. This snippet belongs inside
`main`, after the `Scanner` is created and before it is closed. It is a partial scaffold:
the comment still stands for the required timeline loop. Both branches of the `if` statement
assign `answer`, so Java can prove it is initialized before the condition. Treating end of
input as `n` also lets a browser run finish if its input box has no further line.

## Format Details

- The bar is **32 characters** between the brackets. Fill `t * 32 / 150` of them with `#`
  using integer division, and pad the rest with spaces
- The percent is the integer percent elapsed, `t * 100 / 150`, right-aligned in three columns
- Phases use the [A05](/java/assignments/a05-match-phase-detector) boundaries: `AUTO` below 15,
  `TELEOP` from 15 to 119, `ENDGAME` from 120 to 149, `OVER` at 150
