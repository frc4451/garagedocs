## Scenario

Estimate a voltage drop from a supplied resistance and current, then subtract it from the resting voltage:

```text
vAtMotor = vRest - (current x resistance)
```

Use volts for voltage, amps for current, and ohms for resistance. The `x` in the formula means multiplication; write `*` in Java. The supplied resistance represents opposition to current flow in this model. For optional background on voltage and current, read [Electrical Basics](/hardware/electrical-basics-voltage-current#start-with-three-quantities). You only need the supplied numbers and arithmetic for this console assignment.

This is a classroom circuit model. Its fixed resistance and current do not describe every change in a real battery or drivetrain. The verdict strings are exercise labels, not a battery health test or approval to use a battery.

The thresholds classify the **calculated motor-terminal voltage** from this one simplified
model. They do not classify the resting voltage by itself, measure battery capacity, or
replace your team's battery-testing and electrical-safety procedures. In this assignment,
`Healthy.` means only that the calculated result is at least 9.0 V; `Replace immediately.`
is required exercise output for a result below 7.0 V.

## What To Build

A single file `BatterySanity.java` with one class and one `main`. It should:

1. Read **three** doubles in this order: resting voltage in volts, total resistance in
   ohms, worst-case current in amps
2. Compute `vAtMotor`
3. Print the three inputs and the result, all to **two decimal places**
4. Print **one** verdict line:

<ContentTable
  headers={["Predicted voltage", "Verdict"]}
  rows={[
    ["9.0 V or more", "<code>Healthy.</code>"],
    ["7.0 V up to but not including 9.0 V", "<code>Marginal, consider a fresh battery.</code>"],
    ["Below 7.0 V", "<code>Replace immediately.</code>"]
  ]}
/>

Worked example: resting 12.6 V, resistance 0.025 ohm, current 150 A predicts 8.85 V, which
is marginal.

Work through that example in two steps: `150.0 * 0.025` gives a modeled drop of `3.75 V`,
then `12.6 - 3.75` gives `8.85 V`. Compare `8.85` with the named thresholds only after
the calculation. Exactly `9.0` is healthy, while exactly `7.0` is marginal because the
table includes 7.0 in the middle interval.

## Requirements

- Use `double` for every number. `int` is wrong here: see the hint on division
- Use `printf` or `String.format`. Two decimal places everywhere
- Define the two thresholds as `final double` constants. No bare numbers in the `if` chain
- Exactly one `Scanner`, closed before the program exits

## Stretch Goals

Keep the checked required version unchanged. Try either stretch goal in a separate source
copy with a matching class name so its extra input or output cannot affect **Check**.

- Add a fourth prompt for the **expected** current draw, in addition to the worst-case current. Print two
  predictions and pick the verdict from the worse of the two.
- Reject negative voltage, resistance, or current with a clear message. A conditional is
  enough because the values have already been read as numbers. [Try/Catch](/java/fundamentals/try-catch#why-use-trycatch)
  becomes useful later when you also want to recover from text that is not a number.
