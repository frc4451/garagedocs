## Scenario

Build a lookup table from example distance and RPM pairs. For a distance between two samples, calculate an estimate using linear interpolation.

The supplied numbers are practice data. A working calculation does not establish that a physical launcher will score at that speed.

## What To Build

A single file `ShooterLookup.java` with these `public static` methods:

This is an API checklist, not a complete Java class. Each declaration still needs a body:

```java norun
public static double[][] readSamples(Scanner in, int n);
public static void       sortSamples(double[][] samples);
public static int        upperIndex(double[][] samples, double distance);
public static double     interpolate(double[][] samples, double distance);
public static void       printSamples(double[][] samples);
public static double     rpmFor(double[][] samples, double distance);
```

`main` reads `n` (at least 2), fills a `double[n][2]` where column 0 is distance and column
1 is RPM, sorts by distance ascending, prints the sorted table, then loops: read a distance,
print its RPM, stop on a negative distance.

Each `samples[row]` is a two-value `double[]`: the distance and RPM are one paired row.
That is why sorting must move an entire row reference together. `readSamples` creates and
returns the table; `sortSamples` changes that table in place; `upperIndex` returns an
index; `interpolate` and `rpmFor` return calculated RPM values; and `printSamples` formats
the sorted table. `rpmFor` must make the three-case numeric decision required below. The
query loop in `main` can then print `RPM = ...` followed by the applicable clamp label by
comparing the same query with the first and last distances. That reporting does not move
the RPM decision out of `rpmFor`. Declare all six methods `public static`, inside
`ShooterLookup` and outside `main`, exactly as shown above.

You do not need to finish the later sorting course before this assignment. Use this
insertion-sort process: begin with row 1, save that whole row as the current pair, and
compare its distance with rows to its left. Shift each larger row one position to the
right, then place the saved pair in the open position. Repeat for rows 2 through
`samples.length - 1`. Compare `samples[row][0]`, the distance column, but move or save
`samples[row]`, the whole paired row. The linked [Sorting](/java/fundamentals/sorting-algorithms)
lesson provides the full insertion-sort explanation if you need it.

For the required supplied practice numbers, write an honest comment such as “supplied
exercise data, not measured on a robot.” If you replace them with data your team actually
measured, record where and when that measurement happened. Do not invent measurement
provenance to satisfy the comment rubric.

Print results as `RPM = 3150.00`, and the sorted table as `1.00 m -> 2200.00 rpm`.

Worked example: samples at 1.0 m / 2200 rpm, 2.0 m / 2800 rpm, 3.0 m / 3500 rpm, 4.0 m /
4100 rpm. A query at 2.5 m sits halfway between the second and third samples, so the answer
is 3150.00.

Here is that calculation one step at a time. The first sorted distance at or above `2.5`
is `3.0`, so `upperIndex` identifies the 3.0 m row and the lower row is the 2.0 m row.
The fraction across the bracket is `(2.5 - 2.0) / (3.0 - 2.0) = 0.5`. The RPM rise is
`3500 - 2800 = 700`, so the estimate is `2800 + 0.5 * 700 = 3150`.

Boundary order matters. `rpmFor` first handles `distance <= firstDistance`, then
`distance >= lastDistance`, and only then calls `interpolate`. For a query exactly on an
interior sample, `upperIndex` finds that sample because it searches for the first distance
that is **at or above** the query. The interpolation fraction becomes `1.0` for the lower
bracket, returning that sample's RPM apart from possible floating-point rounding. You may return a matching sample directly to preserve its stored value. Do not call `interpolate` for either outer
boundary.

Use at least two samples with distinct distances for the required exercise. Duplicate-distance handling is an extension below.

- Sort with a sort you write yourself. Insertion sort is plenty at this size
- `rpmFor` decides which of the three cases applies; `interpolate` only ever handles the
  in-between case
- The table is printed after sorting, so the user can check the data went in correctly

## Stretch Goals

Save the checked required version first. Keep stretch work in a separate folder so changed input or output does not replace the required submission.

- Replace the linear scan in `upperIndex` with a binary search and confirm it gives identical
  answers on every query. See [Finding a boundary](/java/fundamentals/searching#finding-a-boundary).
- Reject a table with two samples at the same distance, since interpolating between them
  divides by zero. Decide whether to refuse the input or drop the duplicate.
