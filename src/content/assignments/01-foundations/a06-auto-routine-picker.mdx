### Scenario

Three minutes before a match you agree on an auto routine with your alliance partner. The
decision depends on where you start, what your partner intends to do, and how fresh the
battery is. Written down as rules it is short, which makes it a good first enum problem,
and a good lesson in why rule *order* matters.

### What to build

Four enums and a picker:

```java
enum StartPosition     { LEFT, CENTER, RIGHT }
enum PartnerPlan       { SCORE, DEFENSE, UNKNOWN }
enum BatteryCondition  { FRESH, WARM, COLD }
enum AutoRoutine {
    CENTER_CROSS_AND_SHOOT, CENTER_CROSS_ONLY,
    LEFT_AVOID, RIGHT_AVOID, SIDE_SPRINT, SAFE_HOLD
}
```

`main` reads three words: start position, partner plan, battery condition, each
case-insensitive: converts them with `valueOf` on the uppercased, trimmed input inside a
re-prompt loop, then calls:

```java
static AutoRoutine chooseRoutine(StartPosition pos, PartnerPlan partner, BatteryCondition battery)
```

and prints the routine plus a one-line reason.

### The rules

Apply them in order. The first rule that matches wins:

### Requirements

- `chooseRoutine` is a pure function: enums in, an `AutoRoutine` out, nothing printed
- Invalid input re-prompts rather than crashing. `valueOf` throws
  `IllegalArgumentException` on an unknown name
- The reason line names the rule that fired, so a driver can sanity-check the choice
