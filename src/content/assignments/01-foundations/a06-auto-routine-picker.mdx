## Scenario

Choose a routine from a starting position, partner plan, and battery label. Apply the supplied rules in order so the same inputs always give the same answer.

This console exercise prints a choice; it does not plan a collision-free path or operate a robot.
`FRESH`, `WARM`, and `COLD` are exercise labels supplied as input. The program does not
measure voltage, temperature, state of charge, or battery health.

## What To Build

Four enums and a picker:

```java norun
enum StartPosition     { LEFT, CENTER, RIGHT }
enum PartnerPlan       { SCORE, DEFENSE, UNKNOWN }
enum BatteryCondition  { FRESH, WARM, COLD }
enum AutoRoutine {
    CENTER_CROSS_AND_SHOOT, CENTER_CROSS_ONLY,
    LEFT_AVOID, RIGHT_AVOID, SIDE_SPRINT, SAFE_HOLD
}
```

`main` reads three words in order: start position, partner plan, and battery condition. Trim and uppercase each word before calling that enum's `valueOf` method. Use `toUpperCase(java.util.Locale.ROOT)` so conversion does not depend on the computer's language settings. If a word is invalid, ask for that value again. If input ends, stop the run instead of asking forever.

After reading three valid values, `main` calls this method and prints its returned routine plus a one-line reason. This declaration sketch needs a method body:

```java norun
public static AutoRoutine chooseRoutine(StartPosition pos, PartnerPlan partner, BatteryCondition battery)
```

The method declaration is a contract between the caller and the method. `main` supplies
three enum values in the parentheses. `chooseRoutine` examines those parameters and must
`return` one `AutoRoutine` on every possible path. Keep the declaration inside
`AutoPicker`, but outside `main`. The supplied enums stay outside `AutoPicker` in the
browser file. They have package access, which lets the class in the same file use them.

## The Rules

Apply them in order. The first rule that matches wins:

  headers={["#", "When", "Routine"]}
  rows={[
    ["1", "Partner is <code>UNKNOWN</code>", "<code>SAFE_HOLD</code>: hold position in this exercise"],
    ["2", "Partner is <code>DEFENSE</code>, anywhere", "<code>SIDE_SPRINT</code>"],
    ["3", "<code>CENTER</code> and battery <code>FRESH</code>", "<code>CENTER_CROSS_AND_SHOOT</code>"],
    ["4", "<code>CENTER</code>, any other battery", "<code>CENTER_CROSS_ONLY</code>"],
    ["5", "<code>LEFT</code> and partner <code>SCORE</code>", "<code>LEFT_AVOID</code>"],
    ["6", "<code>RIGHT</code> and partner <code>SCORE</code>", "<code>RIGHT_AVOID</code>"],
    ["7", "Anything not covered above", "<code>SAFE_HOLD</code>"]
  ]}
/>

Treat this table like a checklist from top to bottom. For example,
`CENTER, DEFENSE, FRESH` also satisfies the centre-and-fresh rule, but the earlier
`DEFENSE` rule wins. You can express the ordered checks with early `return` statements,
or with an equivalent ordered structure. A `switch` is useful once you reach rules that
depend on `pos`; it does not replace the higher-priority partner checks.

## Requirements

- `chooseRoutine` is a pure function: enums in, an `AutoRoutine` out, nothing printed
- Invalid input re-prompts rather than crashing. `valueOf` throws
  `IllegalArgumentException` on an unknown name
- The reason line names the rule that fired, so a driver can sanity-check the choice
