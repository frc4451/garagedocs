## Scenario

A trailing moving average replaces each reading with the mean of recent readings. It reduces short-term variation but delays the response to a change.

At the beginning of the array, average only the readings available. Do not fill the missing positions with zeros.

## What To Build

A single file `SmoothOne.java`:

1. Read `n`, a positive `int`, then `n` doubles into a `double[] readings`
2. Read `window`, an `int` from 1 to `n` inclusive
3. Build `double[] smoothed` where `smoothed[i]` is the mean of `readings` from index
   `max(0, i - window + 1)` through index `i`, inclusive at both ends
4. Print the index as an integer, then the raw and smoothed values to two decimal places.

```text
i   raw     smoothed
0   10.10   10.10
1   12.20   11.15
2   11.80   11.37
3    9.40   11.13
4   10.00   10.40
5    8.00    9.13
```

An array of length `n` has valid indices `0` through `n - 1`. The inner loop must start
at `lower`, stop after including `i`, and never use a negative index. Divide the sum by
`i - lower + 1`, the number of entries actually visited. In particular, the first output
divides by 1, not by the full window size.

## Stretch Goals

Save the checked required version first. Keep stretch work in a separate folder so changed input or output does not replace the required submission.

- Make each output O(1) instead of O(window): keep a running sum, add the reading that
  enters the window and subtract the one that leaves. The whole smoother becomes O(n),
  and the difference is the whole point of [Big-O](/java/fundamentals/big-o#the-hidden-loop). Check it still
  matches your two-loop version to two printed decimal places, including the ragged start.
  The two versions may accumulate floating-point additions in a different order, so their
  unrounded `double` values can differ by a tiny amount even when both calculations are
  correct. O(1) here means a constant amount of update work for each new output after the
  running sum has been initialized; the complete pass is O(n).
- Add a centred moving average that looks both ways, and describe what it costs you on a
  live robot. The answer involves the word *latency*.
- Report the standard deviation of the raw readings alongside the smoothed trace, so you can
  say how noisy the encoder was.
