A practice roadmap that pairs with [Java Training](/java). Every assignment names the
lessons it builds on, gives you a scenario and a rubric, and stops short of handing you a
solution. Hints are deliberately just enough to break you out of being stuck, not enough
to skip understanding.

These assignments are **standalone Java programs**. You do not need WPILib installed for
any of them. The point is to get the language locked in before you also have to reason
about robot hardware, the command scheduler, and the 50 Hz periodic loop.

<RulesBox title="Read this page before you start">

- The rubric is yours to fill in honestly — nothing here scores you
- Hints never contain the working answer
- Write your own code; naming a technique you saw is fine, pasting a class is not
- **Java 25** is the standard. Install it locally, and every JavaDoc link here
  points at the Java 25 API
- The in-page editor runs **Java 17** — records, `var`, text blocks, arrow `switch`
  and sealed types all work. What it does *not* have is anything newer than 17;
  pattern matching in `switch`, for instance, arrived in Java 21
- The first Run on a page takes about half a minute while the compiler warms up.
  After that it answers in well under a second

</RulesBox>

### What an assignment looks like

Every assignment uses the same shape, so you always know where to look:

1. **Topic** — a few words naming the concept this targets
2. **Cites** — links into [Java Training](/java). Not optional reading; they define the
   vocabulary the rubric expects
3. **Difficulty and time** — a rough estimate for someone who read the cited lessons and
   is not stuck looking up syntax
4. **Scenario** — the problem in plain language
5. **What to build** — the concrete requirements: method names, expected input and output,
   edge cases. This is the contract you are filling
6. **Hints** — collapsed, for when you are stuck. Method signatures, a one-line skeleton,
   or a pointer to the exact JavaDoc page
7. **Self-grading rubric** — a point breakdown totalling 100
8. **Stretch goals** — optional extensions if you finish early
9. **References** — JavaDoc, background reading, related lessons

### The rubric

Every assignment scores the same four sections. Per-line points shift with the
assignment; the totals do not.

If you cannot honestly give yourself the full 60 in Functionality, you are not done. Edge
cases and code quality come *after* the program works.

### Hints are not solutions

A hint is allowed to be a signature with an empty body, a pointer to the JavaDoc page that
has what you need, or a note that the classic mistake here is comparing two `String`
values with `==`.

A hint is **not** the worked answer with one variable renamed. If a hint looks like the
program with three lines removed, the problem is too hard for this stage or the hint is
too generous — the prompt gets reworked, not the hint.

### Build your own; don't paste

The FRC programs that win competitions are written by students who understand every line.
This track holds that standard.

You will hear about production codebases: your team's robot code, AdvantageKit, public
repositories from other teams. Those are valuable as references. **Naming a technique you
saw is fine. Pasting a class from someone else's repository into your own project is
not.**

When an assignment asks you to design a small version of a technique, that is deliberate.
The smaller version forces you to make the design decisions yourself: which fields belong
on the class, what methods the interface needs, what gets validated in the constructor.
Once you have earned that judgment, reading a 500-line production version teaches you
something. Before you have earned it, copying it teaches you nothing.

A practical rule: **if you cannot explain a line you wrote, rewrite it until you can.**

### Pitfalls that bite almost everyone

- **Comparing strings with `==`** — use `.equals()`. See [Comparing strings](/java/java-conditionals#comparing-strings)
- **Mixing `nextInt()` and `nextLine()`** — a stray newline stays in the buffer
- **Integer division** — `7 / 2` is `3`, not `3.5`. See [Integer vs floating-point division](/java/java-calculations#integer-vs-floating-point-division)
- **Off-by-one in array loops** — use `< array.length`, not `<=`. See [Arrays](/java/java-arrays)
- **`NullPointerException` from an object array** — new object arrays start full of `null`
- **Forgetting `@Override`** — the compiler catches typos and signature mismatches for you
- **`catch (Exception e) {}`** that hides bugs — catch specifics, or let it propagate
