### Choose the project template

GarageDocs uses **Java** and the **Command Robot** template. Choose that combination when following the Kit Bot or FRC curriculum.

Both common templates use WPILib's `TimedRobot` lifecycle. The difference is how the robot's behavior is organized.

| Template | How code is organized | When to choose it |
|---|---|---|
| **Command Robot** | Subsystems represent mechanisms. Commands represent actions and use those subsystems. | Use this for GarageDocs and FRC 4451 robot projects. |
| **Timed Robot** | Most behavior is written directly in mode-specific methods such as `autonomousPeriodic()` and `teleopPeriodic()`. | Use this for a focused experiment or when the project has intentionally chosen that structure. |

Command Robot still extends `TimedRobot`. It adds the command scheduler, button bindings, subsystems, and commands around that lifecycle.

### Before you create the project

Have these ready:

- WPILib VS Code for the current season
- Your FRC team number
- A short project name
- A local folder that is **outside OneDrive**

<RulesBox title="Keep the project outside OneDrive">

WPILib does not support creating projects inside OneDrive because file synchronization and caching can interfere with Gradle. On Windows, check whether the Desktop or Documents folder is managed by OneDrive before selecting it.

</RulesBox>

### Create the project

1. Open **WPILib VS Code**.
2. Press `Ctrl+Shift+P` on Windows or Linux. Press `Cmd+Shift+P` on macOS.
3. Enter `WPILib: Create a new project`, then select that command.
4. Complete the Project Creator with the values below.

| Field | Select or enter | Why |
|---|---|---|
| Project Type | **Template** | Starts from a WPILib robot template |
| Language | **Java** | Matches the GarageDocs curriculum and FRC 4451 projects |
| Base | **Command Robot** | Creates the command-based project structure |
| Project Location | A local folder outside OneDrive | Sets the parent folder for the project |
| Create a New Folder | Checked | Places the project in its own folder |
| Project Name | A clear name such as `KitBot2027` | Names the project and its folder |
| Team Number | Your FRC team number | Tells WPILib which roboRIO receives a deployment |
| Enable Desktop Support | Either setting for Java | WPILib states that this option has no effect on Java projects |

5. Review every field, then select **Generate Project**.
6. Select **Yes** when VS Code asks whether to open the new project.

If generation fails, read the notification in the lower-right corner of VS Code. A nonempty destination folder or an unsupported OneDrive location are two items to check before trying again.

### Check the generated files

Open the Explorer panel on the left side of VS Code. A Java Command Robot project includes these important paths:

| Path | Purpose | First action |
|---|---|---|
| `src/main/java/frc/robot/Main.java` | Starts the robot program | Leave it unchanged |
| `src/main/java/frc/robot/Robot.java` | Connects robot modes to the command scheduler | Read it before changing it |
| `src/main/java/frc/robot/RobotContainer.java` | Creates subsystems and defines controller bindings | Expect most robot setup to begin here |
| `src/main/java/frc/robot/Constants.java` | Holds shared IDs, dimensions, limits, and gains | Replace example values with documented robot values |
| `src/main/java/frc/robot/subsystems/` | Contains code for physical mechanisms | Add one subsystem for each mechanism responsibility |
| `src/main/java/frc/robot/commands/` | Contains actions that use subsystems | Add commands when an action needs its own class |
| `vendordeps/` | Records installed third-party libraries | Add only the libraries required by the robot hardware |
| `build.gradle` | Configures GradleRIO and project dependencies | Leave generated settings intact for the first build |
| `.wpilib/wpilib_preferences.json` | Stores the team number and project preferences | Confirm the team number before deploying |

The template may include an example subsystem and example command. Keep the generated files intact until the project completes its first build. This separates project-generation problems from problems introduced by later edits.

### Build before adding robot code

1. Press `Ctrl+Shift+P` or `Cmd+Shift+P`.
2. Run `WPILib: Build Robot Code`.
3. Read the terminal output.
4. Continue when the build ends with `BUILD SUCCESSFUL`.

If the first build fails, start with the first error in the terminal. Confirm that the project is outside OneDrive, the current WPILib release created it, and VS Code opened the folder containing `build.gradle`.

<RulesBox title="Done when">

The project opens in WPILib VS Code, `.wpilib/wpilib_preferences.json` contains the correct team number, and the unchanged template finishes with `BUILD SUCCESSFUL`.

</RulesBox>
