Elastic is a desktop dashboard for an FRC robot. It reads NetworkTables data, displays that data through widgets, and can serve as the dashboard beside the Driver Station during a match. Use it to show the driver a few values that affect decisions, such as match time, mechanism readiness, selected autonomous routine, and robot pose.

Use [AdvantageScope](/frc/reading-a-match-log) when you need detailed graphs or log replay. Use Elastic when the driver or operator needs a clear live display.

### Launch Elastic

The WPILib installer includes Elastic. Launch the installed desktop application from VS Code:

1. Press `Ctrl+Shift+P` to open the Command Palette.
2. Run **WPILib: Start Tool**.
3. Select **Elastic**.

On Windows, the WPILib installer also places a shortcut in the current year's WPILib Tools folder. You do not need to open a website to run Elastic.

### Connect to the robot

Start the robot program or WPILib simulation before checking the connection.

Elastic can retrieve the robot address from the Driver Station. If the connection indicator stays disconnected, check these items in order:

1. Confirm that the Driver Station or simulation is running.
2. Confirm that the project and Driver Station use the correct team number.
3. Confirm that the laptop is connected to the robot network when using real hardware.
4. Use [Robot Network Troubleshooting](/frc/robot-network-troubleshooting) if the Driver Station also cannot reach the roboRIO.

A disconnected Elastic window does not identify the cause by itself. The Driver Station connection indicators show whether the problem affects the whole robot connection or only the dashboard.

### Publish a value

Elastic reads NetworkTables topics. `SmartDashboard` provides a short way to publish values to those topics.

This complete `Robot.java` example publishes three values. Run it in simulation, open Elastic, and look for the entries under `SmartDashboard`.

```java
package frc.robot;

import edu.wpi.first.wpilibj.TimedRobot;
import edu.wpi.first.wpilibj.smartdashboard.SmartDashboard;

public final class Robot extends TimedRobot {
    private static final String STATUS_KEY = "Robot Status";
    private static final String READY_KEY = "Launcher Ready";
    private static final String TARGET_RPS_KEY = "Launcher Target RPS";

    @Override
    public void robotPeriodic() {
        SmartDashboard.putString(STATUS_KEY, "Running");
        SmartDashboard.putBoolean(READY_KEY, false);
        SmartDashboard.putNumber(TARGET_RPS_KEY, 45.0);
    }
}
```

The key becomes the topic name and widget label. Publishing the same key again updates the existing value.

Choose names that describe what the number represents. `Launcher Target RPS` distinguishes a requested velocity from a measured velocity. Publish the measured value under a separate key such as `Launcher Measured RPS`.

### Add and arrange widgets

1. Select **Add Widget**.
2. Find the topic in the NetworkTables list.
3. Drag a compatible widget onto the active tab.
4. Resize the widget and edit its title, range, or display type.
5. Save the layout with **File → Save** or `Ctrl+S`.

### Build a driver layout

Keep the competition layout focused on information the drive team can act on. A useful first layout can include:

- match time;
- robot connection and battery state;
- selected autonomous routine;
- launcher or mechanism readiness;
- one camera stream;
- warnings that require a driver response.

Place related widgets together. Use separate tabs for competition, testing, and mechanism setup when one screen becomes crowded.

Lock the layout after arranging it. **Edit → Lock Layout** prevents a drag on a control from moving or deleting a widget. Export the finished layout to a JSON file so another Driver Station laptop can import the same arrangement.

### Display robot pose

Elastic can display a `Field2d` object. The robot code must already calculate a `Pose2d`; the dashboard does not create a pose estimate.

The following partial snippet belongs in the class that publishes dashboard data. Call `publishRobotPose` with the field-relative pose produced by the drivetrain or pose estimator.

```java
private final Field2d field = new Field2d();

public void initializeDashboard() {
    SmartDashboard.putData("Field", field);
}

public void publishRobotPose(Pose2d fieldToRobot) {
    field.setRobotPose(fieldToRobot);
}
```

The snippet needs these imports:

```java
import edu.wpi.first.math.geometry.Pose2d;
import edu.wpi.first.wpilibj.smartdashboard.Field2d;
import edu.wpi.first.wpilibj.smartdashboard.SmartDashboard;
```

After publishing the object, add its field widget in Elastic. If the robot icon remains at the origin, inspect the pose value in robot code before changing the dashboard layout.

### Read a dashboard value

Elastic controls can write values back through NetworkTables. Robot code can read them with `SmartDashboard.getNumber`, `getBoolean`, or the matching method for another type.

Treat a dashboard value as a request. The subsystem still applies its limits, enabled-state rules, and other safety checks. Do not use a dashboard control to bypass the commands and subsystem methods that normally control hardware.

```java
private static final String TEST_OUTPUT_KEY = "Test Output";

public void initializeTestOutput() {
    SmartDashboard.setDefaultNumber(TEST_OUTPUT_KEY, 0.0);
}

public double getRequestedTestOutput() {
    return SmartDashboard.getNumber(TEST_OUTPUT_KEY, 0.0);
}
```

`setDefaultNumber` supplies an initial value without replacing a value already stored in NetworkTables. Keep test controls on a testing tab and confirm that the robot is in the intended mode before applying the request.

### Check your work

You are finished when you can:

1. Launch Elastic as a WPILib desktop tool.
2. Connect it to simulation or a robot.
3. Publish a named value and add its widget.
4. Save and lock the layout.
5. Explain which values belong on the driver tab and which belong on a testing tab.
