### Configure the controller before moving the mechanism

Motor configuration connects software assumptions to the physical robot. This lesson covers four controller families used by FRC 4451:

| Controller | Configuration API |
|---|---|
| CTRE Talon FX | `TalonFXConfiguration` applied through the device configurator |
| REV SPARK MAX | `SparkMaxConfig` passed to `configure()` |
| REV SPARK Flex | `SparkFlexConfig` passed to `configure()` |
| Thrifty Nova | Configuration methods called on the `ThriftyNova` object |

In a command-based project, configure a controller in the constructor of the subsystem that owns it. In a Timed Robot project, configure it during robot initialization. Do not send motor output until configuration finishes.

### Decide each setting from the mechanism

| Setting | What it changes | How to verify it |
|---|---|---|
| Inversion | Which physical direction counts as positive output | Command a small positive output and observe the mechanism and encoder |
| Idle mode | Whether the motor resists motion or coasts at zero output | Stop the motor and observe how quickly the mechanism slows |
| Current limit | How much electrical current the controller permits | Watch current and voltage while applying a controlled load |

Brake mode resists motion when motor output is zero. It does not command the mechanism to hold a position. An elevator or arm that must hold a position needs closed-loop control and a safe plan for gravity.

Current limits are mechanism settings. Choose them from the motor data, controller documentation, wiring and breaker protection, expected load, gearing, and test results. The values below demonstrate API structure and are not defaults for every robot.

### CTRE Talon FX

The Talon FX collects settings in a `TalonFXConfiguration`, then applies the complete object through the controller's configurator.

```java
TalonFXConfiguration config = new TalonFXConfiguration();

config.MotorOutput.Inverted = InvertedValue.CounterClockwise_Positive;
config.MotorOutput.NeutralMode = NeutralModeValue.Brake;

config.CurrentLimits.SupplyCurrentLimitEnable = true;
config.CurrentLimits.SupplyCurrentLimit = 40.0; // Example only

m_motor.getConfigurator().apply(config);
```

CTRE identifies inversion by the positive rotor direction: clockwise or counterclockwise when viewed from the motor shaft. Confirm the installed orientation before choosing the enum value.

### REV SPARK MAX

Use `SparkMaxConfig` for a physical SPARK MAX. The motor type is selected separately when the `SparkMax` object is constructed.

```java
SparkMaxConfig config = new SparkMaxConfig();

config
        .inverted(false)
        .idleMode(IdleMode.kBrake)
        .smartCurrentLimit(40); // Example only

m_motor.configure(
        config,
        ResetMode.kResetSafeParameters,
        PersistMode.kPersistParameters);
```

`ResetMode.kResetSafeParameters` starts from known safe parameters before applying this configuration. `PersistMode.kPersistParameters` saves the settings through a power cycle. Apply persistent configuration during startup rather than repeatedly in a periodic method.

### REV SPARK Flex

Use `SparkFlexConfig` for a physical SPARK Flex. The configuration pattern resembles SPARK MAX, but the controller class and configuration class must match the hardware.

```java
SparkFlexConfig config = new SparkFlexConfig();

config
        .inverted(false)
        .idleMode(IdleMode.kBrake)
        .smartCurrentLimit(60); // Example only

m_motor.configure(
        config,
        ResetMode.kResetSafeParameters,
        PersistMode.kPersistParameters);
```

A SPARK Flex connected to a NEO Vortex still needs a limit selected for the mechanism. Riptide used a `60 A` smart current limit for each swerve drive motor. That value describes Riptide's drivetrain and should not be copied to a different mechanism without reviewing its design.

### Thrifty Nova

Thrifty Nova configuration methods return the same controller object, so related settings can be chained together. Current ThriftyLib distinguishes **supply current**, drawn from the robot power system, from **stator current**, flowing through the motor phases and producing torque.

```java
m_motor
        .setInversion(false)
        .setBrakeMode(true)
        .setMaxCurrent(CurrentType.SUPPLY, 40.0) // Example only
        .setMaxCurrent(CurrentType.STATOR, 60.0); // Example only
```

After configuration, inspect `m_motor.getErrors()`. A requested setting is not confirmed until the controller reports that it accepted the setting.

The Nova can operate several supported brushless motors. Confirm the motor selection in Thrifty Config, especially when switching between REV-style motors and the WCP Minion. The Minion requires its documented motor-type setting because its phase-wire colors differ.

### Test one setting at a time

1. Secure the robot and clear the mechanism's motion path.
2. Confirm the CAN ID and controller type in the vendor tool.
3. Apply a small positive output, such as `0.2`, and confirm direction.
4. Stop the motor and confirm the chosen brake or coast behavior.
5. Watch supply voltage and current while adding a controlled load.
6. Check controller faults and temperatures.
7. Power-cycle the robot and confirm settings that should persist.

<RulesBox title="Done when">

Positive output moves the mechanism in its documented positive direction. The idle mode produces the expected stopping behavior. Current remains within the mechanism's approved limits, and the vendor tool shows no unexplained configuration or hardware fault.

</RulesBox>
