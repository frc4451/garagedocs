### FRC programming

This section describes how FRC 4451's competition robot, [Cobra](https://github.com/frc4451/Cobra2026Private), is built, and how you will build the next one. It is not a beginner's guide. It **assumes you have completed [Kit Bot](/kit-bot)** (the 2026 KitBot rebuilt end to end and demonstrated in simulation) and that you have **mastery of Java** from [Java Training](/java) and the [Practice Assignments](/assignments). Lessons say "you did this in Kit Bot R07" and link there instead of repeating it. If a link points at something unfamiliar, do that module first.

Two groups overlap with Kit Bot on purpose, **Environment Setup** and **Basics**, so a returning student can reinstall a toolchain or re-read a vendor API without redoing the build. From [Our Robot Code](/frc/kit-bot-to-cobra) onward, everything is new.

### Curriculum structure

The groups run in the order the sidebar shows, and the order is deliberate: nothing on a page depends on a page after it, except where a lesson says so and links ahead.

**1. Environment Setup:** Installing WPILib (which brings VS Code, the simulator, AdvantageScope and Elastic with it) and the Driver Station, and understanding the project structure. Shared with [Kit Bot R00](/kit-bot/r00-wpilib-setup).

**Networking:** The `10.TE.AM` addressing every robot uses, the ports the field allows, and the diagnostic ladder applied to a robot. Both lessons are the FRC application of the [Networking](/tools/how-a-network-works) and [Command Line](/tools/command-line-basics) pages in the Tools section, and link back to them for every command.

**2. Basics:** Motor control, reading sensors, and handling joystick inputs, as a reference to the vendor APIs. Shared with Kit Bot's [R06](/kit-bot/r06-motor-controllers) and [R10](/kit-bot/r10-joysticks-and-stick-math).

**Our Robot Code:** The bridge from Kit Bot to Cobra (every idea you built by hand and where it lives in the competition robot), a guided tour of the repository and the ROBOTZ Garage library, and Lombok, which appears on half the classes you will read. The tour links ahead to most of the section; that is what a map is for.

**3. Command-Based Programming:** Command-based as Cobra does it: subsystems as thin wrappers over library mechanisms, command factories and readiness Triggers, command groups, the intake end to end, and how the project is organized.

**3.5. Logging and Replay:** AdvantageKit and the IO layer it is built on, which everything after this assumes; reading a match log in AdvantageScope; and log replay, which runs a match's recorded inputs back through the code on a laptop.

**4. Simulation:** Every behaviour at FRC 4451 is developed and proven on a laptop before it touches a robot. Running the simulator, writing the physics models that live behind the IO layer, watching the result in AdvantageScope live, and unit tests that run the same simulation without a GUI. This stage comes before control theory on purpose: the tuning you are about to learn is done in simulation first.

**5. Control Theory:** PID, then feedforward, then motion profiles (trapezoidal, exponential, and why Motion Magic is the default), and how to measure constants instead of guessing at them. Every later group assumes these ideas.

**Manual Tuning:** CTRE's by-hand procedure: one page of shared ground, then a recipe for each mechanism type (flywheel, turret, arm and elevator, profiled). The PID Tuning Practice sessions run these recipes.

**6. Advanced Motor Control:** The Phoenix side of the same ideas: motor configuration records, current limits, the full catalogue of control requests, CANcoder absolute position, and simulating a TalonFX so the real controller runs in the loop.

**7. PID Tuning Practice:** Four hands-on sessions applying Control Theory and the manual-tuning recipes: setup, an elevator (plain loop, then an exponential profile), an arm (plain loop, then Motion Magic in Phoenix Tuner), and a shooter.

**8. Mechanism Examples:** Generating a mechanism with YAMG, then Cobra's elevator and shooter read line by line as worked examples of everything so far.

**9. Pose Estimation:** Where the robot is: pose geometry (state versus change: translations, rotations and poses; transforms, twists and chassis speeds; their 3D versions), wheel odometry, PhotonVision and the vision subsystem, fusing them, QuestNav as a third source, calibration, simulating the cameras, and the swerve drivetrain that does all of it as the group's capstone.

**10. Cobra Architecture:** The pieces of the robot that only make sense once pose, vision and shooting exist: `VirtualSubsystem`, `BobotState`, the VARC alignment pattern the team has carried since 2024, and the math toolbox in two halves (geometry and frames, then numbers, units and the interpolation tables behind aiming).

**11. Autonomous:** PathPlanner, Choreo and BLine, running autos in simulation, and the sim-to-real checklist that ends the section.

The code samples are drawn from a real competition robot rather than invented for the lesson, so the conventions are consistent from one page to the next and the patterns are ones that have survived a season.
