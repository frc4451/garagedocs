### FRC programming

This curriculum explains how FRC 4451's competition robot, [Cobra](https://github.com/frc4451/Cobra2026Private), is built and how to extend that architecture on the next robot.

Complete [Kit Bot](/kit-bot), [Java Fundamentals](/java/fundamentals), and the [Practice Assignments](/java/assignments) first. This section applies those skills to competition-scale code. It links back to earlier material instead of teaching Java syntax or the Kit Bot architecture again.

### Kit Bot refreshers

You do not need to repeat Kit Bot. Before starting, review only the topics you no longer remember:

- **Setup:** [R00: WPILib Setup](/kit-bot/r00-wpilib-setup)
- **Motors and driver input:** [R06: Motor Controllers](/kit-bot/r06-motor-controllers) and [R10: Joysticks and Stick Math](/kit-bot/r10-joysticks-and-stick-math)
- **Subsystems and commands:** [R04: Subsystems](/kit-bot/r04-subsystems), [R05: Commands and Triggers](/kit-bot/r05-commands-and-triggers), and [R11: Teleop Drive](/kit-bot/r11-teleop-drive)
- **IO and runtime modes:** [R07: Drive IO](/kit-bot/r07-drive-io), [R08: Launcher IO](/kit-bot/r08-launcher-io), and [R12: Real vs. Simulation](/kit-bot/r12-real-vs-sim)
- **Command sequences:** [R14: Time-Based Autonomous](/kit-bot/r14-time-based-autonomous)

Use [Kit Bot to Cobra](/frc/kit-bot-to-cobra#the-map) when you need to find the competition-code version of a Kit Bot pattern.

Environment Setup, Networking, and Robot Programming Basics also work as references. A returning student can revisit one of those modules without restarting the curriculum. Electrical foundations, vendor clients, and physical device bring-up remain in [Hardware](/hardware).

### How the track is organized

The sidebar divides the curriculum into six parts. On a first pass, complete the parts and modules in order. Later, use individual modules as references while working on the robot.

Each part ends at a useful checkpoint: a project you can read, code you can simulate, a mechanism you can control, a robot pose you can trust, or an autonomous routine you can test.

#### Part 1: Foundations

1. **Environment Setup** installs WPILib, creates a project, and points to the programming references used throughout the track.
2. **Networking** applies the Tools networking lessons to the roboRIO, radio, Driver Station, and common connection failures.
3. **Robot Programming Basics** reviews motors, controllers, sensors, a small intake, and Elastic. These pages establish the APIs used by the larger examples.

This part gets one motor, one sensor, and one dashboard value working before introducing the competition codebase.

#### Part 2: From Kit Bot to Competition Code

1. **From Kit Bot to Cobra** maps each Kit Bot pattern to Cobra, tours the repository, and explains the Lombok annotations found in its classes.
2. **Command-Based Programming** builds subsystems, command factories, bindings, command groups, and a complete command-based intake.

The repository tour is a map rather than a prerequisite for every linked topic. Read it once, then return to its file paths as later lessons teach each system.

#### Part 3: IO, Simulation, and Debugging

1. **Robot Runtime and IO** introduces AdvantageKit, the IO layer, and `VirtualSubsystem`. Together they define how real hardware, simulation, replay, and always-running services fit into the robot loop.
2. **Simulation** runs the robot on a laptop, adds physics behind the IO layer, displays the result in AdvantageScope, and tests it without a GUI.
3. **Logs and Replay** reads the records produced by real and simulated runs, then feeds recorded inputs through changed code.

This order separates three questions: how data enters the program, how the program behaves in a model, and how to investigate a completed run.

#### Part 4: Mechanism Control

1. **Control Theory** introduces PID, feedforward, motion profiles, Motion Magic, tunable values, and characterization.
2. **Advanced Motor Control** applies those ideas through Phoenix configuration, current limits, control requests, CANcoder feedback, and TalonFX simulation.
3. **Mechanism Components** builds reusable rollers, flywheels, pivots, elevators, and linear rails, then composes them into robot subsystems.
4. **Manual Tuning** gives a by-hand procedure for each mechanism type.
5. **PID Tuning Practice** applies those procedures to a flywheel, elevator, and arm in simulation.

The progression moves from equations, to controller APIs, to reusable mechanism code, and then to measured tuning work. Students tune a component only after they understand its units and control mode.

#### Part 5: Pose and Competition Architecture

1. **Pose and Odometry** introduces field coordinates, WPILib geometry types, and wheel odometry.
2. **Vision and Sensor Fusion** adds PhotonVision, the vision IO layer, fused estimates, QuestNav, calibration, simulation, and a complete swerve example.
3. **Cobra Architecture** applies those pose and unit concepts to Cobra's math toolbox, shared `BobotState`, and VARC target calculations.

This part starts with the robot's location, adds independent measurements, and then shows how the competition code shares those answers with aiming and scoring systems.

#### Part 6: Autonomous and Robot Coordination

1. **Autonomous** covers PathPlanner, Choreo, BLine, and the simulation checks used before a routine reaches the field.
2. **State-Driven Robot Code** coordinates mechanisms through subsystem states and a robot-wide superstructure. The final design exercise applies the pattern to Cobra.

Autonomous comes first because the state-driven lessons use autonomous command sequences as one of their inputs. The superstructure exercise closes the track by combining commands, mechanism readiness, robot state, target calculations, and autonomous behavior.
