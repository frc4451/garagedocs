The Kit Bot turns by driving its left and right sides at different speeds. A swerve robot can also turn each wheel assembly to point in a chosen direction. That assembly is a **module**: one motor drives the wheel, and another steers it. These lessons work from the Kit Bot's two wheel-speed calculations to four module speed-and-angle calculations.

Here, **tank drivetrain** means the Kit Bot's differential drivetrain. Tank controls use separate left and right commands; arcade controls combine forward and turn commands. Both can control the same differential drivetrain. Changing the joystick layout does not give that drivetrain sideways motion.


## Follow the Learning Path

Start here after the [Kit Bot lessons](/kit-bot). You need to recognize a wheel, motor, controller input, and drivetrain subsystem. The calculations begin with arithmetic. When vectors enter the lesson, you will see their components before using their length or angle.

1. **Tank and Swerve:** describe the motion each drivetrain can produce.
2. [Differential Drive Math](/frc/differential-drive-math): calculate the two wheel speeds.
3. [Swerve Drive Math](/frc/swerve-drive-math): extend those calculations to module speeds and angles.
4. [Drivetrain Checks](/frc/drivetrain-checks): compare predictions with code and logs before studying odometry.

## Compare the Hardware

| Feature | Differential Drive | Swerve Drive |
| --- | --- | --- |
| Wheel direction | Wheels stay aligned with the chassis | Each module can steer its wheel |
| Motion directly sideways | Unavailable in the ideal rolling model | Available when modules point sideways |
| Turning | Left and right sides travel at different speeds | Modules point along the motion needed at their locations |
| Calculated targets | Left and right wheel speeds | A speed and steering angle for each module |

For example, imagine approaching a scoring location while facing it. Swerve can move left to correct alignment without changing its heading. A differential robot needs a maneuver involving forward/backward travel and turning. Neither drivetrain can ignore traction, acceleration, or obstacles.

## Describe the Motion

Start with what the robot's center should do. WPILib's `ChassisSpeeds` holds three rates:

| Value | Meaning in Robot Axes | Positive Direction | Unit |
| --- | --- | --- | --- |
| `vx` | Forward/backward velocity | Forward | Meters per second |
| `vy` | Sideways velocity | Left | Meters per second |
| `omega` | Turning rate | Counterclockwise, viewed from above | Radians per second |

One full turn is `2 × pi` radians, about 6.283. A turning rate of 1 radian per second is about 57.3 degrees per second. These are rates, not a position or a final heading. A joystick value such as `0.5` is also not automatically 0.5 meters per second: the drive command first scales the stick input into the requested physical rate.

**Kinematics** converts between the robot's overall motion and its wheel motion using the drivetrain's geometry. It does not calculate the motor voltage needed to reach a requested speed.

If the program scales a forward stick value of `0.5` by an illustrative maximum of `4 m/s`, the requested forward rate is `2 m/s`. The request still needs wheel calculations and controllers. A real drive command may also apply a deadband or change how the stick response feels; inspect the supplied code before assuming a direct multiplication.

## Trace a Request

Follow this sequence when reading drive code: controller input, requested chassis motion, calculated wheel targets, motor controllers, then measured motion. The first three describe what the robot should do. Sensors report what it did.

For differential drive, both a tank control layout and an arcade layout ultimately command the same left and right sides. For swerve, the drive command can request forward travel, sideways travel, and turning together. Changing a control layout does not change the physical drivetrain.

## Check Your Understanding

Draw a robot from above with an arrow marking its front. Draw a second arrow pointing left without rotating the robot. Explain which drivetrain can follow that second arrow while keeping its heading. Then name the extra target each swerve module needs besides wheel speed.

Your explanation should identify sideways travel and a steering angle. You do not need to calculate that angle yet.
