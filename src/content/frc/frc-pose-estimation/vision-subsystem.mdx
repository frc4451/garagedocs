A vision subsystem should turn camera results into observations. Each observation needs enough information for the drivetrain to decide how much to trust it:

- Estimated robot pose
- Capture timestamp
- Tags used
- Estimation method
- Measurement uncertainty
- Source camera

Keep camera processing outside the drivetrain. Keep estimator ownership inside the drivetrain.

### Define the observation

A record keeps related values together:

```java
public record VisionObservation(
    String source,
    Pose3d fieldToRobot,
    double timestampSeconds,
    Matrix<N3, N1> stdDevs,
    int tagCount,
    PoseEstimationMethod method) {}
```

A single mutable “current standard deviation” field is a poor fit because one loop can process several camera frames with different quality. Store uncertainty on the observation it describes.

### Configure one camera

Each camera needs its own `PhotonCamera`, `PhotonPoseEstimator`, and measured mount transform.

```java
public final class VisionIOPhoton {
    private final String source;
    private final PhotonCamera camera;
    private final PhotonPoseEstimator photonEstimator;

    public VisionIOPhoton(
            String source,
            AprilTagFieldLayout fieldLayout,
            Transform3d robotToCamera) {
        this.source = source;
        camera = new PhotonCamera(source);
        photonEstimator =
            new PhotonPoseEstimator(
                fieldLayout,
                robotToCamera);
    }
}
```

The camera name must match the PhotonVision configuration. The field layout must match the physical field and the layout configured on the coprocessor.

### Process unread results once

```java
public List<VisionObservation> update() {
    List<VisionObservation> accepted =
        new ArrayList<>();

    for (PhotonPipelineResult result
            : camera.getAllUnreadResults()) {
        Optional<EstimatedRobotPose> estimate =
            photonEstimator
                .estimateCoprocMultiTagPose(result)
                .or(() ->
                    photonEstimator
                        .estimateLowestAmbiguityPose(result));

        if (estimate.isEmpty()) {
            continue;
        }

        EstimatedRobotPose pose = estimate.get();

        if (!isUsable(pose)) {
            logRejected(pose);
            continue;
        }

        Matrix<N3, N1> stdDevs =
            calculateStdDevs(pose);

        accepted.add(new VisionObservation(
            source,
            pose.estimatedPose,
            pose.timestampSeconds,
            stdDevs,
            pose.targetsUsed.size(),
            classifyMethod(pose)));
    }

    return accepted;
}
```

This method drains unread results once. Other methods should read cached observations or status values instead of calling `getLatestResult()` and creating a second consumption path.

### Reject measurements for stated reasons

Filtering and uncertainty have different jobs:

- **Filtering** removes an observation that should not enter the estimator.
- **Uncertainty** controls the influence of an accepted observation.

A filter can check:

- At least one known tag contributed.
- A single-tag observation is within the tested distance and ambiguity limits.
- The estimated pose lies within plausible field bounds.
- Height, roll, and pitch are plausible for a robot on the floor.
- The timestamp is new and falls within the estimator's retained history.
- The camera and field layout match the active configuration.

```java
private boolean isUsable(
        EstimatedRobotPose estimate) {
    if (estimate.targetsUsed.isEmpty()) {
        return false;
    }

    if (estimate.targetsUsed.size() == 1) {
        PhotonTrackedTarget tag =
            estimate.targetsUsed.get(0);

        double distanceMeters =
            tag.getBestCameraToTarget()
                .getTranslation()
                .getNorm();

        if (tag.getPoseAmbiguity()
                >= ambiguityCutoff) {
            return false;
        }

        if (distanceMeters
                >= singleTagDistanceCutoffMeters) {
            return false;
        }
    }

    Pose3d pose = estimate.estimatedPose;
    return pose.getX() >= 0.0
        && pose.getX() <= fieldLayout.getFieldLength()
        && pose.getY() >= 0.0
        && pose.getY() <= fieldLayout.getFieldWidth();
}
```

The cutoffs are team configuration values. Determine them from logs rather than copying the example numbers into every robot.

### Assign uncertainty

A common starting heuristic gives multi-tag observations smaller x/y standard deviations than single-tag observations, then increases them with distance.

```java
private Matrix<N3, N1> calculateStdDevs(
        EstimatedRobotPose estimate) {
    Matrix<N3, N1> base =
        estimate.targetsUsed.size() > 1
            ? multiTagStdDevs
            : singleTagStdDevs;

    double averageDistanceMeters =
        averageTagDistance(estimate);

    return base.times(
        1.0
        + averageDistanceMeters
            * averageDistanceMeters
            / 30.0);
}
```

This formula is the heuristic used in FRC 4451's 2026 vision code. It is a starting model, not a measured law. [Pose Estimation Calibration](/frc/pose-estimation-calibration) explains how to test it.

If the gyro supplies reliable heading, the vision heading standard deviation can be very large so tag observations mainly correct x and y. A robot that deliberately uses vision heading needs separate validation.

### Publish without owning the drivetrain

The subsystem can send accepted observations through a consumer or queue:

```java
for (VisionObservation observation : io.update()) {
    observationConsumer.accept(observation);
}
```

The drivetrain drains each observation once and calls `addVisionMeasurement`. This keeps estimator updates in one subsystem and lets AdvantageKit replay the observation stream.

Log accepted and rejected poses separately. Also log source, tag count, ambiguity, distance, method, timestamp, and chosen standard deviations. A field plot shows where a bad estimate lands; the supporting values explain why.

<RulesBox title="Implementation checks">

- Construct one `PhotonPoseEstimator` per camera.
- Drain `getAllUnreadResults()` once per loop.
- Keep each result's original timestamp.
- Measure `robotToCamera` in WPILib axes.
- Use the same season and field-layout variant on both processors.
- Reject invalid observations before publishing them.
- Attach uncertainty to each accepted observation.
- Keep raw, accepted, and rejected observations in the log.

</RulesBox>
