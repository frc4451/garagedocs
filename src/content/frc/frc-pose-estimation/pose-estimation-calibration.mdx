Calibrate pose estimation one source at a time. If wheel distance, module angles, gyro direction, camera intrinsics, and camera placement all change during the same test, the log cannot identify which change fixed or caused an error.

For every test, record:

- Hardware and software version
- Starting pose and test path
- Expected measurement
- Logged measurement
- Error
- Configuration change
- Result after the change

### 1. Verify coordinate conventions

Lift the drivetrain so the wheels can move safely. Check the signs before measuring scale:

1. Push or command the robot forward. Robot-relative +X velocity should be positive.
2. Move a swerve module toward the robot's left. Its Robot-relative +Y component should be positive.
3. Rotate the robot counterclockwise when viewed from above. Heading should increase under WPILib's convention.
4. Display each module angle and verify its zero direction.
5. Confirm that the module array order matches `SwerveDriveKinematics`.

Fix sign, axis, and ordering errors before tuning dimensions.

### 2. Measure effective wheel travel

A nominal wheel diameter is a starting value. Compression, tread wear, gearing, and sensor conversion affect the distance reported under load.

1. Mark a straight test line on a consistent surface.
2. Record the initial encoder or module positions.
3. Move the robot a measured distance without turning.
4. Record the final positions.
5. Compare measured travel with reported travel.
6. Repeat in both directions and at more than one speed.

Calculate a scale correction:

```text
corrected conversion =
    current conversion × actual distance / reported distance
```

Apply the result in the sensor conversion used by the IO layer. Repeat until the error is acceptably small and consistent. If the error changes sharply with acceleration, investigate slip before changing the scale again.

### 3. Check rotation and module geometry

For differential drive, effective track width affects calculated rotation. For swerve, module locations, wheel scale, steering offsets, and scrub all affect the motion inferred from module positions.

Run repeated rotations through a measured angle:

1. Start from a marked heading.
2. Rotate several complete turns in one direction.
3. Return to the marked heading.
4. Compare gyro heading, wheel-derived heading, and physical heading.
5. Repeat in the other direction.

A constant scale error suggests a geometry or conversion problem. A direction-dependent error suggests scrub, backlash, or an offset problem. A sudden error during acceleration suggests slip.

### 4. Calibrate camera intrinsics

PhotonVision camera calibration estimates the lens parameters used to convert image points into rays.

- Calibrate at the exact resolution used by the pipeline.
- Fill the image with the calibration board at varied positions and angles.
- Reject blurry captures.
- Review the calibration error reported by the tool.
- Recalibrate after changing the lens, focus, resolution, or camera.

Intrinsics and mounting transform solve different problems. Camera calibration does not determine where the camera sits on the robot.

### 5. Measure robotToCamera

Measure from the same robot origin used by odometry:

- +X forward
- +Y left
- +Z up
- Roll about +X
- Pitch about +Y
- Yaw about +Z

Record how the measurement was taken and the physical reference point used on the camera. A consistent pose offset across the field often indicates an incorrect translation or rotation in this transform.

Use simulation to catch large sign and orientation errors. Confirm the final transform on hardware because simulation cannot reproduce a flexible mount or lens error.

### 6. Test raw vision observations

Place the robot at several surveyed poses and log raw camera estimates without fusing them.

At each pose:

1. Face the tags from several distances and angles.
2. Record single-tag and multi-tag observations separately.
3. Compare translation and heading error with the surveyed pose.
4. Record tag IDs, ambiguity, distance, latency, and estimation method.
5. Repeat while the robot moves.

Calculate translation error with:

```java
double translationErrorMeters =
    observedPose.getTranslation().getDistance(
        knownPose.getTranslation());

Rotation2d headingError =
    observedPose.getRotation().minus(
        knownPose.getRotation());
```

Do not tune the pose estimator until the raw observations are plausible.

### 7. Set rejection limits

Choose limits from the distribution in the logs:

- Identify conditions that consistently produce outliers.
- Set a limit that rejects those conditions.
- Check how many useful observations the limit also removes.
- Record the tested camera settings and field conditions.

A single ambiguity or distance number is not universal. Exposure, resolution, lens, tag placement, and motion change the result.

### 8. Tune uncertainty

Start with conservative vision influence. Run a repeatable path with wheel slip, turns, and tag transitions.

Compare:

- Raw odometry
- Raw vision observations
- Accepted vision observations
- Fused estimate
- A surveyed endpoint or other independent reference

If good observations correct too slowly, reduce their standard deviations in small steps. If accepted noise moves the fused pose too much, increase them. If isolated bad observations cause jumps, improve rejection before increasing every standard deviation.

Tune single-tag and multi-tag observations separately. If uncertainty increases with distance, verify the chosen curve against the logged errors.

### 9. Validate the complete system

A final test should include:

- Multiple field locations
- Forward, sideways, and rotational motion
- Acceleration and wheel slip
- Tags entering and leaving view
- Temporary camera occlusion
- Autonomous pose reset
- Disabled and enabled transitions
- The actual field-layout variant
- Every installed camera or visual-inertial source

Save the log and the configuration that produced it. Record what passed, what failed, and what remains uncertain.

<RulesBox title="Stop and diagnose">

- **Straight travel has a scale error:** check distance conversion and slip.
- **Rotation error grows each turn:** check gyro convention, module geometry, and steering offsets.
- **Every camera pose has the same offset:** check `robotToCamera` and field layout.
- **Only distant single-tag poses jump:** inspect ambiguity, distance, and rejection limits.
- **Static tests pass but moving tests fail:** inspect timestamps, latency, blur, and sample synchronization.
- **The fused estimate ignores good observations:** inspect the standard deviations actually passed to `addVisionMeasurement`.
- **The fused estimate follows every noisy observation:** increase measurement uncertainty after confirming the observations should be accepted.

</RulesBox>
