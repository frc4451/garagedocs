Step 2 is Badge 3's calculus requirement. The student connects rates and accumulated change to one
mechanism's recorded motion and control error. Its evidence comes from the student's Badge 2
project, which holds the elevator; the fork's README links the log and the worksheet. C1–C5, the
calculus rows, support the B3-02.1 row below.

Start after the entry baseline and work plan. This step needs no hardware, so it can continue while
physical checks wait for equipment, and Step 3 can begin once this step is under way. Badge 2 or
mentor-verified equivalent work supplies the Java, graph-reading, units, and mechanism-simulation
prerequisites. The student needs algebra, function notation, and signed arithmetic. A school
calculus course is not a prerequisite: the linked lessons teach the selected material, and the
mentor helps with unfamiliar algebra before checking the calculus rows.

## Lessons and Practice

Read these lessons in order and work through their examples:

1. [Functions and Rates of Change](/java/fundamentals/functions-and-rates-of-change): inputs and
   outputs, average rates, signs, and units.
2. [Derivatives](/java/fundamentals/derivatives): shrinking intervals, limits, instantaneous rate,
   and the derivative rules used in the examples.
3. [Integrals](/java/fundamentals/integrals): signed accumulation, definite and indefinite
   integrals, antiderivatives, initial values, and sampled approximations.
4. [PID Control](/frc/pid-control#the-three-terms): connect the derivative and integral of error to
   D and I.

The mathematical sequence draws on Frank Thorne's
[USC MATH 141 curriculum](https://thornef.github.io/math141/index.html). This step selects the
concepts controls needs and leaves the rest of the university course, including its examination
policy, aside.

Use a personal copy or printout of the
[Badge 3 Calculus Fundamentals worksheet](https://docs.google.com/document/d/1eFejNKApiOwPyziOaORg5K7GruMwVl3d9PG5KJ7cW3c/copy).
Leave the shared master blank. Notes, lessons, and a calculator are allowed on every worksheet
attempt, including the credited one. The mentor keeps the answer key separate and reviews missed
reasoning before the student repeats that part independently.

The worksheet includes signed rates, derivatives of a position model, signed accumulation, and PID
error calculations. Questions 9–10 use the complete Java examples from the derivative and integral
lessons. Write predictions before running them, record observed output with units, and explain
whether each result is exact for the stated model or an approximation. The mentor selects a further
change for the student to predict independently.

## Apply It to a Mechanism

Use the position-controlled elevator from Badge 2. Record a new simulation run for the analysis
below. A saved Badge 2 log can be used instead if it already contains every field item 1 lists. If
entry work has no suitable elevator log, the mentor supplies one and checks the student's
understanding of its units and model. The student still performs and explains the analysis.

Reuse the elevator's feedback controller, tests, and logging. Read
[Simulation in AdvantageScope](/frc/simulation-in-advantagescope) before inspecting the recorded
run. The analysis uses the saved simulation log; it needs no hardware trial or custom PID code, and
the student does not need to enable I or D to finish this step.

1. Record a simulation run with timestamps, the goal, the profile setpoint, measured position, and
   measured velocity. State the position and time units, positive direction, feedback controller
   configuration, and any integral limit or reset policy used.

   Then state which of the two setpoints the error calculation subtracts the measurement from, and
   why. Read `ElevatorIOSim.updateInputs()` to check which value its PID compares with the
   measurement. If the student's elevator follows `Badge2MechanismReference` (the finished Badge 2
   bench solution), the elevator component records its goal as the output `Elevator/GoalMeters`,
   which AdvantageScope lists under `RealOutputs`, and the IO inputs log `Elevator/PositionSetpoint`
   (where the profile is now), `Elevator/Position`, and `Elevator/Velocity`.
2. Export the samples. Open the saved log in AdvantageScope and drag the fields into a Table tab
   ([Choose Another View](/tools/advantagescope-tour#choose-another-view) lists it). The table adds
   a row each time a displayed field changes. To move the samples into a spreadsheet with one row
   per timestamp, use **File > Export Data...** with the CSV (Table) format, and fill in the
   Prefixes option with the elevator's input and output tables to leave out other fields.

   The Badge 2 log records position in meters and velocity in meters per second, because
   AdvantageKit logs a measure in its base unit. Convert to inches (1 in = 0.0254 m) before
   calculating, and work in inches and inches per second from then on.
3. Choose at least five consecutive samples during motion and a section where the setpoint chosen in
   item 1 is constant.
4. For two adjacent intervals, calculate average measured velocity as position change divided by
   elapsed time. Take elapsed time from the logged timestamps: samples rarely arrive at exactly the
   requested loop period, and division by a zero interval is undefined. Compare those values with
   the logged velocity and explain why an interval average need not equal an instantaneous or
   filtered sensor estimate.
5. Estimate displacement over the selected samples using a stated rectangle or trapezoid rule.
   Compare the estimate with final position minus initial position. Include the initial position
   only when recovering final position, and distinguish displacement from total distance if
   direction changes.
6. On the constant-setpoint section, calculate error as the chosen setpoint (goal or profile
   setpoint, as item 1 states) minus measured position. Estimate one error rate and accumulated
   error over the selected interval, with the starting accumulation explicitly set to zero for this
   analysis. Explain the signs of the corresponding D and I contributions for positive gains. This
   offline calculation does not establish the controller's actual internal I state or exact output.
7. Repeat a calculation with a wider sample spacing. Explain what changed and what the data does not
   establish about noise or accuracy. Use the results to propose one measurement, sampling, or
   tuning check.

Keep the worksheet, Java predictions and output, saved log, sample table, calculations, and
explanation with the elevator evidence, and link each one from the fork's README.

## Calculus Rows

These calculus rows, which keep the identifiers from earlier revisions, support B3-02.1. Print this
table or copy it into the fork's README, and record an evidence link and an explanation for each
row. The mentor checks each row; the Step 2 signature on the sign-off sheet covers all five.

| Row | Evidence | Done When |
| --- | --- | --- |
| C1 | Worksheet questions 1–2 | The student calculates signed rates with consistent subtraction order, nonzero elapsed time, units, and a direction explanation. |
| C2 | Questions 3–4 | The student distinguishes position, interval average, and instantaneous derivative; uses the model's derivative; and explains a limit without dividing by zero. |
| C3 | Questions 5–6 | The student distinguishes displacement from distance, includes initial position correctly, compares sampled sums, and explains definite integrals and antiderivatives. |
| C4 | Questions 7–10 and Java evidence | The student explains I/D signs and units, compares predicted and observed output, and independently predicts a mentor-selected change while stating timing and noise limits. |
| C5 | Mechanism analysis | The student shows the recorded samples and calculations above, compares them with the mechanism log, and explains one useful follow-up check and the limits of the evidence. |

The mentor changes one timestamp, model input, or sample interval and asks for the student's
reasoning before rerunning a calculation. Notes remain available, and each row needs the student's
explanation as well as the result. If part of a row is missed, the student reviews it with the
mentor and repeats that part independently; rows already completed stay complete.
