The student builds a camera input path for one stationary game piece and uses observations to choose an acquisition pose. Start from the Badge 2 pose and AprilTag work. Observation IO and geometry can proceed alongside mechanism refinement; Step 10 requires this module and the subsystem states together. Read [Pose Geometry](/frc/pose-geometry), [Vision Simulation](/frc/vision-simulation), and Cobra's object-detection IO and tracker linked below.

## Build the IO Boundary

Create `ObjectDetectionIO`, `ObjectDetectionIOReal`, and `ObjectDetectionIOSim`. The simulated implementation extends the real implementation and supplies a `PhotonCameraSim`, following the same pattern used for AprilTags. Both modes consume PhotonVision results through the real parsing path. REPLAY reads recorded inputs without constructing cameras or field physics.

The input record contains connection state, observation timestamps, target yaw and pitch, available class/confidence information, and rejection reasons. Process unread results once. An empty result means no target in that frame; no new frame means the age of the previous observation continues increasing. Clear or expire targets deliberately rather than treating an old result as current.

The provided coprocessor and color camera already run PhotonVision with a working pipeline. Installation and model training are supplied setup. The student owns the robot-side IO, transform configuration, validity rules, tracking and selection.

## Turn a Measurement into a Location

A camera bearing identifies a ray, not a complete three-dimensional position. For the stationary floor-piece exercise, a known target-center height provides the missing constraint. Intersect the transformed camera ray with that height plane, reject nearly parallel or backward intersections, and bound the accepted distance. Record the assumptions that make the estimate possible.

Use `FieldToRobot`, `RobotToCamera`, and `CameraToPiece` names when drawing the transforms. Use the robot pose at the observation timestamp when history is available. If the exercise uses a stationary robot to avoid motion compensation, state that limitation. The same calculation with the current pose on a moving robot needs a latency-error analysis.

The guided example checks a known target ahead of the camera, then moves it to the side. The student predicts the sign of yaw, verifies the library's yaw convention, and compares estimated field position with the configured simulation position. Log the estimate and truth separately. The selection logic sees only the estimate.

## Prepare for Moving Observations

The stationary physical camera check establishes geometry without demonstrating motion compensation. Before Step 10, the student documents how observations are related to robot pose during the simulated approach. Use pose history at capture time when available, or stop and obtain a fresh stationary observation before calculating a field target. State the permitted observation age and motion conditions; reject frames outside them. A current-pose calculation on a moving robot requires a quantified latency-error bound and a justified acceptance limit.

Test a delayed frame during simulated motion and show the compensation or rejection decision in the log. This bridge belongs to the observation evidence in B3-08.2. The target remains a stationary piece; the robot may move.

## Select an Acquisition Pose

Track the single stationary piece with an expiry time. Select a valid target using a documented rule. Calculate a robot goal that puts the intake at the piece, including the robot-to-intake offset and desired heading. Driving the robot center onto the piece is not equivalent to aligning the intake.

Test no target, stale target, out-of-bounds position, near-horizontal ray, and a deliberately wrong mounting transform. Save both accepted and rejected observations. The mentor chooses a different camera transform for an independent prediction and correction.

## Physical Camera Check

Use the provided Orange Pi 5 or Rubik Pi 3 and camera with the mentor present. Measure the mounting transform and place the stationary target at several known locations. Compare observations and calculated positions with tape measurements. Record lighting, pipeline, target type, distances, timestamp behavior and limitations. This demonstration does not require autonomous motion on hardware.
