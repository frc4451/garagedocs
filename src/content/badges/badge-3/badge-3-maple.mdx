This optional specialization investigates how drivetrain contact changes a simulated path. Rows
B3-10.1–B3-10.4 are extension evidence and do not gate Badge 3 completion. Start after Step 10. Read
[maple-sim](/frc/maple-sim) and [Physics in the IO Layer](/frc/physics-in-the-io-layer). A separate
simulation configuration is acceptable; this step does not require another complete scoring
implementation.

## Pin and Inspect the Dependency

The curriculum reference uses maple-sim `0.4.0-beta` and dyn4j `5.0.2` with the base project's
WPILib dependencies. During this authoring pass, the public vendordep pointed to
`0.4.0-beta-obstacles-fix`, whose Maven artifact could not be resolved. Preserve the verified
vendordep supplied with the reference and record its hash. Treat a later version as a deliberate
dependency change that needs a rebuild and repeated experiments.

Select the AdvantageKit Talon swerve template as the architectural reference because it matches the
base's drive IO structure. Explain how its module and gyro simulation differ from the supplied
`DCMotorSim` implementations. The focused `MapleExperiment` is a smaller independent physics
example; copying it does not complete integration into the student's drive subsystem.

## Assign One Update Owner

The arena advances the drivetrain physics once per robot period, with its internal subticks. The
module and gyro IO read the resulting sensor data. Remove the old drivetrain physics updates from
that configuration so two models do not both move the same robot. Preserve the normal estimator and
path-follower interfaces.

Record true field pose, estimated field pose, requested chassis speeds, measured module states,
battery behavior, and the experiment configuration. BLine receives the estimated pose. True pose is
for simulated observations and comparison, not a shortcut into control.

## Run Two Experiments

First run a known BLine route in open space. Record its start and end poses, completion or timeout,
path error, and elapsed time. Repeat it from the same conditions to establish the variation present
in the model.

Then introduce a known obstacle or field boundary on a controlled route. Predict where contact will
occur and how it may change true motion, wheel readings, and the estimate. Run with a time bound so
a robot blocked by an obstacle cannot command drive indefinitely. Compare the true and estimated
trajectories after contact.

Change one parameter or initial condition, such as approach speed or initial lateral position. Keep
the remaining conditions fixed. Explain what changed, what the logs support, and which contact or
friction assumptions would require hardware measurements. Do not treat one simulated collision as
proof of a physical robot's behavior.

## Reproduce Both Simulators

For this extension, give another member the FuelSim and maple-sim instructions, pinned versions,
expected observations, and log locations. The member repeats a scoring shot, controlled miss,
open-space path, and contact experiment. FuelSim reproduction already completed for the required
handoff can be credited here. Record where instructions needed correction. The mentor checks the
student's explanation of model ownership and truth-versus-estimate separation.

## Badge Check

S means simulation, H means hardware, W means written reasoning, and M means mentor-observed review.
The student records an evidence link, mentor signature, and date for each row. The mentor asks the
student to explain a change and its result before signing.

| Row | Work | Done When |
| --- | --- | --- |
| B3-10.1 | Plan maple-sim integration | W: Identify pinned version and matching template, explain IO changes and update ownership, and predict an experimental result before running it. |
| B3-10.2 | Motion and contact | S: Run a known BLine path in open space and a controlled field-contact experiment. Vary one parameter or initial condition and explain the observed response. |
| B3-10.3 | Truth and estimate | S/W: Log true and estimated pose separately; control uses the normal estimated pose. Explain what the model adds and cannot establish about hardware. |
| B3-10.4 | Reproduce the explorations | S/M: Another member reproduces FuelSim and maple-sim experiments from instructions. Separate configurations or branches are acceptable; a second full scoring implementation is not required. |
