The student refines the pivot while keeping its position reference, travel limits, and profile
ownership explicit. Start after Step 3 and the Badge 2 software-profile baseline. This module can
run alongside flywheel and FuelSim work. Complete the fixture preparation before each physical
reference or motion check. Read [CANcoder Absolute Position](/frc/cancoder-absolute-position),
[Why Motion Magic](/frc/why-motion-magic),
[Trapezoidal Motion Profiling](/frc/trapezoidal-motion-profiling), and
[Exponential Motion Profiling](/frc/exponential-motion-profiling).

## Establish Manual Reference

Write a procedure that begins with the mechanism powered off and placed at its known reference.
After power is restored in the disabled state, the operator explicitly establishes the encoder
reference. Record whether the write succeeded before allowing position requests. Startup must not
move the mechanism automatically to find zero.

Reference validity begins false after a power cycle or a known sensor reset. A matching encoder
number alone does not prove the arm is at the reference mark. The subsystem rejects ordinary
position requests until the reference procedure succeeds. Record a refusal reason and preserve a
separate, mentor-controlled bring-up procedure if manual movement is needed.

The `MechanismRules` example demonstrates the validity gate in isolation. The student connects the
gate to the real reset status, disabled state, and subsystem requests. A second student follows the
written procedure after a power cycle and demonstrates repeatable goals. No limit switch is
required.

## Add Absolute and Fused Feedback

The manual-reference task remains separate from the absolute-encoder task. Record sensor placement,
positive direction, magnet offset, rotor-to-sensor ratio, and sensor-to-mechanism ratio before
configuring fused CANcoder feedback on supported licensed hardware.

Compare the known physical angle with the reported mechanism angle at more than one position. Test
startup and recovery from invalid feedback. An absolute reading does not remove the need to validate
configuration or refuse a goal when the selected feedback is invalid. Retain the
simulation-versus-hardware distinction when interpreting sensor recovery.

## Bound Travel

Reject nonfinite goals and deliberately reject or clamp out-of-range finite goals. Test both ends in
simulation. Configure CTRE software limits using the selected feedback units; record their physical
interpretation on the fixture sheet before enabling hardware.

## Compare Profiles on the Same Model

Retain the Badge 2 software trapezoid as a baseline. Compare it with device-generated Motion Magic
voltage control, then Talon FX torque-current Motion Magic. Talon FXS uses voltage. Record final
goal, intermediate profile reference, measured angle and speed, output mode, gains, and limits.

A profiled position request still requires a feedback controller to follow its intermediate
setpoints. Position within tolerance while moving quickly is not settled. The student records both
position error and speed during the chosen settling interval and checks overshoot over the entire
move.

## Bound Travel and Compare Expo

With reference validity and travel bounds established, complete the Expo comparison below.

Complete this worksheet before the exponential comparison:

| Prompt | Student Response |
| --- | --- |
| What angle and speed units does the selected feedback report? | Show one conversion from degrees to mechanism rotations. |
| Which object advances the trapezoidal profile, and which advances Motion Magic? | Name the owner and period. |
| What units do `MotionMagicExpo_kV` and `MotionMagicExpo_kA` use? | Distinguish these profile parameters from current-output slot gains. |
| What does a larger Expo kA predict under the same available voltage? | Predict before running. |
| How will error, settling, overshoot and repeatability be measured? | Give targets and log fields. |
| Which profile better meets the recorded targets for this model? | Compare traces and state the model's limits. |

Run supported CTRE Expo in simulation against the same initial angle, goal, and model. Physical Expo
is optional. The mentor checks all worksheet reasoning, then asks for an independent prediction with
a changed constraint.

## Badge Check

S means simulation, H means hardware, W means written reasoning, and M means mentor-observed review.
The student records an evidence link, mentor signature, and date for each row. The mentor asks the
student to explain a change and its result before signing.

| Row | Work | Done When |
| --- | --- | --- |
| B3-05.2 | Manual reference | S/H/M: Place the powered-off mechanism at its known reference, establish zero explicitly without automatic setup motion, record reference validity, and refuse normal position commands until valid. A second student follows the procedure after a power cycle. No limit switch is required. |
| B3-05.3 | Absolute and fused reference | S/H/W: Configure the supplied absolute encoder and fused CANcoder feedback on supported licensed hardware. Demonstrate startup and recovery separately from manual zeroing. Explain sensor placement, offsets and ratios. |
| B3-05.4 | Travel and repeatability | S/H: Reject or bound invalid simulated goals. Configure CTRE software limits and repeat valid physical start/end goals against recorded error, settling, overshoot and repeatability targets. |
| B3-05.1 | Pivot profiles and units | S/W: Refine voltage and torque-current Motion Magic on Talon FX and voltage Motion Magic on Talon FXS. Explain software-profile versus device-profile ownership, gearing, typed goals, and gain units. |
| B3-05.5 | Exponential comparison | S/W: Run a supported CTRE exponential-profile comparison on the same pivot; complete the parameter/unit worksheet and explain when each profile is useful. Physical exponential profiling is optional. |
