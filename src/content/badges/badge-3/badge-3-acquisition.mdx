The student integrates one simulated collection and scoring attempt using BLine, the state-owned subsystem, and camera observations. Start after Steps 8 and 9, including the delayed-observation check, and the required FuelSim experiment in Step 6. Read [BLine](/frc/bline) and [Autonomous Simulation](/frc/autonomous-simulation). The task is simulation-only.

## Establish the Sequence

Record the initial robot pose, stationary piece location, search region, return pose, and scoring target. Start from the same conditions for every comparison. First prove the sequence with a single-piece field model and sensor adapter, then connect the FuelSim world from Step 6.

1. Travel to the search region and wait for a valid PhotonVision observation within a stated time bound.
2. Select the target and compute the acquisition pose using the intake offset. Construct the BLine approach from the estimated robot pose. Do not reset odometry to a detected piece or to simulation truth.
3. Approach and run the intake. Confirm collection through the possession IO. Reaching a path endpoint is not proof that collection occurred.
4. Return with the piece, prepare the flywheel and pivot, and wait for measured readiness within a stated bound.
5. Issue a single launch event, consume the held piece once, and record the resulting simulator score. A launch completes the action; a simulator score determines whether it succeeded.

Give the path commands drive requirements and bounded execution. Distinguish successful arrival from a timeout; command completion alone cannot authorize collection or scoring. On interruption, stop drive and feeder outputs and preserve a consistent piece state.

## Connect One Field Model

One world owns the piece. Its available field positions feed PhotonVision's simulated targets. Its intake event changes the possession IO. Its launch operation consumes the held piece and adds the projectile. The robot state machine reads camera and possession inputs; it does not query the world's exact piece location to decide where to drive.

FuelSim does not synchronize PhotonVision targets automatically. The student writes that adapter and updates it from the same world after each physics step. Remove collected targets and do not leave a duplicate piece visible after acquisition. A missed projectile may return to the field according to the model; it is not automatically held again.

Use measured flywheel speed and measured pivot angle at launch. Record the pitch convention, radius, slip assumption, launch height, and field-relative robot velocity. Keep a scored count distinct from held state and launch count. Mirror relevant world state into the saved log so another student can reconstruct the event.

## Required Failure Runs

| Case | Injection | Evidence |
| --- | --- | --- |
| No visible piece | Remove or hide the piece before the search. | Search ends within its bound; no possession or launch is invented. |
| Target Lost | Stop observations before collection. | The stale-target rule is visible and the attempt stops or recovers as documented. |
| Collection Timeout | Prevent possession confirmation at the attempted pickup. | The bounded attempt fails; held and scored remain false. |
| Never Ready | Keep measured speed or angle outside tolerance. | The feeder stays stopped and readiness times out. |
| Interruption | Cancel once during driving and once during scoring. | Drive and feeder stop; the piece is neither duplicated nor consumed twice. |

The mentor's transition-policy tests illustrate these cases; the student demonstrates them through the integrated robot and actual IO path. Repeat any failure runs affected when FuelSim replaces the initial field stand-in.

## Independent Change

The mentor changes the initial piece location within the camera's supported region. The student predicts the acquisition pose, runs the full sequence, and explains any difference using observations, path error, possession, readiness, and score. Save the failure logs alongside the successful run.
