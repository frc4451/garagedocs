The student refines the roller from an output command into a mechanism that can distinguish collection, invalid sensing, and a sustained jam. Start after Step 3. Complete the relevant fixture sheet and voltage baseline before powered physical checks; the scripted sensing and jam experiments run first in simulation. Read [Current Limiting](/frc/current-limiting), [IO Layers](/frc/io-layers), and the linked CTRE CANrange documentation before changing the sensor IO.

## Compare Output Modes

Begin with the saved voltage baseline. Run positive, reverse, and zero effort on Talon FX and Talon FXS simulation. Then add Talon FX `TorqueCurrentFOC` through the typed current capability. Log requested mode and effort, applied voltage, torque current, supply current, measured speed, and configured limits. Supply current is not a replacement for the torque-current measurement in a jam rule.

Use the same model, initial state, and duration for comparisons. Describe the input magnitudes as separate choices in volts and amps, not equivalent values. Show the configured limit changing the response. A current request also needs a bounded operating range; current limiting alone does not detect a trapped game piece.

## Add CANrange IO

The input record needs connection/status information, measurement validity, distance with units, detection result, and sample time or age. Keep three outcomes distinct: present, absent, and invalid. An invalid reading does not prove absence.

In simulation, first supply scripted input sequences through the same interface: absent to present, present to absent, disconnected, and stale. On hardware, move the selected object into and out of the configured range under mentor supervision. Record the selected threshold, hysteresis or debounce, the observed distances, and the subsystem response. Choose those values from the fixture and object, not from an unrelated robot.

The student explains why a detection may be valid while a particular distance is unsuitable for the intended decision. Check the pinned CANrange API and the device's reported health instead of reducing validity to a single distance comparison.

## Detect a Sustained Jam

The teaching example `MechanismRules` requires collecting, valid observations, substantial effort, and low measured speed for a continuous interval. Its 15 A, 1 rotation per second, and 0.2 second values are test inputs for a model. The student selects and justifies values for their mechanism.

Reset the timer when any required condition stops holding. Latch the jam once the interval expires. Stop the roller, or use a justified limited hold with an explicit ending condition. Require an explicit reset before collection resumes. Automatic reversal or repeated retry is not required.

Test a brief startup transient, normal collection, a sustained jam, invalid sensing, stopping the command, and explicit reset. Record the reason for the stop. Simulate the jam by controlling load or observations; a deliberate physical jam is not required.

## Independent Change

The mentor changes the simulated load or a sensor timing condition. The student predicts whether the rule should latch, runs it, and explains the result using the saved signals. CANrange presence and jam detection receive separate evidence because they answer different questions.

## Badge Check

S means simulation, H means hardware, W means written reasoning, and M means mentor-observed review. The student records an evidence link, mentor signature, and date for each row. The mentor asks the student to explain a change and its result before signing.
