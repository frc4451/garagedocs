In Step 10, the student builds three autonomous routines. The first runs PathPlanner on the differential Kit Bot in `KitBotPathPlanner`. The second moves the same PathPlanner workflow onto the swerve drive in `Badge2Robot`. The third keeps that drivetrain, pose source, mechanism commands and logging and swaps the follower for BLine. Each routine follows at least three named paths and runs at least two mechanism actions. The three routines do not need to trace the same route.

The mechanism actions on the Kit Bot come from the template's `Superstructure`; on the swerve robot they come from the composed subsystems of [Step 8](/badges/badge-2-mechanism-composition), which is why composition comes first.

Before moving from the Kit Bot to swerve, work through [Drivetrain Fundamentals](/frc/tank-and-swerve), ending with [Drivetrain Checks](/frc/drivetrain-checks), as assigned in [Step 9](/badges/badge-2-math#tank-to-swerve). The left/right speed calculation becomes a speed-and-angle calculation for each module; a path follower supplies the chassis motion that feeds those calculations.

## Guided Example

Build and verify the first routine on the differential Kit Bot. This establishes the sequence the student will reuse: confirm configuration, draw the first path, run it, add one mechanism action, then extend the routine to three paths and two actions.

### PathPlanner on the Kit Bot

The AdvantageKit 2026 Kit Bot template inherits the differential-drive template's PathPlanner configuration. Its `Drive` constructor calls `AutoBuilder.configure` with the pose supplier, the pose reset, a robot-relative `ChassisSpeeds` supplier built from the left and right wheel velocities through `DifferentialDriveKinematics`, a `runClosedLoop(ChassisSpeeds)` consumer, a `PPLTVController(0.02, maxSpeedMetersPerSec)`, the `ppConfig` from `DriveConstants`, and an alliance flip supplier. `runClosedLoop` converts the chassis speeds to wheel speeds, computes a `kS` and `kV` feedforward for each side, and hands velocity and feedforward to the IO. The [PathPlanner](/frc/pathplanner#autobuilder-configuration-differential) lesson has the differential configuration beside the swerve one.

`PPLTVController` is the follower for a drivetrain that cannot move sideways: it controls forward speed and turn rate, and the robot's heading is the direction of travel. `DriveConstants` carries the numbers `RobotConfig` is built from: mass, moment of inertia, wheel coefficient of friction, wheel radius, gearing, current limit, motors per side and track width. The template ships with defaults; the student confirms each against the Kit Bot they simulate.

|---|---|---|---|

| 10.2 | Confirm odometry | [Wheel Odometry](/frc/wheel-odometry#differential-drive-odometry) | Driving the simulated Kit Bot in a square produces a sensible `Odometry/Robot` trace on the 2D field before any path is followed |

## Independent Change

Move the workflow to swerve, then keep the same drivetrain interfaces and mechanism commands while replacing the PathPlanner follower with BLine. The student chooses the routes, action timing, and the path that demonstrates heading independent of travel.

### PathPlanner on Swerve

The same file workflow, on the swerve template in `Badge2Robot`. The template's `Drive` configures `AutoBuilder` with `PPHolonomicDriveController` and a `RobotConfig` built from `TunerConstants`: module locations from `getModuleTranslations()`, wheel radius, drive gear ratio, slip current and the speed at 12 volts. The holonomic controller commands translation and rotation separately, which is the behavior a differential drivetrain cannot offer and the reason for row 10.14.

|---|---|---|---|

| 10.11 | Explain holonomic control | [PathPlanner](/frc/pathplanner#paths-autos-and-event-markers) | The student explains why the swerve controller can command translation and heading separately, and what `PPLTVController` could not do |
| 10.12 | Confirm `RobotConfig` | [PathPlanner](/frc/pathplanner#configuring-autobuilder) | Module locations, mass, moment of inertia, wheel data, gearing and maximum speed read out of `Drive` and `TunerConstants` |
| 10.13 | Draw three paths | [PathPlanner](/frc/pathplanner#paths-autos-and-event-markers) | At least three named path files for the swerve project |
| 10.14 | Heading independent of travel | [Pose Geometry](/frc/pose-geometry#state-and-change) | At least one path where the robot's heading differs from its direction of travel, with the rotation target visible in the editor |

### BLine on Swerve

The same swerve drive, with BLine-Lib as the follower. BLine follows a sequence of points from the robot's current pose rather than a schedule in time, which the [BLine](/frc/bline#get-to-point) lesson explains and row 10.28 demonstrates.

| # | Work | Lesson | Done when |
|---|---|---|---|
| 10.20 | Install BLine-Lib | [BLine](/frc/bline#installing-it) | The vendordep is installed at the version the README records (0.9.1 when this page was written), and `frc.robot.lib.BLine` imports resolve |
| 10.21 | Wire the builder | [BLine](/frc/bline#wiring-it-to-the-drivetrain) | One `FollowPath.Builder` receives the drive subsystem, its pose supplier, its robot-relative `ChassisSpeeds` supplier, its drive consumer, and three PID controllers |
| 10.22 | Set global constraints | [BLine](/frc/bline#where-paths-come-from) | `Path.setDefaultGlobalConstraints` or `deploy/autos/config.json` sets translation velocity and acceleration, rotation velocity and acceleration, the end tolerances and the handoff radius, and the README states each unit |
| 10.23 | Draw three paths | [BLine](/frc/bline#where-paths-come-from) | At least three named path files in `src/main/deploy/autos/paths/`, loaded by name |
| 10.24 | Build one routine | [Command Groups](/frc/command-groups#autonomous-routines) | One command follows all three paths, with `withPoseReset` applied to the first path only |
| 10.25 | Two mechanism actions | [BLine](/frc/bline#events) | Two actions from the Step 8 subsystems run through `FollowPath.registerEventTrigger` or a `BLineCommands` composition |
| 10.26 | No requirement conflict | [BLine](/frc/bline#events) | No event command requires the drivetrain; the student explains what the scheduler would do if one did |
| 10.27 | Draw and log | [BLine](/frc/bline#check-the-loaded-path) | The loaded paths are drawn on a `Field2d`, and measured pose is logged beside them |
| 10.28 | Two starting offsets | [BLine](/frc/bline#get-to-point) | The routine runs from the drawn start and from a start offset by about half a metre; the robot drives onto the line from where it is rather than replaying a timeline |
| 10.29 | Save the log | [Log Replay](/frc/log-replay) | A `.wpilog` shows all paths, both actions, and the final stopped state |

## Badge Check

<StepsBox title="Path following badge check">

1. The mentor runs the routines in order: PathPlanner on the Kit Bot, PathPlanner on swerve, BLine on swerve. Each run starts from a clean simulation state with the pose reset to the routine's start.
2. For each run, AdvantageScope shows the planned and measured poses on the 2D field and the mechanism goals on a graph.
3. The mentor opens each saved log and asks the student to point at the start and end of every path and every action, and to say what changed at each transition.
4. The mentor switches the alliance in the Sim GUI and reruns one routine. It mirrors correctly.
5. For the BLine routine, the mentor sets a starting offset and watches the robot recover the line.

</StepsBox>
