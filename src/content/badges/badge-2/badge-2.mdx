Badge 2: Intermediate FRC prepares Automation Team students to read, build, test, and explain
competition-scale robot code. Start after [Badge 1](/badges/badge-1), or after a mentor verifies
equivalent work. Badge 1 supplies Java fundamentals, interface-based IO, commands, simulation, and
basic logging. Badge 2 adds the Java practice, AdvantageKit logging and replay, testing, and
architecture needed for its larger projects.

The student first proves a small piece, changes it independently, and then demonstrates it to a
mentor. One complete mechanism comes before the full library; one path comes before an autonomous
routine; one camera comes before two-camera integration.

## Reading Cobra2026 Alongside the Badge

The implementation steps include a **Cobra2026 Connection** with specific files and a reading task.
Start with the [Cobra Repository Tour](/frc/cobra-repository-tour), then return to the relevant
files as the student reaches each concept. These references use the `org.robotzgarage.frc2026`
library and its `frc.robot` integration. The separate `org.robotzgarage.rewrite` tree is not the
reference for this badge sequence.

The student explains the reference and then implements the badge's smaller contract. Cobra's
hardware settings, control modes and game-specific behavior do not replace the lesson's
requirements. The comparison notes identify important differences. Step 4 remains hardware-tool work
without a code-reading assignment, and the written pretest and post-test remain closed-reference
assessments.

## Required Outcomes

The student completes these outcomes in order:

- Three AdvantageKit templates, downloaded from the pinned AdvantageKit v26.0.2 GitHub release,
  become three robot projects. `Badge2Bench`, from the Skeleton template, is where every mechanism
  is built and the physical fixture runs. `Badge2KitBot`, from the Kit Bot template, introduces
  PathPlanner on a differential drivetrain. `Badge2Swerve`, from the TalonFX swerve template, is the
  holonomic drivetrain for PathPlanner, BLine, vision and the capstone. A dedicated hardware lesson
  configures the fixture; a separate software lesson develops IO, replay and configuration builders.
- Talon FX, Talon FXS and Thrifty Nova are introduced in the dedicated hardware lesson. The student
  implements and physically demonstrates the supplied controller on a roller.
- Four typed mechanism families run in general simulation: roller, flywheel, pivot, and elevator.
  The elevator includes drum diameter and radius, reduction, rigging calculations, gravity, limits,
  and a saved motion log.
- Required FX and FXS roller device simulations and a SimThriftyNova physics adapter follow the
  general roller. The ThriftyNova hardware and simulation adapters share tested conversion helpers.
  A software-profiled pivot comes before one CTRE Motion Magic simulation comparison. Additional
  physical controller ports and linear-rail implementation are outside the required path.
- An elevator, pivot, and conveyor form one parent subsystem with measured interlocks and a
  measured/goal drawing. A smaller feed-and-flywheel exercise proves possession and readiness.
- A student-written driver-controller class has tested input shaping and bindings. Timed rumble and
  a separate pivoting intake are optional extensions.
- Pose, frames, and odometry immediately precede path following. A guided differential path prepares
  two complete swerve routines, one with PathPlanner and one with BLine. Each swerve routine uses at
  least three paths and two mechanism actions.
- Two simulated AprilTag cameras provide timestamped observations, named rejection reasons,
  uncertainty, and replayable estimator input.
- Shared robot facts influence commands without owning actuators. The integrated robot stops on
  interruption and successfully replays a saved log with a new diagnostic output.

Java practice and tests prepare the student for these outcomes. The badge does not require every
remaining Java assignment. Formal calculus and advanced physical Talon FX work belong to Badge 3.

## The Repository

Badge 2 work lives in one GitHub repository, `<yourname>Badge02`, such as `JoshBadge02`:

```text
JoshBadge02/
├── README.md
├── java-practice/       Java work from Step 2
├── Badge2Bench/         Skeleton template: every mechanism, and the FX, FXS or Nova fixture
├── Badge2KitBot/        Kit Bot template: PathPlanner on a differential drivetrain
└── Badge2Swerve/        TalonFX swerve template: PathPlanner, BLine, vision and the capstone
```

Mechanisms are written and tested in `Badge2Bench`. In Step 11, the student copies the composed
mechanisms and the controller class into `Badge2Swerve`, where the autonomous routines, vision,
robot state and capstone use them.

`Badge2Bench` is the only project deployed to a roboRIO and the only one that runs in `REAL` mode;
all physical hardware work happens on the bench. `Badge2KitBot` and `Badge2Swerve` run in simulation
and replay only.

Step 2 starts in a local practice folder. [Project Setup](/badges/badge-2-project-architecture)
places that work in `java-practice/` when the repository is created. This folder contains Java
practice rather than a GradleRIO robot project. Open each GradleRIO project in its own VS Code
window when using WPILib build and simulation tasks.

The root README records the template releases and links each numbered badge requirement to its
source, test, written explanation, or saved log. Java examples intended for the robot projects must
work with their WPILib 2026 Java 17 toolchain, even when a linked general Java lesson discusses Java
25.

## Mentor Checks

A mentor signs a row after seeing its evidence. Reading a page or copying working code alone does
not complete a row. The student explains the result and predicts what will happen after a small
change. If more practice is needed, completed checks stand while the student and mentor agree on the
next attempt.

The site and printable packet use the September 29, 2026 curriculum revision. The
[required sheet](/badges/badge-2-sign-off#required-sheet) summarizes the fifteen steps and provides
space for mentor signatures and dates. The repository README records evidence for the detailed
requirements in each lesson. Use the
[printed sign-off sheet (PDF)](/documents/badges/badge-2/badge-2-sign-off.pdf) alongside the
[final review](/badges/badge-2-sign-off). The current site rows determine required practical work;
an older printed row does not restore a retired requirement. Notes and documentation are allowed
except during the pretest and post-test. Simulation work runs on the student's laptop. Steps 4 and 7
also require the provided physical hardware and a mentor-observed demonstration. Physical elevator
and autonomous-driving demonstrations are optional.

The [pretest and post-test (PDF)](/documents/badges/badge-2/badge-2-pretest.pdf) and sign-off sheet
are hosted with the site and included when it is saved for offline use. Download either PDF while
online to print it or open it later without Google Docs access.

## Assessment

Take the ten-question [pretest](/badges/badge-2-pretest) before Java Foundations. It is diagnostic
and has no passing mark. After the capstone, take it again and score at least 18 of 20. The
practical checks separately assess the Java, testing, and robot-building skills; a written score
does not replace them.

Step 8 includes a short guided
[Math Behind PID](/badges/badge-2-mechanism-library#the-math-behind-pid) exercise within the
existing mechanism review. Formal derivatives, integrals, and their worksheet belong to
[Badge 3](/badges/badge-3-calculus), not an additional Badge 2 completion requirement.
