Step 3 creates the repository and the two drivetrain projects. The student downloads AdvantageKit's
2026 Kit Bot and TalonFX swerve templates from GitHub, records where each project came from, and
copies the completed Java practice into the repository. The third project, `Badge2Bench`, where
every mechanism is built, follows in Step 5.

## Before You Start

Complete [Step 2: Java Foundations](/badges/badge-2-java) first. Keep the local `Badge2JavaPractice`
folder until the copied version has been checked inside the repository.

Review [GitHub Remotes](/tools/github-remotes), [Cobra Repository Tour](/frc/cobra-repository-tour),
and the setup sections of the
[AdvantageKit Kit Bot template](https://docs.advantagekit.org/getting-started/template-projects/kitbot-template/)
and
[TalonFX(S) swerve template](https://docs.advantagekit.org/getting-started/template-projects/talonfx-swerve-template/).

Before driving the swerve template, read [Tank and Swerve](/frc/tank-and-swerve). It introduces
steering modules and forward, sideways, and turning requests. The remaining Drivetrain Fundamentals
lessons supply the worked calculations during Step 10; setup here asks the student to build and
drive the supplied template.

## Cobra2026 Connection

Use the [Cobra Repository Tour](/frc/cobra-repository-tour) with
[`Robot.java`](https://github.com/frc4451/Cobra2026Private/blob/main/src/main/java/frc/robot/Robot.java)
and
[`RobotContainer.java`](https://github.com/frc4451/Cobra2026Private/blob/main/src/main/java/frc/robot/RobotContainer.java).
Trace startup from the robot lifecycle into object construction and bindings. Then find the
runtime-mode selection in
[`Constants.java`](https://github.com/frc4451/Cobra2026Private/blob/main/src/main/java/frc/robot/Constants.java).
This gives the student a concrete example of the responsibilities the templates separate.

Cobra is the reading reference. The student still starts the three badge projects from the specified
AdvantageKit v26.0.2 templates, records their versions, and uses the fixture's own configuration.

## Repository Layout

Create one GitHub repository named `<yourname>Badge02`, such as `JoshBadge02`:

```text
JoshBadge02/
├── README.md
├── java-practice/
│   ├── ConfigPractice.java
│   └── assignments/
│       ├── a13-reference-semantics-lab/
│       └── a18-records/
├── Badge2Bench/
│   └── AdvantageKit Skeleton template: every mechanism, hardware and simulated
├── Badge2KitBot/
│   └── AdvantageKit 2026 Kit Bot template: PathPlanner on a differential drivetrain
└── Badge2Swerve/
    └── AdvantageKit TalonFX(S) swerve template: PathPlanner, BLine, vision, capstone
```

Create the repository outside of a synchronized OneDrive folder. Open each GradleRIO project as its
own folder in WPILib VS Code. The WPILib build and simulation commands act on the project folder
that is open.

The root `README.md` records the exact AdvantageKit release tag and template name for each of the
three robot projects, the WPILib 2026 patch version, and the vendor versions preserved in
`vendordeps/`. Keep those versions fixed while comparing mechanism behavior. It also contains one
evidence table for the full badge. Each row links to the folder, source file, test, log, or
explanation that satisfies the requirement. Later steps add rows to the same table.

## Guided Setup

Use **AdvantageKit v26.0.2** for all three Badge 2 robot projects. Open the
[v26.0.2 release page](https://github.com/Mechanical-Advantage/AdvantageKit/releases/tag/v26.0.2),
scroll to **Assets**, and expand the list if needed. Download these two template ZIP files for this
step:

| Project | Release Asset |
| --- | --- |
| `Badge2KitBot` | [AdvantageKit_KitBot2026Template.zip](https://github.com/Mechanical-Advantage/AdvantageKit/releases/download/v26.0.2/AdvantageKit_KitBot2026Template.zip) |
| `Badge2Swerve` | [AdvantageKit_TalonFXSwerveTemplate.zip](https://github.com/Mechanical-Advantage/AdvantageKit/releases/download/v26.0.2/AdvantageKit_TalonFXSwerveTemplate.zip) |

Extract each archive into its matching folder. GitHub's **Source code** archives contain the
upstream repository, so select the named template assets above. Record the release tag, exact
filename, Java version, WPILib version and vendordeps in the README. Keep the template's dependency
versions unless a later step names a specific change.

Step 5 creates `Badge2Bench` from
[AdvantageKit_SkeletonTemplate.zip](https://github.com/Mechanical-Advantage/AdvantageKit/releases/download/v26.0.2/AdvantageKit_SkeletonTemplate.zip)
on the same release. Only the Kit Bot and swerve projects are created here.

For each downloaded project:

1. Preserve the template's Gradle wrapper, `vendordeps/`, source tree, and license files.
2. Set the FRC team number where the template instructions specify it.
3. Open the project folder in WPILib VS Code and run **Build Robot Code** before making structural
   changes.
4. Run **Simulate Robot Code** and confirm the template starts with its shipped simulation
   constants.
5. Record the template name, release tag, download URL, and first successful build date in the root
   README.

For `Badge2Swerve`, the shipped `generated/TunerConstants.java` describes a specific robot and is
sufficient for every Badge 2 simulation row. A student who later deploys to a real swerve chassis
generates constants for that chassis with Phoenix Tuner X as the template instructions describe.
Physical swerve setup is outside Badge 2.


## Prepare the Hardware

Continue to [Step 4: Hardware Setup and Utilization](/badges/badge-2-hardware). That lesson
introduces Talon FX, Talon FXS and Thrifty Nova through hardware inspection, Phoenix Tuner X and
Thrifty Config. The student records the actual fixture and operates it through the vendor tool. The
student creates the `Badge2Bench` project for that fixture in Step 5. Keep the swerve template's
shipped device configuration in simulation.

## Independent Change

Copy the contents of the local `Badge2JavaPractice` folder into `<yourname>Badge02/java-practice/`.
From the copied folder, compile and run `ConfigPractice.java` again. Update
`java-practice/README.md` with the command and observed output. This proves the preserved practice
is usable from its final location.

Both templates drive from a plain `CommandXboxController` and shape the sticks inside their drive
commands. The student's own controller class is built in `Badge2Bench` in
[Step 6](/badges/badge-2-testing#build-a-robot-controller-class) and replaces that shaping in
`Badge2Swerve` in [Step 11](/badges/badge-2-path-following#bring-the-mechanisms-into-badge2swerve).
Leave both templates' controllers unchanged here.

## Badge Check

A **clean clone** is a fresh copy of the repository in a new folder. Building from one proves that
the repository contains the files another student needs.

<StepsBox title="Project Setup Badge Check">

1. The student clones `<yourname>Badge02` into a new folder and compiles
   `java-practice/ConfigPractice.java` there.
2. The student opens `Badge2KitBot` from the clean clone. **Build Robot Code** and **Simulate Robot
   Code** succeed with no edits.
3. The student opens `Badge2Swerve` from the same clone. **Build Robot Code** succeeds with no
   edits, and **Simulate Robot Code** drives the swerve chassis from a controller in the Sim GUI.
4. The student opens the root README and shows the template name, exact release tag, and source link
   for each project.
5. The mentor chooses one completed evidence row. The student follows its link to the named file or
   result.

</StepsBox>

If a clean clone fails to build, start with the first error. Check whether a source file or
`vendordeps/` JSON was omitted, whether both computers use the same WPILib release, and whether a
dependency download needs network access.
