Step 3 creates the repository every later step uses. The student starts two separate GradleRIO projects from AdvantageKit's 2026 templates, records where each project came from, and copies the completed Java practice into the repository.

## Before You Start

Complete [Step 2: Java Foundations](/badges/badge-2-java) first. Keep the local `Badge2JavaPractice` folder until the copied version has been checked inside the repository.

Review [GitHub Remotes](/tools/github-remotes), [Cobra Repository Tour](/frc/cobra-repository-tour), and the setup sections of the [AdvantageKit Kit Bot template](https://docs.advantagekit.org/getting-started/template-projects/kitbot-template/) and [TalonFX(S) swerve template](https://docs.advantagekit.org/getting-started/template-projects/talonfx-swerve-template/).

Before driving the swerve template, read [Tank and Swerve](/frc/tank-and-swerve). It introduces steering modules and forward, sideways, and turning requests. The remaining Drivetrain Fundamentals lessons supply the worked calculations during Step 9; setup here asks the student to build and drive the supplied template.

## Repository Layout

Create one GitHub repository named `<yourname>Badge02`, such as `AlexBadge02`:

```text
AlexBadge02/
├── README.md
├── java-practice/
│   ├── ConfigPractice.java
│   └── assignments/
│       ├── a13-reference-semantics-lab/
│       └── a18-records/
├── KitBotPathPlanner/
│   └── AdvantageKit 2026 Kit Bot template project
└── Badge2Robot/
    └── AdvantageKit TalonFX(S) swerve template project
```

Open each GradleRIO project as its own folder in WPILib VS Code. The WPILib build and simulation commands act on the project folder that is open.

The root `README.md` records the exact AdvantageKit release tag and template name for both projects. It also contains one evidence table for the full badge. Each row links to the folder, source file, test, log, or explanation that satisfies the requirement. Later steps add rows to the same table.

## Guided Setup

Use the official release linked by the template documentation. Do not copy the current contents of a moving default branch and describe them as a release. For each downloaded project:

1. Preserve the template's Gradle wrapper, `vendordeps/`, source tree, and license files.
2. Set the FRC team number where the template instructions specify it.
3. Open the project folder in WPILib VS Code and run **Build Robot Code** before making structural changes.
4. Run **Simulate Robot Code** and confirm the template starts with its shipped simulation constants.
5. Record the template name, release tag, download URL, and first successful build date in the root README.

For `Badge2Robot`, the shipped `generated/TunerConstants.java` describes a specific robot and is sufficient for every Badge 2 simulation row. A student who later deploys to a real swerve chassis generates constants for that chassis with Phoenix Tuner X as the template instructions describe. Physical swerve setup is outside Badge 2.

## Independent Change

Copy the contents of the local `Badge2JavaPractice` folder into `<yourname>Badge02/java-practice/`. From the copied folder, compile and run `ConfigPractice.java` again. Update `java-practice/README.md` with the command and observed output. This proves the preserved practice is usable from its final location.

## Badge Check

A **clean clone** is a fresh copy of the repository in a new folder. Building from one proves that the repository contains the files another student needs.

<StepsBox title="Project Setup Badge Check">

1. The student clones `<yourname>Badge02` into a new folder and compiles `java-practice/ConfigPractice.java` there.
2. The student opens `KitBotPathPlanner` from the clean clone. **Build Robot Code** and **Simulate Robot Code** succeed with no edits.
3. The student opens `Badge2Robot` from the same clone. **Build Robot Code** succeeds with no edits, and **Simulate Robot Code** drives the swerve chassis from a controller in the Sim GUI.
4. The student opens the root README and shows the template name, exact release tag, and source link for each project.
5. The mentor chooses one completed evidence row. The student follows its link to the named file or result.

</StepsBox>

If a clean clone fails to build, start with the first error. Check whether a source file or `vendordeps/` JSON was omitted, whether both computers use the same WPILib release, and whether a dependency download needs network access.
