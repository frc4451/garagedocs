Step 5 adds the first automated tests to `Badge2Robot`. These tests exercise pure Java configuration and decision logic, so a failure points to one rule and runs without a simulated motor controller. Mechanism and HAL simulation tests come later in [Unit Tests in Simulation](/frc/unit-tests-in-simulation).

## Verify the Test Setup

Open `Badge2Robot/build.gradle` from the exact AdvantageKit template release recorded in Step 3. AdvantageKit v26.0.2's shared template declares `testImplementation 'org.junit.jupiter:junit-jupiter:5.10.1'`, `testRuntimeOnly 'org.junit.platform:junit-platform-launcher'`, and a `test` block that calls `useJUnitPlatform()`. Confirm those lines remain present. If the student used a different recorded release, use that release's original `build.gradle` as the source of truth instead of copying v26.0.2's version.

Also confirm that `wpi.java.configureTestTasks(test)` remains in the build. WPILib documents that Java tests live under `src/test/java/`, and Gradle runs them during a normal robot build.

Record the JUnit dependency text and version in the evidence table. This makes the source of the version reviewable and prevents a later copy from silently introducing a different testing stack.

## Guided Example

Create these two complete files. The package path under `src/main/java/` and `src/test/java/` must match the package declaration.

`src/main/java/frc/robot/config/MechanismLimits.java`:

```java
package frc.robot.config;

public record MechanismLimits(double minPosition, double maxPosition) {
    public MechanismLimits {
        if (!Double.isFinite(minPosition) || !Double.isFinite(maxPosition)) {
            throw new IllegalArgumentException("limits must be finite");
        }
        if (minPosition >= maxPosition) {
            throw new IllegalArgumentException("minPosition must be less than maxPosition");
        }
    }

    public double clamp(double requestedPosition) {
        if (!Double.isFinite(requestedPosition)) {
            throw new IllegalArgumentException("requestedPosition must be finite");
        }
        return Math.max(minPosition, Math.min(maxPosition, requestedPosition));
    }
}
```

`src/test/java/frc/robot/config/MechanismLimitsTest.java`:

```java
package frc.robot.config;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

import org.junit.jupiter.api.Test;

public class MechanismLimitsTest {
    @Test
    public void keepsValueInsideRange() {
        MechanismLimits limits = new MechanismLimits(0.2, 1.4);

        assertEquals(0.8, limits.clamp(0.8), 1e-9);
    }

    @Test
    public void clampsBothEdges() {
        MechanismLimits limits = new MechanismLimits(0.2, 1.4);

        assertEquals(0.2, limits.clamp(-0.5), 1e-9);
        assertEquals(1.4, limits.clamp(2.0), 1e-9);
    }

    @Test
    public void rejectsReversedAndEqualRanges() {
        assertThrows(IllegalArgumentException.class, () -> new MechanismLimits(2.0, 1.0));
        assertThrows(IllegalArgumentException.class, () -> new MechanismLimits(1.0, 1.0));
    }

    @Test
    public void rejectsNonFiniteValues() {
        MechanismLimits limits = new MechanismLimits(0.2, 1.4);

        assertThrows(IllegalArgumentException.class, () -> limits.clamp(Double.NaN));
        assertThrows(
                IllegalArgumentException.class,
                () -> new MechanismLimits(Double.NEGATIVE_INFINITY, 1.0));
    }
}
```

`@Test` marks a method for JUnit to run. `assertEquals(expected, actual, tolerance)` checks a floating-point result: the expected value comes first, the value returned by the code comes second, and the tolerance permits a small rounding difference. `assertThrows` passes a lambda containing the operation that should fail; the assertion passes only when that operation throws the named exception.

Run the tests, then run the build and open `build/reports/tests/test/index.html`. The report should list four passing tests.

These tests cover a normal result, both boundary directions, invalid configuration, and non-finite input. They check behavior that could change during a refactor; they do not repeat the implementation line by line.

## See a Useful Failure

Temporarily change the upper clamp assertion from `1.4` to `1.3`. Run the tests and read the failure's expected value, actual value, test method, and source line. Restore `1.4`, run the tests again, and keep the passing version. The failed run is practice evidence; the incorrect assertion does not remain in the repository. In PowerShell, use `.\gradlew.bat test`; in macOS or Linux terminals, use `./gradlew test`.

## Independent Change

Add one method that answers a new configuration question, such as whether a position is inside the inclusive range. Write tests for a value in the middle, both exact limits, and one value outside each side. Give each test method a name that states the behavior it checks.
