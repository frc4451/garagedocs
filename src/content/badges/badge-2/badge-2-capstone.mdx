In Step 13, the student integrates the library, composition, path, vision, and robot-state work already completed in `Badge2Robot` and explains the data flow through it. Both swerve routines come from Step 10; the capstone registers them with the chooser and demonstrates them together with the existing mechanisms, cameras, and derived state. The only added diagnostic is the output used to prove replay. The project is demonstrated from a clean clone, twice, without a source change between runs.

## Guided Example

Prepare the existing Step 10 PathPlanner routine as the first integrated run. Trace a mechanism action from the chooser selection through the composed subsystem and IO request, then trace one camera observation through the estimator and Step 12 derived fact. Save the log and replay it successfully before registering the existing BLine routine in the same chooser.

## Independent Change

Integrate the Step 10 BLine routine without changing its route and action points or the mechanisms, camera integration, and robot-state interfaces it uses. The chooser must run either existing swerve routine from the same clean clone. The earlier path-following evidence still includes all three routines: PathPlanner on the differential Kit Bot, PathPlanner on swerve, and BLine on swerve.

### Data-Flow Explanation

The student explains the data flow, not only runs the program. The chain, in the student's words and with a file named for each arrow:

```text
simulated hardware
  -> IO inputs
  -> component or subsystem
  -> pose and vision observations
  -> BobotState derived facts
  -> command decision
  -> IO request
  -> simulation state
```

The last arrow closes the loop: the request the command produced reaches `TalonFXSimState` or `TalonFXSSimState`, moves the physics model, and appears in the next loop's IO inputs.

## Badge Check

<StepsBox title="Capstone badge check">

1. The mentor clones `<yourname>Badge02` into a new folder and builds `Badge2Robot`. No edits.
2. The student selects the PathPlanner routine in the chooser, enables autonomous in the Sim GUI, and the routine runs to a stop. AdvantageScope shows the path, the mechanism actions, the camera observations and the derived state on one timeline.
3. The student selects the BLine routine and runs it the same way, without touching source.
4. The mentor interrupts one routine at an arbitrary point by disabling the robot. The drivetrain stops and every mechanism enters its documented safe state; the student shows the state in the log.
5. The student walks the data-flow chain above from one simulated encoder to the sim state, naming the file at each arrow.
6. The student replays the saved log successfully through the current code in `REPLAY` mode and shows the newly recorded output in the replayed log.

</StepsBox>
