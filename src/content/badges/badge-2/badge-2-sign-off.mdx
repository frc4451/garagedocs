Step 15 closes Badge 2 after the integrated capstone and successful replay. The student completes the post-test and reviews the accumulated evidence with a mentor. A passing written score does not replace the practical work.

## Required Sheet

The site uses the September 2026 revised Badge 2 requirements. The [Google Docs sign-off sheet](https://docs.google.com/document/d/19bYHl6gLpLtoIs9wSAsRVje0Jok5U5xWoD9A7rcnjWs/edit) and [assessment](https://docs.google.com/document/d/1oHxe6Rt1QnBW95DJVc9To73P6bVHDBe-QlSQtFt8AYI/edit) have not been updated for this revision. The mentor uses the current site rows for practical completion and records the assessment version as described in [Pretest](/badges/badge-2-pretest#printed-test).

The student copies each current required row into a dated evidence record with these columns: row identifier, current work, evidence link, mentor signature, and date. The printed record can be attached to the existing packet. The repository README links the same evidence. The shared Google Docs masters remain unchanged.

| Earlier Requirement | Current Requirement |
| --- | --- |
| Simulation-only completion | Steps 4 and 7 include the provided FX, FXS or Nova fixture, setup record, and physical roller demonstration. |
| Five families on both CTRE controllers | Four required general simulations, required FX and FXS roller device simulations, a selected physical roller adapter, and one CTRE pivot profile comparison. Linear rail row 7.5 and full FXS matrix row 7.7 are retired. |
| Three complete composed subsystems | Required elevator assembly and focused feed-readiness exercise. Pivoting-intake row 8.2 and timed rumble are optional. |
| Three complete autonomous routines | Guided differential comparison and two complete swerve routines. Former differential rows 10.5–10.9 are retired. |
| All pose and vision math before paths | Rows 9.1–9.5 and 9.11 before paths; rows 9.6–9.10 and 9.12 at the start of AprilTag work. |

The hardware/software split adds a fifteenth step. Existing numeric row identifiers remain stable evidence labels and no longer necessarily match lesson numbers. Step 4 contains hardware rows HW.1, 3.8 and HW.2. Row 3.7 belongs to Step 5 with software rows 4.1–4.7. Row HW.3 belongs to Step 7 with the simulation work; rows 6.11–6.12 cover the two CTRE roller simulation checks. The remaining earlier row identifiers are preserved. Former full-matrix requirements remain retired; the two focused roller paths do not restore them.

Existing evidence is retained when it proves the current behavior. The mentor checks the work rather than transferring a signature solely because a row number matches. Newly required physical work and any missing current checks are completed separately. A mistake during practice does not erase completed evidence.

The mentor reviews the physical roller evidence and selects one motor setting to trace from the builder through record validation, IO construction, vendor application, and its verification evidence. The student distinguishes Lombok-generated construction code from AdvantageKit-generated input logging and explains one configuration test or unit conversion. The capability table distinguishes four general models, both CTRE roller device simulations, the selected physical controller and the CTRE pivot profile comparison. The elevator review includes drum diameter, the radius passed to `ElevatorSim`, a predicted travel change, limits, and the saved motion log.

The composition review includes a refused clearance transition, the measured/goal drawing, and feeding refused without possession or flywheel readiness. Required controller input and binding checks remain passing. Optional rumble or extra assemblies do not replace a required check.

The mentor reviews the differential comparison log and both complete swerve routines, two-camera vision, one derived robot fact, safe interruption, and successful replay with a new output. The autonomous capstone remains in simulation; the bench project supplies physical mechanism evidence.

During the existing Step 8 mechanism review, discuss the [Math Behind PID](/badges/badge-2-mechanism-library#the-math-behind-pid): one signed error-rate calculation, one accumulated-error calculation, and their meaning on the mechanism graph. This is guided practice, with no separate worksheet or sign-off row. Formal calculus and former rows 9.13–9.16 have moved to [Badge 3](/badges/badge-3-calculus).

The mentor also asks the student to name one library design they would change after using it and explain the tradeoff. A specific reason matters more than choosing a particular redesign.

## Cross-Step Questions

The student may use notes for these practical-review questions. Answers belong in the student's own words.

1. **Ownership:** A shooter command wants to change the intake roller directly because it knows the shooter is ready. Trace the owning subsystem and show how the readiness fact can influence an allowed command.
2. **Frames:** Vision observations are consistently displaced relative to the robot. Name the transform and frame evidence to check, then describe a test that distinguishes a sign error from using the inverse transform.
3. **Control:** The physical FX, FXS or Nova roller responds differently from its simulation. Name two configuration, conversion, supply, or model differences to inspect and the evidence that would confirm each.
4. **Autonomous:** Run from the drawn start and from an offset. Explain each follower's inputs, progress model, and recovery using the observed logs. Do not assume one follower must fail or recover identically in every case.
5. **Java and Tests:** Show a record, callback, or collection from the project. Use the controller subclass to explain an override and runtime dispatch. Explain who owns its data, when it is read, and one test that could detect a mistake in that behavior.

If an explanation needs work, the mentor reviews the relevant lesson and tries another example. Completed checks remain complete.

## Assessment and Signature

Use a fresh copy of the [ten-question assessment](/badges/badge-2-pretest). The student scores at least 18 of 20 without notes or internet. The mentor compares the first and final papers with the student after scoring the second sitting. For a paper using the temporary 26-point version, retain that paper and use the questions 1–10 subtotal out of 20; calculus questions do not affect Badge 2 completion.

| # | Work | Done When |
| --- | --- | --- |
| 14.1 | Post-test | The final score is at least 18 of 20 and is recorded beside the initial score, with each test version identified |
| 14.2 | Evidence review | Every current required row in Steps 2–14 is signed and links to evidence in the README; retired and optional rows are excluded |
| 14.3 | Cross-step explanation | The student answers the five practical questions and explains one design improvement |
| 14.4 | Final signature | The mentor records the completion date after confirming the capstone and successful replay |

## After Badge 2

Badge 2 introduces FX, FXS and Nova, includes both CTRE roller simulation paths, and records which controller was demonstrated physically. Badge 3 refines that foundation with torque-current control, characterization, advanced sensing and reference work. Before advanced physical FX work, review the actual fixture and establish or reuse a matching voltage baseline. A student who used Nova or FXS physically completes that fixture-specific bridge without repeating the controller-introduction lesson.

The supplied Badge 3 base may contain additional mechanism families and vendor implementations. The mentor distinguishes those supplied assets from the four families required here. The saved Badge 2 elevator log supports the calculus application.

A student with Badge 2 can begin contributing to FRC 4451's competition code with a mentor. [State-Driven Robot Code](/frc/why-state-machines) extends composed subsystems into a superstructure. BLine remains the path-following standard for the next badge. [Badge 3](/badges/badge-3) continues with mechanism refinement, hardware, object detection, autonomous acquisition, simulator experiments, and leadership evidence.
