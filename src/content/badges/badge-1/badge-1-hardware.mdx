Step 7 puts the Step 6 code on a real Kit Bot. The subsystem design stays the same; `RobotContainer` already picks the real IO implementation when `RobotBase.isReal()` is true ([R12](/kit-bot/r12-real-vs-sim)). A mentor helps you check the image, network, controller settings, and safe test area before enabling. Hardware may need different directions or settings from the simulation.

### Rows

| # | Step | Where it is taught | Done when |
|---|---|---|---|
| 7.1 | Image the roboRIO and set the team number | [R00 Part 2: Image the roboRIO](/kit-bot/r00-roborio-imaging) | The Driver Station reaches the controller over USB and shows the correct team number and current image year |
| 7.2 | Update and configure the radio | [R00 Part 3: Configure the Robot Radio](/kit-bot/r00-radio-setup) | The radios have the approved firmware and matching settings; the Driver Station has communications and `ping` reaches the roboRIO |
| 7.3 | Set CAN IDs and check the bus | [R12 Part 2: First Deploy](/kit-bot/r12-first-deploy#prepare-the-spark-max-controllers) | Every SPARK MAX appears once with the ID used in `Constants` |
| 7.4 | Deploy with the real IO | [R12 Part 2: First Deploy](/kit-bot/r12-first-deploy#deploy-the-real-branch) | *WPILib: Deploy Robot Code* succeeds and the console reports `IO: real` |
| 7.5 | Safety check before the first enable | [R12 Part 2: First Deploy](/kit-bot/r12-first-deploy#perform-the-safety-check) | Robot on blocks, mechanism clear, and one person stationed at Driver Station **Disable** |
| 7.6 | Drive the real Kit Bot | [R11](/kit-bot/r11-teleop-drive) on hardware | Forward is forward and the turn direction is correct; the robot holds still inside the deadband |
| 7.7 | Launch on hardware | [R08](/kit-bot/r08-launcher-io-part-2) on hardware | The bumpers intake and launch; the feeder and intake-launcher roller run independently in the intended sequence; AdvantageScope shows both motors |
| 7.8 | Autonomous on carpet | [R14](/kit-bot/r14-time-based-autonomous) on hardware | The routine chosen in Glass drives and stops within its timeout |

Rows 7.1 through 7.5 are taught as one bring-up sequence: controller image, radio path, CAN inventory, safe deploy, then first motion. Keep the mentor beside the student through the entire sequence, even when a row has already been practiced on another robot.

### Badge checks

Two signatures, because the hardware rows and the driving rows usually happen on different days.

<StepsBox title="Flash hardware">

1. Image the roboRIO with the current year's image and set the team number. Show the Driver Station connected.
2. Flash the radio to the current firmware and configure it for the team number. Show the laptop on the robot network and a successful `ping` to the roboRIO.

</StepsBox>

<StepsBox title="Hardware demonstration">

1. With the robot on blocks and disabled, deploy and show `IO: real`. Review the first action with the mentor before enabling.
2. Drive the wheels forward and reverse and turn, still on blocks. Confirm direction and deadband.
3. Disable before moving the robot off the blocks. With the mentor ready at Disable and the area clear, enable on carpet. Drive a short course; intake and launch a game piece; show the launcher graph.
4. Select and run one autonomous routine from Glass. It stops on its own.
5. Disable, and explain one difference observed between the simulator and the robot (a direction that had to be inverted, a speed that differed, a value that was noisier).

</StepsBox>

You perform each step. The mentor supervises hardware safety and stays ready at Disable during motion. Ask questions and practice first; repeat any unfinished check when you are ready.

Save the three hardware artifacts listed in the [Kit Bot capstone](/kit-bot/rc-capstone#evidence-to-save): the labeled CAN-ID photo, the drive video, and the intake-and-launch side view. Add them to the Kit Bot repository or link them from its README.

<RulesBox title="Stop and ask">

- A motor that spins the wrong way is fixed in `Constants` or the IO implementation, never by swapping wires under power.
- If a SPARK MAX is missing from the client, disable and check its power, USB connection, firmware, and CAN wiring with the mentor. The missing device alone does not identify the cause.
- The Driver Station says *No Robot Code*: the deploy failed or the code crashed on start. Read the console before redeploying.

</RulesBox>
