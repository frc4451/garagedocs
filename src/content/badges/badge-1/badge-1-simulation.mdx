In Step 6, the student recreates the 2026 [Kit Bot](/kit-bot) on their laptop.
A **simulation** runs the robot code against software models instead of physical motors.

Each lesson should be done in sequence. They build upon each other.

### Rows

| # | Work | Show the mentor |
|---|---|---|
| 6.1 | [R00](/kit-bot/r00-wpilib-setup), [R01](/kit-bot/r01-project-anatomy), [R02](/kit-bot/r02-robot-lifecycle) | Build, open simulation, identify the four files, and show the teleop print stopping when disabled |
| 6.2 | [R03](/kit-bot/r03-constants) through [R05](/kit-bot/r05-commands-and-triggers) | Constants compile; the heartbeat counts while disabled; the A button resets and the B button prints while enabled |
| 6.3 | [R06](/kit-bot/r06-motor-controllers), [R07 Parts 1–2](/kit-bot/r07-drive-io), [R08 Parts 1–3](/kit-bot/r08-launcher-io) | Forward and reverse distance signs, independent launcher controls, and two distance settings |
| 6.4 | [R09 Parts 1–2](/kit-bot/r09-characterization), with a mentor | Save samples and gains; use the equations and a calculator to check one full sample set |
| 6.5 | [R10](/kit-bot/r10-joysticks-and-stick-math) through [R13 Part 2](/kit-bot/r13-pose-and-field-view) | Drive with a deadband, show `IO: sim`, graph both launcher motors, open a saved log, and show the field pose |
| 6.6 | [R14](/kit-bot/r14-time-based-autonomous) | Select each autonomous option and show its output stopping |
| 6.7 | [Capstone](/kit-bot/rc-capstone) | The complete project demonstrated from a fresh clone |

**R00 Part 2**, **R00 Part 3**, and **R12 Part 2** are skipped in this step; they are physical-hardware work for Step 7. R15 is a follow-up catalog.

For row 6.3:
- forward increases both distance readings; reverse decreases both; 
- a right turn increases the left reading and decreases the right. 
- R07 Part 2 sets no exact distance for the two-second drive.
- For the launcher, the student shows left-bumper intake, right-bumper launch, A-button eject, and the D-pad distance settings. 
- Simulation shows motor readings, not fuel scoring.

### Badge check

A **fresh clone** is a new copy downloaded from GitHub into a different folder.
Demonstrating from one proves that the repository contains the files another student needs.
The demonstration uses a laptop with WPILib and REVLib prepared; the mentor may help with installation or network access beforehand.

<StepsBox title="Simulation badge check">

1. The student clones their version of the Kit Bot repository into a new folder and opens it in WPILib VS Code.
2. The student builds and launches simulation. The console shows `IO: sim`.
3. The student drives forward, reverse, and turns, then centers the sticks. The deadband removes small requests.
4. The student demonstrates the launcher controls and two D-pad settings, then shows the launcher graphs and the moving field pose.
5. The student shows both saved characterization runs and explains one result with their notes and a calculator. Releasing a test button ends the test.
6. In Glass, the student runs each autonomous option. The outputs stop, and the sticks cannot drive during "Do nothing" autonomous.

</StepsBox>

The student operates the keyboard and controller, with notes and documentation allowed, and explains what they changed and what the result shows. If a check needs help, the student practices that part with the mentor and repeats it; completed phase checks remain valid.

If a fresh clone fails to build, the first error is the place to start. Possible causes include a file that was never committed, a missing vendor library, a different WPILib version, or an unavailable dependency download. Not every failure means code was lost.
