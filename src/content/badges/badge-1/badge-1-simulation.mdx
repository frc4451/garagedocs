Step 6 is the [Kit Bot](/kit-bot) section's required path, done in simulation on the student's laptop. Every Kit Bot lesson ends with a *Done when* box; the rows below collect them by phase so the mentor can sign a phase at a time. No hardware is involved until [Step 7](/badges/badge-1-hardware).

<RulesBox title="Before you start">

[Step 5](/badges/badge-1-java) signed off. The Kit Bot lessons assume that Java; a student who skips ahead spends the time in the Java section anyway, one confusing error at a time.

Put the Kit Bot project in its own GitHub repository before the first lesson checkpoint, created the way [A00](/java/assignments/a00-practice-repository-setup) created the Practice repository: on GitHub, the mentor added as a collaborator, committed at each lesson's checkpoint. The capstone requires it.

</RulesBox>

### Badge check

The capstone page already defines a ten-minute demonstration. The badge check is that demonstration with one added condition: it starts from a **clean clone** of the student's repository on a laptop that has never built it, so what works is what was committed.

<StepsBox title="Simulation badge check">

1. Clone the repository into a new folder and open it in the WPILib VS Code.
2. Build and launch the simulator. Show the `IO: sim` confirmation.
3. Drive forward, reverse and turn with the controller. Show that the robot holds still inside the deadband.
4. Intake, launch and eject with the bumpers and A. Show the launcher graph in AdvantageScope and the pose moving on the field view.
5. Run both stepped characterization commands. Show the accepted samples, calculated `kS` and `kV`, and the hand check for one mechanism.
6. Select an autonomous option in Glass, run it, and show that the drivetrain and launcher stop.

</StepsBox>

The mentor signs when all six happen without help. A build that fails on the clean clone is the most common failure and the most useful one: it means a file was never committed, and the fix is Step 3's lesson applied.

<RulesBox title="What does not count">

- A simulator that only runs on the student's original folder.
- A working robot in a repository the mentor cannot open.
- A demonstration where the mentor drives the keyboard.

</RulesBox>
