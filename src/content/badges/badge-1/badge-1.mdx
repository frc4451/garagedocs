Badge 1 is the Automation Team's first-year badge. A student who holds it can, without a mentor driving:

1. **Use Git** to keep their own work in a GitHub repository: clone, branch, commit, push, open a pull request, and recover from the common mistakes.
2. **Reason with Boolean logic**: truth tables, equivalent expressions, implication, and the inference rules used to justify conclusions from known facts.
3. **Write fundamental Java**: variables, methods, conditionals, loops, classes and objects, inheritance and interfaces, lambdas, and the small amount of dependency injection the robot code uses.
4. **Build a Kit Bot** in WPILib simulation and on the real robot: a command-based project with a drivetrain and a launcher behind IO layers, teleop driving, telemetry in AdvantageScope, a time-based autonomous, and a working deploy to the roboRIO.

The [Kit Bot](/kit-bot) section is the instruction material for the badge. The steps below put it, and the Tools, Java and Practice lessons it depends on, in the order the [sign-off sheet](/badges/badge-1-sign-off) follows.

### The steps

| # | Step | What it proves |
|---|---|---|
| 1 | [Pretest](/badges/badge-1-pretest), first sitting | Where the student starts; nothing is expected |
| 2 | [Accounts and Tools](/badges/badge-1-tools) | GitHub, Git, VS Code, the shell, WPILib and the JDK are installed and the student can use each one |
| 3 | [Git](/badges/badge-1-git) | The student owns a repository, works on branches, and can open and finish a pull request |
| 4 | [Boolean Logic](/badges/badge-1-boolean-logic) | The student completes and corrects a classroom worksheet, then explains modus ponens and modus tollens |
| 5 | [Java Fundamentals](/badges/badge-1-java) | The Java the Kit Bot code assumes, checked by Practice assignments and a short mentor conversation |
| 6 | [Kit Bot in Simulation](/badges/badge-1-simulation) | The required Kit Bot path, every lesson's *Done when* met, demonstrated from a clean clone |
| 7 | [Kit Bot on the Robot](/badges/badge-1-hardware) | The roboRIO imaged, the radio flashed, the same code driving the real Kit Bot |
| 1 | [Pretest](/badges/badge-1-pretest), second sitting | The same ten questions after the capstone; the difference is the measure |

The order matters. The pretest comes before any lesson so it measures a true start. Git comes early so every later artifact lands in a repository. Boolean Logic gets its own classroom check before the longer Java step. Java comes before the Kit Bot lessons that assume it. Simulation comes before hardware, because a bug found in the simulator costs nothing and the same bug on the practice field can cost a mechanism.

### How the sheet works

The printed packet begins with the sign-off sheet and includes the required Boolean Logic worksheet. The student keeps it and brings it to each check. Every row names a lesson or assignment and a **done when** the mentor can see. "Participated" is not a check; a repository URL, a completed worksheet, a running simulation, a log file or a demonstration is.

Evidence lives in the student's `garagedocs-practice` repository from [A00](/java/assignments/a00-practice-repository-setup) and their Kit Bot repository. A mentor signs a row after opening the repository or watching the demonstration.

### Before and after

There are no prerequisites. The [pretest](/badges/badge-1-pretest) is taken twice: in the first week before any lesson, and again after the capstone. It is ten short questions on the shell, networking, Git and Java, thirty minutes, and it is not a gate. A low first score is expected; the two scores side by side are the badge's own measure of what it taught.
