In Step 3, you save code in a **repository**, a project folder with a history of changes. A **branch** lets you work on a change before adding it to the shared version. Code and project notes go in GitHub; your badge packet and Boolean Logic worksheet stay on paper.

Use a practice repository for rows 3.1 to 3.6. The mentor supplies a small text-file change, so these checks do not require Java. Make the deliberate conflict only in this practice repository.

### Badge check

A **pull request** asks someone to review your branch before it joins `main`. Your mentor provides a repository you can access and a small written task, such as correcting a README sentence.

<StepsBox title="Git badge check">

1. Clone a repository the mentor provides.
2. Create a branch named for the change.
3. Make the change and commit it with a message that says what and why.
4. Push the branch and open a pull request against `main`.
5. Read the mentor's review comment and address it with a follow-up commit on the same branch.
6. The mentor merges the pull request.

</StepsBox>

For this check, commit on your own branch and use a normal push. If you commit on `main` or get stuck resolving a conflict, stop and ask the mentor to help recover the work. Then demonstrate the branch workflow again. A mistake during practice does not erase completed rows.
