In Step 3, the student saves code in a **repository**, a project folder with a history of changes.
A **branch** lets them work on a change before adding it to the shared version.
Code and project notes go in GitHub; the badge packet and Boolean Logic worksheet stay on paper.

### Rows

Rows 3.1 to 3.7 use a repository named `<yourname>Badge01` (for example, `AlexBadge01`)
that the student creates in row 3.2 and pushes to their own GitHub account in row 3.5.
The mentor supplies a small text-file change, so these checks do not require Java.
The deliberate conflict in row 3.4 happens only in this repository. The same repository holds the Java assignments in Step 5.

### Badge check

A **pull request** asks someone to review a branch before it joins `main` or another branch.
The mentor provides a repository the student can access and a small written task, such as correcting a README sentence.

<StepsBox title="Git badge check">

1. The student clones the repository the mentor provides.
2. The student creates a branch named for the change.
3. The student makes the change and commits it with a message that says what and why.
4. The student pushes the branch and opens a pull request against `main`.
5. The student reads the mentor's review comment and addresses it with a follow-up commit on the same branch.
6. The mentor merges the pull request.

</StepsBox>

For this check, the student commits on their own branch and does not force-push. If they commit on `main` or get stuck resolving a conflict, they stop and ask the mentor to help recover the work, then demonstrate the branch workflow again. A mistake during practice does not erase completed rows.
