An array or `ArrayList` keeps its elements in numbered positions. A linked structure stores each value in a separate **node** object. Each node also holds a reference named `next`, which leads to the following node. A **singly linked list** has one forward link per node.

The reference named `head` points to the first node. The final node's `next` reference is `null`, which means that no object is there.

```text
head
  |
  v
[10 | next] -> [20 | next] -> [30 | null]
```

This lesson assumes that you have worked with objects, references, constructors, and `null`. Review [Objects and References](/java/fundamentals/java-objects-and-references#understanding-object-references) if a variable referring to an object is still unfamiliar.

### Trace the References

Walking a list means copying one reference at a time into a temporary variable. We will call that variable `current`.

```text
head
  |
  v
[10] -> [20] -> [30] -> null
  ^
  |
current
```

After one step, `head` still points to the first node while `current` points to the second:

```text
head
  |
  v
[10] -> [20] -> [30] -> null
          ^
          |
        current
```

That distinction protects the route into the list. Advancing `head` would discard the program's reference to the first node. Advance `current` instead.

<RulesBox title="Trace before Changing">

On paper, draw `head`, `current`, every node, and every `next` arrow. Move only `current` for the first trace. Then predict the values that a walk will print: `10`, `20`, `30`, or something else. Check the answer when you run the complete example below.

</RulesBox>

### Insert without Losing the Tail

Suppose `current` already points to the node containing `10`, and you want to insert `15` after it. The **tail** here means the part of the list after `current`. Save that route before replacing it.

```text
Before: current -> [10] -> [20] -> [30] -> null

After fresh.next = current.next:
current -> [10] -> [20] -> [30] -> null
                    ^
                    |
               [15 | next] <- fresh

After current.next = fresh:
current -> [10] -> [15] -> [20] -> [30] -> null
```

Predict what would remain reachable from `head` if the two assignments were reversed. Then trace both assignments on paper. Assigning `current.next = fresh` first would replace the only link to `20`, so the list would lose the old tail.

Insertion takes a fixed number of reference assignments only when the caller already holds a reference to the node that will come before the insertion. Finding that node by index or value still requires a walk from `head`.

### Remove around a Node

Removal from a handmade singly linked list also needs the predecessor, which is the node before the one being removed. If `current` points to `10`, one assignment bypasses `15`:

```text
Before: current -> [10] -> [15] -> [20] -> null
After:  current -> [10] --------> [20] -> null
```

The program can no longer reach the removed node through `head` after `current.next` is set to `current.next.next`. An unreachable object becomes **eligible for garbage collection**. Garbage collection (GC) is Java's automatic process for reclaiming storage from unreachable objects. Java does not promise that GC will reclaim that node immediately.

### A Complete Singly Linked List

The example below puts the node class and list operations inside `Main`, so you can run it as one file.

`private static` means the nested class and helper methods belong to `Main` and are used only by this example. The `get` method rejects a negative index, an empty list, and an index past the final node with `IndexOutOfBoundsException`.

```java
public class Main {
    private static class Node {
        public int value;
        public Node next;

        public Node(int value) {
            this.value = value;
            this.next = null;
        }
    }

    private static void insertAfter(Node node, int value) {
        Node fresh = new Node(value);
        fresh.next = node.next;
        node.next = fresh;
    }

    private static void removeAfter(Node node) {
        if (node.next != null) {
            node.next = node.next.next;
        }
    }

    private static int get(Node head, int index) {
        if (index < 0) {
            throw new IndexOutOfBoundsException("index: " + index);
        }

        Node current = head;
        for (int position = 0; position < index; position++) {
            if (current == null) {
                throw new IndexOutOfBoundsException("index: " + index);
            }
            current = current.next;
        }

        if (current == null) {
            throw new IndexOutOfBoundsException("index: " + index);
        }
        return current.value;
    }

    private static void printList(Node head) {
        Node current = head;
        while (current != null) {
            System.out.print(current.value + " ");
            current = current.next;
        }
        System.out.println();
    }

    public static void main(String[] args) {
        Node head = new Node(10);
        head.next = new Node(20);
        head.next.next = new Node(30);

        printList(head);
        insertAfter(head, 15);
        printList(head);
        removeAfter(head);
        printList(head);
        System.out.println("Index 2: " + get(head, 2));
    }
}
```

Expected output:

```text
10 20 30 
10 15 20 30 
10 20 30 
Index 2: 30
```

### Why Indexing Is Expensive

An index tells an array where an element is located. A singly linked list has no direct route to its fifth node, so `get(head, 5)` must follow five `next` references from `head`. The work grows with the index.

The table separates a handmade singly linked structure from Java's `LinkedList`. “Known predecessor” means your code already holds the needed node reference and does not first search by index or value.

“Constant time” and “fixed work” describe how an operation scales as the list grows. They do not promise that two operations take the same number of nanoseconds.

### Java's LinkedList

Java's `LinkedList` is **doubly linked**. Each internal node links to both the next and previous nodes. The class implements `List`, for ordered list operations, and `Deque`. A **deque** (pronounced “deck”) is a double-ended queue that can add or remove elements at either end.

The public `LinkedList` API does not give your program its internal node objects. Operations such as `add(500, value)` or `remove(object)` may still walk through the list to locate a position or value. End operations such as `addFirst`, `addLast`, `removeFirst`, and `removeLast` do not need that search.

These statements belong inside a `main` method. They use a `Deque` reference because the task needs only double-ended queue operations. The generic type `<String>` means this deque stores `String` objects. The imports belong above `public class Main`.

```java norun
import java.util.Deque;
import java.util.LinkedList;

Deque<String> tasks = new LinkedList<>();
tasks.addLast("intake");
tasks.addFirst("initialise");
tasks.addLast("shoot");

System.out.println(tasks.removeFirst());
System.out.println(tasks.removeLast());
System.out.println(tasks);
```

Expected output:

```text
initialise
shoot
[intake]
```

Add the statements to the `main` method in the earlier `Main.java` example if you want to run them locally.

<RulesBox title="Choose from Measured Needs">

`ArrayList` is a good default when code reads elements by index or mostly adds at the end. `LinkedList` directly supports deque operations at both ends, but `ArrayDeque` supports the same interface and is often another candidate.

Do not choose between them from a broad claim that one is always faster. Workload, list size, memory use, and Java implementation details all matter. Measure a representative program when performance affects a design decision.

</RulesBox>

### Why Learn the Handmade Version

The handmade version makes references visible. The same node-and-reference reasoning appears in trees and graphs, and it explains what happens when two variables point to the same object.

It also prepares you to use an **iterator**, an object that visits collection elements one at a time. A for-each loop uses an iterator behind the scenes. Iteration avoids repeatedly calling `get(i)` on a linked list and walking many of the same links again.

<RulesBox title="Common Mistakes">

- **Losing the head:** Advance a separate `current` reference.
- **Losing the tail:** Save the old `next` reference before changing the predecessor's link.
- **Walking past the end:** Check for `null` before reading a node's fields.
- **Accepting an invalid index:** Reject negative indexes and indexes at or beyond the list size.
- **Hiding a search inside “cheap”:** State whether the needed predecessor is already known.
- **Repeating indexed access:** Use a for-each loop or iterator for a full pass through Java's `LinkedList`.

</RulesBox>
