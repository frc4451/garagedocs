### Last In, First Out

<ReferenceImage
  src="/media/java/queue-vs-stack.svg"
  alt="Comparison of queue first-in-first-out order and stack last-in-first-out order"
  caption="A queue removes the oldest item first; a stack removes the newest item first."

A stack keeps one end open for adding and removing items. That open end is the **top**. The last item pushed onto the top is the first item popped back off, so a stack follows **last in, first out**, or **LIFO**.

Picture a stack of robot parts trays. You place each new tray on top, and you must remove the top tray before you can reach the one below it.

<ContentTable
  headers={["Operation", "What It Does"]}
  rows={[
    ["<code>push</code>", "Add an item to the top"],
    ["<code>pop</code>", "Remove and return the top item"],
    ["<code>peek</code>", "Return the top item without removing it"]
  ]}
/>

Before you run this example, predict the three action names it will print. Will `peek()` change which action comes off next?

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class Main {
    public static void main(String[] args) {
        Deque<String> history = new ArrayDeque<>();
        history.push("moveArm");
        history.push("closeClaw");
        history.push("liftArm");

        System.out.println("Peek: " + history.peek());
        System.out.println("Pop: " + history.pop());
        System.out.println("Pop: " + history.pop());
        System.out.println("Left: " + history.size());
    }
}
```

Expected output:

```text
Peek: liftArm
Pop: liftArm
Pop: closeClaw
Left: 1
```

### Which Class to Use

Java has an older class named `Stack`, but the Java API recommends the `Deque` interface for stack behavior. A **deque**, pronounced “deck,” is a double-ended queue. It can add or remove items at either end. We use only `push`, `pop`, and `peek` here so one end consistently acts as the top.

`Deque<String> history = new ArrayDeque<>();` separates three choices:

- `Deque<String>` is the variable's interface and describes the operations the code can use.
- `ArrayDeque<>` is the object that stores the items in a resizable array.
- `String` is the element type, so this stack accepts strings.

`ArrayDeque` is a good general-purpose stack implementation. It grows as needed, most operations take amortized constant time, and it is likely to be faster than the legacy `Stack` class when used this way.

A later lesson covers the rest of the `Deque` operations. For now, don't mix stack operations such as `push` with opposite-end operations such as `addLast`.

<RulesBox title="ArrayDeque Limits">

`ArrayDeque` does not accept `null`. This rule keeps `peek()` returning `null` useful as a clear signal that the stack is empty.

`ArrayDeque` is not thread-safe. The examples in this lesson use it from one thread.

</RulesBox>

### Empty Stacks

An empty stack has no top item. Predict each result before reading the table: What should `isEmpty()`, `peek()`, and `pop()` do when nothing has been pushed?

<ContentTable
  headers={["Expression", "Empty-Stack Result"]}
  rows={[
    ["<code>stack.isEmpty()</code>", "Returns <code>true</code>"],
    ["<code>stack.peek()</code>", "Returns <code>null</code>"],
    ["<code>stack.pop()</code>", "Throws <code>NoSuchElementException</code>"],
    ["<code>stack.poll()</code>", "Returns <code>null</code> and removes nothing"]
  ]}
/>

Use `isEmpty()` before `pop()` when an empty stack is an expected possibility:

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class Main {
    public static void main(String[] args) {
        Deque<String> actions = new ArrayDeque<>();
        actions.push("drive");

        while (!actions.isEmpty()) {
            System.out.println("Undo " + actions.pop());
        }

        System.out.println("Nothing left: " + actions.isEmpty());
        System.out.println("Top: " + actions.peek());
    }
}
```

Expected output:

```text
Undo drive
Nothing left: true
Top: null
```

This is the core of an undo history: push each completed action, then pop the newest action when the user asks to undo. A full undo system also needs code that reverses each action and may need a second stack for redo. Those behaviors are an extension, not something `Deque` supplies automatically.

### Matching Brackets

A bracket checker pushes every opening bracket. When it reaches a closing bracket, it pops the most recent opening bracket and checks whether the pair matches.

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class Main {
    public static boolean isBalanced(String text) {
        Deque<Character> openings = new ArrayDeque<>();

        for (char current : text.toCharArray()) {
            if (current == '(' || current == '[' || current == '{') {
                openings.push(current);
            } else if (current == ')' || current == ']' || current == '}') {
                if (openings.isEmpty()) {
                    return false;
                }

                char open = openings.pop();
                if ((current == ')' && open != '(')
                        || (current == ']' && open != '[')
                        || (current == '}' && open != '{')) {
                    return false;
                }
            }
        }
        return openings.isEmpty();
    }

    public static void main(String[] args) {
        System.out.println(isBalanced("([])"));
        System.out.println(isBalanced("([)]"));
    }
}
```

Expected output:

```text
true
false
```

`String.toCharArray()` produces the characters to inspect. Each loop variable has the primitive type `char`, but Java collections store objects rather than primitive values. `Deque<Character>` therefore uses the wrapper class `Character`. Java automatically **boxes** a `char` into a `Character` during `push` and **unboxes** it back to a `char` during `pop`.

Trace `([)]` carefully:

<ContentTable
  headers={["Read", "Action", "Stack Afterward, Top First"]}
  rows={[
    ["<code>(</code>", "Push it", "<code>[(]</code>"],
    ["<code>[</code>", "Push it", "<code>[[, (]</code>"],
    ["<code>)</code>", "Pop <code>[</code>; it does not match <code>)</code>", "<code>[(]</code>"]

/>

The checker returns `false` at the third character. Both kinds of brackets appear twice, but nesting order matters: the `[` opened last, so it must close first. The checker also fails if it sees a closing bracket while the stack is empty or finishes with an opening bracket still on the stack.

### Where Stacks Show Up

**Reversing data.** Push each item, then pop every item. Because the last item pushed comes out first, the order reverses. If you reverse a `String`, a `StringBuilder` is a mutable sequence of characters. Its `append` method builds the result one character at a time without replacing the original string.

**Method calls.** You have already seen Java's call stack. Each method call adds a frame containing information for that call, and returning removes the frame. If an application recurses too deeply, Java throws `StackOverflowError`.

Writing recursive methods is covered later. The useful connection here is that both systems finish the most recently started work first.

**Postfix expressions.** In postfix notation, an operator comes after its values. For example, `3 4 +` means `3 + 4`. A stack can hold the numbers until an operator appears. Evaluating complete postfix expressions is an extension because it also requires parsing text and handling operators correctly.

### Build a Stack

Building a small stack once makes the behavior concrete. This version stores `int` values in an array and begins with room for two values so you can see it resize.

```java
import java.util.Arrays;

public class Main {
    private static class IntStack {
        private int[] data = new int[2];
        private int size = 0;

        public void push(int value) {
            if (size == data.length) {
                data = Arrays.copyOf(data, data.length * 2);
            }
            data[size++] = value;
        }

        public int pop() {
            if (size == 0) {
                throw new IllegalStateException("stack is empty");
            }
            return data[--size];
        }

        public int peek() {
            if (size == 0) {
                throw new IllegalStateException("stack is empty");
            }
            return data[size - 1];
        }

        public boolean isEmpty() {
            return size == 0;
        }
    }

    public static void main(String[] args) {
        IntStack scores = new IntStack();
        scores.push(10);
        scores.push(20);
        scores.push(30);

        System.out.println(scores.peek());
        System.out.println(scores.pop());
        System.out.println(scores.pop());
        System.out.println(scores.isEmpty());
    }
}
```

Expected output:

```text
30
30
20
false
```

The `size` field is both the number of stored values and the next free array index. In `data[size++] = value`, the postfix increment `size++` uses the current index for the assignment and then adds one to `size`. If `size` is 2, the value goes into `data[2]`, then `size` becomes 3.

In `data[--size]`, the prefix decrement `--size` subtracts one before using the index. If `size` is 3, it becomes 2 first, so `pop()` returns `data[2]`, the current top value.

Most pushes write one array slot, so they take constant time. When the array is full, `Arrays.copyOf` allocates a larger array and copies every stored value. That one push takes time proportional to the number of values, but doubling the capacity makes resizing occasional.

Across many pushes, the average cost per push is constant; this is called **amortized constant time**. `pop()` and `peek()` take constant time in this implementation.

<RulesBox title="Common Mistakes">

- Check `isEmpty()` before `pop()` when empty is a valid state.
- Prefer `ArrayDeque` behind a `Deque` variable instead of the legacy `Stack` class.
- Don't push `null` into an `ArrayDeque`.
- Use stack operations consistently. `push` adds at the front; mixing it with `addLast` changes the order.
- Keep the final `isEmpty()` check in a bracket matcher so leftover opening brackets fail.

</RulesBox>
