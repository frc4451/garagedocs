### Both Ends

A stack uses one end. A queue adds at one end and removes at the other. A **deque**, short for double-ended queue and pronounced “deck,” lets you work at both ends.

A deque is a **superset** of a stack and a queue: it provides every end operation either structure needs, plus more. The earlier methods map to explicit deque methods like this:

<ContentTable title="Stack, Queue, and Deque Methods" headers={["Use", "Earlier Method", "Deque Meaning"]} rows={[
  ["Stack", "<code>push(x)</code>", "<code>addFirst(x)</code>"],
  ["Stack", "<code>pop()</code>", "<code>removeFirst()</code>"],
  ["Stack or queue", "<code>peek()</code>", "<code>peekFirst()</code>"],
  ["Queue", "<code>add(x)</code>", "<code>addLast(x)</code>"],
  ["Queue", "<code>offer(x)</code>", "<code>offerLast(x)</code>"],
  ["Queue", "<code>remove()</code>", "<code>removeFirst()</code>"],
  ["Queue", "<code>poll()</code>", "<code>pollFirst()</code>"]
]} />

**Linear** means arranged in a sequence. A deque is linear even though you can change either end. It does not provide numbered positions such as `get(3)`.

### Method Families

The throwing family reports failure with an exception. The special-value family returns `false` when a capacity-limited deque cannot accept an element, or `null` when an empty deque has nothing to return.

<ContentTable title="Deque Methods" headers={["Action", "Front", "Back", "Failure Result"]} rows={[
  ["Add", "<code>addFirst</code>", "<code>addLast</code>", "Throws if a capacity limit prevents insertion"],
  ["Offer", "<code>offerFirst</code>", "<code>offerLast</code>", "Returns <code>false</code> if a capacity limit prevents insertion"],
  ["Remove", "<code>removeFirst</code>", "<code>removeLast</code>", "Throws if empty"],
  ["Poll", "<code>pollFirst</code>", "<code>pollLast</code>", "Returns <code>null</code> if empty"],
  ["Get", "<code>getFirst</code>", "<code>getLast</code>", "Throws if empty"],
  ["Peek", "<code>peekFirst</code>", "<code>peekLast</code>", "Returns <code>null</code> if empty"]
]} />

Choose methods whose failure behavior fits your program. `ArrayDeque` has no fixed capacity, so ordinary additions grow its backing array instead of failing because it is full.

### Try Both Ends

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class Main {
    public static void main(String[] args) {
        Deque<String> deque = new ArrayDeque<>();
        deque.addLast("middle");
        deque.addFirst("start");
        deque.addLast("end");

        System.out.println(deque);
        System.out.println("first: " + deque.peekFirst());
        System.out.println("last: " + deque.peekLast());
        deque.removeFirst();
        deque.removeLast();
        System.out.println(deque);
    }
}
```

Expected output:

```text
[start, middle, end]
first: start
last: end
[middle]
```

### Circular Storage

`ArrayDeque` uses a resizable array. It treats the last slot as being beside the first, like positions around a circle. An internal **front index**, a whole number marking the current first slot, can move after a removal instead of shifting every element. When an index reaches the physical end, the next position wraps to slot zero.

Most additions write one slot. Occasionally the array runs out of room, so `ArrayDeque` allocates a larger array and copies the elements. One resize costs more, but those copies are spread across many additions. This average-over-a-sequence guarantee is called **amortized constant time**. It does not mean every individual addition takes the same work.

The circular layout is an implementation detail. Do not assume a capacity, growth amount, or internal index value.

### Stack and Queue Use

For a stack, add and remove at the same end. For a queue, add at the back and remove from the front.

<RulesBox title="Keep One Vocabulary">

`push(x)`, `pop()`, and `peek()` mean `addFirst(x)`, `removeFirst()`, and `peekFirst()`. Mixing stack names with explicit end names is legal, but harder to trace. Pick one vocabulary for each use.

</RulesBox>

### Choose an Implementation

<ContentTable headers={["Class", "Good Fit", "Important Limit"]} rows={[
  ["<code>ArrayDeque</code>", "A general-purpose stack, queue, or deque", "Rejects <code>null</code>; not thread-safe"],
  ["<code>LinkedList</code>", "Code that also needs <code>List</code> operations", "Indexed access can require walking through nodes"],
  ["<code>LinkedBlockingDeque</code>", "An optional deque shared safely between threads", "Blocking and concurrency behavior add concepts most programs do not need"]
]} />

`ArrayDeque` is a strong default for single-threaded deque work. Its documentation says most operations take amortized constant time. `LinkedList` also supports `List` and `Deque`, but neither class is universally faster; the choice depends on the operations and constraints your program needs.

`ArrayDeque` rejects `null`, which keeps `null` available as the clear “empty” result from methods such as `pollFirst()`. `LinkedList` permits `null`, but using it in a deque makes that result ambiguous, so avoid null deque elements.

Use `LinkedBlockingDeque` only when multiple threads need blocking, thread-safe operations. It can wait for space or an element. Concurrency is optional here; ordinary examples should stay with `ArrayDeque`.

### Trace a Sliding Window

A **sliding window** is a fixed-width group that moves through an array. For `values = {4, 2, 12, 3}` and width `k = 3`, the windows are `{4, 2, 12}` and `{2, 12, 3}`.

The deque stores candidate **indices**, the numbered positions of values. Its front identifies the largest value still eligible for the window. Trace the arrival of index `2`, whose value is `12`:

1. The window ends at index `2`, so its left bound is `2 - 3 + 1 = 0`.
2. Expire front indices less than `0`. None expire.
3. Remove index `1` from the back because its value `2` cannot beat the incoming `12` now or in a later shared window.
4. Remove index `0` for the same reason: `4` is no larger than `12`.
5. Add index `2`. The front now identifies the maximum, `12`.

At index `3`, the left bound becomes `1`. Index `2` has not expired. Its value `12` is greater than the incoming `3`, so index `3` joins behind it.

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class Main {
    public static void printWindowMaximums(int[] values, int k) {
        if (values.length == 0) {
            return;
        }
        if (k < 1 || k > values.length) {
            throw new IllegalArgumentException("k must be from 1 through values.length");
        }

        Deque<Integer> candidates = new ArrayDeque<>();
        for (int i = 0; i < values.length; i++) {
            int left = i - k + 1;
            while (!candidates.isEmpty() && candidates.peekFirst() < left) {
                candidates.removeFirst();
            }
            while (!candidates.isEmpty()
                    && values[candidates.peekLast()] <= values[i]) {
                candidates.removeLast();
            }
            candidates.addLast(i);
            if (left >= 0) {
                System.out.println(values[candidates.peekFirst()]);
            }
        }
    }

    public static void main(String[] args) {
        int[] values = {4, 2, 12, 3};
        printWindowMaximums(values, 3);
    }
}
```

Expected output:

```text
12
12
```

For a nonempty array, `k` must be at least `1` and no greater than `values.length`. This method prints nothing for empty input. Each index enters once and can leave once, so the total work grows **linearly**: doubling the input roughly doubles the work.

### Undo and Redo

Use one deque for actions you can undo and another for actions you can redo. Undo moves the newest action from undo to redo. Redo moves it back.

A new action must clear redo. Suppose you perform `A`, perform `B`, then undo `B`. The current history is `A`, and redo could restore `B`. If you perform `C` instead, the history becomes `A, C`. Restoring `B` would follow the abandoned branch, so `doAction(C)` clears redo.

### Rolling Buffers

A **rolling buffer** keeps only the newest fixed number of items. Add each reading at the back. If the size passes the limit, remove one from the front.

Before writing the code, predict the bounds: with a limit of `20`, what are the smallest and largest possible sizes immediately after the trim step? What happens when reading number `21` arrives?

This pattern works for recent robot sensor readings. Check that the limit is positive, and do not calculate an average while the buffer is empty.

<RulesBox title="Common Mistakes">

- Mixing front and back operations without tracing the order.
- Mixing throwing and special-value methods without planning for failure.
- Adding `null` to an `ArrayDeque`.
- Assuming iteration follows insertion time. A deque iterates from front to back.
- Treating implementation comparisons as universal performance rules.

</RulesBox>
