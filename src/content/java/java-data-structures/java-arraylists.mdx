This lesson builds on [Arrays](/java/fundamentals/java-arrays) and [Arrays and Their Trade-offs](/java/fundamentals/java-arrays-and-their-trade-offs). You will create an `ArrayList`, change its elements, and remove selected elements without skipping any.

<span id="the-problem-it-solves"></span>

## Store a Changing Number of Values

An array's length is fixed when Java creates it. An `ArrayList` is a list backed by an array that can grow as you add elements. The list manages the replacement array and copying for you.

This complete `Main.java` program creates a list and appends three readings. To run it in the browser, select **Run** beneath the code. To run it locally, replace the contents of `Main.java`, save it, and follow [Compile And Run](/java/fundamentals/java-setup#compile-and-run).

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> readings = new ArrayList<>();
        readings.add(120);
        readings.add(118);
        readings.add(125);

        System.out.println("Count: " + readings.size());
        System.out.println("Second: " + readings.get(1));
    }
}
```

The output is:

```text
Count: 3
Second: 118
```

`List<Integer>` is the variable's type. `List` is an interface that describes list operations. `new ArrayList<>()` creates the object that performs those operations. The `<>` is called the diamond; Java infers `Integer` from the variable declaration.

<span id="how-it-grows"></span>

## Understand Size and Capacity

An `ArrayList` has a **size**, the number of elements currently in the list, and a **capacity**, the number its internal array can currently hold. Capacity is always at least as large as size. When the internal array fills, the list creates a larger one and copies its elements. Java does not specify the exact growth amount.

Most appends do not resize the internal array. An occasional append must allocate and copy, but the average work per append stays constant over a long sequence. This is called **amortized constant time**.

If you expect about 1,000 elements, `new ArrayList<Integer>(1000)` requests that initial capacity. The list is still empty, so `size()` returns `0`. The argument reserves room; it does not add elements.

<span id="common-operations"></span>

## Read and Change Elements

Like an array, a list uses indices starting at zero. `get` reads an element, while `set` replaces the element at an existing index. `add(value)` appends, and `add(index, value)` inserts before the element currently at that index.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> motors = new ArrayList<>();
        motors.add("frontLeft");
        motors.add("frontRight");
        motors.add(0, "rearLeft");

        String replaced = motors.set(1, "frontLeftDrive");

        System.out.println("Replaced: " + replaced);
        System.out.println("First: " + motors.get(0));
        System.out.println("List: " + motors);
    }
}
```

The output is:

```text
Replaced: frontLeft
First: rearLeft
List: [rearLeft, frontLeftDrive, frontRight]
```

`set` returns the value it replaced. Neither `get` nor `set` changes the list's size. An index less than `0` or at least `size()` is invalid for `get` and `set` and causes an `IndexOutOfBoundsException`.

## Insert and Remove

Inserting at an index shifts the element at that index and all later elements one position to the right. Removing by index shifts all later elements one position to the left.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("drive");
        names.add("shooter");
        names.add("climber");

        names.add(1, "intake");
        String removed = names.remove(2);

        System.out.println("Removed: " + removed);
        System.out.println(names);
    }
}
```

The output is:

```text
Removed: shooter
[drive, intake, climber]
```

The valid insertion indices run from `0` through `size()`. Inserting at `size()` appends. The valid removal indices run from `0` through `size() - 1`.

<RulesBox title="Choose the Integer Removal">

A `List<Integer>` has two `remove` methods. A plain `int` selects `remove(int index)`. Pass an `Integer` object when you mean `remove(Object value)`:

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> numbers = new ArrayList<>();
        numbers.add(10);
        numbers.add(20);
        numbers.add(30);

        int removedAtIndex = numbers.remove(1);
        boolean removedValue = numbers.remove(Integer.valueOf(10));

        System.out.println("Removed at index: " + removedAtIndex);
        System.out.println("Removed value 10: " + removedValue);
        System.out.println(numbers);
    }
}
```

The output is:

```text
Removed at index: 20
Removed value 10: true
[30]
```

</RulesBox>

<span id="iterating"></span>

## Remove While Iterating

A for-each loop is appropriate when you only read the elements. Removing directly from the list during that loop is unsafe. `ArrayList` iterators detect structural changes on a best-effort basis and can throw `ConcurrentModificationException`; code must not depend on the exception occurring.

For a beginner-friendly removal loop, walk backwards by index:

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> readings = new ArrayList<>();
        readings.add(5);
        readings.add(-2);
        readings.add(-7);
        readings.add(9);

        for (int i = readings.size() - 1; i >= 0; i = i - 1) {
            if (readings.get(i) < 0) {
                readings.remove(i);
            }
        }

        System.out.println(readings);
    }
}
```

The output is:

```text
[5, 9]
```

Removing index `i` shifts only elements after `i`. A backwards loop has already visited those elements, so the shift cannot make the loop skip an unchecked value. A forward loop can skip adjacent matches after a removal shifts the next match into the current index.

<RulesBox title="Lambda Preview">

After you learn lambdas, `readings.removeIf(value -> value < 0)` expresses the same result. Treat that as a preview for now. The backwards-index loop uses only the loops and list methods already taught.

</RulesBox>

<span id="costs"></span>

## Read the Costs

Let **n** mean the number of elements. **O(1)** means the amount of work does not grow as n grows. **O(n)** means the work can grow in proportion to n. **Amortized O(1)** means the average stays constant across many operations, even though an occasional operation does more work. These labels describe how work grows, not an exact time.

<ContentTable
  title="ArrayList Operation Costs"
  headers={["Operation", "Cost", "Reason"]}
  rows={[
    ["<code>get(i)</code> or <code>set(i, value)</code>", "O(1)", "Uses an array index"],
    ["<code>add(value)</code> at the end", "Amortized O(1)", "An occasional append resizes and copies"],
    ["<code>add(0, value)</code> at the front", "O(n)", "Shifts existing elements right"],
    ["<code>remove(i)</code> near the front", "O(n)", "Shifts later elements left"],
    ["<code>contains(value)</code>", "O(n)", "May check every element"],
    ["<code>size()</code>", "O(1)", "Reads the stored element count"]
  ]}
/>

The later [Big-O](/java/fundamentals/java-big-o) lesson develops this notation. For now, remember that indexed reads are steady, appending is usually inexpensive, and inserting or removing near the front may move many elements.

<span id="it-stores-objects-not-primitives"></span>

## Store Objects

Generic type arguments must be reference types, so `List<int>` does not compile. Use `List<Integer>` for integer values. Java converts an `int` to an `Integer` when needed; this conversion is called **boxing** or **autoboxing**. It converts an `Integer` back to an `int` when needed through **unboxing**.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> scores = new ArrayList<>();
        scores.add(1000);

        int score = scores.get(0);
        System.out.println(score + 1);
    }
}
```

The output is:

```text
1001
```

Use `.equals()` when you need to compare two wrapper objects by value. The `==` operator on two `Integer` references can compare whether they refer to the same object, and some small boxed values may share cached objects. That makes `==` an unreliable value comparison.

<RulesBox title="Choose an ArrayList When">

- The number of elements changes while the program runs.
- The program mostly appends and reads by index.
- Insertions and removals near the front are uncommon.

An array remains useful when its length is fixed or when a large primitive collection needs to avoid wrapper objects.

</RulesBox>
