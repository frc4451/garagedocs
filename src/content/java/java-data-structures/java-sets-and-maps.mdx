### Keep One of Each Value

A set stores distinct values. Adding a value that is already present does not add a second copy. This complete program turns repeated team numbers into a set of unique team numbers:

```java
import java.util.HashSet;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        int[] teams = {6328, 6329, 6328, 6327, 6329};
        Set<Integer> uniqueTeams = new HashSet<>();
        for (int team : teams) {
            uniqueTeams.add(team);
        }
        System.out.println("Distinct teams: " + uniqueTeams.size());
        System.out.println("Contains 6328: " + uniqueTeams.contains(6328));
    }
}
```

Expected output:

```text
Distinct teams: 3
Contains 6328: true
```

### Membership and Duplicates

`contains(value)` answers a **membership** question: is this value in the set? `add(value)` returns `true` when the value was new and `false` when it was already present. That return value can detect a duplicate:

```java norun
Set<Integer> seen = new HashSet<>();
for (int value : values) {
    if (!seen.add(value)) {
        System.out.println("duplicate: " + value);
    }
}
```

This is a fragment. Place it inside `main`, add `import java.util.HashSet;` and `import java.util.Set;`, and define `values` before running it.

These average-time claims assume that hash codes spread elements well among the hash table's buckets. They are useful expectations, not a promise that every individual operation takes exactly the same time.

### Keys and Values

A map connects a **key** to a **value**. The key is what you look up, such as a team number. The value is the information stored for that key, such as how many times the team number appeared. Each key appears at most once, although many keys may have the same value.

Start counting with `put` and `getOrDefault`:

```java norun
Map<Integer, Integer> count = new HashMap<>();
for (int value : values) {
    int oldCount = count.getOrDefault(value, 0);
    count.put(value, oldCount + 1);
}
```

`put(key, value)` creates or replaces the mapping for a key. `getOrDefault(key, 0)` returns the stored value, or `0` when the key is missing. A missing key is different from a present key whose stored value happens to be zero. Use `containsKey(key)` when that distinction matters.

After the longer form is comfortable, you may see the same count written as:

```java norun
count.merge(value, 1, Integer::sum);
```

If the key is missing, `merge` stores `1`. Otherwise, `Integer::sum` names the method that adds the old count and `1`. The earlier `put` form is easier to trace and is all you need for this lesson.

<RulesBox title="Check for Missing Keys">

```java norun
Integer stored = count.get(key);
```

`get` returns `null` when there is no mapping, but it can also return `null` for a present key mapped to `null`. For counting maps, avoid `null` values and use `getOrDefault`. Assigning a missing result directly to `int` attempts to unbox `null` and throws `NullPointerException`.

</RulesBox>

### Entries and Order

A map entry is one key-value pair. `entrySet()` provides a set view of all mappings, and each `Map.Entry` provides `getKey()` and `getValue()`:

```java norun
for (Map.Entry<Integer, Integer> entry : count.entrySet()) {
    System.out.println(entry.getKey() + " -> " + entry.getValue());
}
```

Use entries when you need both parts of every mapping. A `HashMap` does not promise insertion order, sorted order, or a stable order between runs. If output order matters, sort the result or choose a collection with the order you need.

### Arrays or Maps

An array is often the clearest counter when every key is an integer in a known compact range:

```java norun
// Every value is in the inclusive range 1 through 100_000.
int[] count = new int[100_001];
for (int value : values) {
    count[value]++;
}
```

Array lookup uses the integer directly as an index. A hash map accepts sparse integers, strings, and other key types, but stores extra bookkeeping for hashing. Choose from the actual bounds and memory available instead of memorizing one contest-specific cutoff.

Negative bounded values can be shifted:

```java norun
// Every value is in the inclusive range -1000 through 1000.
int[] count = new int[2001];
count[value + 1000]++;
```

The smallest value maps to index `0`, and the largest maps to index `2000`. Before using an array, verify that every computed index stays between `0` and `length - 1`.

### Sorted Sets and Maps

`TreeSet` stores distinct values in sorted order. `TreeMap` stores entries sorted by key. Their basic add, remove, and lookup operations take O(log N) time.

Here, logarithmic means that doubling the number of stored items adds only about one more comparison level. For 8 sorted items, a tree search needs roughly 3 comparison levels; for 16, roughly 4. This is slower than the expected O(1) lookup of a well-distributed hash table, but it provides sorted traversal and nearest-value searches.

```java
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        TreeSet<Integer> scores = new TreeSet<>();
        scores.add(5);
        scores.add(1);
        scores.add(9);
        System.out.println("Sorted: " + scores);
        System.out.println("At least 6: " + scores.ceiling(6));
        System.out.println("At most 6: " + scores.floor(6));
    }
}
```

Run this as `Main.java`. It prints:

```text
Sorted: [1, 5, 9]
At least 6: 9
At most 6: 5
```

`ceiling(x)` returns the least stored value greater than or equal to `x`. `floor(x)` returns the greatest stored value less than or equal to `x`. Either method returns `null` when no value qualifies, so keep the result as `Integer` and check it before unboxing.

### Coordinate Keys

For a grid with `rows` rows and `cols` columns, valid zero-based coordinates satisfy both bounds: `0 <= r && r < rows` and `0 <= c && c < cols`. When those bounds are known, a two-dimensional array is direct:

```java norun
boolean[][] visited = new boolean[rows][cols];
visited[r][c] = true;
```

You can encode a valid coordinate as `r * cols + c`. Multiplying the row by the row width reserves one non-overlapping block of `cols` keys per row. Use `long` arithmetic so the multiplication cannot overflow `int`:

```java norun
Set<Long> visited = new HashSet<>();
long key = (long) r * cols + c;
visited.add(key);
```

This formula is one-to-one only under the paired bounds above and with `cols > 0`. If coordinates can be negative or do not have known bounds, use a value object instead of inventing an unexplained multiplier.

<RulesBox title="Keep Hash Keys Stable">

Equal objects must have equal hash codes. A hash-based collection uses the hash code to choose where to search, then uses equality to identify the key. Override `equals` and `hashCode` together, and include the same fields in both.

```java
import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

public class Main {
    public static final class Point {
        private final int row;
        private final int col;

        public Point(int row, int col) {
            this.row = row;
            this.col = col;
        }

        @Override
        public boolean equals(Object other) {
            if (this == other) return true;
            if (!(other instanceof Point)) return false;
            Point point = (Point) other;
            return row == point.row && col == point.col;
        }

        @Override
        public int hashCode() {
            return Objects.hash(row, col);
        }
    }

    public static void main(String[] args) {
        Set<Point> visited = new HashSet<>();
        visited.add(new Point(2, 4));
        System.out.println(visited.contains(new Point(2, 4)));
    }
}
```

Expected output:

```text
true
```

Run this as `Main.java`. The fields are `final` because changing a field used by `equals` or `hashCode` after insertion can put the object in the wrong bucket and make a lookup fail. A record supplies value-based equality and hashing for its components. Review [Enums and Records](/java/fundamentals/java-enums-and-records#grouped-values-with-records) before using a record as a coordinate key, and keep its component values stable too.

</RulesBox>

### Count Pairs

Suppose the values are `2, 3, 2, 4` and the target sum is `6`. The valid index pairs contain `2 + 4`. Because there are two earlier `2` values, the answer is `2` pairs.

```java
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        int[] values = {2, 3, 2, 4};
        int target = 6;
        Map<Integer, Integer> earlierCount = new HashMap<>();
        long pairs = 0;

        for (int value : values) {
            int complement = target - value;
            int matches = earlierCount.getOrDefault(complement, 0);
            pairs += matches;
            System.out.println(value + ": add " + matches + " pair(s)");
            int oldCount = earlierCount.getOrDefault(value, 0);
            earlierCount.put(value, oldCount + 1);
        }
        System.out.println("Total pairs: " + pairs);
    }
}
```

Run it as `Main.java`. It prints:

```text
2: add 0 pair(s)
3: add 0 pair(s)
2: add 0 pair(s)
4: add 2 pair(s)
Total pairs: 2
```

For each value, the map counts only earlier values. The program looks up the complement before inserting the current value, so an element cannot pair with itself and each pair of indexes is counted once. The map stores duplicate counts; a set would remember only whether a complement had appeared.

### Common Mistakes

- A set answers membership, not how many copies occurred. Use a map for duplicate counts.
- `get` can return `null` for a missing key. Use `getOrDefault` for counters or `containsKey` when presence itself matters.
- `HashSet` and `HashMap` iteration order is unspecified. Do not build expected output around the order you happen to observe.
- Boxed integers are objects. Use `.equals` for value equality instead of relying on `==`.
- A mutable custom key can become unreachable after a field involved in equality or hashing changes.
