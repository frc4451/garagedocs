### First In, First Out

A queue holds items until they are ready to be processed. In a regular queue, the first item added is the first item removed. This order is called **first in, first out**, or **FIFO**.

Picture a line of people: a person joins at the back, and the person at the front is served next. Java calls the front the **head** and the back the **tail**.

<ContentTable
  headers={["Operation", "Meaning", "If It Cannot Complete"]}
  rows={[
    ["<code>offer</code>", "Add at the tail", "Returns <code>false</code> if a capacity limit prevents it"],
    ["<code>add</code>", "Add at the tail", "Throws if a capacity limit prevents it"],
    ["<code>poll</code>", "Remove and return the head", "Returns <code>null</code> when empty"],
    ["<code>remove</code>", "Remove and return the head", "Throws <code>NoSuchElementException</code> when empty"],
    ["<code>peek</code>", "Return the head without removing it", "Returns <code>null</code> when empty"],
    ["<code>element</code>", "Return the head without removing it", "Throws <code>NoSuchElementException</code> when empty"]
  ]}
/>

The methods come in two families. `offer`, `poll`, and `peek` report an expected failure with `false` or `null`. `add`, `remove`, and `element` throw an exception instead. This lesson uses the first family so an empty queue can be handled directly.

### Using One

`Queue<String>` says that the variable follows queue rules and holds strings. `ArrayDeque<String>` creates the object that stores them. An `ArrayDeque` grows as needed and rejects `null`, so `null` from `poll` clearly means the queue was empty.

```java
import java.util.ArrayDeque;
import java.util.Queue;

public class Main {
    public static void main(String[] args) {
        Queue<String> tasks = new ArrayDeque<>();
        tasks.offer("calibrate");
        tasks.offer("driveForward");
        tasks.offer("shoot");

        System.out.println("next: " + tasks.peek());
        while (!tasks.isEmpty()) {
            System.out.println("running: " + tasks.poll());
        }
        System.out.println("after drain: " + tasks.poll());
    }
}
```

Expected output:

```text
next: calibrate
running: calibrate
running: driveForward
running: shoot
after drain: null
```

The loop **drains** the queue, which means it removes every remaining item. Save the example in a local file named `Main.java`, then run `javac Main.java` and `java Main`. You can also use Run below.

<RulesBox title="Prefer ArrayDeque">

`LinkedList` also implements `Queue`, but `ArrayDeque` is the usual FIFO choice. The Java API notes that it is likely to be faster than `LinkedList` when used as a queue.

Do not add `null` as a queue item. `ArrayDeque` rejects it, and `Queue` uses `null` from `poll` and `peek` to mean empty.

</RulesBox>

### Queue Uses

A queue works well when work should stay in arrival order. A program can buffer sensor readings and process the oldest unread value first.

The next class is a small FIFO work list for learning queue behavior. It is not WPILib's command scheduler and should not replace WPILib command scheduling on a robot.

```java
import java.util.ArrayDeque;
import java.util.Queue;

public class Main {
    private final Queue<String> pending = new ArrayDeque<>();

    public void schedule(String action) {
        pending.offer(action);
    }

    public void runNext() {
        String action = pending.poll();
        if (action != null) {
            System.out.println("executing " + action);
        }
    }

    public boolean hasWork() {
        return !pending.isEmpty();
    }

    public static void main(String[] args) {
        Main scheduler = new Main();
        scheduler.schedule("calibrate");
        scheduler.schedule("drive");
        while (scheduler.hasWork()) {
            scheduler.runNext();
        }
    }
}
```

Expected output:

```text
executing calibrate
executing drive
```

To run it locally, save it as `Main.java`, then run `javac Main.java` and `java Main`.

Queues also power **breadth-first search**, an algorithm taught in the later [Graphs lesson](/java/fundamentals/graphs#breadth-first-search). It explores a graph, a set of connected locations, one distance level at a time.

Its **frontier** is the queue of locations waiting to be explored. A **visited** marker records locations already added so they are not added repeatedly. Return to that use after learning graphs.

### Priority Queues

A regular queue uses arrival order. A `PriorityQueue` uses value order instead. With integers, Java's natural order puts the smallest number at the head.

```java
import java.util.PriorityQueue;
import java.util.Queue;

public class Main {
    public static void main(String[] args) {
        Queue<Integer> priorities = new PriorityQueue<>();
        priorities.offer(50);
        priorities.offer(10);
        priorities.offer(30);
        while (!priorities.isEmpty()) {
            System.out.println(priorities.poll());
        }
    }
}
```

Expected output:

```text
10
30
50
```

Save the example as `Main.java`, then run `javac Main.java` and `java Main`. Items with equal priority can come out in either order. If ties must follow arrival order, include an arrival number in the comparison.

### Define the Comparison

Java knows how to compare integers. For your own class, provide a **comparator**, an object that says which of two values comes first. The lambda `(a, b) -> ...` is a compact comparison. It returns a negative number, zero, or a positive number to place `a` before, tied with, or after `b`.

```java
import java.util.Comparator;
import java.util.PriorityQueue;
import java.util.Queue;

public class Main {
    private static final class Task {
        private final String name;
        private final int priority;

        private Task(String name, int priority) {
            this.name = name;
            this.priority = priority;
        }
    }

    public static void main(String[] args) {
        Comparator<Task> first = (a, b) -> Integer.compare(a.priority, b.priority);
        Queue<Task> tasks = new PriorityQueue<>(first);
        tasks.offer(new Task("shoot", 3));
        tasks.offer(new Task("stopMotors", 1));
        tasks.offer(new Task("driveForward", 2));

        while (!tasks.isEmpty()) {
            System.out.println(tasks.poll().name);
        }
    }
}
```

Expected output:

```text
stopMotors
driveForward
shoot
```

Save the example as `Main.java`, then run `javac Main.java` and `java Main`. `Integer.compare(a, b)` safely compares two `int` values. Do not use `a - b`; subtraction can overflow and reverse the intended order. For largest-first order, compare `b.priority` with `a.priority`.

<RulesBox title="Poll for Priority Order">

A `PriorityQueue` uses a **heap**, a tree-shaped arrangement that keeps the highest-priority item at the head without sorting every position. Only `peek` and repeated `poll` calls promise priority order. Iteration, including a for-each loop, does not.

```java
import java.util.PriorityQueue;

public class Main {
    public static void main(String[] args) {
        PriorityQueue<Integer> values = new PriorityQueue<>();
        values.offer(50);
        values.offer(10);
        values.offer(30);

        System.out.println("iteration:");
        for (int value : values) {
            System.out.println(value);
        }
        System.out.println("polling:");
        while (!values.isEmpty()) {
            System.out.println(values.poll());
        }
    }
}
```

The iteration section is not guaranteed to be sorted, so its exact output may vary. The polling section is guaranteed to print:

```text possible
polling:
10
30
50
```

Save the example as `Main.java`, then run `javac Main.java` and `java Main`.

</RulesBox>

### Keep the Top K

To keep the largest `K` values, maintain a smallest-first priority queue with at most `K` items. When the queue grows past `K`, `poll` removes the smallest candidate.

Adding or removing one heap item takes time proportional to `log K`. Here, `log K` means the work grows by about one step each time `K` doubles. Processing `n` values takes `O(n log K)` time, while sorting all of them takes `O(n log n)` time.

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.PriorityQueue;

public class Main {
    public static List<Double> topK(double[] values, int k) {
        PriorityQueue<Double> keep = new PriorityQueue<>();
        for (double value : values) {
            keep.offer(value);
            if (keep.size() > k) {
                keep.poll();
            }
        }
        List<Double> result = new ArrayList<>(keep);
        Collections.sort(result, Collections.reverseOrder());
        return result;
    }

    public static void main(String[] args) {
        double[] scores = {65.5, 48.0, 113.0, 34.75, 107.5, 59.5, 88.5, 99.75};
        System.out.println(topK(scores, 3));
    }
}
```

Expected output:

```text
[113.0, 107.5, 99.75]
```

`Collections.sort` sorts the result list. `Collections.reverseOrder()` supplies a comparator that puts larger values first. Save the example as `Main.java`, then run `javac Main.java` and `java Main`.

This is the priority-queue version of the top-K query in [A26](/java/assignments/a26-stream-filter). It works well when input is large or arrives one value at a time.

<RulesBox title="Common Mistakes">

- Mixing the throwing and special-value method families.
- Forgetting that `poll` can return `null` on an empty queue.
- Expecting `PriorityQueue` iteration to follow priority order.
- Assuming equal-priority items keep their arrival order.
- Subtracting values in a comparator, which can overflow.
- Offering `null` to an `ArrayDeque` or `PriorityQueue`, which throws `NullPointerException`.

</RulesBox>
