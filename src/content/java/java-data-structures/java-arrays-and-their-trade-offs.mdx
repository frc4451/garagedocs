## Start with Arrays

You have already used arrays to store a fixed number of values of one type. This lesson compares that fixed capacity with the number of values your program is currently using. It also shows the work required to insert, remove, or copy values.

If you need a syntax refresher, review [Arrays](/java/fundamentals/java-arrays#creating-arrays---basic-types) in Loops and Iteration.

<span id="what-an-array-is"></span>

## Read by Index

An array provides numbered slots. Java checks an index against the array's length, then reads or replaces the selected slot. The amount of work for that access does not grow as the array gets longer.

```java
public class Main {
    public static void main(String[] args) {
        int[] readings = {120, 118, 125, 121, 119};
        System.out.println("First: " + readings[0]);
        System.out.println("Fourth: " + readings[3]);
        readings[3] = 123;
        System.out.println("Updated fourth: " + readings[3]);
    }
}
```

Run the example in the browser from this lesson's code block, or replace `Main.java` with it and follow [Compile And Run](/java/fundamentals/java-setup#compile-and-run). It prints:

```text
First: 120
Fourth: 121
Updated fourth: 123
```

The Java Language Specification defines an array's length, index range, and component access. It does not require a particular memory layout, so Java code should rely on those defined behaviors instead of assuming how a JVM arranges the slots.

<RulesBox title="What Arrays Are Good At">

- **Reading by index:** the work does not grow with the array's length
- **Writing by index:** the work does not grow with the array's length
- **Fixed capacity:** the array never resizes behind your code

</RulesBox>

## Capacity and Logical Size

An array's `length` is its **capacity**, the number of slots created for it. That length never changes. A program can separately track its **logical size**, the number of slots that currently contain values the program considers part of its data.

This complete example creates space for five readings but stores only three:

```java
public class Main {
    private static final int[] readings = new int[5];
    private static int count = 0;

    public static void main(String[] args) {
        addReading(120);
        addReading(118);
        addReading(125);
        System.out.println("Capacity: " + readings.length);
        System.out.println("Logical size: " + count);
        System.out.println("Average: " + average());
    }

    public static void addReading(int value) {
        if (count < readings.length) {
            readings[count] = value;
            count++;
        }
    }

    public static int average() {
        if (count == 0) {
            return 0;
        }
        int total = 0;
        for (int i = 0; i < count; i++) {
            total += readings[i];
        }
        return total / count;
    }
}
```

Run it from the code block or as `Main.java`. The output is:

```text
Capacity: 5
Logical size: 3
Average: 121
```

The loop stops at `count`, not `readings.length`. The two unused `int` slots contain their default value, `0`, but those zeros are spare capacity rather than sensor readings. This pattern works well for a buffer with a known maximum size.

To store a sixth value in an array of length five, create a longer array and copy the existing values. `Arrays.copyOf` returns a new array with the requested length:

```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        int[] readings = {120, 118, 125, 121, 119};
        int[] bigger = Arrays.copyOf(readings, 6);
        bigger[5] = 122;
        System.out.println(Arrays.toString(bigger));
    }
}
```

The result is `[120, 118, 125, 121, 119, 122]`. Copying a longer array requires work for each existing element, so the work grows with the number of values copied.

<span id="inserting-and-removing"></span>

## Insert and Remove

An array has no built-in insert or remove operation. Your code chooses a logical size and shifts values to keep the used portion together. Inserting at an index shifts later values one slot to the right. Start at the end so a value is not overwritten before it is copied.

Removing at an index shifts later values one slot to the left. For an object array, clear the old final position to `null` so that unused slot no longer refers to the removed object.

```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        String[] names = {"drive", "intake", "climber", null, null};
        int size = 3;
        int insertIndex = 1;
        for (int i = size; i > insertIndex; i--) {
            names[i] = names[i - 1];
        }
        names[insertIndex] = "shooter";
        size++;
        System.out.println("After insert: " + Arrays.toString(names));

        int removeIndex = 2;
        for (int i = removeIndex; i < size - 1; i++) {
            names[i] = names[i + 1];
        }
        size--;
        names[size] = null;
        System.out.println("After remove: " + Arrays.toString(names));
        System.out.println("Logical size: " + size);
    }
}
```

Run it from the code block or as `Main.java`. It prints:

```text
After insert: [drive, shooter, intake, climber, null]
After remove: [drive, shooter, climber, null, null]
Logical size: 3
```

Inserting or removing near the beginning moves more values than doing so near the end. In the worst case, the number of moves grows with the logical size.

## Avoid Common Mistakes

<RulesBox title="Common Array Mistakes">

- **Going past the end.** Valid indices run from `0` through `length - 1`. An invalid index causes `ArrayIndexOutOfBoundsException`.
- **Confusing capacity with logical size.** A partly filled array's `length` counts every slot, including unused ones.
- **Copying only the reference.** `int[] b = a;` makes both variables refer to the same array. Use `a.clone()` or `Arrays.copyOf(a, a.length)` when you need a separate array. See [Objects And References](/java/fundamentals/java-objects-and-references#reference-assignment-copies-the-reference).
- **Using an unfilled object slot.** Every slot in `new String[5]` starts as `null`, not as an empty string. Calling a method through that `null` reference causes `NullPointerException`.

</RulesBox>

<span id="two-dimensional-arrays"></span>

## Use Two-Dimensional Arrays

A two-dimensional array is an array whose elements are arrays. It can represent a grid or table. Each row has its own length, so use `grid[row].length` for the inner loop.

```java
public class Main {
    public static void main(String[] args) {
        int[][] grid = new int[3][4];
        grid[1][2] = 7;
        for (int row = 0; row < grid.length; row++) {
            for (int column = 0; column < grid[row].length; column++) {
                if (column > 0) {
                    System.out.print(" ");
                }
                System.out.print(grid[row][column]);
            }
            System.out.println();
        }
    }
}
```

Run it from the code block or as `Main.java`. The program prints three rows of four numbers. Every value is `0` except the `7` at row 1, column 2:

```text
0 0 0 0
0 0 7 0
0 0 0 0
```

## Use Object Arrays

An object array stores references. Creating the array creates its slots, but it does not create the objects that will occupy them. Until you assign an object, each slot contains `null`.

```java
public class Main {
    public static void main(String[] args) {
        Robot[] competition = new Robot[2];
        System.out.println("Before assignment: " + competition[0]);
        competition[0] = new Robot("SpeedBot", 12345);
        competition[1] = new Robot("PowerBot", 67890);
        for (Robot robot : competition) {
            robot.activate();
            System.out.println(robot);
        }
    }

    private static class Robot {
        private final String name;
        private final int teamNumber;
        private boolean active;

        public Robot(String name, int teamNumber) {
            this.name = name;
            this.teamNumber = teamNumber;
            this.active = false;
        }

        public void activate() {
            active = true;
        }

        @Override
        public String toString() {
            String status = active ? "Active" : "Inactive";
            return name + " (Team " + teamNumber + ") - " + status;
        }
    }
}
```

Run it from the code block or as `Main.java`. It prints:

```text
Before assignment: null
SpeedBot (Team 12345) - Active
PowerBot (Team 67890) - Active
```

<span id="reading-the-cost-notation"></span>

## Read Growth Notation

The following data-structure lessons use `n` for the number of values involved in an operation. **O(1)** describes work that does not grow with `n`. **O(n)** describes work that can grow in direct proportion to `n`.

For example, reading one array slot by index is O(1). Shifting every later value after removing index 0 is O(n). These labels describe how work grows, not the exact running time. [Big-O](/java/fundamentals/java-big-o) develops the notation.

The later ArrayList lesson also uses **amortized O(1)**. It means that an occasional operation may require a larger copy, while the average work per operation stays bounded across a long sequence.

<span id="choosing-an-array"></span>

## Choose an Array

Choose an array when you know the required capacity or a safe maximum, mostly access values by index, and rarely insert or remove values in the middle.

<RulesBox title="Choose an Array When">

- You know the size in advance or have a safe maximum.
- You mostly read and write by index.
- You rarely insert or remove from the middle.
- You need fixed capacity with no automatic resizing.

If the logical size changes often, continue to [ArrayLists](/java/fundamentals/java-arraylists#the-problem-it-solves). If you frequently add or remove at both ends, see [Deques](/java/fundamentals/java-deques#both-ends).

</RulesBox>
