A `while` loop repeats a block while its condition is `true`. This lesson builds on [conditions](/java/fundamentals/java-conditionals), [reassignment](/java/fundamentals/java-variables), and [console input](/java/fundamentals/java-console-input). You will trace a finite loop, calculate a running total, and stop an input loop safely.

<span id="while-loops-with-conditions"></span>

## Check The Condition First

Java checks a `while` loop's condition before each pass through its body. If the condition is `true`, Java runs the body and returns to the condition. If it is `false`, Java skips the body and continues below the loop.

This complete `Main.java` program prints the integers 1 through 3. To run it locally, replace the entire contents of `Main.java`, save the file, and use the [Compile And Run](/java/fundamentals/java-setup#compile-and-run) steps from Java Setup.

```java
public class Main {
    public static void main(String[] args) {
        int count = 1;

        while (count <= 3) {
            System.out.println("Count: " + count);
            count = count + 1;
        }

        System.out.println("Done");
    }
}
```

The loop has three working parts:

1. **Condition:** `count <= 3` decides whether another pass starts.
2. **Body:** `System.out.println` uses the current value.
3. **Update:** `count = count + 1` changes a value used by the condition.

The update happens near the end of each pass. Java then checks the condition again.

## Trace Each Pass

| Check | `count <= 3` | Output | Next Count |
| --- | --- | --- | --- |
| First | `1 <= 3` is `true` | `Count: 1` | `2` |
| Second | `2 <= 3` is `true` | `Count: 2` | `3` |
| Third | `3 <= 3` is `true` | `Count: 3` | `4` |
| Fourth | `4 <= 3` is `false` | Body is skipped | `4` |

After the false check, the program continues below the loop and prints `Done`:

```text
Count: 1
Count: 2
Count: 3
Done
```

## Run Zero Times

A `while` loop can run zero times because Java checks the condition before entering the body. Change the starting declaration in the first program to `int count = 4;`. The first check is false, so the program prints only `Done`.

That behavior is useful when there may be no work to do. It also means the loop body cannot prepare a value that the first condition needs. Set up those values before the `while` line.

## Build A Running Total

A loop can update more than one value. In this complete `Main.java` example, `round` controls how many passes run and `totalPoints` accumulates a sum. Replace the entire file when you switch from the first example to this one.

```java
public class Main {
    public static void main(String[] args) {
        int round = 1;
        int totalPoints = 0;

        while (round <= 4) {
            totalPoints = totalPoints + round;
            System.out.println("After round " + round + ": " + totalPoints);
            round = round + 1;
        }

        System.out.println("Final total: " + totalPoints);
    }
}
```

`totalPoints` starts at zero. Each pass replaces it with the old total plus the current round number. The four additions are 1, 2, 3, and 4, so the final total is 10.

## Plan The Stopping Condition

Before writing a loop, identify what can make its condition false. Then check that every path through the body either moves toward that stopping value or has another documented way to leave the loop.

- `count = 1`, `count <= 3`, and `count = count + 1` stops after three passes.
- Starting at `4` makes the body run zero times.
- Removing the update leaves `count` equal to `1`, so the condition stays true.
- Updating with `count = count - 1` moves away from this boundary. The loop then runs far longer than intended and eventually reaches integer overflow, so it is the wrong update for this stopping condition.

If a local terminal program keeps printing because a loop does not stop, press Ctrl+C in the terminal. Then inspect the starting value, condition, and update before running it again.

## Read Until A Sentinel

Some loops do not know their number of passes in advance. A **sentinel** is a special input value that tells the loop to stop. The next program adds integers until it reads the sentinel `0` or reaches end-of-input (EOF).

`input.hasNextLine()` checks whether the input source has another line before the body calls `nextLine()`. It returns `false` at EOF, and it can wait while interactive terminal input remains open. A final line can still be read when EOF follows it without a line-ending character. The `try` and `catch` use the specific `NumberFormatException` introduced in [Try-Catch](/java/fundamentals/java-try-catch): an invalid line prints a message and the next pass reads the next line.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        long sum = 0;

        System.out.println("Enter integers, one per line. Enter 0 to stop.");

        while (input.hasNextLine()) {
            String line = input.nextLine();

            try {
                int number = Integer.parseInt(line);

                if (number == 0) {
                    break;
                }

                sum = sum + number;
            } catch (NumberFormatException exception) {
                System.out.println("Skipped invalid integer: " + line);
            }
        }

        System.out.println("Sum: " + sum);
        input.close();
    }
}
```

The `break` statement ends the nearest loop immediately. Execution continues with the first statement below that loop, which prints the sum. Input after the first `0` is not read.

With these four browser input lines, the program skips `two`, stops at `0`, and prints a sum of 7:

```text
3
two
4
0
```

```text
Enter integers, one per line. Enter 0 to stop.
Skipped invalid integer: two
Sum: 7
```

With `0` as the first input line, the sum is zero because the program reaches `break` before adding a number. If the supplied input ends without `0`, `hasNextLine()` becomes false and the program prints the sum collected so far. The example uses `long` for a larger total than `int` can hold; as with every fixed-size integer type, the calculation assumes the final total fits its type.

### Run With Browser Input

In the browser, put every input line in **Sample input** before selecting **Run**. The browser supplies those saved lines and then EOF. You cannot type another line after the run begins.

Try the four-line sample above. Then test `0` by itself, an empty **Sample input** box, and `5` followed by EOF. Each run stops and prints its sum.

### Run With Terminal Input

To use interactive input, save the complete program as `Main.java`, then compile and run it in VS Code's terminal using the steps from [Console Input](/java/fundamentals/java-console-input#run-it-in-a-terminal). Type one value per line and press Enter after each value. Enter `0` to finish normally.

To test EOF without entering `0`, put input such as `5` in the `in.txt` file from [Repeat Input From A File](/java/fundamentals/java-console-input#repeat-input-from-a-file). Run the program with that file as its input. After reading `5`, the program reaches the file's end, leaves the loop, and prints `Sum: 5`.

## Infinite Loops

An **infinite loop** repeats without reaching a stopping point. The condition in `while (true)` never becomes false, but the loop can still end when a reachable statement such as `break`, `return`, or `throw` transfers control out of it. A `while (true)` loop is infinite only when no such exit occurs.

The input example does not need `while (true)`: `hasNextLine()` gives it a second stopping path when input ends. Prefer a condition that states when another pass is possible. Use `while (true)` only when every intended exit is handled inside the body and the surrounding program is designed to keep that work running.

In an FRC robot program, WPILib calls robot lifecycle methods repeatedly. Do not put a blocking `while` loop inside one of those methods to imitate that schedule. The [Kit Bot lifecycle lesson](/kit-bot/r02-robot-lifecycle) explains how those repeated calls work.
