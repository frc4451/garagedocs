A derivative tells you how quickly a quantity changes at a particular input. For position as a
function of time, that rate is velocity. For velocity as a function of time, it is acceleration. In
PID, the D term uses the rate at which the error changes.

Read [Functions and Rates of Change](/java/fundamentals/functions-and-rates-of-change) first. It
introduces function notation, slopes, units, and limits. The optional Java example also uses
[Methods](/java/fundamentals/methods), [Arrays](/java/fundamentals/arrays-and-their-trade-offs), and
[For Loops](/java/fundamentals/for-loops). No robot hardware is needed.

## From an Interval to an Instant

Return to the numerical position model <Equation tex="x(t)=t^2" />, with time entered in seconds and
position read in metres. At two seconds, the position is four metres. Write the interval length as
<Equation tex="h" /> seconds. The average velocity from time 2 to time <Equation tex="2+h" /> is:

<Equation display tex="\frac{x(2+h)-x(2)}{h}=\frac{(2+h)^2-4}{h}" />

Expanding the square means multiplying <Equation tex="(2+h)(2+h)" />. That gives
<Equation tex="4+4h+h^2" />. Subtract 4, then divide each remaining term by the nonzero
<Equation tex="h" />:

<Equation display tex="\frac{4h+h^2}{h}=4+h\qquad(h\ne0)" />

<ContentTable title="Rates near Two Seconds" headers={["Interval h (s)", "Average velocity (m/s)"]} rows={[
  ["1", "5"], ["0.5", "4.5"], ["0.1", "4.1"], ["−0.1", "3.9"], ["−0.01", "3.99"]
]} />

A negative <Equation tex="h" /> examines the interval on the other side of two seconds. Both
differences in the quotient reverse sign, so it still gives the average rate over that interval.
From either side, <Equation tex="4+h" /> approaches 4 as <Equation tex="h" /> approaches zero. The
instantaneous velocity at two seconds is therefore 4 metres per second.

## The Derivative Notation

The definition at a general time is:

<Equation display tex="x'(t)=\lim_{h\to0}\frac{x(t+h)-x(t)}{h}" />

Read <Equation tex="x'(t)" /> as “x prime of t.” The symbol <Equation tex="\lim_{h\to0}" /> means to
take the limit as <Equation tex="h" /> approaches zero through nonzero values. The derivative exists
at an interior point when this two-sided limit is a finite number. A corner or a jump can prevent
that from happening.

Another notation for the same derivative is <Equation tex="\frac{\mathrm{d}x}{\mathrm{d}t}" />, read
as “the derivative of x with respect to t.” Here the entire symbol names a derivative. It is not an
instruction to divide two Java variables named `dx` and `dt`.

On a graph, a line through two points is a **secant**. Its slope gives the average rate between
them. The **tangent** at a point has the limiting slope as the nearby point approaches. It describes
the curve's local direction.

<CalculusGraph kind="slope" />

In the graph, the secant from two to three seconds has slope 5. The tangent at two seconds has slope
4. The derivative describes the curve at two seconds even though that longer interval has a
different average.

## Differentiate a Formula

Finding a derivative is called **differentiation**. For <Equation tex="x(t)=t^2" />, the same
expansion works at any time:

<Equation display tex="\frac{(t+h)^2-t^2}{h}=2t+h" />

As <Equation tex="h" /> approaches zero, the rate approaches <Equation tex="2t" />. Thus
<Equation tex="x'(t)=2t" />. At two seconds this gives 4 metres per second; at three seconds it
gives 6 metres per second.

Several rules let us differentiate polynomials without repeating the limit calculation. A
**polynomial** adds constant multiples of nonnegative whole-number powers, such as
<Equation tex="t^2+3t+1" />. In the table, <Equation tex="c" /> is a constant and
<Equation tex="n" /> is a positive integer.

<ContentTable title="First Derivative Rules" headers={["Function", "Derivative", "Reason or example"]} rows={[
  ["\\(c\\)", "\\(0\\)", "A constant does not change"],
  ["\\(t\\)", "\\(1\\)", "An increase of one in the input increases the output by one"],
  ["\\(t^n\\)", "\\(nt^{n-1}\\)", "The power rule: the derivative of t cubed is three times t squared"],
  ["\\(c f(t)\\)", "\\(c f'(t)\\)", "A constant multiplier also multiplies the rate"],
  ["\\(f(t)+g(t)\\)", "\\(f'(t)+g'(t)\\)", "Differentiate each term, then add; subtraction works the same way"]
]} />

For example, the derivative of <Equation tex="3t^2+2t+7" /> is <Equation tex="6t+2" />. The constant
7 changes the graph's height but not its slope. These rules are a starting set. Products of changing
functions, quotients, and nested functions require additional rules covered in the full MATH 141
course.

## Estimate a Rate in Java

A sensor supplies samples at distinct times. With the current and previous readings, a **backward
difference** estimates the current rate using the interval that has just ended:

<Equation display tex="\text{estimated rate}=\frac{x_{\text{current}}-x_{\text{previous}}}{t_{\text{current}}-t_{\text{previous}}}" />

It is an interval average, not an exact instantaneous derivative for a general changing signal. With
a known formula, we can also examine a forward interval. This complete Java program compares three
such intervals beginning at two seconds:

```java
public class Main {
  public static void main(String[] args) {
    double timeSeconds = 2.0;
    double[] intervalsSeconds = {1.0, 0.5, 0.25};

    for (double intervalSeconds : intervalsSeconds) {
      double changeMeters =
          positionMeters(timeSeconds + intervalSeconds) - positionMeters(timeSeconds);
      double averageVelocity = changeMeters / intervalSeconds;
      System.out.println(averageVelocity);
    }
    System.out.println(2.0 * timeSeconds);
  }

  private static double positionMeters(double timeSeconds) {
    return timeSeconds * timeSeconds;
  }
}
```

Select **Run**, or replace `Main.java` with this program using
[Java Setup](/java/fundamentals/setup). Expected output:

```text
5.0
4.5
4.25
4.0
```

The enhanced `for` loop reads each value in `intervalsSeconds` into `intervalSeconds`, one value per
pass. The first three output lines are interval averages; the last comes from the exact derivative
of the model. Try adding `0.125` to the interval array and predict the new line before running it.

The intervals in this example are positive and nonzero. Real timestamp differences need validation
before division. Making an interval extremely small can amplify measurement noise and floating-point
roundoff, so “smaller” is not a guarantee of a better numerical estimate. Use the actual interval,
or the fixed period required by the controller API. WPILib's `PIDController` assumes calls arrive at
its configured period.

## The D Term in PID

Let <Equation tex="r(t)" /> be the requested position, called the **setpoint**, and
<Equation tex="y(t)" /> the measured position. Their difference is the error:

<Equation display tex="e(t)=r(t)-y(t)" />

The derivative contribution to the controller output is:

<Equation display tex="u_D(t)=k_D\frac{\mathrm{d}e}{\mathrm{d}t}" />

The gain <Equation tex="k_D" />, written `kD` in code, scales the error's rate into output units.
For position error in metres and voltage output, its units are volt-seconds per metre. Multiplying
by metres per second leaves volts.

Suppose error falls from 0.30 metres to 0.26 metres in 0.020 seconds. Its estimated rate is −2
metres per second. An illustrative gain of 0.10 volt-seconds per metre produces a D contribution of
−0.20 volts. These numbers explain the arithmetic; they are not tuning recommendations.

For a fixed setpoint approached from below, positive error shrinks and the D contribution opposes
the positive P contribution. That can reduce overshoot. With a moving setpoint, the derivative is
the requested velocity minus the measured velocity. D therefore responds to changes in the setpoint
as well as in the measurement. A sudden setpoint step can produce a large sampled derivative, often
called **derivative kick**.

Differencing also magnifies noise. A 0.001-metre change caused entirely by measurement noise over
0.020 seconds looks like 0.05 metres per second. Check signal quality and timing before treating a
jagged derivative as real motion. Continue to [PID Control](/frc/pid-control#the-three-terms) for
the complete controller and tuning context.

## Check Your Understanding

1. Differentiate <Equation tex="2t^3+5t-4" /> and evaluate the result at <Equation tex="t=2" />.
2. Explain how a position of 4 metres differs from a velocity of 4 metres per second.
3. Error rises from −0.20 metres to −0.10 metres in 0.05 seconds. Find the estimated error rate and
   the sign of D when the gain is positive.
4. Explain why a zero current error does not, by itself, imply a zero D contribution.

<details>
<summary>Check Your Reasoning</summary>

1. The derivative is <Equation tex="6t^2+5" />; its value at 2 is 29.
2. Position describes location relative to the reference; velocity describes the signed rate of
   position change.
3. The rate is +2 metres per second, so the D contribution is positive.
4. Error can be passing through zero while still changing. D depends on that change, not only the
   current value.

</details>
