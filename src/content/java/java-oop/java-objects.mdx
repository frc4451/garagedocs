## Create Separate Objects

The [Classes](/java/fundamentals/java-classes) lesson introduced fields, constructors, `new`, and instance methods. An **object** is one instance of a class. Each use of `new` creates a separate object and returns a reference that identifies it.

The complete program below creates two `Robot` objects. This small class is only an educational data model: its name and task count are stored values, not data measured from hardware, and its methods do not control a physical robot.

`Robot` is nested inside `Main` so the browser playground can run the example as one file. The `static` on the nested class only allows `main` to create a `Robot` without first creating a `Main`; each `Robot` still has its own instance fields.

In the browser, select **Run** beneath the complete program. To run it locally, replace the entire contents of `Main.java`, save the file, and follow [Compile And Run](/java/fundamentals/java-setup#compile-and-run).

```java
public class Main {
    public static class Robot {
        private String name;
        private int taskCount;

        public Robot(String name, int taskCount) {
            this.name = name;
            this.taskCount = taskCount;
        }

        public void setTaskCount(int taskCount) {
            this.taskCount = taskCount;
        }

        public String status() {
            return name + " tasks: " + taskCount;
        }
    }

    public static void main(String[] args) {
        Robot practiceBot = new Robot("Practice", 2);
        Robot competitionBot = new Robot("Competition", 5);

        practiceBot.setTaskCount(3);

        System.out.println(practiceBot.status());
        System.out.println(competitionBot.status());
    }
}
```

The output is:

```text
Practice tasks: 3
Competition tasks: 5
```

Both objects use the fields and methods declared by `Robot`, but their field values are independent. Changing `practiceBot` does not change `competitionBot`.

## Store and Copy References

A **class-type variable** is a variable whose declared type names a class. For example, `Robot first` declares `first` with the class type `Robot`. A class-type variable stores a **reference**, a value that identifies an object. Assigning one reference variable to another copies that value. It does not create another object.

Replace `Main.java` with this complete program:

```java
public class Main {
    public static class Robot {
        private String name;
        private int taskCount;

        public Robot(String name, int taskCount) {
            this.name = name;
            this.taskCount = taskCount;
        }

        public void setTaskCount(int taskCount) {
            this.taskCount = taskCount;
        }

        public String status() {
            return name + " tasks: " + taskCount;
        }
    }

    public static void main(String[] args) {
        Robot first = new Robot("Practice", 2);
        Robot alias = first;

        alias.setTaskCount(3);

        System.out.println(first.status());
        System.out.println(alias.status());
        System.out.println(first == alias);
    }
}
```

The output is:

```text
Practice tasks: 3
Practice tasks: 3
true
```

Only one `Robot` object exists. `first` and `alias` both identify it, so a change made through either variable is visible through the other.

## Compare References

For class types, `==` answers one narrow question: do these two values refer to the same object, or are both values `null`? Two separately created objects are different objects even when their fields currently hold matching values.

Add these statements at the end of `main` in the previous program:

```java norun
Robot sameValues = new Robot("Practice", 3);

System.out.println(first == alias);       // true: one object
System.out.println(first == sameValues);  // false: two objects
```

Do not assume that `equals` always compares field contents. Every class inherits an `equals` method from `Object`, and that default method treats two references as equal only when they identify the same object. A class can define a different meaning for `equals`. A later lesson develops object comparison after you learn more about references.

## Use Null Carefully

A class-type variable can hold `null`, which means it does not refer to an object. Calling an instance method through `null` causes a `NullPointerException`.

This guarded example does not call a method unless the reference identifies an object:

```java
public class Main {
    public static class Robot {
        public void printReady() {
            System.out.println("Ready");
        }
    }

    public static void main(String[] args) {
        Robot selectedRobot = null;

        if (selectedRobot != null) {
            selectedRobot.printReady();
        } else {
            System.out.println("No robot selected");
        }
    }
}
```

The output is `No robot selected`. Removing the guard and evaluating `selectedRobot.printReady()` would cause the exception.

## Pass a Reference Value

The [Parameters And Arguments](/java/fundamentals/java-methods#parameters-and-arguments) section established that Java copies each argument's value into its parameter. An object argument follows the same rule: Java copies the reference value. The parameter and the caller's variable then identify the same object, so the method can call that object's methods and change its state.

Replace `Main.java` with this complete program:

```java
public class Main {
    public static class Robot {
        private String name;
        private int taskCount;

        public Robot(String name, int taskCount) {
            this.name = name;
            this.taskCount = taskCount;
        }

        public void setTaskCount(int taskCount) {
            this.taskCount = taskCount;
        }

        public String status() {
            return name + " tasks: " + taskCount;
        }
    }

    public static void updateRobot(Robot robot) {
        robot.setTaskCount(10);
        robot = new Robot("Temporary", 99);
    }

    public static void main(String[] args) {
        Robot practiceBot = new Robot("Practice", 2);

        updateRobot(practiceBot);

        System.out.println(practiceBot.status());
    }
}
```

The output is `Practice tasks: 10`. The call first copies the reference stored in `practiceBot` into the parameter `robot`, so `robot.setTaskCount(10)` changes the object that the caller can see. The next assignment makes only the local parameter identify a new `Robot`. It does not change the reference stored in `practiceBot`, so the caller still identifies the original object with a task count of 10. Java passes the argument **by value** because it copies the reference value itself.

<RulesBox title="Object Reference Rules">

- Each `new` expression creates a separate object.
- A class-type variable stores a reference that identifies an object, or it stores `null`.
- Copying a non-null reference into another variable makes both variables identify the same object.
- For references, `==` is true when both values identify the same object or when both are `null`.
- A method parameter receives a copy of the argument's reference value.

</RulesBox>

Read [Objects And References](/java/fundamentals/java-objects-and-references) next for a deeper reference model.
