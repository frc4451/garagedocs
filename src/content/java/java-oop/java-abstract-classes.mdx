## Abstract Classes

This lesson builds on [Inheritance](/java/fundamentals/inheritance). You should already know how a subclass uses `extends`, calls `super(...)`, and overrides a method.

An abstract class describes a family of objects while leaving part of the work for its subclasses. It can store fields, initialize them in a constructor, and provide methods that subclasses inherit. It can also declare an abstract method with no body when each concrete subclass needs to supply that behavior. A **concrete class** is complete enough for Java to create its objects.

The following complete console program models two subsystems. It is a Java inheritance example, not a WPILib subsystem model. The parent class handles each subsystem's name and enabled state. Each concrete subclass supplies its own `periodic()` behavior.

Predict which lines will print. Then select **Run** below the code, or replace the contents of a local `Main.java`, save it, and follow [Compile and Run](/java/fundamentals/setup#compile-and-run).

```java
public class Main {
    public abstract static class Subsystem {
        private final String name;
        private boolean enabled;

        protected Subsystem(String name) {
            this.name = name;
            this.enabled = false;
        }

        public final void enable() {
            enabled = true;
        }

        public final boolean isEnabled() {
            return enabled;
        }

        public final void describe() {
            System.out.println(name + " enabled: " + enabled);
        }

        public abstract void periodic();

        public final void update() {
            if (enabled) {
                periodic();
            }
        }
    }

    public static final class Intake extends Subsystem {
        public Intake() {
            super("intake");
        }

        @Override
        public void periodic() {
            System.out.println("checking intake sensor");
        }
    }

    public static final class Arm extends Subsystem {
        public Arm() {
            super("arm");
        }

        @Override
        public void periodic() {
            System.out.println("holding arm position");
        }
    }

    public static void main(String[] args) {
        Subsystem intake = new Intake();
        Subsystem arm = new Arm();

        intake.enable();
        intake.describe();
        intake.update();

        arm.describe();
        arm.update();
    }
}
```

The console should print:

```text
intake enabled: true
checking intake sensor
arm enabled: false
```

`Subsystem`, `Intake`, and `Arm` are nested inside `Main` so the complete example fits in one file. The `static` modifier lets `main()` construct those nested classes without first constructing a `Main` object.

The declaration `public abstract void periodic();` ends with a semicolon because it has no method body. `Intake` and `Arm` are concrete classes, so each must have an implementation of every abstract method it inherits. That implementation can be declared in the concrete class or inherited from another superclass.

The variable type can still be the abstract type, as in `Subsystem intake`. The object assigned to that variable must come from a class that Java can instantiate, such as `Intake`.

<a id="abstract-classes-cannot-be-instantiated"></a>

## Constructing Subclasses

You cannot write `new Subsystem(...)` because `Subsystem` is abstract. Its constructor still has a job: it initializes the `Subsystem` part of every concrete subclass object. When `new Intake()` runs, the `Intake` constructor calls `super("intake")`, and that call initializes `name` and `enabled` before the rest of the `Intake` constructor continues.

The constructor is `protected`, so subclasses and other classes in the same package can call it. This example uses that access because subclass constructors need `super(...)`. An abstract constructor is not possible in Java. Constructors are never inherited or overridden.

This partial snippet belongs inside the `main()` method in the complete program above. Its first line does not compile, so keep it commented while running the second line.

```java norun
// Subsystem unfinished = new Subsystem("unfinished"); // compile error
Subsystem working = new Intake();                      // allowed
```

## Mixing Abstract and Concrete

The concrete methods `enable()`, `describe()`, and `update()` are complete implementations. The subclasses inherit them. A concrete subclass does not need to rewrite a method that it already inherits in usable form.

<RulesBox title="What `abstract` Changes">

**On a method:** the declaration has no body. A concrete subclass needs an implementation, either one it declares or one it inherits.

**On a class:** a class instance creation expression cannot create an object directly from that class. The class can still be used as a variable, parameter, or return type.

A class that declares an abstract method must also be abstract. An abstract class does not have to declare any abstract methods, although abstract classes are intended to be completed by subclasses.

</RulesBox>

## Partial Implementations

An abstract subclass can complete some inherited methods and leave others abstract for a later subclass. This complete `Main.java` program defines the small `Motor` model it uses. Select **Run** below the code, or use the linked [Compile and Run](/java/fundamentals/setup#compile-and-run) steps.

```java
public class Main {
    public abstract static class Subsystem {
        public abstract void periodic();
        public abstract void stop();
    }

    public static final class Motor {
        private double output;

        public void setOutput(double output) {
            this.output = output;
        }

        public double getOutput() {
            return output;
        }
    }

    public abstract static class MotorSubsystem extends Subsystem {
        protected final Motor motor;

        protected MotorSubsystem(Motor motor) {
            this.motor = motor;
        }

        @Override
        public final void stop() {
            motor.setOutput(0.0);
        }
    }

    public static final class Intake extends MotorSubsystem {
        public Intake(Motor motor) {
            super(motor);
        }

        @Override
        public void periodic() {
            motor.setOutput(0.6);
        }
    }

    public static void main(String[] args) {
        Motor motor = new Motor();
        Intake intake = new Intake(motor);
        intake.periodic();
        System.out.println(motor.getOutput());
        intake.stop();
        System.out.println(motor.getOutput());
    }
}
```

The console should print:

```text
0.6
0.0
```

Here, `Motor` only stores a requested output number. The value `0.6` is an example request, not a measured speed, and no physical motor moves.

`MotorSubsystem` remains abstract because it does not provide `periodic()`. It does provide `stop()`, so `Intake` inherits that implementation and only needs to provide `periodic()`.

## Abstract Class or Interface

This is a preview of the next lesson. An **interface** declares a capability that a class promises to provide. Abstract classes and interfaces can both define a type that several classes share. Their members and inheritance rules differ.

<ContentTable
  headers={["Question", "Abstract class", "Interface"]}
  rows={[
    ["How many can one class use?", "Extend one class", "Implement many interfaces"],
    ["Per-object instance fields?", "Yes", "No; every interface field is <code>public static final</code> and belongs to the interface"],
    ["Constructors?", "Yes", "No"],
    ["Methods with bodies?", "Yes", "Yes; <code>default</code>, <code>static</code>, and <code>private</code> methods can have bodies"],
    ["Abstract methods?", "Yes", "Yes"],
    ["Member visibility?", "Members can be <code>public</code>, <code>protected</code>, or <code>private</code>", "Methods can be public or private; interfaces do not declare protected methods"]
  ]}
/>

An abstract class fits when closely related subclasses need the same instance fields, constructor setup, or inherited implementation. An interface fits when classes need to promise a capability without sharing per-object state, especially when otherwise unrelated classes need the same role.

An interface `default` method supplies an inherited instance-method body. A `static` interface method belongs to the interface itself. A `private` interface method can help other methods inside that interface, but implementing classes cannot call or override it. These bodies make interfaces more flexible, but they do not give an interface constructors or per-object instance fields.

The official [dev.java abstract classes guide](https://dev.java/learn/inheritance/abstract-classes/) provides another worked comparison with interfaces if you want a second example.

## A Template Method

A parent method can define a sequence and call subclass-supplied steps. This structure is often called a template method. The following console demonstration calls the step three times. Predict the order, then select **Run** below the code or use [Compile and Run](/java/fundamentals/setup#compile-and-run) with a local `Main.java`.

```java
public class Main {
    public abstract static class AutoRoutine {
        public final void run(int stepCount) {
            initialize();
            for (int stepIndex = 0; stepIndex < stepCount; stepIndex++) {
                performStep(stepIndex + 1);
            }
            cleanUp();
        }

        protected void initialize() {
        }

        protected abstract void performStep(int stepNumber);

        protected void cleanUp() {
        }
    }

    public static final class ConsoleRoutine extends AutoRoutine {
        @Override
        protected void initialize() {
            System.out.println("preparing routine");
        }

        @Override
        protected void performStep(int stepNumber) {
            System.out.println("step " + stepNumber);
        }

        @Override
        protected void cleanUp() {
            System.out.println("routine complete");
        }
    }

    public static void main(String[] args) {
        AutoRoutine routine = new ConsoleRoutine();
        routine.run(3);
    }
}
```

The console should print:

```text
preparing routine
step 1
step 2
step 3
routine complete
```

`performStep()` is required because it is abstract. `initialize()` and `cleanUp()` are optional hooks because they already have empty bodies. A subclass may override either hook.

The `final` modifier prevents a subclass from overriding `run()`, so a subclass cannot replace that method's order of calls. It does not make the whole object unchangeable, and it does not prevent overriding the non-final hook methods. A real robot routine also needs the scheduling and safety behavior taught in the FRC lessons; this console program only demonstrates the Java class structure.

<RulesBox title="Common Mistakes">

- **Giving an abstract method a body.** Its declaration ends with a semicolon instead of braces.
- **Declaring an abstract method in a concrete class.** The class must also be declared abstract.
- **Constructing an abstract class.** Construct a concrete subclass and store it in a variable of the abstract type when that type is useful.
- **Leaving a concrete subclass incomplete.** It needs implementations for all inherited abstract methods, whether declared itself or inherited.
- **Writing `private abstract`.** A private method cannot be overridden, so this combination does not compile.
- **Calling an overridable method from a constructor.** The subclass method can run before the subclass fields have been initialized.

</RulesBox>
