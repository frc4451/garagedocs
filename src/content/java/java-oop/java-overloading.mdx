## Learn Overloading

The [Methods](/java/fundamentals/java-methods) lesson introduced parameters, arguments, and return types. The [Classes](/java/fundamentals/java-classes) and [Objects](/java/fundamentals/java-objects) lessons introduced constructors, `new`, instance fields, and instance methods. This lesson builds on those ideas.

You will give one operation several valid parameter lists, trace which version Java selects, and use one constructor to supply defaults to another. The examples are console models. They print requested actions and do not control robot hardware.

For each complete program, select **Run** beneath the code in the browser. To run one locally, replace the contents of `Main.java`, save the file, and follow [Compile And Run](/java/fundamentals/java-setup#compile-and-run).

## What Overloading Is

**Overloading** means declaring several constructors or methods with the same name and different parameter lists. Java selects an applicable declaration from the number and compile-time types of the arguments at each call.

The parameter types form the important part of a method's **signature**. These declarations overload `setTarget` because their parameter lists differ:

```java norun
public void setTarget(double position) { }
public void setTarget(double position, double requestedOutput) { }
public void setTarget(int presetNumber) { }
```

Parameter names do not distinguish signatures. Changing `position` to `angle` would still leave the same parameter type. A different return type alone also cannot create an overload:

```java norun
public double reading() { return 0.0; }
// public int reading() { return 0; } // Does not compile: same name and parameter list
```

These are partial snippets. Place them inside a class and outside every other method. They do not include a complete `Main` program.

<span id="what-it-replaces"></span>

## One Name, Several Calls

Without overloading, closely related operations may need names such as `printStatus()` and `printStatusWithLabel(String)`. Overloading can keep the shared operation name when every version has the same general purpose. Separate names remain clearer when the operations mean different things or when two values have the same type but different meanings.

## Constructor Overloading

A class can declare several constructors. Each `new` expression supplies arguments that select one of them.

<span id="basic-constructor-overloading"></span>

### Run Constructor Overloads

Select **Run** under this complete program. The nested `RobotConfig` class lets the browser run both classes from one source file.

```java
public class Main {
    public static class RobotConfig {
        private String name;
        private int teamNumber;

        public RobotConfig(String name) {
            this.name = name;
            this.teamNumber = 0;
        }

        public RobotConfig(String name, int teamNumber) {
            this.name = name;
            this.teamNumber = teamNumber;
        }

        public String description() {
            return name + ", team " + teamNumber;
        }
    }

    public static void main(String[] args) {
        RobotConfig practice = new RobotConfig("Practice");
        RobotConfig competition = new RobotConfig("Competition", 4451);

        System.out.println(practice.description());
        System.out.println(competition.description());
    }
}
```

The output is:

```text
Practice, team 0
Competition, team 4451
```

The first call has one `String` argument, so it selects `RobotConfig(String)`. The second has a `String` followed by an `int`, so it selects `RobotConfig(String, int)`.

<span id="constructor-chaining-with-this"></span>

## Constructor Delegation With `this()`

The constructors above repeat the assignment to `name`. A constructor can **delegate** to another constructor in the same class by calling `this(...)`. The arguments select the destination constructor exactly as the arguments after `new` do.

<span id="improved-constructor-with-chaining"></span>

### Put Initialization in One Constructor

```java
public class Main {
    public static class RobotConfig {
        private String name;
        private int teamNumber;
        private String driveType;

        public RobotConfig(String name) {
            this(name, 0);
        }

        public RobotConfig(String name, int teamNumber) {
            this(name, teamNumber, "Tank");
        }

        public RobotConfig(String name, int teamNumber, String driveType) {
            this.name = name;
            this.teamNumber = teamNumber;
            this.driveType = driveType;
        }

        public String description() {
            return name + ", team " + teamNumber + ", " + driveType;
        }
    }

    public static void main(String[] args) {
        System.out.println(new RobotConfig("Practice").description());
        System.out.println(new RobotConfig("Competition", 4451).description());
        System.out.println(new RobotConfig("Demo", 4451, "Swerve").description());
    }
}
```

The output is:

```text
Practice, team 0, Tank
Competition, team 4451, Tank
Demo, team 4451, Swerve
```

Follow the first expression carefully. `new RobotConfig("Practice")` enters the one-parameter constructor. Its `this(name, 0)` call enters the two-parameter constructor, whose `this(name, teamNumber, "Tank")` call reaches the three-parameter constructor. Only that last constructor assigns the fields.

GarageDocs teaches Java 25, which permits some statements before an explicit `this(...)` or `super(...)` call under the flexible-constructor-body rules. The browser runner uses Java 17, where an explicit constructor invocation must be the first statement. Keep `this(...)` first in these lessons so the same code works in the browser and in Java 25.

<RulesBox title="Constructor Overloading Rules">

- Each constructor needs a different parameter list (different types, count, or order)
- Put `this(...)` first for Java 17 browser compatibility. Java 25 permits a restricted prologue before it.
- A constructor has no return type, not even `void`
- Every constructor has the class's name
- Two constructors with identical parameter lists do not compile

</RulesBox>

## Method Overloading

Methods can use the same name with different parameter lists. Java checks the arguments at compile time and selects the most specific applicable overload. In the next program, an integer literal selects `report(int)`, while a decimal literal selects `report(double)`.

<span id="basic-method-overloading"></span>

### Trace Overload Selection

```java
public class Main {
    public static void report(int presetNumber) {
        System.out.println("preset: " + presetNumber);
    }

    public static void report(double requestedOutput) {
        System.out.println("requested output: " + requestedOutput);
    }

    public static void report(double forward, double turn) {
        System.out.println("forward: " + forward + ", turn: " + turn);
    }

    public static void main(String[] args) {
        report(2);
        report(0.5);
        report(0.7, -0.2);
    }
}
```

The output is:

```text
preset: 2
requested output: 0.5
forward: 0.7, turn: -0.2
```

The values represent requests in this console model. They are not measured speed, and no motor moves.

<span id="method-chaining"></span>

## Delegate between Overloads

An overload can call another overload. This ordinary method call uses `this.methodName(...)`; it does not have the constructor rule attached to `this(...)`.

<span id="method-overloading-with-chaining"></span>

### Supply Defaults Once

```java
public class Main {
    public static class ArmRequest {
        public void printTarget(double targetDegrees) {
            this.printTarget(targetDegrees, 0.30);
        }

        public void printTarget(double targetDegrees, double requestedOutput) {
            System.out.println(
                "target: " + targetDegrees + " degrees, requested output: " + requestedOutput
            );
        }
    }

    public static void main(String[] args) {
        ArmRequest arm = new ArmRequest();
        arm.printTarget(90.0);
        arm.printTarget(45.0, 0.20);
    }
}
```

The output is:

```text
target: 90.0 degrees, requested output: 0.3
target: 45.0 degrees, requested output: 0.2
```

The one-argument overload supplies the default `0.30` and delegates to the two-argument overload. The example does not estimate motion time because a requested output alone does not determine how fast a physical arm will move.

## Read Calls before Running Them

For each call, write the argument types and count, then match them to a declaration. This habit catches many overload mistakes before compilation.

<span id="frc-drivetrain-with-overloading"></span>

### Check a Drivetrain Console Model

```java
public class Main {
    public static class DriveRequest {
        public void print(double forward) {
            this.print(forward, 0.0);
        }

        public void print(double forward, double turn) {
            System.out.println("forward: " + forward + ", turn: " + turn);
        }
    }

    public static void main(String[] args) {
        DriveRequest request = new DriveRequest();
        request.print(0.5);
        request.print(0.7, -0.2);
    }
}
```

The output is:

```text
forward: 0.5, turn: 0.0
forward: 0.7, turn: -0.2
```

The first call selects `print(double)`, which supplies a zero turn request and calls `print(double, double)`. The second call goes directly to `print(double, double)`. A real FRC drivetrain method would also need the subsystem's coordinate convention, units or normalized ranges, safety behavior, and hardware implementation.

## Overloading and Overriding

The similar names describe different features. **Overloading** uses one name with different parameter lists, and the compiler selects among them from the call. **Overriding** is introduced with inheritance: a subclass supplies its own implementation of an inherited instance method with the same signature. You do not need inheritance to use overloading.
