The previous [Objects lesson](/java/fundamentals/objects) showed that two variables can identify the same object. This lesson follows that idea through assignment, method calls, `null`, and equality.

<a id="understanding-object-references"></a>

## Object References

A class-type variable stores a **reference value**. A non-null reference identifies an object; the special value `null` identifies no object. The reference and the object are different things.

Java does not promise that a reference is a memory address you can inspect. Treat it as a value Java uses to identify an object.

<a id="creating-object-references"></a>

### Creating References

This complete program creates one `Robot` object and stores its reference in `practiceBot`:

```java
public class Main {
    public static class Robot {
        private String name;
        private int taskCount;

        public Robot(String name, int taskCount) {
            this.name = name;
            this.taskCount = taskCount;
        }

        public void setTaskCount(int taskCount) {
            this.taskCount = taskCount;
        }

        public String status() {
            return name + " tasks: " + taskCount;
        }
    }

    public static void main(String[] args) {
        Robot practiceBot = new Robot("Practice", 2);
        System.out.println(practiceBot.status());
    }
}
```

The declaration has three parts:

- `Robot` is the variable's type.
- `practiceBot` is the variable's name.
- `new Robot("Practice", 2)` creates an object and produces a reference to it.

In the browser, select **Run** beneath the complete program. To run it locally, replace `Main.java` with the complete program, save the file, then use [Compile And Run](/java/fundamentals/setup#compile-and-run). The program prints `Practice tasks: 2`.

<a id="reference-assignment-copies-the-reference"></a>

## Assignment Copies References

Assigning one object variable to another copies the reference value. It does not create another object.

<a id="reference-assignment-example"></a>

### Assignment Example

Replace the `main` method in the previous program with this version. Keep it inside `Main` and outside the `Robot` class:

```java norun
public static void main(String[] args) {
    Robot practiceBot = new Robot("Practice", 2);
    Robot selectedBot = practiceBot;
    selectedBot.setTaskCount(5);

    System.out.println(practiceBot.status());
    System.out.println(selectedBot.status());
    System.out.println(practiceBot == selectedBot);
}
```

The output is:

```text
Practice tasks: 5
Practice tasks: 5
true
```

Both variables identify the same object. Calling `setTaskCount` through `selectedBot` changes that shared object's state, so the change is also visible through `practiceBot`. Here, **state** means the values stored in the object's fields.

Reassigning a variable changes which object that variable identifies. It does not move or replace the original object. Next, replace `main` with this version:

```java norun
public static void main(String[] args) {
    Robot practiceBot = new Robot("Practice", 5);
    Robot selectedBot = practiceBot;
    selectedBot = new Robot("Competition", 0);

    System.out.println(practiceBot.status());
    System.out.println(selectedBot.status());
}
```

This creates a second object. The variables now identify different objects, so the output is `Practice tasks: 5` followed by `Competition tasks: 0`.

<a id="the-null-reference"></a>

## Null References

The value `null` means that a reference identifies no object. It is useful when “no object selected” is a meaningful state.

<a id="working-with-null-references"></a>

### Checking for Null

Calling an instance method through `null` throws a `NullPointerException`. Guard a reference when `null` is an allowed value:

Replace `Main.java` with this complete program, save it, and compile and run it:

```java
public class Main {
    public static class Robot {
        public void printReady() {
            System.out.println("Ready");
        }
    }

    public static void main(String[] args) {
        Robot selectedBot = null;

        if (selectedBot != null) {
            selectedBot.printReady();
        } else {
            System.out.println("No robot selected");
        }
    }
}
```

The output is `No robot selected`. If you remove the guard and call `selectedBot.printReady()`, the stack trace identifies the line where Java tried to use the null reference.

<RulesBox title="Handling Null">

- Use `null` only when “no object” is a valid state.
- Check `reference != null` before using a reference that may be null.
- When a method receives a required object, reject `null` near the start so the failure points to the bad input.
- Read the first relevant line of a `NullPointerException` stack trace to find the operation that failed.

</RulesBox>

<a id="objects-as-method-parameters"></a>

## Method Parameters

Java passes every argument **by value**. A method parameter receives a copy of the argument's value. For an object argument, that value is a reference.

<a id="objects-as-parameters"></a>

### Mutation and Reassignment

This complete program separates two actions that can look similar. Replace `Main.java`, save it, and compile and run it.

The helper method is `static` so `main` can call it through the class. The next lesson explains `static` in detail; here, focus on what happens to the reference parameter.

```java
public class Main {
    public static class Robot {
        private String name;
        private int taskCount;

        public Robot(String name, int taskCount) {
            this.name = name;
            this.taskCount = taskCount;
        }

        public void setTaskCount(int taskCount) {
            this.taskCount = taskCount;
        }

        public String status() {
            return name + " tasks: " + taskCount;
        }
    }

    public static void updateRobot(Robot robot) {
        robot.setTaskCount(10);
        robot = new Robot("Temporary", 99);
    }

    public static void main(String[] args) {
        Robot practiceBot = new Robot("Practice", 2);

        updateRobot(practiceBot);

        System.out.println(practiceBot.status());
    }
}
```

The output is `Practice tasks: 10`.

When `updateRobot` starts, `robot` and `practiceBot` contain copies of the same reference. The call to `setTaskCount` mutates the shared object. The following assignment changes only the local parameter `robot`; it cannot change the reference stored in `practiceBot`.

This is why “Java passes objects by reference” is misleading. Java passes a copy of a reference value.

<a id="objects-as-return-values"></a>

## Return Values

A method can return a reference. The caller can store that reference in a variable.

<a id="methods-returning-objects"></a>

### Returning an Object

The complete program below has two `static` helper methods so `main` can call them through the class. One creates a robot from new values. The other makes a separate object with the same field values, which is a **copy**. Replace `Main.java`, save it, and compile and run it.

```java
public class Main {
    public static class Robot {
        private String name;
        private int taskCount;

        public Robot(String name, int taskCount) {
            this.name = name;
            this.taskCount = taskCount;
        }

        public String getName() {
            return name;
        }

        public int getTaskCount() {
            return taskCount;
        }

        public String status() {
            return name + " tasks: " + taskCount;
        }
    }

    public static Robot buildPracticeBot() {
        Robot newBot = new Robot("Practice", 2);
        return newBot;
    }

    public static Robot copyRobot(Robot original) {
        return new Robot(original.getName(), original.getTaskCount());
    }

    public static void main(String[] args) {
        Robot original = buildPracticeBot();
        Robot copy = copyRobot(original);

        System.out.println(copy.status());
        System.out.println(original == copy);
    }
}
```

`return newBot` copies the reference value back to the caller. The object remains available because `original` now identifies it. `copyRobot` reads the original object's values and uses `new` to create a separate object with those values. The output is `Practice tasks: 2` followed by `false`, confirming that the copy has matching state and a different identity.

This copy is complete for the model shown because `Robot` has only `name` and `taskCount` fields. If a class later gains another field, its copy operation has to decide how to copy that field too. Fields that refer to other mutable objects require an additional design choice: share those objects or make copies of them.

A method may also return `null` to mean “no result,” but the caller then has to check for `null`. When possible, design the method so its return contract is clear and document whether `null` is allowed.

<a id="object-equality-and-the-equals-method"></a>

## Identity and Equality

For references, `==` tests **identity**: whether both values identify the same object, or whether both are `null`. The `equals` method tests the equality rule defined by the object's class.

The implementation inherited from `Object` uses identity. A class can override `equals` to compare selected field values instead.

<a id="implementing-equals-method"></a>

### Implementing Equals

The `==` comparison is the essential idea for this lesson. The implementation below is an optional preview of concepts taught in later object-oriented programming lessons. It treats two sensors as equal when their type and ID match. A changing reading does not take part in equality.

Several unfamiliar pieces appear in the preview:

- `Object` is the common parent class of Java objects, so the method can receive any object reference.
- `@Override` asks the compiler to check that this method replaces a method inherited from `Object`.
- `compared instanceof Sensor` checks whether the reference identifies a `Sensor`. It is also false when `compared` is `null`.
- `(Sensor) compared` is a **cast**. After the type check, it tells the compiler to treat the reference as a `Sensor` so the code can read sensor fields.

Replace `Main.java` with the complete program, save it, and compile and run it:

```java
public class Main {
    public static class Sensor {
        private String type;
        private int id;
        private double reading;

        public Sensor(String type, int id, double reading) {
            this.type = type;
            this.id = id;
            this.reading = reading;
        }

        @Override
        public boolean equals(Object compared) {
            if (this == compared) {
                return true;
            }
            if (!(compared instanceof Sensor)) {
                return false;
            }

            Sensor other = (Sensor) compared;
            return this.id == other.id
                    && java.util.Objects.equals(this.type, other.type);
        }

        @Override
        public int hashCode() {
            return java.util.Objects.hash(type, id);
        }

        public void setReading(double reading) {
            this.reading = reading;
        }
    }

    public static void main(String[] args) {
        Sensor first = new Sensor("Distance", 7, 1.2);
        Sensor second = new Sensor("Distance", 7, 3.4);
        Sensor alias = first;

        System.out.println(first == second);
        System.out.println(first.equals(second));
        System.out.println(first == alias);
    }
}
```

The output is:

```text
false
true
true
```

`first` and `second` identify separate objects, so `==` is false. Their selected fields match, so `equals` is true. `alias` holds the same reference as `first`, so `==` is true.

The `instanceof Sensor` check prevents a cast when `compared` is null or has another type. `Objects.equals` safely compares the two type references: it returns true when both are null or when the first non-null value's `equals` method accepts the second. That choice lets this small model accept a null `type` without throwing an exception during equality checks.

Override `hashCode` whenever you override `equals`. A **hash code** is an integer summary that hash-based collections use to narrow a search. Equal objects must produce the same hash code. The example uses `type` and `id` in both methods, keeping the two definitions consistent. You will study hash-based collections later.

<a id="object-equality-and-collections"></a>

## Equality in an Array

This optional section continues the `equals` preview with arrays, which were introduced earlier. This helper searches for an equal sensor:

<a id="objects-in-collections"></a>

### Searching Objects

Place this helper inside `Main` and outside `main`. It assumes the `Sensor` class from the optional preview is also inside `Main`:

```java norun
public static boolean containsEqualSensor(Sensor[] sensors, Sensor target) {
    for (int i = 0; i < sensors.length; i++) {
        if (sensors[i] != null && sensors[i].equals(target)) {
            return true;
        }
    }
    return false;
}
```

Call it from `main` with:

```java norun
Sensor[] sensors = {
    new Sensor("Distance", 7, 1.2),
    null
};
Sensor target = new Sensor("Distance", 7, 9.8);
System.out.println(containsEqualSensor(sensors, target));
```

The output is `true`. The method skips null array elements, then asks each sensor whether it equals `target`. A later lesson introduces `ArrayList` and other collections whose search operations also rely on `equals`.

<RulesBox title="Reference and Equality Rules">

- Each `new` expression creates a separate object.
- Assignment copies a reference value; it does not copy the object.
- A copied reference can mutate the same object through another variable.
- Reassigning one variable does not reassign another variable.
- Java passes a copy of every argument value, including reference values.
- Use `==` to test whether two references identify the same object.
- Use `equals` to test the equality rule defined by a class.
- Override `hashCode` whenever you override `equals`.

</RulesBox>
