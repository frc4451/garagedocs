## One Class, Many Types

`ArrayList<String>` is a generic type. Its type argument, `String`, lets the compiler reject an attempt to add an `Integer` and treat a retrieved element as a `String` without a cast.

```java
public class Main {
    public static class Box<T> {
        private T value;
        public void put(T value) { this.value = value; }
        public T get() { return value; }
    }

    public static void main(String[] args) {
        Box<String> name = new Box<>();
        name.put("Robonauts");
        Box<Integer> number = new Box<>();
        number.put(118);
        System.out.println(name.get() + " " + number.get());
    }
}
```

`T` is a **type parameter**. Each use supplies a **type argument**. The diamond in `new Box<>()` asks Java to infer that argument from the declaration on the left.

Select **Run** beneath the complete program in the browser. To run it locally, replace `Main.java`, save it, then follow [Compile And Run](/java/fundamentals/setup#compile-and-run). It prints:

```text
Robonauts 118
```

`name.put(118)` would be a compile-time error.

## Why Not Use Object

An `Object` reference can identify any object, so it loses the specific type the caller expects. The caller must cast on the way out:

```java
public class Main {
    public static class ObjectBox {
        private Object value;
        public void put(Object value) { this.value = value; }
        public Object get() { return value; }
    }

    public static void main(String[] args) {
        ObjectBox box = new ObjectBox();
        box.put("Robonauts");
        try {
            Integer number = (Integer) box.get();
            System.out.println(number);
        } catch (ClassCastException exception) {
            System.out.println("Wrong cast detected at runtime");
        }
    }
}
```

Run it in the browser or locally. It prints:

```text
Wrong cast detected at runtime
```

The cast compiles because the object might have been an `Integer`; runtime inspection finds a `String`. `Box<String>` instead checks values passed to `put` and returns `String` from `get`.

## Generic Methods

A method can declare its own type parameter before its return type.

```java
public class Main {
    public static <T> T firstOrDefault(T[] items, T fallback) {
        return items.length > 0 ? items[0] : fallback;
    }
    public static void main(String[] args) {
        System.out.println(firstOrDefault(new String[] {"Drive"}, "none"));
        System.out.println(firstOrDefault(new Integer[] {}, -1));
    }
}
```

Run the complete program in the browser or locally. It prints:

```text
Drive
-1
```

The compiler infers `T` as `String` for the first call and `Integer` for the second.

## Bounded Types

A maximum-finding method must compare values, so its type parameter needs a **bound**.

```java
public class Main {
    public static <T extends Comparable<T>> T max(T[] items) {
        if (items.length == 0) {
            throw new IllegalArgumentException("empty array");
        }
        T best = items[0];
        for (T item : items) {
            if (item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }
    public static void main(String[] args) {
        System.out.println(max(new Integer[] {45, 88, 61}));
        System.out.println(max(new String[] {"Robonauts", "Cheesy Poofs", "Citrus"}));
    }
}
```

The output is:

```text
88
Robonauts
```

`Comparable<T>` supplies `compareTo(T other)`. A positive result means the current item comes after `best`, so the method saves it as the new maximum. The bound uses `extends` even though `Comparable` is an interface.

<a id="generics-and-arrays-do-not-mix"></a>

## Generic Arrays

`new T[10]` is rejected. Arrays check their component type when storing values at runtime, but `T` is not a **reifiable type** with a fully available runtime representation. A generic class can use `Object[]` and isolate an unchecked cast:

```java
public class Main {
    public static class Ring<T> {
        private final Object[] slots;
        private int next;
        private int size;
        public Ring(int capacity) {
            if (capacity <= 0) throw new IllegalArgumentException("capacity must be positive");
            slots = new Object[capacity];
        }
        public void add(T value) {
            slots[next] = value;
            next = (next + 1) % slots.length;
            if (size < slots.length) size++;
        }
        public T oldest() {
            if (size == 0) throw new IllegalStateException("ring is empty");
            int oldestIndex = size < slots.length ? 0 : next;
            return valueAt(oldestIndex);
        }
        @SuppressWarnings("unchecked")
        private T valueAt(int index) {
            return (T) slots[index];
        }
    }
    public static void main(String[] args) {
        Ring<Double> volts = new Ring<>(3);
        volts.add(12.4);
        volts.add(12.1);
        volts.add(11.9);
        volts.add(12.0);
        System.out.println(volts.oldest());
    }
}
```

It prints:

```text
12.1
```

The fourth addition overwrites `12.4`, making `12.1` the oldest stored value. The compiler cannot prove the cast, so it reports an unchecked warning without the annotation. The class maintains safety by accepting writes only through `add(T)`. The annotation hides a warning; it does not add a check. Keep it on the smallest declaration whose safety you can explain. `ArrayList<T>` is often a simpler backing store.

<a id="erasure-and-what-it-costs-you"></a>

## Erasure and Limits

Java compiles generic declarations using **type erasure**. Roughly, a type variable becomes its leftmost bound, or `Object` if it has no bound, and the compiler inserts needed casts. One runtime class represents `Box<String>` and `Box<Integer>`.

- `new T()` is rejected because `T` does not name a constructor to invoke.
- `new T[n]` and `value instanceof T` are rejected because those operations require suitable runtime type information.
- `Box<int>` is rejected because type arguments are reference types; use `Box<Integer>`.
- A class type parameter cannot appear in a static field because the field belongs to the class, not to one parameterized use.

Erasure does not remove every trace of generics. Class files can retain generic signatures for compilers and reflection. The practical limit is that an object is not separately testable as `Box<String>` with `instanceof Box<String>`.

<a id="wildcards-briefly"></a>

## Wildcards

`List<Integer>` is not a subtype of `List<Number>`. Otherwise, code could add a `Double` through the `List<Number>` reference. A wildcard can accept several related list types:

```java
import java.util.List;
public class Main {
    public static double total(List<? extends Number> values) {
        double sum = 0.0;
        for (Number value : values) sum += value.doubleValue();
        return sum;
    }
    public static void main(String[] args) {
        System.out.println(total(List.of(1, 2, 3)));
        System.out.println(total(List.of(1.5, 2.5)));
    }
}
```

The output is:

```text
6.0
4.0
```

You can read each element as `Number`. You cannot add a non-null number because the compiler does not know the list's actual element subtype.

<RulesBox title="Common Mistakes">

- A raw declaration such as `List values` remains legal for compatibility, but `javac -Xlint:rawtypes` reports a warning. Other operations may report unchecked warnings. Compilation normally continues after warnings.
- Prefer `ArrayList<T>` to a generic array unless you can state and maintain the array invariant.
- Use wrapper types such as `Integer`, not primitive type arguments such as `int`.
- Add the bound that supplies operations such as `compareTo`.
- Suppress only the specific unchecked warning you have justified.

</RulesBox>
