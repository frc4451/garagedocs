## Describing a Capability

This lesson builds on [Inheritance](/java/fundamentals/java-inheritance), [Abstract Classes and Methods](/java/fundamentals/java-abstract-classes), arrays, loops, methods, and access modifiers. You will use an interface to give otherwise different classes the same capability, then call that capability through one shared type.

The complete examples run in the Java 17 browser playground and with the course's local Java 25 setup. In the browser, select **Run** beneath a complete program. To run one locally, replace the contents of `Main.java`, save the file, and follow [Compile And Run](/java/fundamentals/java-setup#compile-and-run). Run one `Main` program at a time.

An interface names a capability and lists the methods that provide it. A class that implements the interface promises to provide those methods.

These are console models: stopping a device prints a message and does not control a physical intake or camera. The following example is complete and runnable. The console should print the two lines shown below it.

```java
public class Main {
    public interface Stoppable {
        public void stop();
    }

    public static class Intake implements Stoppable {
        @Override
        public void stop() {
            System.out.println("intake stopped");
        }
    }

    public static class Camera implements Stoppable {
        @Override
        public void stop() {
            System.out.println("camera stopped");
        }
    }

    public static void main(String[] args) {
        Stoppable[] devices = {new Intake(), new Camera()};

        for (Stoppable device : devices) {
            device.stop();
        }
    }
}
```

Output:

```text
intake stopped
camera stopped
```

`Intake` and `Camera` do not share a specialized parent class, though every Java class other than `Object` ultimately inherits from `Object`. Both classes implement `Stoppable`, so a `Stoppable` variable can refer to an object of either class. The array uses that shared interface type to hold both objects.

The types are nested inside `Main` so each code block remains one complete file. `public static` lets `main` use each nested type without first constructing a `Main` object. In a larger project, these types would usually be separate files, and a top-level interface would be `public interface Stoppable`.

An interface describes methods that an object has. It does not create an object, and you cannot write `new Stoppable()`. You construct a class that implements the interface instead.

## Implementing Several

A class can extend one class and implement several interfaces. In a class declaration, `extends` comes first and `implements` follows:

```java
public class Main {
    public static class Subsystem {
        public void reportStatus() {
            System.out.println("subsystem ready");
        }
    }

    public interface Stoppable {
        public void stop();
    }

    public interface Named {
        public String name();
    }

    public static class Intake extends Subsystem implements Stoppable, Named {
        @Override
        public void stop() {
            System.out.println("intake stopped");
        }

        @Override
        public String name() {
            return "intake";
        }
    }

    public static void main(String[] args) {
        Intake intake = new Intake();
        intake.reportStatus();
        System.out.println(intake.name());
        intake.stop();
    }
}
```

Output:

```text
subsystem ready
intake
intake stopped
```

This is the case that [single inheritance](/java/fundamentals/java-inheritance#java-has-single-inheritance) cannot cover by itself. `Intake` gets shared class behavior from `Subsystem` and promises two separate capabilities through `Stoppable` and `Named`.

<RulesBox title="Interface Methods Are Public">

An abstract interface method is public even if its declaration omits `public`. GarageDocs writes the modifier so the access level stays visible while you learn. A class implementation must also be `public`:

```java norun
public interface Stoppable {
    public void stop();
}

public class Intake implements Stoppable {
    @Override
    private void stop() { }
}
```

This partial snippet does not compile because `private` gives `stop` less access than the interface promises. A compiler may report that the method is “attempting to assign weaker access privileges.”

</RulesBox>

## Default Methods

A `default` method is an interface instance method with a body. An implementing class inherits that behavior unless the class overrides it.

```java
public class Main {
    public interface Stoppable {
        public void stop();

        public default void emergencyStop() {
            System.out.println("emergency stop requested");
            stop();
        }
    }

    public static class Intake implements Stoppable {
        @Override
        public void stop() {
            System.out.println("intake stopped");
        }
    }

    public static void main(String[] args) {
        Stoppable intake = new Intake();
        intake.emergencyStop();
    }
}
```

Output:

```text
emergency stop requested
intake stopped
```

The default method can call `stop()` because every `Stoppable` object promises to provide it. A class inherits the default only when a concrete method from its superclass does not already provide that method. If two inherited interfaces provide conflicting defaults, the class must override the method to resolve the conflict. Adding a default method can let existing implementations gain an operation without editing each class, but interface changes still require design work and testing.

<RulesBox title="Default Methods and Shared State">

An interface cannot declare per-object instance fields. A default method can use its parameters, call other instance methods, and read interface constants. When implementations need shared instance fields or constructor logic, use an [abstract class](/java/fundamentals/java-abstract-classes#abstract-class-or-interface).

</RulesBox>

## Static and Private Methods

A `static` interface method belongs to the interface itself. It does not run on one implementing object and is not inherited by implementing classes. Call it with the interface name, as in `Stoppable.stopAll(devices)`.

A `private` interface method is an internal helper with a body. Only other methods declared inside that same interface can call it. Implementing classes and outside code cannot call or override it. Java allows private interface methods so default and static methods in the interface can share implementation code.

This Java 17 example shows both forms:

```java
public class Main {
    public interface Stoppable {
        public void stop();

        public default void emergencyStop() {
            announce("emergency stop requested");
            stop();
        }

        public static void stopAll(Stoppable[] devices) {
            for (Stoppable device : devices) {
                device.stop();
            }
        }

        private void announce(String message) {
            System.out.println(message);
        }
    }

    public static class Intake implements Stoppable {
        @Override
        public void stop() {
            System.out.println("intake stopped");
        }
    }

    public static void main(String[] args) {
        Stoppable intake = new Intake();
        intake.emergencyStop();
        Stoppable.stopAll(new Stoppable[] {intake});
    }
}
```

Output:

```text
emergency stop requested
intake stopped
intake stopped
```

## Constants

Every field declared in an interface is implicitly `public static final`. It belongs to the interface, must receive a value when declared, and its variable cannot later be assigned a different value. If the value is a reference to a mutable object, `final` protects the reference binding rather than making that object unchangeable. Review [Static and Final](/java/fundamentals/java-static-and-final) for that distinction.

```java
public class Main {
    public interface RobotLimits {
        // Invented value for this console example, not a real robot limit.
        public static final double MAX_SPEED_METERS_PER_SECOND = 4.5;
    }

    public static void main(String[] args) {
        System.out.println(RobotLimits.MAX_SPEED_METERS_PER_SECOND);
    }
}
```

Output:

```text
4.5
```

The `4.5` meters-per-second value is invented for this example; it is not a limit for a real robot.

An interface cannot hold a different field value for each object. If several classes need shared changing data or per-object state, the data belongs in a class instead.

## Functional Interfaces

A lambda is a short way to supply the behavior for a functional interface. Lambdas are taught later in [Passing Functions as Data](/java/fundamentals/java-functions-as-data#functional-interfaces), so this section is an optional preview. You do not need lambda syntax for the required playground task on this page.

A functional interface describes one operation to implement. In the common case, that means one abstract method:

```java
public class Main {
    @FunctionalInterface
    public interface ReadingTest {
        public boolean matches(int reading);
    }

    public static void main(String[] args) {
        ReadingTest above100 = reading -> reading > 100;
        System.out.println(above100.matches(120));
        System.out.println(above100.matches(80));
    }
}
```

Output:

```text
true
false
```

The arrow `->` separates the lambda's input from its behavior. Here, `reading` is the input and `reading > 100` produces the `boolean` result required by `matches`. Keep this shape in mind for the optional exercise; the later lambda lesson explains it in detail.

The `@FunctionalInterface` annotation is optional. When present, the compiler checks that the interface remains functional. Default, static, and private methods do not add abstract requirements. The precise Java rule also ignores abstract declarations that match public methods of `Object`, and compatible inherited abstract methods can count as one function contract. Java also excludes sealed interfaces, which restrict their implementations; this example uses an ordinary, unrestricted interface. Those exceptions matter when reading library interfaces; for interfaces you write now, keep one clearly named abstract method.

Interfaces preserve the class's single `extends` slot, but implementing one still creates a promise that the class and its callers may depend on. Choose an interface when the promise describes a useful role or capability. Choose an abstract class when related subclasses need shared state or constructor behavior.

## Naming

Capability names often end in *-able*, such as `Stoppable`, `Comparable`, and `Runnable`. Role names are often nouns, such as `Command` or `MotorController`.

Java code normally does not add an `I` prefix such as `IStoppable`. Use the name that states the capability or role.

## Programming to the Interface

An interface can be the type of a variable, parameter, return value, or array element. The value still refers to an object created from an implementing class.

```java
public class Main {
    public interface SpeedSource {
        public int readSpeedRpm();
    }

    public static class FixedSpeedSource implements SpeedSource {
        private final int speedRpm;

        public FixedSpeedSource(int speedRpm) {
            this.speedRpm = speedRpm;
        }

        @Override
        public int readSpeedRpm() {
            return speedRpm;
        }
    }

    public static void printSpeed(SpeedSource source) {
        System.out.println(source.readSpeedRpm() + " rpm");
    }

    public static void main(String[] args) {
        SpeedSource source = new FixedSpeedSource(120);
        printSpeed(source);
    }
}
```

Output:

```text
120 rpm
```

This is a console model with a preset input. It does not read a sensor or control hardware, and `120 rpm` is an invented test value. `FixedSpeedSource` acts like a small fake because it returns a known value that the program can check.

Through `source`, the program can call methods declared by `SpeedSource` and the public methods available from `Object`. It cannot call extra methods that exist only on `FixedSpeedSource` unless the program first works with the more specific class type. This limit helps keep callers dependent on the small promise they need.

The same idea supports [dependency injection](/java/fundamentals/java-dependency-injection#injecting-an-interface): a constructor or method accepts an interface, and its caller supplies the implementing object. A test can then supply a small fake implementation.

<RulesBox title="Common Mistakes">

- **Forgetting `public` on an implementation.** The method would have weaker access than the interface method.
- **Trying to construct an interface.** Construct an implementing class and store its reference in an interface variable.
- **Expecting instance fields or constructors.** Interfaces declare neither per-object state nor constructors.
- **Calling a static method on an object.** Use the interface name.
- **Calling a private helper from an implementing class.** Only methods inside the declaring interface can call it.
- **Adding another abstract requirement to a functional interface.** Check the compiler error and any existing lambda users before changing its contract.

</RulesBox>
