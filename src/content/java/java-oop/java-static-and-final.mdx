## Two Different Questions

This lesson builds on [Classes](/java/fundamentals/java-classes), [Objects](/java/fundamentals/java-objects), and [Objects and References](/java/fundamentals/java-objects-and-references). You will use those ideas to decide where a field belongs and whether a variable may be assigned again.

`static` and `final` often appear together, but they answer different questions:

- **`static`** asks whether a member belongs to the class as a whole or to each object.
- **`final`** asks whether a variable can be assigned again after its first assignment.

A declaration can use either keyword, both keywords, or neither. Reading each keyword separately makes a declaration such as `public static final int AUTO_SECONDS = 15;` easier to understand.

## Static: One Copy, Shared

An **instance field** belongs to an object. Each new object gets its own copy. A **static field**, also called a class variable, belongs to the class. The class has one shared copy, even when the program creates many objects.

This runnable example keeps a separate `id` in each `Sensor` object and one shared count in the `Sensor` class:

```java
public class Main {
    public static class Sensor {
        public static int built = 0;
        public String id;

        public Sensor(String id) {
            this.id = id;
            built++;
        }
    }

    public static void main(String[] args) {
        Sensor gyro = new Sensor("gyro");
        Sensor encoder = new Sensor("encoder");

        System.out.println(gyro.id);
        System.out.println(encoder.id);
        System.out.println(Sensor.built);
    }
}
```

The program prints:

```text
gyro
encoder
2
```

The expression `this.id = id;` assigns the constructor parameter on the right to the current object's field on the left. Each object keeps its own `id`. The expression `built++` adds one to the single field shared by every `Sensor` object.

Access a static field through its class name, as in `Sensor.built`. Java permits access such as `gyro.built`, but that spelling suggests that `built` belongs to `gyro`. The class name shows the field's real owner.

<RulesBox title="Choose Shared State Carefully">

A mutable static field gives every part of the program that can access it a way to change the same value. A private static field limits that access to its declaring class. Shared mutation is useful for a count across all objects, but it can also make code harder to follow.

Use an instance field when each object needs its own value. Use a static field only when one shared value matches the design. Do not add `static` only to make a compiler error disappear.

</RulesBox>

The Java Language Specification defines [static fields in section 8.3.1.1](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html#jls-8.3.1.1).

## Static Methods

A static method belongs to the class and has no current object, so it has no `this` reference. It can directly use its parameters, local variables, and static members. To use an instance member, the method needs an object reference, often through a parameter.

```java
public class Main {
    public static class Units {
        public static double feetToInches(double feet) {
            return feet * 12.0;
        }
    }

    public static void main(String[] args) {
        System.out.println(Units.feetToInches(2.5));
    }
}
```

The call uses the class name and prints `30.0`. The `Math` class works the same way for methods such as `Math.abs` and `Math.max`.

The program entry point `public static void main(String[] args)` is static because the Java Virtual Machine calls it without first creating a `Main` object. `String[] args` is an array of text values supplied when the program starts. This lesson does not need to use those values.

<RulesBox title="The Static Context Error">

```java norun
public class Robot {
    public String name;

    public static void main(String[] args) {
        System.out.println(name); // compile error
    }
}
```

`name` belongs to a `Robot` object, but the static `main` method has no current `Robot`. A typical compiler message says that a non-static variable cannot be referenced from a static context.

Identify which object owns the value, create or receive that object, and access the field through its reference:

```java norun
Robot robot = new Robot();
robot.name = "Drive";
System.out.println(robot.name);
```

Making `name` static would change the design to one name shared by every `Robot`.

</RulesBox>

## Final: Set Once

A `final` variable can be assigned once. An assignment uses `=` to make a variable hold a value or reference. After the first assignment, another assignment to that variable causes a compile error.

```java
public class Main {
    public static void main(String[] args) {
        final int maxSpeed = 100;
        int currentSpeed = 40;

        currentSpeed = 60;
        // maxSpeed = 120; // compile error: maxSpeed is final

        System.out.println(maxSpeed + " " + currentSpeed);
    }
}
```

The program prints `100 60`. Removing `//` from the second assignment to `maxSpeed` lets you read the compiler message. Add the comment back before continuing.

A final instance field can receive its value in its declaration, an instance initializer, or the constructor chain. If the declaration and initializers do not assign it, construction must finish with the field assigned exactly once. One constructor may call another constructor with `this(...)`, so each constructor does not have to contain the assignment itself.

The next program is a console model of a motor controller. A CAN ID is the number software uses to address one device on the robot's Controller Area Network (CAN). The example stores the ID but does not connect to hardware or command a real motor.

```java
public class Main {
    public static class Motor {
        private final int canId;
        private double requestedOutput;

        public Motor(int canId) {
            this.canId = canId;
            this.requestedOutput = 0.0;
        }

        public int getCanId() {
            return this.canId;
        }

        public void setRequestedOutput(double requestedOutput) {
            this.requestedOutput = requestedOutput;
        }

        public double getRequestedOutput() {
            return this.requestedOutput;
        }
    }

    public static void main(String[] args) {
        Motor leftMotor = new Motor(10);
        leftMotor.setRequestedOutput(0.5);

        System.out.println(leftMotor.getCanId());
        System.out.println(leftMotor.getRequestedOutput());
    }
}
```

The CAN ID stays `10`, while the requested output can change as the program runs. The word `final` applies to the `canId` variable. It does not make every field in the `Motor` object final.

The Java Language Specification defines [final variables in section 4.12.4](https://docs.oracle.com/javase/specs/jls/se25/html/jls-4.html#jls-4.12.4) and the constructor assignment rule for [final instance fields in section 8.3.1.2](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html#jls-8.3.1.2).

## Final Does Not Mean Immutable

When a final variable holds a primitive value such as an `int`, that value cannot be replaced. When a final variable holds an object reference, the variable must keep referring to the same object. The object's contents may still change.

Arrays are objects, so a final array reference demonstrates this distinction:

```java
public class Main {
    public static void main(String[] args) {
        final int[] sensorReadings = {12, 18};

        sensorReadings[0] = 15;
        // sensorReadings = new int[] {20, 25}; // compile error

        System.out.println(sensorReadings[0]);
    }
}
```

The program prints `15`. The assignment `sensorReadings[0] = 15;` changes an element inside the same array. The commented assignment would make the variable refer to a different array, which `final` prevents.

An **immutable object** is an object whose observable state cannot change after construction. Declaring a reference `final` does not make the referenced object immutable. Immutability depends on the object's class and the operations it provides.

## Putting Them Together: Constants

A value shared by the class and protected from reassignment is commonly declared `static final`. Java's naming convention writes constant names in uppercase words separated by underscores. The 15-second and 135-second periods in this next console example are fictional practice values, not a statement of current FRC match rules:

```java
public class Main {
    public static class MatchConstants {
        public static final int AUTO_SECONDS = 15;
        public static final int TELEOP_SECONDS = 135;
        public static final int TOTAL_SECONDS = AUTO_SECONDS + TELEOP_SECONDS;
    }

    public static void main(String[] args) {
        System.out.println(MatchConstants.AUTO_SECONDS);
        System.out.println(MatchConstants.TOTAL_SECONDS);
    }
}
```

The program prints:

```text
15
150
```

Each keyword and name choice has a separate job:

- `public` lets code in other classes access the field.
- `static` gives the class one shared field.
- `final` prevents the field from being assigned again.
- `int` is the field's type.
- `AUTO_SECONDS` follows the uppercase naming convention for constants.

Use `private static final` when only the declaring class needs the value. Limiting access prevents other classes from depending on an implementation detail.

Java uses **constant variable** as a narrower language-specification term: a final variable of primitive type or `String` initialized with a constant expression. The three `int` fields above meet that definition. A declaration such as `public static final int[] IDS = {1, 2};` is final and often given a constant-style name, but it is not a constant variable under that formal rule, and its array elements can change.

A named constant also explains a value's purpose. `DEADBAND` communicates more than the number `0.08` by itself and gives the value one place to update.

<RulesBox title="Reading Public Static Final">

Read `public static final int AUTO_SECONDS = 15;` from left to right:

- Other classes may read it.
- The class owns one shared copy.
- The variable cannot be assigned again.
- It stores an `int` named `AUTO_SECONDS`, initialized to `15`.

</RulesBox>

<RulesBox title="Common Mistakes">

- **Using `static` to silence a compiler error:** decide which object owns the value, then access that object.
- **Reading a static field through an object:** use `Sensor.built` so the owner is clear.
- **Putting per-object state in a static field:** if each motor needs a different CAN ID, make the ID an instance field.
- **Assuming `final` freezes an object:** a final reference cannot change targets, but a mutable object's state can still change.
- **Leaving a final field unassigned:** make sure each construction path initializes it exactly once, using a declaration, initializer, or constructor.
- **Using uppercase names for changing values:** reserve the constant naming style for values intended to stay fixed.

</RulesBox>

## Check Your Understanding

1. Two `Sensor` objects have different `id` values. Should `id` be static or an instance field?
2. A static method receives `Sensor sensor` as a parameter. Can it read `sensor.id`?
3. If `final int[] ports = {0, 1};`, can the program assign `ports[0] = 2`? Can it assign a new array to `ports`?
4. In `private static final double DEADBAND = 0.08;`, what decision does each keyword express?

<details>
<summary>Check your answers</summary>

1. `id` should be an instance field because each object needs its own value.
2. Yes. The method has an object reference and can use that reference to access an instance member when access rules allow it.
3. It can change `ports[0]` because the array is mutable. It cannot assign a different array to the final variable `ports`.
4. `private` limits access to the declaring class, `static` creates one class-owned field, and `final` prevents reassignment.

</details>
