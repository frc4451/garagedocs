## Classes And Objects

Object-oriented programming organizes a program around objects that have related information and actions. Robot code often represents a drivetrain, elevator, sensor, or controller as an object.

A **class** defines a type of object. It can describe the information an object stores and the actions it can perform. An **object** is one concrete value created from that definition. An object is also called an **instance** of its class.

Think of a class as a blueprint. One blueprint can guide the construction of several houses, and each house is separate. In the same way, one `TeamMember` class can produce several `TeamMember` objects, each with its own name and role.

## Run The Example

The browser runs one source file, so this example places `TeamMember` inside `Main`. Select **Run** beneath this complete program:

```java
public class Main {
    public static class TeamMember {
        private String name;
        private String role;

        public TeamMember(String name) {
            this.name = name;
            this.role = "Student";
        }

        public void assignRole(String newRole) {
            this.role = newRole;
        }

        public String getName() {
            return this.name;
        }

        public String getRole() {
            return this.role;
        }
    }

    public static void main(String[] args) {
        TeamMember avery = new TeamMember("Avery");
        TeamMember jordan = new TeamMember("Jordan");

        avery.assignRole("Driver");

        System.out.println(avery.getName() + ": " + avery.getRole());
        System.out.println(jordan.getName() + ": " + jordan.getRole());
    }
}
```

The output is:

```text
Avery: Driver
Jordan: Student
```

`TeamMember` is a `public static` nested class because the browser expects one public outer class named `Main`. Here, `static` lets the program create a `TeamMember` without first creating a `Main` object. It does not make the fields or methods of each `TeamMember` object static.

A class body can contain several kinds of declarations. This first class uses instance fields, a constructor, and instance methods. Later lessons introduce other class-body declarations.

## Instance Fields

A field is a variable declared inside a class and outside its methods and constructors. These declarations create two **instance fields**:

```java norun
private String name;
private String role;
```

An instance field is a non-`static` field. Each object gets its own values for these fields. Changing `avery`'s role to `"Driver"` does not change `jordan`'s role, which remains `"Student"`. Instance fields are also called **instance variables**.

## Constructors

A **constructor** initializes a new object. Its name matches the class name, and it has no return type:

```java norun
public TeamMember(String name) {
    this.name = name;
    this.role = "Student";
}
```

The parameter `name` receives the argument passed when the object is created. Inside an instance constructor or method, `this` means the current object. In `this.name = name;`, `this.name` selects the current object's field and `name` selects the parameter. The next line gives that same object its starting role.

## Create An Object

An object variable stores a **reference**, a value that identifies an object. The variable does not contain a separate copy of the object.

Trace this statement from right to left:

```java norun
TeamMember avery = new TeamMember("Avery");
```

1. `new` creates a `TeamMember` object.
2. `TeamMember("Avery")` calls the matching constructor to initialize that object.
3. The expression produces a reference to the new object.
4. The `TeamMember` variable `avery` stores that reference so later statements can use the object.

The second `new` expression creates a different object for `jordan`. The two variables refer to two objects with separate instance-field values.

## Instance Methods

An instance method runs for a particular object. Read this call as “ask the object referred to by `avery` to assign the role `"Driver"`”:

```java norun
avery.assignRole("Driver");
```

The dot selects the `assignRole` method through `avery`. The parentheses make the call, and `"Driver"` is the argument copied into the method's `newRole` parameter. During this call, `this` means the same object that `avery` refers to.

The calls `avery.getName()` and `avery.getRole()` return values from that object. The same method calls through `jordan` read `jordan`'s field values instead.

## Field Access

The `private` modifier restricts where code can directly use a member. In the ordinary two-file version of this example, an unrelated class such as `Main` cannot directly assign a private `TeamMember` field. It uses the public methods that `TeamMember` provides.

The one-file browser arrangement has a Java access-control detail: the enclosing `Main` class and its nested `TeamMember` class belong to the same **nest**, so Java permits them to access each other's private members. The example still uses public methods because those methods form the interface that unrelated classes can use.

Keeping an object's state behind a controlled interface is **encapsulation**. It gives the class one place to define how its values may change. The class must still implement any checks needed to reject invalid values.

## Optional Local Files

After completing [Java Setup](/java/fundamentals/java-setup), you can arrange the same program as two files. Save the complete example as `Main.java`. Create `TeamMember.java` in the same folder, copy only the entire nested `TeamMember` declaration into it, and change its first line from `public static class TeamMember` to `public class TeamMember`. In `Main.java`, remove that nested declaration while keeping the outer `Main` class and its `main` method.

Compile and run the paired files from that folder with the commands for your terminal.

**PowerShell:**

```powershell
javac Main.java TeamMember.java
java Main
```

**macOS or Linux terminal:**

```bash
javac Main.java TeamMember.java
java Main
```

`Main.java` remains the runner because it contains `main`. `TeamMember.java` defines the class that the runner creates and uses.
