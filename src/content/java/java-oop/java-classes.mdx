### Introduction to object-oriented programming

Object-oriented programming splits a problem into the things it involves and gives each one its own code. Robot code is organised this way: a drivetrain, an elevator, a sensor and a controller are each represented by a class, and the program is built from objects of those classes working together.

### Classes and objects: the blueprint analogy

A **class** defines what its objects know (their fields) and what they can do (their methods). A class is to an object what a blueprint is to a house: the blueprint describes every house that can be built from it, and each house built is a separate thing with its own address.

### The relationship between a class and an object

Every object created from a class is an **instance** of it. The instances share the structure the class defines and each has its own state: two `Motor` objects have the same fields, holding different values.

### Creating our own classes

A class has two kinds of members. **Instance variables** hold an object's state, and **methods** define what it does. The example below is a class representing a team member.

### Basic class structure

```java
public class TeamMember {
    // Instance variables (attributes)
    private String name;
    private int age;
    private String role;
    
    // Constructor
    public TeamMember(String memberName) {
        this.name = memberName;
        this.age = 0;
        this.role = "Student";
    }
    
    // Methods (behaviors)
    public void assignRole(String newRole) {
        this.role = newRole;
        System.out.println(name + " is now the " + newRole);
    }
    
    public String getName() {
        return this.name;
    }
}
```

### Instance variables and encapsulation

Variables declared inside a class, outside any method, are **instance variables** (also called fields). Marking each one `private` means only the class's own methods can read or change it; outside code goes through those methods. Keeping state inside the object this way is called **encapsulation**, and it is what lets a class guarantee its own values stay valid.
