Every lesson here has an editor that runs Java in the browser. You can also check the Practice assignments there.

A local setup gives you Java 25, file-based program input, and a debugger. The browser uses Java 17, while **Java 25 is the standard** for this curriculum and the robot. The Kit Bot section assumes you have completed this local setup.

If you cannot install software on the computer you use (a school machine with locked-down permissions is common), the online option at the end of this lesson works for every lesson and assignment.

### Installing a JDK

You need a Java Development Kit. Install **Java 25**, the version every JavaDoc link on this site points at. Download the free [Eclipse Temurin JDK 25](https://adoptium.net/temurin/releases/?version=25). Robot code is different: the WPILib installer in [R00](/kit-bot/r00-wpilib-setup#what-wpilib-installs) brings its own JDK, and you never point it at this one.

<StepsBox title="Install steps">

1. Open the [Eclipse Temurin JDK 25 downloads](https://adoptium.net/temurin/releases/?version=25). Select your operating system and architecture, then download the **JDK** installer.
2. Run the installer. On Windows, accept the option to add Java to `PATH` if offered.
3. Open a new terminal and confirm the install:

```
javac --version
java --version
```

Both commands should print a version number of 17 or higher. If `javac` is missing but `java` works, you installed a runtime (JRE) instead of a development kit (JDK).

</StepsBox>

### Compiling and running

A single-file program is the shape every Practice Assignment takes. Keep the class name and the file name matching: `HelloTeam` lives in `HelloTeam.java`, and `java HelloTeam` is how you run it.

```java
// File: Main.java
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader in = new BufferedReader(new InputStreamReader(System.in));
        int n = Integer.parseInt(in.readLine().trim());
        System.out.println(n * 2);
    }
}
```

Compile and run:

```
javac Main.java
java Main
```

Newer JDKs also let you skip the compile step for single-file programs, which is convenient while iterating:

```
java Main.java
```

### Testing against sample input

Several Practice Assignments read from standard input. A04 asks for five values, A24 takes a whole session of commands. Put that input in a file instead of typing it every run.

Save the input as `in.txt`, then redirect it into your program:

```
java Main < in.txt
```

To compare your output against the expected output, save that as `expected.txt` and diff them:

<CodeTabs>
<CodeTab label="Windows (PowerShell)">

```
java Main < in.txt > out.txt
Compare-Object (Get-Content out.txt) (Get-Content expected.txt)
```

No output from `Compare-Object` means the files match.

</CodeTab>
<CodeTab label="macOS / Linux">

```
java Main < in.txt > out.txt
diff out.txt expected.txt
```

No output from `diff` means the files match.

</CodeTab>
</CodeTabs>

<RulesBox title="A workflow that holds up">

- Keep one folder per track, one subfolder per assignment.
- In each assignment folder: the `.java` file the assignment names, `in.txt`, and `expected.txt` for what it should print.
- Before you call an assignment done, run the sample once more. It catches the case where you fixed one thing and broke another.

</RulesBox>

### Setting up VS Code

The command line above is enough to check the installation. Use **Visual Studio Code (VS Code)** for every local Java lesson and assignment. It is the editor FRC 4451 also uses for robot code.

Install the free [Extension Pack for Java](https://marketplace.visualstudio.com/items?itemName=vscjava.vscode-java-pack). It catches many typos as you type, completes method names, and provides a debugger. The WPILib copy of VS Code already includes Java support.

The [VS Code lessons](/tools/vscode-tour#open-the-folder-not-the-file) in the Tools section explain the editor in more detail. For these lessons, **open the folder** that contains your `.java` files. Opening only one file prevents the Java tools from seeing the project.

Use the *Run* link above `main` to start the program. Program output and keyboard input both appear in the [integrated terminal](/tools/vscode-tour#the-integrated-terminal).

<RulesBox title="Feeding sample input in VS Code">

The *Run* link reads from the terminal, so type the sample by hand or paste it. To feed a file instead, run from the integrated terminal exactly as above: `java Main < in.txt`. `` Ctrl+` `` opens it.

</RulesBox>

### If you cannot install anything

Every lesson and assignment on this site has an editor that compiles and runs Java in the browser, with an input box for programs that read from standard input. It runs Java 17 rather than 25 and you lose the debugger, but every assignment here can be completed that way.

<ExerciseBox title="Verify your setup" description="Confirm the whole loop works before the first assignment asks for it:">

1. Create a folder with `Main.java` containing the program above.
2. Create `in.txt` containing a single line with the number `21`.
3. Run the program with input redirected. Confirm it prints `42`.
4. Change `in.txt` to `-5` and run again without editing the Java file. Confirm it prints `-10`.

Step 4 is the point of the exercise: you changed the test case without touching code or retyping input.

</ExerciseBox>
