Most lesson examples and Practice checks run in the browser. The runner needs an internet connection and uses Java 17. A local setup works offline after installation and gives you Java 25, saved files, and a debugger.

**Java 25 is the curriculum standard** for local Java lessons. WPILib robot projects use the JDK bundled with WPILib. The Kit Bot section assumes that you have completed this local setup.

If you cannot install software on your computer, use the browser for supported examples and checks. Ask a mentor which approved computer you can use for debugger, multi-file, and file-system tasks.

<span id="installing-a-jdk"></span>

## Install a JDK

A Java Development Kit (JDK) contains the compiler and runtime used in this lesson. Install **Eclipse Temurin JDK 25**:

1. Open the official [Eclipse Temurin installation page](https://adoptium.net/installation/).
2. Choose the instructions for your operating system: the Windows MSI package, the macOS PKG package, or the Linux package for your distribution.
3. Select **JDK 25**. If you do not know which processor architecture to choose, ask a mentor before downloading the package.
4. Run the installer. On Windows, keep the option that adds Java to `PATH` when the installer offers it. On macOS or Linux, approve the package installation when your computer asks.
5. Close any open terminal windows after installation. Open a new terminal so it can read the updated `PATH`.

If the computer asks for an administrator password that you do not have, stop and ask the computer's owner or a mentor. Do not try a different installer to bypass the restriction.

### Check Both Tools

Type these commands into the new terminal. The [Command Line prompt explanation](/tools/command-line-basics#the-prompt) shows how to distinguish a command, its output, and the next prompt. Return here after you can identify all three.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
javac --version
java --version
```

</CodeTab>
<CodeTab label="Terminal">

```bash
javac --version
java --version
```

</CodeTab>
</CodeTabs>

Both outputs should report version 25. The `javac` output normally starts with `javac 25`, while the `java` output may start with `openjdk 25` or a vendor name. `javac` is the compiler, and `java` is the launcher that runs a compiled program. A working `java` command by itself does not confirm that the compiler is installed.

If either command is missing or reports an older version, close and reopen the terminal once. If the result stays the same, show both outputs to a mentor and check the JDK installation and `PATH`. The Tools explanation of [PATH and command-not-found errors](/tools/files-pipes-and-path#path-and-command-not-found) gives the next checks.

## Prepare VS Code

Use **Visual Studio Code (VS Code)** for local Java lessons and Practice Assignments. It is the editor FRC 4451 also uses for robot code.

1. Install [Visual Studio Code](https://code.visualstudio.com/) if it is not already on the computer.
2. Open VS Code. Select the **Extensions** icon in the Activity Bar.
3. Search for and install Microsoft's [Extension Pack for Java](https://marketplace.visualstudio.com/items?itemName=vscjava.vscode-java-pack).

The WPILib copy of VS Code already includes Java support. Use the regular VS Code installation for these lessons unless a mentor directs you to the WPILib copy.

For this curriculum, open the folder that contains your Java files. The [VS Code folder explanation](/tools/vscode-tour#open-the-folder-not-the-file) shows why the editor uses an opened folder as its workspace. Standalone Java files are supported, but opening the folder keeps the file tree, terminal, and Java tools in the same place.

## Create Your First File

1. In VS Code, select **File → Open Folder**.
2. In the folder picker, open a location you can find again, such as **Documents**. Use its new-folder control to create a folder named `java-setup`, select that folder, and choose **Select Folder** or **Open**.
3. Follow the actions in [Create And Find A File](/tools/vscode-tour#create-save-and-find-a-file), but stay in the `java-setup` folder and create `Main.java` instead of the practice page's `notes.txt`. When that page asks what to enter in the file, use the complete program below instead of its sample sentence. Complete its save-and-find steps, then return here.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Java setup works.");
    }
}
```

4. Confirm that `Main.java` contains the program above and is saved. The filename must be `Main.java`, and the name after `class` must be `Main`, including the capital `M`.

The next lesson explains every part of this structure. For this setup check, change only the text inside the quotation marks.

<span id="compiling-and-running"></span>

## Compile and Run

Open VS Code's integrated terminal with **Terminal → New Terminal**. The [integrated terminal explanation](/tools/vscode-tour#the-integrated-terminal) shows where it appears. The prompt should show the `java-setup` folder because that is the folder open in VS Code.

If the prompt shows a different folder, use [Where Am I, And What Is Here](/tools/command-line-basics#your-current-folder) to check the location and [Moving Around](/tools/command-line-basics#moving-around) to change it. Return here when the terminal's file list includes `Main.java`.

Compile the saved source file:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
javac Main.java
```

</CodeTab>
<CodeTab label="Terminal">

```bash
javac Main.java
```

</CodeTab>
</CodeTabs>

A successful compile prints no message and returns to the prompt. It creates `Main.class` in the same folder. Run that compiled class:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
java Main
```

</CodeTab>
<CodeTab label="Terminal">

```bash
java Main
```

</CodeTab>
</CodeTabs>

The terminal should show:

```text
Java setup works.
```

The prompt appears again below that line when the program finishes.

### Edit and Run Again

Change the text inside the quotation marks to `I changed and reran this program.` Save the file, then run `javac Main.java` followed by `java Main` in the same terminal.

The second run should show the new sentence. This save, compile, and run loop is the local workflow for the first lessons.

<RulesBox title="First Checks">

- **`javac` is not recognized or not found:** Repeat **Check Both Tools** and show the two version results to a mentor.
- **`file not found: Main.java`:** Check the terminal's current folder and file list. The list must include `Main.java`.
- **The filename and class name differ:** Rename the file to `Main.java`, or change the word after `class` to `Main`, so they match.
- **The old sentence still prints:** Save `Main.java`, run `javac Main.java` again, and then run `java Main`.
- **The compiler points to a line of code:** Compare the quotation marks, semicolon, parentheses, and braces with the complete program above. Change one difference, save, and compile again.

</RulesBox>

<ExerciseBox title="Verify Your Setup" description="Show that the complete edit loop works before the first assignment uses it:">

1. Change the printed sentence to a message of your choice.
2. Predict the exact line that the program will display.
3. Save, compile, and run the program.
4. Compare the result with your prediction. If they differ, use the first checks above.

</ExerciseBox>

## Test Sample Input Later

You do not need a sample-input file for Setup, Printing, or A01. The [Console Input](/java/fundamentals/java-console-input) lesson first teaches how a program reads text. When that lesson sends you back here, save its sample input as `in.txt` in the same folder as the compiled program.

The commands below use a class named `Main`. If an assignment gives its class a different name, replace `Main` in the command with that class name.

Run the appropriate command from that folder:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-Content -LiteralPath in.txt | java Main
```

</CodeTab>
<CodeTab label="Terminal">

```bash
java Main < in.txt
```

</CodeTab>
</CodeTabs>

PowerShell uses a pipeline to send the file's lines to the program. Bash and zsh use the `<` input-redirection operator. These commands are a later reference, so return to Printing without using them now.

When an assignment supplies exact expected output, save that text as `expected.txt`. Save one program run as `out.txt`:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-Content -LiteralPath in.txt | java Main > out.txt
```

</CodeTab>
<CodeTab label="Terminal">

```bash
java Main < in.txt > out.txt
```

</CodeTab>
</CodeTabs>

In VS Code's Explorer, right-click `expected.txt` and select **Select for Compare**. Then right-click `out.txt` and select **Compare with Selected**. Check the line order, spaces, and extra prompts shown by the comparison.
