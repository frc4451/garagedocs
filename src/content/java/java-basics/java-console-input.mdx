A program reads **standard input** from its terminal or the browser editor's input box. `Scanner` provides methods for reading that input.

### Read a line and a number

This is a complete program. Save it as `Main.java` when working locally.

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        String name = input.nextLine();
        int count = Integer.parseInt(input.nextLine());

        System.out.println(name + " collected " + count + " readings.");
        input.close();
    }
}
```

Supply these two lines before running in the browser:

```text
Avery
3
```

The result is `Avery collected 3 readings.`. In VS Code, enter each line in the terminal and press Enter.

`import` lets this file use the short name `Scanner`. `new Scanner(System.in)` creates a reader connected to standard input. `nextLine()` reads one line as text. `Integer.parseInt` converts that text to an `int`.

### Choose a reading method

| Method | Reads | Returns |
|---|---|---|
| `nextLine()` | The remainder of one line | `String` |
| `next()` | One whitespace-separated token | `String` |
| `nextInt()` | One integer token | `int` |
| `nextDouble()` | One decimal-number token | `double` |

A **token** is one piece of input separated by whitespace. With `nextInt()`, `3 4` on one line can supply two calls.

For all-numeric input, token methods are convenient:

```java
import java.util.Locale;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        input.useLocale(Locale.US);
        double distanceMeters = input.nextDouble();
        double timeSeconds = input.nextDouble();
        System.out.printf(Locale.US, "%.2f m/s%n", distanceMeters / timeSeconds);
        input.close();
    }
}
```

Input `6 2` produces `3.00 m/s`. Use a positive time for this example. `Locale.US` makes the decimal separator a period, matching the sample. `%.2f` prints two decimal places and `%n` ends the line.

### Mixing token reads and line reads

`nextInt()` consumes the number but usually leaves the newline behind. An immediate `nextLine()` then reads the remaining empty part of that line.

Choose one approach:

- Read complete lines and convert them with `Integer.parseInt` or `Double.parseDouble`.
- Use token methods throughout when every value is a separate token.
- If a full text line follows a numeric token on the next line, call `nextLine()` once to consume the current line's remainder, then again to read the text.

### Input errors and repeatable tests

Entering `three` where an integer is expected causes an exception. [Try-Catch](/java/fundamentals/java-try-catch) explains how to handle that case. First get a valid sample working.

Use one Scanner for standard input. Close it after the program's final read; closing it also closes its input source.

The browser runner needs an internet connection. For local sample files, use the operating-system commands in [Java Setup](/java/fundamentals/java-setup#testing-against-sample-input).
