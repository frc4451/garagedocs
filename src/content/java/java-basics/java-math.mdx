## Use Java's Math Tools

This lesson adds calculations that robot programs use for ranges and controller input. You will call methods from Java's `Math` class, write a clamp, apply a deadband, and keep the direction of a curved input.

Complete [Calculations](/java/fundamentals/calculations), [Conditionals](/java/fundamentals/conditionals), and [Methods](/java/fundamentals/methods) first. The main path through **Keep a Curve's Direction** prepares you for [A08: Stick Curve Calculator](/java/assignments/a08-stick-curve-calculator). Later sections marked **Optional for now** explain overflow, bits, and floating-point edge cases.

The `Math` class provides static methods, so you call them with the class name. You do not create a `Math` object. A value's **absolute value** is its distance from zero.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(Math.abs(-3.5));   // 3.5
        System.out.println(Math.max(4, 9));   // 9
        System.out.println(Math.min(4, 9));   // 4
    }
}
```

Replace the contents of `Main.java` with this complete program and run it with [Java Setup](/java/fundamentals/setup). The comments show the expected output.

## Clamp a Value

A **clamp** keeps a value inside a chosen range. For example, a program can keep a requested controller output between `-1.0` and `1.0`. This says what the code requests; it does not predict a motor's measured speed.

Java 25 has `Math.clamp`, but the browser runner uses Java 17. This helper works in both places:

```java
public class Main {
    public static double clamp(double value, double min, double max) {
        return Math.max(min, Math.min(max, value));
    }

    public static void main(String[] args) {
        System.out.println(clamp(0.4, -1.0, 1.0));  // 0.4
        System.out.println(clamp(1.7, -1.0, 1.0));  // 1.0
        System.out.println(clamp(-3.0, -1.0, 1.0)); // -1.0
    }
}
```

Read the return expression from the inside out. `Math.min(max, value)` limits the upper end. `Math.max(min, ...)` then limits the lower end. This beginner helper assumes finite inputs and `min <= max`; `NaN` and infinite values need an explicit policy.

## Deadband and Sign

A **deadband** treats small input magnitudes as zero. A controller reading near its center can vary slightly, so code can ignore readings below a chosen threshold. These examples assume finite inputs and a nonnegative threshold.

The playground and A08 use this contract: return `0.0` when the magnitude is below the threshold, and return the original input when its magnitude is at or above the threshold.

```java
public class Main {
    public static double deadband(double input, double threshold) {
        if (Math.abs(input) < threshold) {
            return 0.0;
        }
        return input;
    }

    public static void main(String[] args) {
        System.out.println(deadband(0.03, 0.08));  // 0.0
        System.out.println(deadband(0.08, 0.08));  // 0.08
        System.out.println(deadband(-0.6, 0.08));  // -0.6
    }
}
```

The strict `<` comparison matters: an input whose magnitude equals the threshold is kept. Follow this contract in A08.

Some robot libraries use a **rescaled deadband**. It maps the deadband edge to zero, then stretches the remaining range so full input still produces full output. `Math.signum` returns `-1.0`, `0.0`, or `1.0` for an ordinary finite value, which lets the method preserve direction:

```java norun
public static double rescaledDeadband(double input, double threshold) {
    if (Math.abs(input) < threshold) {
        return 0.0;
    }
    return Math.signum(input)
        * (Math.abs(input) - threshold)
        / (1.0 - threshold);
}
```

This partial method belongs inside `Main`, outside the `main` method. It is an optional variation with a different result: `rescaledDeadband(0.54, 0.08)` returns `0.5`, while `rescaledDeadband(-1.0, 0.08)` returns `-1.0`. It assumes inputs from `-1.0` through `1.0` and a threshold from `0.0` up to, but not including, `1.0`. Do not substitute it for A08's simpler deadband.

## Keep a Curve's Direction

A **power** uses a base and an exponent. For whole-number exponents, `2` to the power `3` means `2 × 2 × 2`. A power can change how an input grows. For values between `-1.0` and `1.0`, squaring the magnitude makes small inputs smaller while leaving full magnitude at `1.0`. Squaring a negative number removes its sign, so multiply by `Math.signum` to restore the original direction.

```java
public class Main {
    public static double squareKeepSign(double value) {
        return Math.signum(value) * value * value;
    }

    public static void main(String[] args) {
        System.out.println(squareKeepSign(0.5));   // 0.25
        System.out.println(squareKeepSign(-0.5));  // -0.25
        System.out.println(squareKeepSign(1.0));   // 1.0
    }
}
```

`value * value` clearly expresses a square. `Math.pow(base, exponent)` calculates a power and returns a `double`. When the exponent is a variable, A08 uses `Math.signum(value) * Math.pow(Math.abs(value), exponent)`.

## Powers, Roots, and Distance

The **square root** of a nonnegative number is the nonnegative value that produces the original number when multiplied by itself. For example, `Math.sqrt(144)` is `12.0` because `12 × 12 = 144`.

`Math.hypot(dx, dy)` calculates the length of a right triangle's **hypotenuse**, the side opposite its square corner. If `dx` and `dy` are perpendicular distances, the result is the straight-line distance. It also avoids intermediate overflow or underflow that can occur in `Math.sqrt(dx * dx + dy * dy)`.

```java
public class Main {
    public static void main(String[] args) {
        double dxMeters = 3.0;
        double dyMeters = 4.0;

        System.out.println(Math.hypot(dxMeters, dyMeters)); // 5.0
        System.out.println(Math.sqrt(-1.0));                // NaN
    }
}
```

`NaN` means “not a number.” It is a `double` value used when a floating-point calculation has no numeric result, such as the real-number square root of `-1.0`.

## Round a Value

Rounding methods differ in direction and return type. A `long` is a whole-number type with a larger range than `int`. `Math.round(double)` returns the nearest `long`; a value exactly halfway between two whole numbers rounds to the larger one. For example, `2.5` rounds to `3`, and `-2.5` rounds to `-2`. For the values below, a cast to `int` discards the fractional part and moves toward zero. `Math.floor` rounds down and `Math.ceil` rounds up; both return a `double` with a whole-number value.

```java
public class Main {
    public static void main(String[] args) {
        double positive = 2.7;
        double negative = -2.7;

        System.out.println(Math.round(positive)); // 3, returned as long
        System.out.println(Math.floor(positive)); // 2.0
        System.out.println(Math.ceil(positive));  // 3.0
        System.out.println((int) positive);       // 2
        System.out.println((int) negative);       // -2
        System.out.println(Math.floor(negative)); // -3.0
    }
}
```

To round a finite value to two decimal places, multiply by `100.0`, round, then divide by `100.0`:

```java
public class Main {
    public static void main(String[] args) {
        double reading = 12.34567;
        double twoPlaces = Math.round(reading * 100.0) / 100.0;
        System.out.println(twoPlaces); // 12.35
    }
}
```

This pattern suits a small display example. It does not make binary floating-point values exact, and very large values can exceed the useful range of the intermediate calculation.

## Find a Remainder

The `%` operator gives the remainder after division. It can test divisibility or wrap a nonnegative value around a fixed range.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(17 % 5);      // 2
        System.out.println(12 % 4);      // 0
        System.out.println(370 % 360);   // 10
    }
}
```

Java's remainder has the sign of the left operand, so `-30 % 360` is `-30`. Here, the **modulus** is the positive divisor that sets the size of the repeating range. For `int` values and a positive modulus, `Math.floorMod` gives a result from `0` through one less than the modulus:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(-30 % 360);                // -30
        System.out.println(Math.floorMod(-30, 360));  // 330
        System.out.println(Math.floorMod(-450, 360)); // 270
    }
}
```

You may also see `((value % modulus) + modulus) % modulus`. With `int`, the addition can overflow for extreme values. `Math.floorMod(value, modulus)` states the purpose and avoids that intermediate addition.

## Integer Ranges and Overflow

**Optional for now.** Read this section before a lesson asks you to count values that can grow for a long time. An `int` stores whole numbers from `-2,147,483,648` through `2,147,483,647`. Integer arithmetic wraps when its mathematical result falls outside the type's range; it does not throw by default.

```java
public class Main {
    public static void main(String[] args) {
        int largest = Integer.MAX_VALUE;
        System.out.println(largest);     // 2147483647
        System.out.println(largest + 1); // -2147483648
        System.out.println(Long.MAX_VALUE);
    }
}
```

Milliseconds exceed `Integer.MAX_VALUE` after about 24.9 days. At a hypothetical `2,048` counts per revolution and `5,000` revolutions per minute, a signed `int` count would wrap after about 210 minutes, or 3 hours 30 minutes, if every count accumulated without reset. Those numbers describe the arithmetic example, not a particular encoder or controller.

The type of each operand controls multiplication. Assigning the result to `long` afterward cannot repair an `int` result that already wrapped.

```java
public class Main {
    public static void main(String[] args) {
        int ticksPerRevolution = 2048;
        int revolutions = 1_500_000;

        long wrong = ticksPerRevolution * revolutions;
        long right = (long) ticksPerRevolution * revolutions;

        System.out.println(wrong); // -1222967296
        System.out.println(right); // 3072000000
    }
}
```

`Math.addExact` and `Math.multiplyExact` throw `ArithmeticException` when an `int` or `long` result overflows. One more edge case matters: `Math.abs(Integer.MIN_VALUE)` is still negative because its positive magnitude does not fit in an `int`. The same rule applies to `Math.abs(Long.MIN_VALUE)`.

## Read Bit Flags

**Optional for now.** Read this section when an API gives you a **status word**, an integer whose individual binary digits represent separate flags. Binary uses only `0` and `1`. The `0b` prefix marks a binary literal, so `0b1011` means binary digits `1011`. Java numbers the rightmost bit as bit `0`, the next as bit `1`, and so on.

The literal `0b1011` has bits `3`, `1`, and `0` set. Shifting `1` left three places makes `1 << 3`, whose value is `8`, a mask for bit `3`. The `0x` prefix marks hexadecimal, a base-16 notation whose digits continue with `A` through `F`. `F` represents `15`, so `0xFF` represents `255`. Each hexadecimal digit stands for four bits.

<ContentTable
  title="Bitwise Operators"
  headers={["Operator", "Effect", "Example"]}
  rows={[
    ["<code>&amp;</code>", "Keeps a 1 where both bits are 1", "Test a flag: <code>(status &amp; fault) != 0</code>"],
    ["<code>|</code>", "Keeps a 1 where either bit is 1", "Set a flag: <code>status | enabled</code>"],
    ["<code>^</code>", "Keeps a 1 where the bits differ", "Toggle selected bits"],
    ["<code>~</code>", "Flips every bit", "Clear a flag: <code>status &amp; ~overTemperature</code>"],
    ["<code>&lt;&lt;</code> / <code>&gt;&gt;&gt;</code>", "Shifts bits left / shifts right with zeros", "Build a mask: <code>1 &lt;&lt; 3</code>"]
  ]}
/>

```java
public class Main {
    public static void main(String[] args) {
        final int enabled = 1 << 0;
        final int overTemperature = 1 << 1;
        final int fault = 1 << 2;

        int status = enabled | overTemperature;
        System.out.println(Integer.toBinaryString(status));   // 11
        System.out.println((status & fault) != 0);            // false
        System.out.println((status & overTemperature) != 0); // true

        status = status & ~overTemperature;
        System.out.println(Integer.toBinaryString(status));   // 1

        byte raw = (byte) 0xF0;
        System.out.println(raw);                              // -16
        System.out.println(raw & 0xFF);                       // 240
    }
}
```

Java's `byte` is signed, from `-128` through `127`. `0xF0` represents `240`, which is outside that range. Casting its low eight bits to `byte` produces `-16` because two's-complement wraps the eight-bit value by `256`: `240 - 256 = -16`. When documentation defines those bits as an unsigned number from `0` through `255`, `raw & 0xFF` recovers the nonnegative `int`. Check the device or protocol documentation before deciding what a byte represents.

## Compare Floating-Point Values

**Optional for now.** Many decimal fractions cannot be represented exactly as binary floating-point values. The calculation `0.1 + 0.2` demonstrates the difference:

```java
public class Main {
    public static void main(String[] args) {
        double sum = 0.1 + 0.2;
        System.out.println(sum);                         // 0.30000000000000004
        System.out.println(sum == 0.3);                  // false
        System.out.println(Math.abs(sum - 0.3) < 1e-9);  // true
    }
}
```

The notation `1e-9` means `0.000000001`. The `==` operator is correct when you need exact equality, such as checking a value against a sentinel that the program assigned directly. For a calculated measurement, compare the absolute difference with a tolerance chosen for that value's units and required precision. `Math.abs(currentMeters - targetMeters) < toleranceMeters` checks whether two positions are close enough for the task.

Special values need separate handling in safety-critical calculations. `Double.isNaN(value)` detects `NaN`, and `Double.isFinite(value)` rejects both infinity and `NaN`.

<RulesBox title="Common Checks">

- Use `Math.round` when you want its documented rule. An `(int)` cast truncates toward zero.
- Use `value * value` for a square when it makes the expression clearer.
- Use `Math.floorMod` with a positive modulus when an `int` value can be negative.
- Choose a tolerance in the value's units when calculated `double` values only need to be close.
- Check for `NaN` when an invalid floating-point input could reach a square root or later calculation.
- Cast an operand to `long` before integer multiplication when the mathematical result may exceed the `int` range.
- Interpret packed bytes according to the API or device documentation that produced them.

</RulesBox>
