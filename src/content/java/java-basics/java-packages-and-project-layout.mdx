## Packages and Folders

A package groups related Java types under a shared name. In the Gradle layout used by the robot projects linked from this course, the folders below `src/main/java` match the package name. The folder `src/main/java` is the **source root**, where the package path begins.

This illustrative WPILib fragment shows where the package declaration goes. It is not the complete `Drive` class from a robot project.

```java norun
// File: src/main/java/frc/robot/subsystems/Drive.java
package frc.robot.subsystems;

public class Drive {
    public Drive() {
    }
}
```

The package declaration gives this class the full name `frc.robot.subsystems.Drive`. Keeping the folder path aligned with the package helps VS Code and build tools find the source file.

File names follow a separate rule. If a top-level class is `public`, its source file must use the class name, including capitalization. The `public class Drive` above belongs in `Drive.java`. A top-level class without `public` does not have that filename requirement, although matching the filename to the main class still helps readers find it.

Two packages can each contain a class named `Drive`. Their full names keep them distinct, such as `frc.robot.subsystems.Drive` and `example.library.Drive`.

## Import

Code can use a type from its own package by its short name. Java also makes the public types in `java.lang`, including `String`, `Math`, and `System`, available without import declarations.

For a type from another package, write its full name or add an `import` after the `package` declaration. This illustrative WPILib fragment is incomplete and requires WPILib as a configured dependency:

```java norun
package frc.robot;

import edu.wpi.first.wpilibj.TimedRobot;
import frc.robot.subsystems.Drive;

public class Robot extends TimedRobot {
    private final Drive drive;

    public Robot() {
        drive = new Drive();
    }
}
```

An import lets the compiler connect the short name `Drive` to `frc.robot.subsystems.Drive` within this file. It does not download or install `Drive`. The class must already be part of the project, the Java Development Kit (JDK), or a dependency configured by the build system. In a WPILib project, add vendor libraries through the documented dependency tools instead of typing an import and expecting the library to appear.

You can also skip the import and write a full name where you use the type. The following illustrative field declaration belongs inside a class body; it is not a complete file:

```java norun
private final frc.robot.subsystems.Drive drive =
        new frc.robot.subsystems.Drive();
```

<RulesBox title="Wildcard Imports">

`import java.util.*;` makes the accessible types declared in `java.util` available by short name when needed. It does not import subpackages such as `java.util.concurrent`, and inaccessible types remain inaccessible.

Use explicit imports in course and robot code so readers can see where each type comes from. Two wildcard imports can make a short name ambiguous when both packages contain an accessible type with that name. A single-type import takes precedence over wildcard imports, so `import java.util.List;` resolves `List` to `java.util.List` even if another wildcard-imported package also contains `List`.

</RulesBox>

## Project Layout

The Gradle Java plugin uses `src/main/java` for production Java source and `src/test/java` for test source by default. A project can change those source directories in its build configuration.

This tree shows a small example. The filenames under `frc/robot` are examples, not files that every WPILib project must contain.

```text
my-project/
├── build.gradle              build configuration and dependencies
├── settings.gradle           Gradle project settings
├── src/
│   ├── main/
│   │   └── java/             source root for program code
│   │       └── frc/robot/
│   │           ├── Main.java
│   │           └── subsystems/
│   │               └── Drive.java
│   └── test/
│       └── java/             source root for test code
└── build/                    generated Gradle output
```

Three details control where you work:

1. `src/main/java` is the source root. The package `frc.robot.subsystems` starts below it at `frc/robot/subsystems/`.
2. Packages group related code. A subpackage is a separate package, so `frc.robot` and `frc.robot.subsystems` do not share package-private access.
3. Gradle writes generated output under `build/` by default. Edit source files under `src/`, because another build can replace generated files.

WPILib's command-based project template has a more specific layout. Open [R01: Project Anatomy](/kit-bot/r01-project-anatomy) when you need the roles of `Main.java`, `Robot.java`, `RobotContainer.java`, and `Constants.java` in that template.

## Naming

Package names normally use lowercase words separated by dots. Widely distributed libraries often begin with a reversed internet domain, such as `com.example.product`, to reduce name collisions. WPILib robot projects commonly use `frc.robot` as their base package.

Class names use UpperCamelCase. Keep each public top-level class in the file whose name matches that class. These conventions help the next programmer predict where a type belongs.

## Visibility Follows Packages

Use explicit visibility in GarageDocs examples. Make types and members `public` when other classes need them, and make internal fields and helper methods `private`.

```java norun
package frc.robot.subsystems;

public class Drive {
    private double lastCommandedSpeed;

    public Drive() {
        lastCommandedSpeed = 0.0;
    }

    public void arcadeDrive(double speed) {
        lastCommandedSpeed = speed;
    }
}
```

This illustrative class only stores a requested value. It does not send a command to a motor or measure speed.

Another class can call `arcadeDrive`, but it cannot read `lastCommandedSpeed` directly. Java also supports package-private access when a declaration has no access modifier. Package-private access applies only inside the same package, not in a subpackage. You should recognize this form in other code, although examples in this course state their intended access.

<RulesBox title="Common Mistakes">

- If the editor or compiler cannot find a type, check its spelling, capitalization, package declaration, folder below the source root, and import.
- If a public top-level class reports a filename error, match the filename and capitalization to the class name.
- If two wildcard imports provide the same short type name, add one explicit import or use one type's full name.
- If an imported library type is still missing, check the project's configured dependencies. An import cannot install a dependency.
- If a change disappears after a build, confirm that you edited a source file under `src/` rather than generated output under `build/`.

</RulesBox>

## Build a Two-File Project

This worked example runs on your computer and does not use the browser Java runner. Open the folder where you keep course exercises in VS Code, then choose **View → Terminal**. The terminal prompt should show that exercise folder as its current folder.

1. In Explorer, select **New Folder** and create `package-demo`.
2. Inside `package-demo`, create the folders `src`, then `team`, then `util`.
3. Inside `package-demo/src/team/util`, create `Clamp.java`.
4. Inside `package-demo/src/team`, create `Main.java`.
5. Save both files. The finished paths are `package-demo/src/team/util/Clamp.java` and `package-demo/src/team/Main.java`.

This small project uses `src` as its source root because the compile command names both source files directly. Gradle's Java plugin uses `src/main/java` by default. A source root is a project or build-tool choice, so package `team.util` begins at `team/util` below whichever source root the project uses.

Put this code in `Clamp.java`:

```java norun
package team.util;

public class Clamp {
    private static final String DESCRIPTION = "Keeps a value inside a range.";

    private Clamp() {
    }

    public static double clamp(double value, double minimum, double maximum) {
        return Math.max(minimum, Math.min(value, maximum));
    }
}
```

For this example, `value`, `minimum`, and `maximum` are finite `double` values, and `minimum` is less than or equal to `maximum`. The range includes both endpoints. Use ordinary finite numbers and keep the endpoints in that order for this exercise.

`Math.min` returns the smaller argument, and `Math.max` returns the larger one. Read the return expression from the inside out. `Math.min(value, maximum)` first lowers a value that is above the maximum. `Math.max(minimum, ...)` then raises a value that is below the minimum. A value already inside the range passes through unchanged.

Put this code in `Main.java`:

```java norun
package team;

import team.util.Clamp;

public class Main {
    public static void main(String[] args) {
        System.out.println(Clamp.clamp(-0.4, 0.0, 1.0));
        System.out.println(Clamp.clamp(0.6, 0.0, 1.0));
        System.out.println(Clamp.clamp(1.3, 0.0, 1.0));
    }
}
```

In the terminal, move into the new project folder. Choose the tab for your operating system and run each line separately.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Set-Location package-demo
javac -d out src/team/util/Clamp.java src/team/Main.java
java -cp out team.Main
```

</CodeTab>
<CodeTab label="Terminal">

```bash
cd package-demo
javac -d out src/team/util/Clamp.java src/team/Main.java
java -cp out team.Main
```

</CodeTab>
</CodeTabs>

The program prints:

```text
0.0
0.6
1.0
```

The `javac` command compiles both source files. `-d out` tells the compiler to place the `.class` files under a new `out` folder and create the package folders there. The `java` command runs the compiled program. `-cp out` makes `out` the **class path**, which is where Java searches for compiled classes. `team.Main` is the full class name, so Java can find `out/team/Main.class`.

If `javac` reports that it cannot find a file, confirm that the terminal is inside `package-demo` and compare the two saved paths with the command. If `java` reports that it cannot find `team.Main`, confirm that the compile command succeeded and that `out/team/Main.class` exists.

3. Remove `import team.util.Clamp;`, compile, and read the first error. Restore the import and compile again.
4. In `Main.main`, add `System.out.println(Clamp.DESCRIPTION);` after the other print statements. Compile the project. The compiler should report that `DESCRIPTION` has private access in `Clamp`. Remove that line, compile again, and confirm that compilation succeeds. The field declaration stays inside `Clamp`, directly below `public class Clamp {`.
5. Explain which folder is the source root, why `Clamp.java` is in `team/util`, and why the run command uses `team.Main`.
