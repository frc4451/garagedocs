### Before You Start

This lesson builds on [interfaces](/java/fundamentals/interfaces), method calls, parameters and return values, `ArrayList`, generics such as `List<Integer>`, and [runtime polymorphism](/java/fundamentals/runtime-polymorphism#two-kinds-of-type). If `List<Integer>` is unfamiliar, review generics and lists first. `Integer` is the object type a generic list uses to hold `int` values.

Runtime polymorphism matters here: a variable can have an interface type while its object supplies the method implementation. When Java calls that interface method, the object's implementation runs.

### The Repetition Problem

Suppose you need to filter sensor readings in several ways. These methods repeat the list creation, loop, `if`, and return statement. Only the test changes.

```java norun
public static List<Integer> above100(List<Integer> readings) {
    List<Integer> result = new ArrayList<>();
    for (int reading : readings) {
        if (reading > 100) {
            result.add(reading);
        }
    }
    return result;
}

public static List<Integer> evenOnly(List<Integer> readings) {
    List<Integer> result = new ArrayList<>();
    for (int reading : readings) {
        if (reading % 2 == 0) {
            result.add(reading);
        }
    }
    return result;
}
```

You already pass values into methods to vary what a method does. Here, we want to pass the **test** that decides whether each reading belongs in the result.

### Pass the Test

Java represents this test with an object. An interface first states the method the object must provide:

```java norun
@FunctionalInterface
public interface ReadingTest {
    public boolean matches(int reading);
}
```

`filter` accepts that object as its `test` parameter. Follow the calls: `main` calls `filter(readings, above100)`, then `filter` calls `test.matches(reading)` once for each item. Because `test` refers to the `above100` object, runtime dispatch selects that object's `matches` method.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    @FunctionalInterface
    public interface ReadingTest {
        public boolean matches(int reading);
    }

    public static List<Integer> filter(List<Integer> readings, ReadingTest test) {
        List<Integer> result = new ArrayList<>();
        for (int reading : readings) {
            if (test.matches(reading)) {
                result.add(reading);
            }
        }
        return result;
    }

    public static void main(String[] args) {
        List<Integer> readings = List.of(48, 101, 120, 135);

        ReadingTest above100 = new ReadingTest() {
            @Override
            public boolean matches(int reading) {
                return reading > 100;
            }
        };

        ReadingTest even = new ReadingTest() {
            @Override
            public boolean matches(int reading) {
                return reading % 2 == 0;
            }
        };

        System.out.println(filter(readings, above100));
        System.out.println(filter(readings, even));
    }
}
```

Expected output:

```text
[101, 120, 135]
[48, 120]
```

Use **Run** below to try the example in your browser. To run it locally with Java 17 or Java 25, save it as `Main.java`, then run `javac Main.java` followed by `java Main`.

### Read the Anonymous Class

The expression beginning with `new ReadingTest()` creates an object from an **anonymous class**, a class declared without a name where it is needed.

```java norun
ReadingTest above100 = new ReadingTest() {
    @Override
    public boolean matches(int reading) {
        return reading > 100;
    }
};
```

Read its punctuation from the outside in:

- `new ReadingTest()` starts an object-creation expression. The empty parentheses belong to that expression.
- The outer `{` and `}` contain the anonymous class body.
- The inner `{` and `}` contain the `matches` method body.
- The semicolon after the outer `}` ends the assignment statement. The class body does not replace that semicolon.

`@Override` asks the compiler to confirm that this method implements the interface method. [Lambda Expressions](/java/fundamentals/lambdas#the-same-thing-shorter) will provide shorter syntax for the same one-method job.

### Functional Interfaces

An interface with one abstract method is a **functional interface**. `ReadingTest` has one abstract method, `matches`, so it qualifies.

`@FunctionalInterface` documents that intent and makes the compiler reject a change that would stop the interface from being functional. The annotation is optional. Java also provides common functional interfaces, which the [Functional Interfaces](/java/fundamentals/functional-interfaces#stop-defining-your-own) lesson introduces.

<RulesBox title="Why the Interface Matters">

The parameter `ReadingTest test` gives the supplied object a known type. That type promises a `matches(int)` method returning `boolean`, so `filter` can call the method without knowing which test the caller supplied.

</RulesBox>

### Store Now, Call Later

Passing behavior can solve a different problem: choosing work now but running it later. This example uses `ArrayList<Action>` so it relies only on list storage you already know.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    @FunctionalInterface
    public interface Action {
        public void run();
    }

    public static class ActionQueue {
        private final List<Action> pending = new ArrayList<>();

        public void schedule(Action action) {
            pending.add(action);
        }

        public void runAll() {
            for (Action action : pending) {
                action.run();
            }
            pending.clear();
        }
    }

    public static void main(String[] args) {
        ActionQueue actions = new ActionQueue();
        Action announce = new Action() {
            @Override
            public void run() {
                System.out.println("Action ran");
            }
        };

        System.out.println("Before schedule");
        actions.schedule(announce);
        System.out.println("After schedule");
        actions.runAll();
    }
}
```

Expected output:

```text
Before schedule
After schedule
Action ran
```

`schedule(announce)` stores the object. It does not call `announce.run()`. The later call to `runAll()` reaches `action.run()`, so that is when the message prints. This store-now, call-later pattern appears in callbacks, event handlers, and the [Command Pattern](/java/fundamentals/command-pattern#an-action-as-an-object).

<RulesBox title="Two Different Uses">

- **Remove duplication:** keep one loop and pass in the step that varies.
- **Defer execution:** store an action now and invoke it later.

Both uses pass an object whose method contains behavior, but they solve different problems.

</RulesBox>

### Return Behavior

A method can return an implementation too. `greaterThan` receives a number and returns a new test object:

```java norun
public static ReadingTest greaterThan(int threshold) {
    return new ReadingTest() {
        @Override
        public boolean matches(int reading) {
            return reading > threshold;
        }
    };
}
```

The anonymous object **captures** `threshold`: its `matches` method can still use that parameter after `greaterThan` has returned. Each call creates an object that remembers the value from that call, so `greaterThan(100)` and `greaterThan(500)` produce tests with different thresholds.

A captured local variable or parameter must be `final` or **effectively final**. Effectively final means the code assigns it once and never reassigns it. `threshold` qualifies because the method never changes it.

```java norun
ReadingTest high = greaterThan(100);
List<Integer> result = filter(readings, high);
```

Reassigning `threshold` inside `greaterThan` would make the capture a compile-time error. The remembered threshold is separate from the later `reading` argument passed to `matches`.

<RulesBox title="Common Mistakes">

- Adding a second abstract method to a functional interface. `@FunctionalInterface` catches this change.
- Reassigning a local variable that an anonymous class captures.
- Calling `run()` when you meant to store an action for later.
- Adding this pattern when a direct method call would be clearer and no behavior needs to vary or wait.

</RulesBox>

1. Define a `ReadingTest` interface and a `filter` method. Supply two anonymous implementations, such as `above100` and `even`, then use a test returned by `greaterThan` for the third way.
2. Define a `Transformer` interface with `int apply(int value)` and write a `map` method that applies it to every element of a list.
3. Write a `greaterThan(int)` method that returns a `ReadingTest`, and use it twice with different thresholds.
4. Define an `Action` interface and an `ActionQueue` backed by `ArrayList<Action>`. Before running it, predict exactly when a queued action will print. Then check your prediction.
5. Prepare for a later comparison-sorting lesson: define a `NumberComparison` interface with `int compare(int left, int right)`. Write two anonymous implementations and call each one directly. Do not write the sorting algorithm yet.
