### The Same Behavior, with Less Boilerplate

<ReferenceImage
  src="/media/java/callback.svg"
  alt="Diagram showing a main program calling a library function that later calls a callback function"
  caption="A callback lets one part of a program store behavior and run it later. In Java, a lambda is a concise way to supply that behavior when a functional interface is expected."
  sourceUrl="https://commons.wikimedia.org/wiki/File:Callback-notitle.svg"
  sourceLabel="Wikimedia Commons, public domain"
/>

The previous lesson used an anonymous class to implement `ReadingTest`:

```java norun
ReadingTest above100 =
    new ReadingTest() {
      @Override
      public boolean matches(int reading) {
        return reading > 100;
      }
    };
```

Most of that code repeats facts Java already knows. The target interface supplies the method's parameter and return types. Because the interface has one abstract method, Java also knows which method the behavior implements.

A lambda keeps the part that changes: the parameter name and the method body.

```java norun
ReadingTest above100 = reading -> reading > 100;
```

Both forms provide behavior for the same functional interface. A lambda is not an anonymous class with text removed, however. Lambdas have their own rules for scope, `this`, and object identity.

<RulesBox title="The Interface Supplies the Target Type">

A lambda does not have a complete type by itself. Its context must provide a compatible functional interface.

```java norun
ReadingTest above100 = reading -> reading > 100; // target: ReadingTest
```

The target type tells Java that `reading` is an `int` and that the body must produce a `boolean`. The same lambda text could target a different compatible interface elsewhere.

</RulesBox>

<span id="syntactic-sugar"></span>

### Lambda Syntax

```java norun
// One parameter and an expression body: parentheses are optional.
reading -> reading > 100

// Parentheses are also valid around one parameter.
(reading) -> reading > 100

// Two parameters: parentheses are required.
(left, right) -> left + right

// No parameters: empty parentheses are required.
() -> System.out.println("done")

// A block body needs braces and an explicit return when it produces a value.
(left, right) -> {
  int sum = left + right;
  return sum * 2;
}

// Explicit parameter types can help when inference is not enough.
(int left, int right) -> left + right
```

<RulesBox title="Expression Body versus Block Body">

```java norun
reading -> reading > 100
reading -> {
  return reading > 100;
}
```

An expression body returns the expression's value. A value-producing block body needs `return`. A `void`-compatible expression, such as a call to `println`, does not return a value:

```java norun
() -> System.out.println("hello")
```

</RulesBox>

### Applying Lambdas to `filter`

The `filter` method from the previous lesson can now receive each rule without an anonymous class:

```java norun
List<Integer> high = filter(readings, reading -> reading > 100);
List<Integer> even = filter(readings, reading -> reading % 2 == 0);
List<Integer> inRange =
    filter(readings, reading -> reading >= 50 && reading <= 150);
```

The behavior that differs is visible beside each call. That is the main benefit: the reader sees the rule without first working through class boilerplate.

### Lambdas in Library Calls

The standard library accepts functional interfaces in collection methods, sorting APIs, and thread constructors.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
  public static void main(String[] args) {
    List<String> names =
        new ArrayList<>(List.of("intake", "drive", "shooter"));

    names.sort(
        (left, right) -> Integer.compare(left.length(), right.length()));
    names.removeIf(name -> name.startsWith("in"));
    names.forEach(name -> System.out.println(name));
  }
}
```

Expected output:

```text
drive
shooter
```

Robot command APIs use the same idea. One callback can describe what should happen, while another can answer whether a command should finish.

```java norun
// Conceptual examples; use the method names from the library in your project.
button.whenPressed(() -> intake.run());
command.until(() -> sensor.isTriggered());
```

### Capturing Local Variables

A lambda can read a local variable declared in its enclosing scope:

```java norun
int threshold = 100;
ReadingTest test = reading -> reading > threshold;
```

That local variable must be `final` or **effectively final**, which means the code assigns it once and never reassigns it.

```java norun
int threshold = 100;
ReadingTest test = reading -> reading > threshold;
threshold = 200; // Compile error: threshold is not effectively final.
```

The lambda captures the local variable's value. If that value is an object reference, the lambda can observe changes inside the same object even though the local reference cannot be reassigned.

```java
public class Main {
  public static void main(String[] args) {
    int[] count = {0};
    Runnable increment = () -> count[0]++;

    increment.run();
    increment.run();
    System.out.println(count[0]);
  }
}
```

Expected output:

```text
2
```

The array makes the rule visible, but a named object or a field is usually clearer in application code. The local variable `count` still refers to the same array; only the array's contents change.

### `this` Means the Enclosing Object

`this` has different meanings in a lambda and an anonymous class.

```java norun
public class Robot {
  private final String name = "robot";

  public void anonymousVersion() {
    Runnable action =
        new Runnable() {
          @Override
          public void run() {
            // `this` is the anonymous Runnable object.
            System.out.println(this.getClass());
          }
        };
  }

  public void lambdaVersion() {
    Runnable action =
        () -> {
          // `this` is the enclosing Robot object.
          System.out.println(this.name);
        };
  }
}
```

Inside a lambda, `this` refers to the enclosing instance. Inside an anonymous class, it refers to the anonymous instance.

<RulesBox title="When Not to Use a Lambda">

- **The target is not a functional interface.** Use a class when the interface requires multiple independent abstract methods.
- **The body is long.** Extract a named method and consider a [method reference](/java/fundamentals/method-references#when-a-lambda-forwards-directly).
- **The behavior needs its own fields or constructor.** Use a named class.
- **The logic needs to call itself.** Put the recursive logic in a named method.
- **The same behavior appears repeatedly.** Store it in a well-named variable or method and reuse it.

</RulesBox>

<RulesBox title="Common Mistakes">

- **Writing `return` without braces, or using braces without `return`** for a value-producing body.
- **Reassigning a captured local variable.**
- **Omitting parentheses around zero or multiple parameters.**
- **Using a lambda where Java has no target functional interface.**
- **Using `left - right` in a comparator** instead of `Integer.compare(left, right)`. Subtraction can overflow.
- **Leaving a long block inside a lambda** when a named method would explain the behavior better.

</RulesBox>

2. Sort a `List<String>` by length, then alphabetically among names with equal lengths.
