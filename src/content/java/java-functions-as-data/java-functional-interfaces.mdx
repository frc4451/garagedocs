### Start with the Standard Shapes

The first lesson in this module defined a `ReadingTest` interface so you could see how Java stores behavior. For general-purpose operations, first check `java.util.function`. The package provides standard interfaces for the shapes Java APIs use most often.

A **functional interface** has one abstract method. Its method signature determines the inputs, return type, and checked exceptions that a lambda or method reference must match. Default and static methods do not add abstract methods, so an interface can provide them and still be functional.

The earlier `filter` method can use `Predicate<T>` instead of a course-specific interface:

```java
import java.util.ArrayList;
import java.util.List;
import java.util.function.Predicate;

public class Main {
  public static <T> List<T> filter(List<T> items, Predicate<T> test) {
    List<T> result = new ArrayList<>();
    for (T item : items) {
      if (test.test(item)) {
        result.add(item);
      }
    }
    return result;
  }

  public static void main(String[] args) {
    List<Integer> readings = List.of(75, 120, 200);
    List<Integer> high = filter(readings, reading -> reading > 100);
    System.out.println(high);
  }
}
```

Expected output:

```text
[120, 200]
```

Using a standard interface makes this method familiar to readers and compatible with other library APIs.

### `Supplier` Defers a Read

`Supplier<T>` represents a call with no arguments that produces a `T`. It is useful when the caller needs to decide **when** to read or create a value.

```java norun
Supplier<Double> reading = () -> sensor.getDistance();
```

Creating the supplier does not read the sensor. Each call to `reading.get()` runs the lambda and asks for the current value.

Compare a snapshot with a supplier:

```java norun
double snapshot = sensor.getDistance();
Supplier<Double> liveReading = () -> sensor.getDistance();
```

`snapshot` keeps the value read at that line. `liveReading` keeps behavior that can read again later. A supplier does not cache its result unless you add that behavior yourself.

<RulesBox title="Why Timing Matters in Robot Code">

Joystick positions, encoder counts, and sensor distances change while the robot runs. Code constructed during startup often needs a way to read the latest value during each later execution cycle.

```java norun
// Snapshot: reads once while constructing the command.
new DriveCommand(joystick.getY());

// Deferred read: the command can request the current value later.
new DriveCommand(() -> joystick.getY());
```

The command's constructor determines which form it accepts. If it expects a supplier, pass the supplier itself. Calling `get()` before passing it would turn the deferred read back into a snapshot.

</RulesBox>

The primitive specialization `DoubleSupplier` returns a `double` without boxing it as a `Double`:

```java norun
DoubleSupplier reading = () -> sensor.getDistance();
double now = reading.getAsDouble();
```

Use the type required by the API. In performance-sensitive code, a primitive specialization can also avoid repeated boxing.

<span id="lazy-and-expensive-work"></span>

### `Supplier` Defers Expensive Work

A supplier can also postpone work that might not be needed.

```java norun
// The report is built before log is called, even when isDebug is false.
log(isDebug, "state: " + buildExpensiveReport());

// The report is built only if logLazy calls message.get().
logLazy(isDebug, () -> "state: " + buildExpensiveReport());

public static void logLazy(boolean enabled, Supplier<String> message) {
  if (enabled) {
    System.out.println(message.get());
  }
}
```

Java evaluates method arguments before entering the method. The supplier moves the expensive call inside behavior that `logLazy` can choose whether to run.

`Optional` uses the same distinction:

```java norun
String lazyDefault = maybeName.orElseGet(() -> computeDefault());
String eagerDefault = maybeName.orElse(computeDefault());
```

`orElseGet` invokes its supplier only when the `Optional` is empty. The argument to `orElse` is evaluated before the call, whether or not the value is needed.

### Primitive Specializations

Generic type arguments cannot be primitive types. Java therefore provides specialized functional interfaces for common primitive inputs and outputs.

Choose the interface that communicates the operation and matches the API. Do not replace clear working code solely to remove boxing; measure performance-sensitive code before optimizing it.

WPILib's `Trigger` can use a `BooleanSupplier`, which lets the trigger evaluate a changing condition when the scheduler polls it.

### Composing Behavior

Several standard functional interfaces provide default methods that create a new function from existing ones.

```java
import java.util.function.Function;
import java.util.function.Predicate;

public class Main {
  public static void main(String[] args) {
    Predicate<Integer> positive = value -> value > 0;
    Predicate<Integer> small = value -> value < 100;
    Predicate<Integer> both = positive.and(small);

    Function<Integer, Integer> doubled = value -> value * 2;
    Function<Integer, String> describe = value -> "value: " + value;
    Function<Integer, String> combined = doubled.andThen(describe);

    System.out.println(both.test(25));
    System.out.println(combined.apply(5));
  }
}
```

Expected output:

```text
true
value: 10
```

For functions, `first.andThen(second)` runs `first` before `second`. `first.compose(second)` runs `second` first and passes its result into `first`.

### When a Custom Interface Helps

The standard interfaces cover common, general-purpose shapes, but they are not the only valid functional interfaces. A custom interface can be clearer when it gives a domain operation a meaningful name, documents a specific contract, or declares a checked exception that a standard interface does not.

Use `@FunctionalInterface` on an interface you intend to target with lambdas. The annotation is not required, but it asks the compiler to report an error if a later edit stops the interface from being functional.

<RulesBox title="Common Mistakes">

- **Defining a generic callback** when a standard interface already expresses the same contract clearly.
- **Passing a snapshot where deferred behavior is required.**
- **Calling `get()` when you meant to store or pass the supplier.**
- **Using `orElse` with an expensive default** when `orElseGet` should defer the work.
- **Reversing `andThen` and `compose`.**
- **Assuming a supplier caches.** Each `get()` can run its body again.
- **Choosing a primitive specialization by guesswork.** Match the receiving API and optimize measured hotspots.

</RulesBox>
