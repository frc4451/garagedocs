**AdvantageScope** is a data visualization application from Team 6328, Mechanical Advantage. It is included with WPILib and can display live NetworkTables data and several log formats. FRC 4451 uses it for graphs, field views, controller inputs, and console messages.

This reference uses the 2026 application. You can begin with a saved log supplied by a mentor; you do not need to write robot code first. To create your own data, follow [R13: Telemetry](/kit-bot/r13-telemetry-with-advantagescope). If opening applications or switching windows is unfamiliar, keep the [VS Code Tour](/tools/vscode-tour) nearby.

This page introduces the application. [Poses on the field](/tools/advantagescope-poses-on-the-field) covers the 2D and 3D views, and [Controllers and the console](/tools/advantagescope-controllers-and-the-console) covers those two tabs. The [AdvantageScope documentation](https://docs.advantagescope.org/) is the reference for current controls and supported formats.

## Data Sources

**Live data** arrives while a program runs. A **log** is a saved record you can open later. **NetworkTables** carries named values from robot code to other programs. A **field**, also called a topic, is one named value; its **key** is the name used to find it. For example, `Launcher/Feeder/velocityRPM` identifies the feeder's speed in revolutions per minute.

AdvantageScope displays fields available through the selected live source or log. If a value is missing, first check whether the program publishes or records it under the expected key.

[Kit Bot R13](/kit-bot/r13-telemetry-with-advantagescope) configures NetworkTables publishing and WPILib data logging. Cobra uses [AdvantageKit](/frc/advantagekit), which records logged inputs and values passed to `Logger.recordOutput`. Check the active source and exact key path before comparing the two projects.

AdvantageScope supports additional formats, including Driver Station logs and selected vendor formats. Consult [Log Files](https://docs.advantagescope.org/overview/log-files/) for the version you installed.

## Open AdvantageScope

Use the copy included with the WPILib installation from [R00: WPILib Setup](/kit-bot/r00-wpilib-setup):

1. Open **WPILib VS Code 2026**. Keep your project open if you will also run simulation.
2. Click **View → Command Palette**. This opens the searchable command box at the top of the editor.
3. Type `WPILib: Start Tool`, select that command, then choose **AdvantageScope**.
4. Wait for the separate AdvantageScope window. Its field list can be empty until you connect to data.

If **Start Tool** is missing, confirm that you opened WPILib VS Code rather than another VS Code installation. Return to [R00 setup](/kit-bot/r00-wpilib-setup) if the WPILib tools are not installed.

The [AdvantageScope installation guide](https://docs.advantagescope.org/overview/installation/) also offers a separate download. Use the release chosen for your project so screenshots and shared layouts match. Record the application version when asking for help.

## Connect to Data

Choose one starting path:

| Your Starting Point | Action | Expected Result |
|---|---|---|
| A saved log from a mentor or R13 | Click **File → Open Log(s)...**. In the file picker, open the folder containing the log, select its `.wpilog` file, and click **Open**. | Recorded fields appear in the left sidebar. The file does not need a running robot. |
| The R13 simulation is running on this computer | Click **File → Connect to Simulator → Default**. For stock WPILib, choose the ordinary NetworkTables source if the default was changed. | The connection uses `127.0.0.1`, meaning this computer. The title stops showing **Searching** when connected. |
| An authorized physical-robot test | Set the robot address in preferences, then choose **File → Connect to Robot** and the source used by that project. | The sidebar fills with data from the running robot program. Follow [Robot Network Troubleshooting](/frc/robot-network-troubleshooting) if it cannot connect. |

For the Kit Bot, use ordinary NetworkTables. A project using AdvantageKit needs its corresponding NetworkTables source. These are different selections in the connection submenu.

Open preferences with **App → Show Preferences...** on Windows/Linux or **AdvantageScope → Settings...** on macOS. Confirm the robot address with the network plan. FRC 4451's radio-network address is `10.44.51.2`; a USB connection uses a different address. [The Robot Network](/frc/robot-network) explains those choices.

In a live connection, **Low Bandwidth** requests fields as you use them; earlier values for an unused field will not be available. **Logging** requests all fields and uses more bandwidth. It is a viewing mode, not a replacement for configuring a saved robot log.

If the field list stays empty, work through these checks in order:

1. Read the window title. If it says **Searching**, confirm that the simulator is still running and that you selected Simulator, not Robot.
2. Expand the small arrows beside the sidebar's tables. Data may be present inside a collapsed group.
3. Search for `Launcher/Feeder/velocityRPM` only if you ran the R13 project that publishes it. A different sample log may use different names; ask its author for one known field.
4. If other fields appear but that one does not, check the exact topic name and the R13 publishing code. For a saved log, confirm that it was recorded after you added that code.

Do not change firewall or network settings simply because one field is missing.

The **timeline** controls the selected time across supported tabs. Mode colors depend on the data and current AdvantageScope version. Click or scrub to align graphs, field views, and messages. During a live connection, use the red arrow control to lock or unlock the current time.

## Make a First Graph

A Line Graph places time from left to right and a numeric value vertically. A **trace** is the line showing one field's values. For this first graph, use a saved R13 log or the running R13 simulation. A mentor-supplied log needs equivalent numeric fields identified by the mentor.

1. Click the **+** button near the tab bar and select **Line Graph**.
2. In the sidebar, search for `Launcher/Feeder/velocityRPM`. Select the result to locate it.
3. Put the pointer over the field name, hold the mouse button, move it into the graph's **left** field list, then release the button. This action is called dragging. The field name should now appear in that list.
4. Find `Launcher/Feeder/appliedVolts` and drag it into the **right** list. The left scale now represents RPM and the right scale volts. Do not compare the heights of the two lines as if their units were equal.
5. For a saved log, press the playback button and move to an interval containing a recorded action. For live R13 simulation, return to the Simulation GUI and follow [Graph the Launch Sequence](/kit-bot/r13-telemetry-with-advantagescope#graph-the-launch-sequence), then switch back to AdvantageScope.
6. Click the graph at a time of interest. Read the selected values in the legend. Compare the voltage change with the speed response.

A flat zero trace is data: the feeder may be idle. A missing trace needs a different check: confirm that the field is in the list and has samples in the selected interval. Scroll over the graph to zoom; drag along it to inspect another time. During a live connection, use the red arrow to return to the newest data.

Use the **discrete** list for values such as true/false states or text, which are categories rather than a numeric scale. The [Line Graph reference](https://docs.advantagescope.org/tab-reference/line-graph/) covers axis ranges and display options.

For a mechanism, compare the commanded value, measured value, and control output. This can reveal lag, overshoot, steady-state error, or saturation, but the graph alone does not establish the cause. [Simulation in AdvantageScope](/frc/simulation-in-advantagescope#the-line-graph-commanded-versus-measured) explains how to investigate.

## Save a Layout

A layout stores your tabs, selected fields, and view settings. It does not replace the log containing the measurements.

1. Choose **File → Export Layout...** after arranging your tabs.
2. Choose a folder you can find again and a descriptive name such as `kit-bot-launcher.json`. Save the file.
3. Later, choose **File → Import Layout...** and open that file. Connect to the appropriate source or open its log as well.

If imported tabs are empty, compare their requested field names with the current sidebar. A layout made for Cobra does not automatically match Kit Bot keys.

<RulesBox title="Common Blockers">

- **Wrong live source or address.** Confirm Robot versus Simulator and the selected protocol.
- **Missing publication or log entry.** Verify the key in the code and source tree.
- **Bandwidth mode does not retain an unused field.** Use Logging mode only when bandwidth permits.
- **Layout not saved.** Export a shared layout after checking its fields and labels.
- **Version mismatch.** Record the AdvantageScope version used to create a layout or reproduce a problem.

</RulesBox>
