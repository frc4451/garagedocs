Use the Joysticks tab to inspect recorded controller state and the Console tab to align text messages with the shared timeline. Confirm the required data is present before relying on either view.

Before starting, follow the [AdvantageScope Tour](/tools/advantagescope-tour) to open a file and use the timeline. For Kit Bot, use the saved log from [R13: Open the Saved WPILOG](/kit-bot/r13-telemetry-with-advantagescope#open-the-saved-wpilog). The log must include an interval when the controller was connected and used.

## Inspect Controller Inputs

Choose the data source first. Ordinary live NetworkTables from stock WPILib does **not** supply the joystick data for this tab. Use a WPILib log with joystick logging, or an AdvantageKit log or stream. A connected graph alone does not establish that controller data is available.

Click the **+** near the tab bar, then choose **Joysticks**. This displays supported controller layouts for ports 0 through 5. Button and axis values follow the selected time in the data source.

<StepsBox title="Showing a Controller">

1. Find the table at the bottom of the tab. Click its controller-type selector and pick a **layout** for each port you care about. Options include *Xbox Controller*, *PS4/PS5*, a flight stick and *Generic Joystick*, which shows every button, axis and POV in a grid and works for anything.
2. The **port number** is the one the Driver Station shows in its USB tab and the one the code passed to <code>new CommandXboxController(0)</code>. Valid ports range from 0 to 5. Cobra assigns its driver to port 0 and operator to port 1. Kit Bot uses Joystick 0; follow [Kit Bot R10](/kit-bot/r10-joysticks-and-stick-math) for that project.
3. Select a time when you know a button was pressed, or press the playback button to watch the interval. A recorded button press should light the corresponding button. An axis is a value such as a stick's horizontal position; a POV is a directional-pad angle.
4. If no control changes, first confirm the log covers the action, then compare the port with the Driver Station assignment. Use **Generic Joystick** if the physical layout is unfamiliar. If the source has no joystick fields, check its logging setup rather than reassigning controls at random.

</StepsBox>

Stock WPILib does not provide joystick state through a plain live NetworkTables connection. The tab supports WPILib logs with joystick logging enabled, AdvantageKit logs, and AdvantageKit streaming. See the [Joysticks reference](https://docs.advantagescope.org/tab-reference/joysticks/).

Cobra's AdvantageKit setup provides controller data live and in logs. A plain WPILib log needs `DriverStation.startDataLog(...)` to record it. Verify the fields in the source tree rather than assuming the line was called.

**Reading controller data.** Align the input with a mechanism graph. A recorded press with no response narrows the investigation to bindings, command scheduling, subsystem state, or code after the input. No recorded press can reflect the controller, port, Driver Station, or missing logging.

## Read Console Messages

**+ → Console** displays updates from one string field. Select the field that corresponds to the active log source. Rows share the timeline with other tabs.

Click **+ → Console**, find a string field from the table below in the sidebar, and drag it into the viewer. A string is text. If no rows appear, confirm that the chosen field has messages in the selected interval. The Console cannot show messages that were never recorded:

For Cobra, inspect `/RealOutputs/Console`; for replay, inspect `/ReplayOutputs/Console`. A Kit Bot `.wpilog` can contain `messages` from `DataLogManager.log`. Driver Station event text is available through its Driver Station log source. Confirm the actual keys because prefixes can vary by source and version.

Use the Console controls to filter, select, and export messages:

- **Filter** (`Ctrl+F` jumps to the box): type a word and only rows containing it stay. Try `Elevator`, `Exception` or a command name. Start the filter with `!` to *hide* matching rows instead, which is how you remove a chatty message you do not care about.
- **Highlight**: the colour-palette icon toggles colouring for rows containing *warning* or *error*. Leave it on.
- **Jump**: click a row to select its time on the shared timeline. Every other tab moves to that instant. The ↓ button jumps to a typed time.
- **Export**: the save icon writes the console to a text file, for pasting into a pull request or an issue.

**Reading a crash.** For example, a `NullPointerException` row tells you that code tried to use a missing object reference. Select its time, read the following stack-trace lines, and locate the first line naming your project's class and source line. Then compare a relevant numeric field at that time. A controller press just before the exception helps you reproduce the sequence; it does not by itself prove the controller caused the fault. The timing may reveal related events, but correlation alone does not establish the cause. [Reading Docs and Errors](/tools/reading-docs-and-errors#read-an-error) explains stack traces.

**Writing useful messages.** Log state transitions, command starts and ends, disconnections, and other events that help explain behavior. Record frequently changing numeric values as numeric fields instead of printing each loop. Excessive console output makes relevant messages harder to find and can affect timing.

## Copy Logs From the Robot

For your first practice, use a simulation log already saved on the computer. Downloading from hardware is a later task during an authorized, disabled-robot session. A **download** copies a file from the robot to your computer.

1. Open AdvantageScope preferences and confirm both the robot address and log folder for that project. See [Log Download Configuration](https://docs.advantagescope.org/overview/log-files/#downloading-from-the-robot).
2. Choose **File → Download Logs...**. Once connected, inspect the newest files at the top. Select the log matching your test.
3. Click the downward-arrow download button. Choose a folder you can find again, such as a folder named for that day's test, and confirm the destination.
4. Wait for the download to finish. Open the copied file in AdvantageScope and check that its time interval and expected fields match the test. Keep the original until the copy has been checked.

If no files appear, check the configured log folder and robot connection before changing the robot program. Existing files are skipped during a multi-file download, so inspect the destination rather than assuming another copy was created.

If the mentor chooses USB removal instead, shut down the robot and follow the hardware procedure before unplugging its storage. Do not pull a stick while the program may still be writing it. The [Hardware section](/hardware) is the starting point for physical connections and handling.

Driver Station `.dslog` and `.dsevents` files are stored on the driver-station computer. Keep the pair together. To compare those records with a robot log, use **File → Open Log(s)...** and select the related files together. AdvantageScope aligns their timestamps. Check for a known shared event before drawing conclusions about timing. The records complement each other; neither guarantees that every relevant event was captured.

<RulesBox title="Common Blockers">

- **Unsupported live source.** Stock WPILib joystick state is not available through plain live NetworkTables.
- **Missing joystick logging.** Verify the WPILib log configuration before the event.
- **Wrong console field.** Match the field to the log or live source.
- **Printing every loop.** Log numeric values as numbers and reserve console messages for events.
- **Treating timing as proof.** Use aligned data to form and test a diagnosis.
- **Wrong controller port.** Compare AdvantageScope with the Driver Station USB assignment.

</RulesBox>
