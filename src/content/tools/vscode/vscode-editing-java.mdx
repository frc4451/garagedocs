## Before You Edit

Java support runs a **language server**, a background tool that reads the open project and explains the code to VS Code. It supplies completion, navigation, and **diagnostics**, which are the underlines and messages about possible problems. A **Gradle build** is the project's complete compile-and-check task. Editor diagnostics help while you type; a clear Problems panel does not prove that the Gradle build passes.

Use stock VS Code with the Extension Pack for Java and Java 25 for this site's standalone Java curriculum. Use WPILib VS Code 2026 for a 2026 robot project. WPILib supplies and manages the Java 17 robot toolchain. See [Java Setup](/java/fundamentals/setup) and [R00, Run Simulation](/kit-bot/r00-wpilib-setup#step-5-run-simulation).

Open the full project folder. Wait for Java project loading to finish in the Status Bar before deciding that a missing diagnostic or action means the code is correct.

## Read Diagnostics

Red or yellow underlines mark editor diagnostics. Hover over an underline to read its message. Open **View → Problems** or use `Ctrl+Shift+M` / `Cmd+Shift+M` to see messages grouped by file. Select a message to open its line.

Start with the earliest relevant error. Fix it, save, and wait for the list to refresh. One missing brace can cause many later messages.

## Use Completion and Snippets

Start typing, or press `Ctrl+Space`, to open suggestions. Use arrow keys to inspect them, Enter or Tab to accept one, and Escape to close the list. After typing `object.`, read the highlighted method's parameter and return types before accepting it.

The Java extension documents these snippet prefixes: `sysout` or `sout` for `System.out.println`, `main` or `psvm` for a `main` method, `fori` for an indexed array loop, and `foreach` or `iter` for an enhanced loop. A snippet appears as a suggestion. Select it, then press Tab to move through its editable fields. If a prefix does not appear, open the Command Palette and choose **Insert Snippet** to inspect the snippets installed on that computer.

Parameter hints show which argument you are filling and the required type. Open them with `Ctrl+Shift+Space` on Windows/Linux or `Cmd+Shift+Space` on macOS. Suggestions can match more than the start of a name, so inspect the full highlighted entry instead of assuming a short abbreviation selected the intended method.

## Hover and Go to Definition

- Hover over a name to see its type and available documentation.
- Choose **Go → Go to Definition** or press `F12` on a name. Your code opens at its declaration. A dependency may open attached source or generated/decompiled content, depending on what the dependency supplies.
- Choose **Go → Go Back** to return if the configured return shortcut is unknown.
- Choose **Go → Go to References** or press `Shift+F12` before changing a widely used method.
- Open Explorer and expand **Outline** to select a class, field, or method in the current file.

The breadcrumbs above the editor show the file path and the class or method containing the cursor. Select a segment to move among nearby files or symbols. Open **Go to Symbol in Editor** with `Ctrl+Shift+O` / `Cmd+Shift+O` when a long file is easier to search than scroll.

## Review Fixes and Refactors

Put the cursor on a diagnostic or symbol and choose the lightbulb, **Refactor...** from the context menu, or `Ctrl+.` / `Cmd+.`. A **quick fix** addresses a specific diagnostic, such as adding an import. A **refactoring** changes code structure while preserving intended behavior, such as renaming a symbol or extracting a method.

Generated constructors, accessors, `toString`, or equality methods are proposed code. Before saving, read every generated field and parameter, check null and unit assumptions, and confirm that equality matches the class's intended identity. For Rename (`F2`), preview or review all changed references, including tests. Strings, configuration, and code outside the open project may still contain the old name.

**Organize Imports** sorts imports, removes imports the language server believes are unused, and may offer choices for unresolved classes. Run it through the Command Palette or with `Shift+Alt+O` on Windows/Linux or `Shift+Option+O` on macOS. Review ambiguous classes and the resulting diff before saving. The Keyboard Shortcuts editor is the source of truth when a platform or extension binding differs.

## Formatting

Open the Command Palette and choose **Format Document**. The default shortcuts differ by platform: `Shift+Alt+F` on Windows, `Ctrl+Shift+I` on Linux, and `Shift+Option+F` on macOS. Save, then inspect the diff so formatting does not hide a behavior change.

Cobra2026 follows the [AdvantageKit Spotless Profile](/java/fundamentals/code-style). Its workspace recommends the Spotless Gradle extension and selects it as the default Java formatter. Run the project's `spotlessApply` task before review and use `spotlessCheck` when you want to check without changing files. The Gradle task is authoritative because it uses the formatter and rules declared by the project.

The generated Kit Bot project and other FRC 4451 repositories may use different shared settings and build rules. Follow the files in the project you opened. Do not assume that a formatter configured in Cobra is present in every project.

## Running a Single File

For a supported standalone Java file containing `public static void main(String[] args)`, the Java extension places **Run | Debug** above `main`. Save the file, select **Run**, and look for output in the Terminal. If the links are absent, confirm the file ends in `.java`, Java loading has finished, and the containing folder is open.

For robot code, do not use the standalone **Run** link. In WPILib VS Code 2026, open the robot project root and follow [R00, Step 5](/kit-bot/r00-wpilib-setup#step-5-run-simulation). A successful start opens the WPILib simulation controls described there; a compile error remains in the task terminal with a file and line to inspect.
