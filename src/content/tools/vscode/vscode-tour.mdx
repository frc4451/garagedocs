Visual Studio Code (VS Code) is a code editor. FRC 4451 uses it for Java lessons, robot projects, and configuration files. This tour names the parts of the window, then walks through opening a folder, creating and saving a file, and opening a terminal in the correct folder.

## Choose the Right Copy

You may have two separate installations. Use the one that matches the work:

Follow [R00, Install WPILib](/kit-bot/r00-wpilib-setup#step-1-install-wpilib) before opening a robot project. WPILib installs its editor in a year-specific folder. You do not need to browse to that folder to start it, so this guide does not depend on an operating-system path that may vary.

The two installations can have different settings and extensions. WPILib advises against using Settings Sync between stock VS Code and WPILib VS Code because synchronized settings can break either setup. Stock VS Code can use Java 25 for this site's Java curriculum. The 2026 robot project uses the Java 17 toolchain supplied and managed by WPILib.

Keep three typing locations separate. Type file contents in the **Editor**. Type commands after the prompt in the **Terminal**. Type website addresses and use lesson controls in your **browser**.

## Open the Folder, Not the File

For a project, open the root folder rather than one file. A robot project root contains `build.gradle`; opening that folder lets Java and WPILib find the project's dependencies and tasks.

<StepsBox title="Open the Folder">

1. Start the appropriate VS Code installation. Use **WPILib VS Code 2026** for a 2026 robot project.
2. Choose **File → Open Folder...**. If the welcome page is visible, **Open Folder...** there performs the same action.
3. In the system folder picker, select the project folder itself. Choose **Select Folder** on Windows and most Linux desktops, or **Open** on macOS.
4. If **Workspace Trust** appears, read the folder path. Trust it only when you know the source and intend to allow its code and tasks to run.
5. Select **Explorer** in the Activity Bar. The project name should appear at the top, with `build.gradle` visible for a robot project.

</StepsBox>

If only one file appears and the Explorer has no project folder heading, choose **File → Open Folder...** again and select the parent project folder. Use **File → Open Recent** to reopen a folder you used before.

## Create, Save, and Find a File

Use these practice names only when another lesson has not supplied its own folder and file names.

<StepsBox title="Create a Practice File">

1. Choose **File → Open Folder...** and create or select a folder named `editor-practice`.
2. In Explorer, select the **New File...** button beside the folder name. If the button is hidden, right-click the folder and choose **New File...**.
3. Type `notes.txt`, including `.txt`, and press Enter. The new editor tab opens.
4. Type `terminal commands go in the terminal`.
5. Save with **File → Save**, `Ctrl+S` on Windows/Linux, or `Cmd+S` on macOS. The unsaved dot on the tab disappears.
6. Open **Quick Open** with `Ctrl+P` or `Cmd+P`, type `notes`, and select `notes.txt`.
7. Right-click the file in Explorer and choose **Reveal in File Explorer** on Windows, **Reveal in Finder** on macOS, or **Open Containing Folder** on Linux.

</StepsBox>

If the file is named `notes.txt.txt`, rename it in Explorer to `notes.txt`. If the saved file disappears after you close its tab, reopen the intended folder and check whether you created the file in a different location.

## The Command Palette

Open the Command Palette through **View → Command Palette...**, `Ctrl+Shift+P` on Windows/Linux, or `Cmd+Shift+P` on macOS. Type part of a command, such as `format`, then select the full command name. The list changes with the active file and installed extensions.

For a robot command, first confirm that **WPILib VS Code 2026** has the robot project folder open. Type `WPILib:` in the palette. If no WPILib commands appear, check the editor copy, Workspace Trust, and project root before reinstalling anything.

## The Integrated Terminal

Choose **View → Terminal** or press `` Ctrl+` ``. A prompt appears in the bottom panel. The text before the cursor identifies the shell and often includes the current folder. On Windows, type `Get-Location` in PowerShell; on macOS/Linux, type `pwd`. Press Enter. The printed path should end with the project folder shown at the top of Explorer.

If the path is different, close that terminal with its trash-can button and choose **Terminal → New Terminal** after reopening the correct project folder. See [The Prompt](/tools/command-line-basics#the-prompt) and [Current Folder](/tools/command-line-basics#your-current-folder) before running project commands.

## Choose Settings Deliberately

Open Settings through **File → Preferences → Settings** on Windows/Linux, **Code → Settings → Settings** on macOS, or `Ctrl+,` / `Cmd+,`. Search for a setting by name.

- **User** settings apply to every folder opened in that VS Code installation.
- **Workspace** settings apply only to the open project and can override User settings.
- **Default** shows the editor's original value.

Choose text size and zoom for the person or room using the screen. `Ctrl+=` / `Ctrl+-` on Windows/Linux and `Cmd+=` / `Cmd+-` on macOS adjust window zoom. Treat Auto Save and Format on Save as project choices: know when a file is saved, and review formatting changes before a build or commit.

<RulesBox title="Check Your Work">

- The intended folder name is at the top of Explorer.
- A robot project is open in WPILib VS Code 2026 and shows `build.gradle`.
- A saved tab has no unsaved dot.
- The terminal's printed current folder matches the folder open in Explorer.
- Editor diagnostics are hints from language tools. A project build is still the final check.

</RulesBox>
