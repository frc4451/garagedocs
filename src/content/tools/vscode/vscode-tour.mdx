**Visual Studio Code (VS Code)** is Microsoft's code editor. FRC 4451 uses it for Java lessons, robot projects, and configuration files. WPILib includes a copy configured with its robot programming tools.

Extensions add language support, build commands, and debugging tools. The Java tools can show types, find definitions, and report errors while you edit.

### The Command Palette

Open the Command Palette with:

**`Ctrl+Shift+P`** (Windows/Linux); **`Cmd+Shift+P`** (macOS)

The **Command Palette** searches available commands by name. Type a word such as *format*, *rename*, or *deploy*, then select the matching command. Available commands depend on the installed extensions and current context.

The palette also displays assigned keyboard shortcuts. Use those labels to learn shortcuts for commands you repeat.

### Open the folder, not the file

For a project, open its root folder so the tools can find its configuration and dependencies.

VS Code calls an opened folder or set of folders a **workspace**. For a Gradle project, open the folder containing `build.gradle`. Java tooling also supports standalone files, but those files do not automatically have the dependencies and configuration of the full robot project.

Choose **File → Open Folder** and select the project root. When prompted about Workspace Trust, trust code only when you know its source and intend to allow its tools and tasks to run. Restricted Mode limits those features while you inspect unfamiliar code.

**File → Open Recent** (`Ctrl+R`) lists folders you have had open before. That is the normal way to get back to the robot project each day.

### The Explorer

The Explorer (`Ctrl+Shift+E` / `Cmd+Shift+E`) is the file tree. Hover over a folder for the *new file* and *new folder* buttons; right-click for rename, delete, copy path. Files you have changed but not committed show a colour and a letter. **M** means modified, and **U** means untracked. These markers come from Git integration.

The **Outline** lists symbols in the current file, such as classes and methods. Click one to navigate. If entries are missing, check for syntax errors and whether language support has finished loading.

### The integrated terminal

`` Ctrl+` `` opens the integrated terminal. Check its current folder and selected shell before running a command. Windows commonly uses PowerShell; macOS/Linux use the configured shell. The examples in [The command line](/tools/command-line-basics#running-a-program-and-giving-it-arguments) apply here too.

The `+` at the top right of the terminal opens a second one; the split icon puts two side by side. A common arrangement is one terminal running a long job (simulation, a server) and another for commands.

### Settings

`Ctrl+,` / `Cmd+,` opens Settings, with a search box across every option. Three levels matter:

- **User:** applies to you in every project. Theme, font size, whether to auto-save.
- **Workspace:** applies to this project and everyone who opens it. Stored in `.vscode/settings.json` inside the project and committed, so the whole team gets the same formatter settings. WPILib projects come with one.
- **Default:** shows what VS Code does out of the box.

Workspace wins over User. If a setting seems not to apply, check the *Workspace* tab: the project may be overriding you, on purpose.

Settings Sync can share your settings and extensions across your own machines. On a shared laptop, use FRC 4451's account policy and separate user profiles. Signing out does not automatically remove preferences already stored locally.

### Themes and layout

`Ctrl+K Ctrl+T` on Windows/Linux or `Cmd+K Cmd+T` on macOS opens the colour theme picker. Choose a theme with readable contrast for code, comments, and diagnostics.

`Ctrl+K Z` enters **Zen mode**: just the editor, full screen, nothing else. `Escape` twice leaves it. Useful when you are reading rather than navigating.

<RulesBox title="Common mistakes">

- **Missing project configuration.** Open the project root for builds and dependency-aware editing.
- **Restricted features.** Check Workspace Trust before troubleshooting disabled tasks or extensions.
- **Overlooking the current branch.** Read the Status Bar before recording changes.
- **Confusing diagnostics with a build.** Run the project build even when the editor reports no errors.

</RulesBox>
