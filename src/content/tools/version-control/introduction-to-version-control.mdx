## What Version Control Does

Version control records selected versions of a project's files. You can compare those versions, find when a behavior changed, and recover code that worked before.

Git is the version control program used in this curriculum. It runs on your computer. GitHub is a website that can store a copy of a Git repository and provide tools for sharing and reviewing changes.

## Four Words To Know

| Term | Meaning |
|---|---|
| Repository | A project folder and the history Git records for it. Often shortened to repo. |
| Commit | A recorded snapshot of selected files, with a message describing the change. |
| Branch | A line of development, such as work on a new autonomous routine. |
| Remote | Another repository that your local repository exchanges commits with. A repository on GitHub can be a remote. |

**Local** means on your computer. A local repository includes the project files you can see in the folder and Git's recorded history. You can edit files and create commits locally without sending anything to GitHub.

## From One Edit To GitHub

Suppose you change one sentence in `README.md`:

1. **Edit and save the file.** The new sentence exists in the project folder on your computer. Git has not recorded a new commit.
2. **Stage the saved change.** Staging selects the current version of `README.md` for the next commit. The file is still only on your computer.
3. **Commit the staged change.** Git records a local snapshot and a message describing it. The commit is not yet on GitHub.
4. **Push the commit.** Git sends the commit to a remote repository, such as the project's repository on GitHub.

Saving, staging, committing, and pushing are separate actions. Git does not automatically record every save, and a commit does not automatically go to GitHub.

The [Local Git Workflow](/tools/local-git-workflow) lesson walks through the first three actions in a practice folder. [GitHub Remotes](/tools/github-remotes) explains how a local repository exchanges commits with GitHub.

<RulesBox title="Why Version Control Matters">

Use the history to compare changes to autonomous routines, review a teammate's work, and identify the version used at an event. Commit messages and review discussions also preserve the reasons for decisions after students graduate.

</RulesBox>

## What Git Records

Git records changes when you commit them. A normal full clone includes the project history and can create commits without an internet connection. A shallow clone can contain less history.

Git can only protect work that reaches a commit, and GitHub can only hold work that you share with it. Keep backups for files outside Git and for important work that has not been committed and pushed.
