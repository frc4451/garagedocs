### What is version control?

Version control records selected changes to files so you can compare versions and return to earlier work. For a robot project, that history helps you find when a behavior changed and recover code that worked before.

### Key concepts

| Term | Meaning |
|---|---|
| Repository | The project and its recorded history. Often shortened to repo. |
| Commit | A saved snapshot of tracked files, with a message describing the change. |
| Branch | A line of development, such as work on a new autonomous routine. |
| Remote | Another repository that your local repository exchanges commits with. |

Git is the version control tool used in this curriculum. GitHub hosts repositories online and provides pull requests, reviews, and other collaboration tools.

<RulesBox title="Why version control matters for a robotics team">

Use the history to compare changes to autonomous routines, review a teammate's work, and identify the version used at an event. Commit messages and review discussions also preserve the reasons for decisions after students graduate.

</RulesBox>

### Understanding version control systems

Git records changes when you commit them. Saving a file in the editor does not create a commit, and committing does not send the work to GitHub. You must push commits to share them with the remote repository.

Git is distributed: a normal full clone includes the project history and can create commits without an internet connection. Shallow clones can contain less history. Neither a local repository nor GitHub protects work that was never recorded and shared. Keep backups for files outside Git as well.
