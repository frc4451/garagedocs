### Connecting to GitHub

Git runs on your computer. GitHub hosts a remote copy of the repository where teammates can share commits and review changes. A local commit reaches GitHub only after you push it.

### Setting up GitHub

Complete [Creating Your GitHub Account](/tools/creating-your-github-account) first. It covers email verification, 2FA, and accepting a team organization invitation. Then choose an authentication method from the section below.

To work on an existing project, copy its clone URL from GitHub's **Code** menu. Replace `repository-url` below with that URL:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git clone repository-url
cd repository-folder
git remote -v
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git clone repository-url
cd repository-folder
git remote -v
```

</CodeTab>
</CodeTabs>

Replace `repository-folder` with the folder created by the clone. `git remote -v` displays the configured remote names and URLs. A clone normally names its source `origin`.

For an existing local project, create an empty GitHub repository first. Inside the local project, use `git remote add origin repository-url` with its URL. This adds the connection; it does not upload files yet.

### Syncing with remote

These commands have different effects. Replace `branch-name` with the branch you intend to share or update, and check your current branch with `git status` first.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git fetch origin                 # Download remote history without integrating it
git pull origin branch-name      # Fetch and integrate into the current branch
git push -u origin branch-name    # Publish the local branch and set its upstream
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git fetch origin                 # Download remote history without integrating it
git pull origin branch-name      # Fetch and integrate into the current branch
git push -u origin branch-name    # Publish the local branch and set its upstream
```

</CodeTab>
</CodeTabs>

`pull` integrates the fetched history using merge or rebase according to its options and configuration; it can stop for conflicts or incompatible settings. Check and preserve local work before integrating changes. See [Git's pull reference](https://git-scm.com/docs/git-pull).

After setting an upstream, `git pull` and `git push` can use it without a remote and branch argument. A push sends commits, not unsaved or uncommitted files.

### Authentication methods

GitHub supports HTTPS and SSH connections. HTTPS can use a credential manager or personal access token; SSH uses a key added to your account. Follow the team's supported setup and the [GitHub authentication documentation](https://docs.github.com/en/authentication). Your GitHub account password is not used as the password for Git over HTTPS.

Enable two-factor authentication for your account. Keep tokens and private keys out of the repository. Access to a private repository also requires permission from its owner, even when authentication succeeds.

### Understanding remote repository workflow

Fetch to inspect incoming work, integrate changes when ready, and push commits you want to share. If a push is rejected, read the error: an out-of-date branch, missing permission, and an authentication failure need different fixes. Do not force-push to bypass an unexplained rejection.
