### Working with Git locally

Open a repository folder in your terminal. If you are starting a new project, initialize it with `git init`. If the project already exists on GitHub, [clone it](/tools/github-remotes#setting-up-github) instead.

### Understanding the three areas of Git

| Area | What it contains |
|---|---|
| Working directory | The files you edit and save. |
| Staging area, also called the index | The versions selected for the next commit. |
| Repository history | Snapshots already recorded as commits. |

Saving a file changes the working directory. Staging copies its current version into the index. A commit records the staged version. If you edit a file after staging it, stage it again to include those later edits.

### Basic Git workflow

In a practice repository, create or edit `README.md` and save it. Then run:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git status
git diff
git add README.md
git diff --staged
git commit -m "Describe the practice project"
git log --oneline
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git status
git diff
git add README.md
git diff --staged
git commit -m "Describe the practice project"
git log --oneline
```

</CodeTab>
</CodeTabs>

`status` lists changed and untracked files. `diff` shows unstaged changes to tracked files; a new, untracked file will not appear there. After `add`, `diff --staged` shows what the commit will record. Read that diff before committing.

The commit command saves the staged changes with the supplied message. The log should then show that message in the newest commit. The commit remains local until you push it.

Repeat the sequence twice more, once adding a new file and once editing `README.md` again, so `git log --oneline` shows three commits with messages that say what changed.

### Essential commands

| Command | Use |
|---|---|
| `git init` | Create a repository in the current folder. |
| `git clone repository-url` | Copy an existing repository. Replace `repository-url` with its URL. |
| `git status` | Check the current branch and file states. |
| `git add filename` | Select a file's current changes for the next commit. |
| `git commit` | Commit staged changes and open an editor for the message. |
| `git log` | Read commit history. |
| `git diff` | Compare unstaged changes with the index. |
| `git diff --staged` | Compare staged changes with the current commit. |

Use explicit file paths when staging so unrelated changes stay out of the commit. Files
excluded by [`.gitignore`](/tools/gitignore), such as build output, usually do not belong
in project history.
