### Graphical Git interface

GitHub Desktop provides buttons and views for common Git operations. The underlying concepts are the same as in [Local Git workflow](/tools/local-workflow): edit files, select changes, commit, then push to share them.

### Setting up GitHub Desktop

Install GitHub Desktop from its official download page, sign in to GitHub, and check the name and email used for commits. Clone a repository or add one already on your computer. Set the external editor you want Desktop to open.

### Basic operations

1. Select the repository and confirm the current branch.
2. Edit and save a file in your editor.
3. Open **Changes** and read the diff.
4. Select the files or lines you want to include.
5. Write a summary and commit to the current branch.
6. Push the commit when it is ready to share.

The selections control what goes into the commit. Check the remaining Changes list afterward to see what was left out. A local commit is not yet on GitHub.

### Branching with GitHub Desktop

Use the branch menu to create a branch from the intended starting point or switch to an existing one. Preserve unfinished work when changing branches. Desktop also supports local merges; pull requests add a review process on GitHub.

For a team change, publish the feature branch and open a pull request. Review the destination branch and describe the behavior and test results. See [Pull requests and collaboration](/tools/pull-requests).

### Advanced features

Use History to inspect earlier commits and their diffs. Desktop can also help revert commits, handle conflicts, and retain unfinished work when switching branches. Read the confirmation text before undoing or discarding changes: these actions have different effects.

### Understanding GUI vs command line

Choose the interface that helps you inspect the operation and its result. Desktop, VS Code, and the terminal can work with the same local repository. When following a terminal example, check that its current folder and branch match the repository open in Desktop.
