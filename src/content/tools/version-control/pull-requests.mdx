### Collaborating with pull requests

A pull request (PR) proposes merging one branch into another. It gives reviewers a place to inspect the diff, discuss the behavior, and record why the team accepted or rejected a change.

### Creating pull requests

1. Push the feature branch to GitHub.
2. Select **Compare & pull request**, or create a pull request from the repository's Pull requests tab.
3. Check the source and destination branches.
4. Describe the problem, resulting behavior, and tests performed.
5. Request a reviewer and link related issues when relevant.

Use a draft pull request if you want feedback before the work is ready to merge. New commits pushed to its source branch update the same pull request.

### Reviewing pull requests

Read the description, then inspect the changes. Check that the implementation matches the stated behavior and that the tests address it. Run the code or simulation when the change needs confirmation beyond reading the diff.

Make comments specific: identify the behavior, explain the concern, and suggest a change when you can. Distinguish required fixes from optional preferences. Submit an approval, request changes, or leave comments according to the review outcome.

### PR best practices

Keep the request focused so reviewers can understand and test it. Explain architectural choices and limits rather than narrating each edited line. For robot behavior, include the simulation evidence and any remaining hardware checks.

Respond to review comments with the change made or the reason for keeping the current approach. Update the description if the scope changes.

### Merging pull requests

Check the repository's required reviews and status checks before merging. Resolve conflicts and review the combined result. A passing build confirms only the checks that ran; it does not prove the robot behaves correctly.

| Method | Effect on history |
|---|---|
| Merge commit | Combines the branches and preserves their separate commits. |
| Squash merge | Records the proposed changes as one commit on the destination branch. |
| Rebase and merge | Replays the proposed commits onto the destination branch. |

Use the team's chosen method. After merging, update the related issue or documentation and delete the feature branch if it is no longer needed.
