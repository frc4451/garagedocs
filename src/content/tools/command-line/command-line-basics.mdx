## Your First Command

This page teaches you to open a terminal, run a command that does not change your computer, recognize its output, and move between folders. You need only the terminal built into your operating system. Use a normal window for every practice step on this page; do not open it as an administrator.

A **terminal** is the application that displays a command-line session. A **shell** interprets the commands you enter. These pages use PowerShell on Windows and bash or zsh on macOS/Linux; the latter examples are labeled Terminal.

Each example provides PowerShell and Terminal tabs. Some commands share names, but their options and output may differ. PowerShell aliases such as `ls` and `cat` refer to PowerShell commands on Windows; they do not make the two shells interchangeable.

## The Prompt

A **prompt** indicates that the shell is ready for input. Examples include `PS C:\Users\jordan>` in PowerShell and `jordan@macbook ~ %` in zsh. Prompts are configurable, so yours may look different. The path often shows the **current working folder**, the folder a command uses when you give it a file name without a longer path.

Type a command after the prompt, press Enter, and read the output. Do not type the example prompt itself. When the command finishes, the prompt returns on a new line.

Run one command and identify each part of the result:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Write-Output "terminal ready"
```

</CodeTab>
<CodeTab label="Terminal">

```bash
printf '%s\n' "terminal ready"
```

</CodeTab>
</CodeTabs>

The line you typed is the **command**. The line `terminal ready` is the command's **output**. The next prompt means the shell finished the command and is ready again.

## Your Current Folder

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-Location          # the folder you are in ("pwd" works too)
Get-ChildItem         # what is in it ("ls" or "dir" work too)
Get-ChildItem -Force  # include hidden files, like .wpilib
```

</CodeTab>
<CodeTab label="Terminal">

```bash
pwd                   # the folder you are in
ls                    # what is in it
ls -la                # long form, including hidden files like .wpilib
```

</CodeTab>
</CodeTabs>

Run the first command in your operating-system tab. The displayed path is your current working folder. Run the second command and find one displayed name. A folder can contain other items; a file contains saved information. If the list is empty, run the version that includes hidden items. Listing an item does not change it.

A command that uses a short file name looks in this current folder unless the command says otherwise.

## Moving Around

The commands below are separate examples. Start with `cd ~`, list the folders there, choose one folder name that appears, and type `cd` followed by that name. Run the location command again to confirm the result, then use `cd ..` to return.

The longer paths are examples only. Replace `jordan` with the account name on your computer and `Cobra2026` with a folder that exists. A Mac home path normally begins with `/Users`; a Linux home path normally begins with `/home`. Keep quotation marks around any path that contains a space.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
cd Documents          # into a folder that is here
cd ..                 # up one level
cd ~                  # back to your user folder
cd C:\Users\jordan\Cobra2026   # an absolute path, from the drive down
cd "C:\Users\jordan\FIRST Robotics"   # quote it if there is a space
```

</CodeTab>
<CodeTab label="Terminal">

```bash
cd Documents          # into a folder that is here
cd ..                 # up one level
cd ~                  # back to your home folder
cd /Users/jordan/Cobra2026     # an absolute path, from the root down
cd "/Users/jordan/FIRST Robotics"   # quote it if there is a space
```

</CodeTab>
</CodeTabs>

Press **Tab** after part of a path or command to request completion. Repeated Tab presses may cycle matches or list them, depending on the shell and configuration.

**Up arrow** recalls previous commands. Check the recalled command before running it again.

After the `cd` command you choose, run `Get-Location` in PowerShell or `pwd` in Terminal to confirm the current folder before you work with a file.

## Running a Program and Giving It Arguments

A command names a program or shell operation and may include **arguments**. Options, also called flags or switches, select behavior. Spaces separate arguments unless quoting groups them.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
ping -n 3 127.0.0.1          # send three packets to this computer
Test-NetConnection 127.0.0.1 # test this computer
```

</CodeTab>
<CodeTab label="Terminal">

```bash
ping -c 3 127.0.0.1          # send three packets to this computer
```

</CodeTab>
</CodeTabs>

Each command defines its own options. Windows `ping` uses `-n` for a packet count; macOS and Linux `ping` use `-c`. The address `127.0.0.1` means this computer, so this example does not contact another device. The output should show three replies and then a summary.

## Reading the Help

Use help to look up options and examples:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-Help Test-NetConnection          # PowerShell's own commands
Get-Help Test-NetConnection -Examples
ping /?                              # the older Windows tools use /?
```

</CodeTab>
<CodeTab label="Terminal">

```bash
man ping                             # macOS/Linux manual; press q to leave
```

</CodeTab>
</CodeTabs>

## Stopping a Foreground Program

While a program is running in the terminal and the prompt has not returned, that program is in the **foreground**. Press **Ctrl+C** to request that the foreground program stop. When it stops, the prompt returns.

This key press applies to the program attached to the active terminal. It does not close the terminal or stop programs in other terminal tabs. Some programs take a moment to stop or handle the interrupt themselves. If Ctrl+C copies selected text in your terminal application, clear the selection and press Ctrl+C again.

On macOS/Linux, `ping` continues until interrupted unless you give it a count. Windows `ping` uses a finite default count, and the shown examples set the count to three.

`clear` (or `cls` in PowerShell) clears the visible terminal output. It does not undo commands.

## Copying Output Out

Copy diagnostic output as text when sharing it. Use the terminal's Copy action or its configured shortcut: commonly `Ctrl+Shift+C` in Windows/Linux terminals and `Cmd+C` on macOS. The next exercise saves harmless sample text in the current folder. List the folder first and confirm that `terminal-output.txt` is not a file you need. The `>` symbol replaces a file with the same name.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Write-Output "terminal ready" > terminal-output.txt
Get-Content terminal-output.txt
```

</CodeTab>
<CodeTab label="Terminal">

```bash
printf '%s\n' "terminal ready" > terminal-output.txt
cat terminal-output.txt
```

</CodeTab>
</CodeTabs>

The read-back command should print `terminal ready`. If it does not, run the location and listing commands again and look for `terminal-output.txt` in the displayed folder.

## Administrator Access

Reading settings usually needs no elevation. Some changes, including network configuration, require administrator rights. On Windows, open PowerShell with **Run as administrator** when the procedure requires it. On macOS/Linux, use `sudo` for the specific command. An access error can also reflect file permissions or policy; read the message before retrying with more privileges.

<RulesBox title="Common Mistakes">

- **Unquoted spaces.** Quote a path containing spaces so it stays one argument.
- **Wrong path syntax.** Use the syntax in the tab for your shell.
- **Wrong current folder.** Check the location and contents before assuming a file is missing.
- **Too much output.** Save it to a file or use a filter to find the relevant lines.
- **Unneeded elevation.** Use a normal shell unless the operation requires administrator rights.

</RulesBox>
