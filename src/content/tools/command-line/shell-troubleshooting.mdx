### The shape of a diagnosis

Record what you observe, change one relevant thing, and repeat the check. This page covers commands for Java, Git, Gradle, processes, ports, logs, and remote shells.

Network problems have their own ladder in [Network Diagnostics](/tools/network-diagnostics). Every command below is shown for PowerShell and for the macOS/Linux Terminal.

### Is it installed, and which one is running?

Compare the tool version and path with the project requirements. Java lessons use Java 25 locally. WPILib includes its own JDK, but a separately opened shell can still select another installation.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
java -version                  # what runs when you type java
javac -version                 # the compiler: should match
git --version
Get-Command java               # where that java lives
Get-Command java -All          # every java on the PATH; the first wins
$env:JAVA_HOME                 # what build tools will use, which may differ from the above
```

</CodeTab>
<CodeTab label="Terminal">

```bash
java -version                  # what runs when you type java
javac -version                 # the compiler: should match
git --version
which java                     # where that java lives
which -a java                  # every java on the PATH; the first wins
echo $JAVA_HOME                # what build tools will use, which may differ from the above
/usr/libexec/java_home -V      # macOS: every JDK installed, whether on the PATH or not
```

</CodeTab>
</CodeTabs>

If `java`, `javac`, and `JAVA_HOME` refer to different installations, determine which one the failing tool uses. [Files, pipes and PATH](/tools/files-pipes-and-path#path-and-command-not-found) explains command lookup.

### What is running, and how to stop it

Identify the process before stopping it. A closed window does not always mean the process exited. Replace `12345` below with the ID you inspected; the stop commands are alternatives. Prefer the program's normal stop command first, and save work before terminating it.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-Process java, node                            # processes by name (error if none: that is an answer too)
Get-Process | Sort-Object CPU -Descending | Select-Object -First 5    # highest accumulated CPU time
Stop-Process -Id 12345                            # stop by process id
Stop-Process -Name java                           # stop every java (careful: includes VS Code's language server)
Stop-Process -Id 12345 -Force                     # stop without a confirmation prompt
```

</CodeTab>
<CodeTab label="Terminal">

```bash
ps aux | grep -i "[j]ava"                         # processes by name; the [j] trick hides grep itself
top                                               # live view of the busiest; q to leave
kill 12345                                        # ask a process (by id, the second column of ps) to stop
pkill java                                        # every java (careful: includes VS Code's language server)
kill -9 12345                                     # if it ignores the first request
```

</CodeTab>
</CodeTabs>

On macOS/Linux, `kill` sends SIGTERM by default; a program can handle it to clean up. `kill -9` prevents that cleanup. PowerShell `Stop-Process` terminates the process; `-Force` suppresses confirmation rather than providing a stronger signal. See [Stop-Process](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/stop-process). For Gradle, try the wrapper's `--stop` command before terminating a daemon.

### Who is holding this port?

An address-in-use error can mean another process is listening on the port. Inspect its identity before deciding whether to stop it or choose another port:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-NetTCPConnection -LocalPort 5173 -State Listen        # OwningProcess is the process id
Get-Process -Id 12345                                     # what that process is
Get-NetTCPConnection -State Listen | Select-Object LocalPort, OwningProcess | Sort-Object LocalPort   # everything listening
```

</CodeTab>
<CodeTab label="Terminal">

```bash
lsof -i :5173                          # macOS/Linux: the process on that port, with its PID
lsof -iTCP -sTCP:LISTEN -n -P          # everything listening
ss -ltnp                               # Linux: the same, faster
```

</CodeTab>
</CodeTabs>

If the listener is an old instance you no longer need, stop that instance and retry. To test a service on another machine, use [Network diagnostics](/tools/network-diagnostics#rung-5-is-anyone-listening-on-the-port).

### Watching a log

If the application writes a log, watch it while reproducing the failure. Compare timestamps and messages with your actions.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
Get-Content build.log -Wait -Tail 20                  # last 20 lines, then live
Get-Content app.log -Wait | Select-String "error"     # live, only the lines that matter
.\gradlew build *> build.log                          # run something and capture everything it prints
```

</CodeTab>
<CodeTab label="Terminal">

```bash
tail -f -n 20 build.log                    # last 20 lines, then live
tail -f app.log | grep -i "error"          # live, only the lines that matter
./gradlew build > build.log 2>&1           # run something and capture everything it prints
```

</CodeTab>
</CodeTabs>

When asking for help, include the relevant log, the command you ran, and what you expected to happen.

### Reading a Java stack trace

An uncaught Java exception usually prints a **stack trace**. It identifies the exception and the chain of calls where it occurred:

```text
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
        at frc.robot.subsystems.Hood.lookup(Hood.java:42)
        at frc.robot.subsystems.Hood.periodic(Hood.java:31)
        at edu.wpi.first.wpilibj2.command.CommandScheduler.run(CommandScheduler.java:280)
        at frc.robot.Robot.robotPeriodic(Robot.java:65)
        ...
```

1. Read the exception type and message. Here, index 5 is outside an array of length 5.
2. Locate a relevant frame in code you own, such as `Hood.java:42`. This is where the error became visible, which may differ from where the incorrect value originated.
3. Follow the caller frames to understand how that method was reached. Do not skip all `org.` packages: the ROBOTZ Garage library uses that prefix too.

Read each `Caused by:` block as well. It records an underlying exception; both the cause and the wrapping exception may provide useful context.

### Reading a Gradle failure

Gradle builds the robot project. A failure may come from compilation, tests, dependency resolution, configuration, or another task. Start with the failing task and its message:

```text
> Task :compileJava FAILED
/home/jordan/Cobra2026/src/main/java/frc/robot/subsystems/Hood.java:42: error: cannot find symbol
        double angle = table.lookup(distance);
                            ^
  symbol:   method lookup(double)
  location: variable table of type InterpolatingDoubleTreeMap
1 error

FAILURE: Build failed with an exception.

* What went wrong:
Execution failed for task ':compileJava'.
```

For a compile failure, look for `error:` with a file and line number. For other failures, read the `What went wrong` block and any cause messages. Request more detail when needed; the following commands are separate diagnostic options.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
.\gradlew build --stacktrace          # the full Java stack trace behind the failure
.\gradlew build --info                # what Gradle was doing at each step
.\gradlew build --offline             # do not try to download anything: the pit has no internet
.\gradlew clean build                 # throw away previous output and start over
.\gradlew --stop                      # end the background daemon when builds behave strangely
```

</CodeTab>
<CodeTab label="Terminal">

```bash
./gradlew build --stacktrace          # the full Java stack trace behind the failure
./gradlew build --info                # what Gradle was doing at each step
./gradlew build --offline             # do not try to download anything: the pit has no internet
./gradlew clean build                 # throw away previous output and start over
./gradlew --stop                      # end the background daemon when builds behave strangely
```

</CodeTab>
</CodeTabs>

A dependency-resolution failure can involve connectivity, credentials, a missing version, or repository configuration. `--offline` only works if the required dependencies are cached. For a wrapper permission error on macOS/Linux, check its executable permission. For an invalid `JAVA_HOME`, inspect the configured path and JDK.

### Is Git in the state I think it is?

Before touching anything in a repository that is behaving oddly:

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
git status                        # branch, what is changed, whether a merge is in progress
git log --oneline -10             # the last ten commits
git remote -v                     # where push and pull go
git stash list                    # anything stashed and forgotten
```

</CodeTab>
<CodeTab label="Terminal">

```bash
git status                        # branch, what is changed, whether a merge is in progress
git log --oneline -10             # the last ten commits
git remote -v                     # where push and pull go
git stash list                    # anything stashed and forgotten
```

</CodeTab>
</CodeTabs>

`git status` is the same on every platform and is the first thing to run when VS Code's Source Control view looks wrong; it says in words what the view is summarizing. What to do about it is in the [Git lessons](/tools/local-workflow#essential-commands).

### Use a shell on another machine with SSH

`ssh` connects to a remote machine. Commands then run under the remote account and operating system; only tools installed there are available. Replace the example user, address, and paths with those for your device.

<CodeTabs>
<CodeTab label="PowerShell">

```powershell
ssh pi@10.0.0.11                      # user@address; asks for the password
ssh pi@raspberrypi.local              # or by name
# First connection: verify the host key fingerprint before accepting it.
exit                                  # back to your own shell
scp .\config.json pi@10.0.0.11:/home/pi/     # copy a file to the machine
scp pi@10.0.0.11:/home/pi/app.log .          # copy a file back
```

</CodeTab>
<CodeTab label="Terminal">

```bash
ssh pi@10.0.0.11                      # user@address; asks for the password
ssh pi@raspberrypi.local              # or by name
# First connection: verify the host key fingerprint before accepting it.
exit                                  # back to your own shell
scp ./config.json pi@10.0.0.11:/home/pi/     # copy a file to the machine
scp pi@10.0.0.11:/home/pi/app.log .          # copy a file back
```

</CodeTab>
</CodeTabs>

Check the remote hostname and account before changing files. Follow the device's setup documentation for SSH access. FRC-specific instructions are in [Troubleshooting a robot connection](/frc/network-troubleshooting#rung-5-the-roborio-answers-but-the-code-is-not-running).

A changed SSH host key can follow re-imaging, but can also mean the address now reaches a different device. Confirm the target and key through a trusted source before updating `known_hosts`.

<RulesBox title="Common mistakes">

- **Assuming a version.** Check the version and path used by the failing process.
- **Stopping every Java process.** This can also stop the editor's Java tooling. Inspect the process ID first.
- **Reading only the last line.** Locate the failing task, error message, and relevant cause.
- **Ignoring caller frames.** Follow the stack trace to see where the value came from.
- **Losing the evidence.** Save the relevant log before restarting or changing the setup.

</RulesBox>
