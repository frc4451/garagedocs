### Read the robot as a system

An FRC robot has two paths that work together:

- The **power path** carries battery energy through the main breaker and power-distribution device to each load.
- The **data path** carries commands and measurements through Ethernet, Controller Area Network (CAN), USB, and sensor wiring.

The roboRIO runs the robot program. The radio connects the Driver Station and other Ethernet devices. Motor controllers turn CAN commands into electrical output for motors. Sensors report what the robot did.

```text
Power:  battery -> main breaker -> PDH or PDP -> protected branch circuits
Data:   Driver Station -> radio -> roboRIO -> CAN devices and sensor ports
Vision: camera -> coprocessor -> Ethernet -> radio or switch -> roboRIO
```

### Know what each device owns

| Device | Main job | Configuration interface |
|---|---|---|
| NI roboRIO | Runs robot code and connects robot buses | Imaging Tool and roboRIO web dashboard |
| CTRE device | Controls a motor or reports a CTRE sensor | Phoenix Tuner X |
| REV device | Controls a motor, power, pneumatics, or servos | REV Hardware Client 2 |
| Thrifty Bot device | Controls or measures through CAN | Thrifty Config |
| VH-109 radio | Connects the robot network to the Driver Station | Radio web interface |
| PhotonVision coprocessor | Processes camera images | PhotonVision web interface |
| Quest 3S | Reports headset pose to QuestNav | QuestNav Setup Tool and web interface |

Configuration clients prove that hardware can communicate before robot code is involved. Use the vendor client to identify a device, update supported firmware, assign a unique ID, and inspect faults. Then make the ID and bus name match the constants in code.

### Trace one complete action

When a driver presses a button to run an intake:

1. The Driver Station sends controller state through the radio.
2. The roboRIO scheduler runs the bound command.
3. The subsystem sends a request over CAN.
4. The motor controller applies power to the motor.
5. The controller and sensors report current, velocity, position, and faults.
6. Robot code records the values for the driver and programmers.

If the mechanism does not move, check that chain in order. A green Driver Station connection does not prove that the motor controller has power, the CAN ID is correct, or the mechanism is safe to move.

<RulesBox title="Done when">

On a powered-off robot, point to the battery, breaker, power distribution, roboRIO, radio, one motor controller, and one sensor. Trace the power path and data path for that mechanism without skipping a device.

</RulesBox>
