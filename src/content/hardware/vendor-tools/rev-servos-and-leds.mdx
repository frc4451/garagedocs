### A servo needs power and a control signal

Finn and Riptide use WPILib's `Servo` class for PWM servos. The class name does not identify the servo brand. Record the physical servo model, voltage range, current demand, PWM channel, and mechanical travel before copying the code.

A REV Smart Robot Servo can operate as an angular servo or be programmed for limited travel or continuous rotation. Record its exact model and programmed mode because the same PWM command has different meaning in angular and continuous modes.

A REV Servo Hub can provide CAN-controlled channels and separate servo power. Use REV Hardware Client 2 to set its CAN identity and inspect it. Do not claim that a robot used a Smart Robot Servo or Servo Hub based only on a source-file import, class name, or unused option.

### Limit servo travel before moving a mechanism

1. Disconnect the servo horn or unload the linkage when practical.
2. Confirm the servo supply voltage is within the servo's rating.
3. Set a center or known-safe command first.
4. Move in small steps toward each end.
5. Stop before the mechanism binds.
6. Record the safe software limits and the physical installation direction.

### Blinkin LED Driver

Ember and Riptide control a REV Blinkin LED Driver with a roboRIO PWM output. The program sends a PWM value that selects a color or pattern. The LED strip still needs the correct power and common ground described by REV.

When the displayed color is wrong, check the PWM channel, command value, signal ground, strip type, power wiring, and Blinkin mode before changing the state logic.

<RulesBox title="Done when">

Each servo has a recorded model, supply voltage, PWM or CAN channel, and tested safe travel. Each LED controller has documented power, signal, strip type, and the command values used by the robot. Unused imports and alternative code paths are labeled as such.
