### One controller family, three motor assemblies

`TalonFX` is the Phoenix 6 class used for the integrated controller in these motors. The Java class can look the same while the physical motor model, mechanism ratio, current limit, and simulation model differ.

| Motor assembly | Controller | Team evidence |
|---|---|---|
| Falcon 500 | Integrated Talon FX | Ember and Riptide mechanism code uses Talon FX and Falcon 500 simulation models. |
| Kraken X60 | Integrated Talon FX | Cobra's generated drivetrain and shooter constants identify Kraken X60 models. |
| Kraken X44 | Integrated Talon FX | Cobra's shared motor catalog includes the X44 model. Treat that as code support unless the robot hardware record confirms an installation. |

### Configure the hardware you actually have

1. Read the motor label before opening code.
2. Use Phoenix Tuner X to identify the controller, assign its CAN ID, and apply approved firmware.
3. Record the CAN bus as well as the ID. The same number can exist on separate buses.
4. Set current limits for the motor, wiring, breaker, and mechanism.
5. Set inversion and neutral behavior with the robot disabled and the mechanism clear.
6. Enter the correct mechanism ratio and feedback units.
7. Match the `DCMotor` simulation model to the physical motor.
8. Test at low voltage and confirm direction, sensor direction, current, and temperature.

A Falcon 500 model in simulation does not prove that a Falcon 500 is installed. A shared `TalonFX` IO class also does not prove which mechanism used it. Confirm the motor from the physical robot record and the mechanism constants.

<RulesBox title="Done when">

The motor label, Phoenix device identity, Java constant, current limit, mechanism ratio, and simulation model describe the same motor. The mechanism moves in the expected direction at a small request and reports plausible position, velocity, current, and temperature.

</RulesBox>
