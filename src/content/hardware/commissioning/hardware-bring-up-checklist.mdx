### Make each layer prove itself

Bring-up is the first controlled test of a new or rebuilt electrical system. Keep the robot disabled and mechanisms unloaded until the earlier layers pass.

| Stage | Check | Evidence |
|---|---|---|
| 1. Unpowered inspection | Polarity, protection, conductor insertion, labels, strain relief, CAN termination | Signed wiring checklist and photos |
| 2. Power only | Expected device lights, no heat or smell, stable branch voltages | Meter readings and device count |
| 3. Controller | Correct roboRIO image and team number | Imaging Tool or web dashboard screenshot |
| 4. Network | Radio mode, Ethernet links, roboRIO and clients reachable | Driver Station status and `ping` results |
| 5. CAN clients | Every expected device appears once with approved firmware and unique ID | Exports or screenshots from vendor clients |
| 6. Robot code | Deploy succeeds, real IO selected, no startup exception | Deploy result and roboRIO log |
| 7. Actuators | One output at a time, low request, correct direction, immediate stop | Test sheet signed by the operator and mentor |
| 8. Sensors | Values change in the expected direction and units | AdvantageScope or vendor-client trace |

### Use the right client

- **Phoenix Tuner X:** CTRE devices, firmware, IDs, licenses, faults, self-test, plots, and limited control.
- **REV Hardware Client 2:** current REV devices, firmware, IDs, parameters, faults, telemetry, and controlled motor tests.
- **Thrifty Config:** supported Thrifty Bot devices, firmware, IDs, and product-specific settings.
- **roboRIO tools:** controller image, team number, web status, and logs.
- **Radio web interface:** firmware, mode, and team network settings.
- **PhotonVision web interface:** cameras, networking, calibration, pipelines, updates, logs, and backups.
- **QuestNav Setup Tool:** headset profile and application installation.

### Stop on the first failed layer

Do not compensate for a hardware-client failure by changing robot code. If a device is absent from its client, first check power, cables, bus topology, duplicate IDs, and firmware compatibility. Code cannot control a device the bus cannot identify reliably.

<RulesBox title="Done when">

Starting from a powered-off robot, the team completes each stage in order and saves the named evidence. Every motor is tested individually at low output before the full mechanism or drivetrain is enabled.

</RulesBox>
