Use the `Drive` subsystem from R07 and `StickCurve` from R10 to create a command that reads the driver's sticks on each robot tick.

**Refreshers:** [Commands and triggers](/kit-bot/r05-commands-and-triggers) and [Functional Interfaces](/java/fundamentals/java-functional-interfaces).

### The default command, in its own class

Create `src/main/java/frc/robot/commands/TeleopDrive.java` with this complete file. It moves the existing stick-reading code into one named class. Autonomous routines will use `Drive.driveAt` instead of reading the controller.

```java
package frc.robot.commands;

import edu.wpi.first.wpilibj.DriverStation;
import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.subsystems.drive.Drive;
import frc.robot.subsystems.drive.DriveConstants;
import frc.robot.subsystems.drive.StickCurve;

import java.util.function.DoubleSupplier;

public class TeleopDrive extends Command {

    private final Drive drive;
    private final DoubleSupplier forwardSupplier;
    private final DoubleSupplier rotationSupplier;

    public TeleopDrive(Drive drive,
                       DoubleSupplier forwardSupplier,
                       DoubleSupplier rotationSupplier) {
        this.drive = drive;
        this.forwardSupplier = forwardSupplier;
        this.rotationSupplier = rotationSupplier;
        addRequirements(drive);
    }

    @Override
    public void execute() {
        if (!DriverStation.isTeleopEnabled()) {
            drive.stop();
            return;
        }

        double speed = StickCurve.shape(
            forwardSupplier.getAsDouble(),
            DriveConstants.TELEOP_DEADBAND,
            1.0);

        double rotation = StickCurve.shape(
            rotationSupplier.getAsDouble(),
            DriveConstants.TELEOP_DEADBAND,
            1.0);

        drive.arcadeDrive(speed, rotation);
    }

    @Override
    public void end(boolean interrupted) {
        drive.stop();
    }

    @Override
    public boolean isFinished() {
        return false;   // default commands run forever; the scheduler interrupts them
    }
}
```

Notice `shape` is called with `1.0` as the max output, not `DriveConstants.MAX_DRIVE_PERCENT`. `arcadeDrive` (R07) already multiplies by `MAX_DRIVE_PERCENT` internally, since it's documented to take `speed`/`rotation` in the full `[-1, 1]` range. Passing `MAX_DRIVE_PERCENT` into `shape` too would cap twice, leaving you well under the 85% you'd expect at full stick. One cap, one place: `arcadeDrive` owns it.

Two things to absorb from this shape:

- **The constructor takes `DoubleSupplier`s instead of raw numbers.** A raw number would capture one old stick reading. A supplier tells the command how to request the current reading on every tick. That is why `() -> -driver.getLeftY()` keeps following the stick.
- **`addRequirements(drive)` in the constructor**. This is how the command says "I need the drivetrain." The scheduler then ensures no other command can use it at the same time.

### Wiring it in

In `RobotContainer`, import `frc.robot.commands.TeleopDrive`. Replace only the drive default-command call. Keep the launcher, D-pad, X, and Y bindings. The partial snippet shows a B-button demonstration; remove the old heartbeat B binding first.

```java
private void configureBindings() {
    drive.setDefaultCommand(
        new TeleopDrive(
            drive,
            () -> -driver.getLeftY(),     // forward = up on stick = negative Y
            () -> driver.getRightX()     // right stick right = positive X = right turn
        )
    );

    driver.b().onTrue(drive.stopCommand());
}
```

The two `() -> ...` lambdas are `DoubleSupplier` instances. They close over the `driver` controller, so every time the command's `execute()` asks for `forwardSupplier.getAsDouble()`, the driver's current stick position flows in.

The `B` button binds directly to `drive.stopCommand()`. The action operates only the drivetrain, so `Drive` owns the command factory and supplies its requirement. The controller-specific `TeleopDrive` class stays separate because `Drive` should not know about joysticks.

### The two stick conventions

For the `arcadeDrive` equations in this course:

| Input | Read it as | Expected result |
|---|---|---|
| Left stick forward | `-driver.getLeftY()` | Both sides move forward |
| Right stick right | `driver.getRightX()` | Left side forward, right side backward |

Check those signs in simulation. This is a robot-relative right turn; it does not depend on where the robot sits on the field.

The mode check in `execute()` matters: a default command can be scheduled whenever its subsystem is free, including in autonomous. `isTeleopEnabled()` prevents this command from reading the sticks in another mode.

`stopCommand()` stops once, then ends. The default command can resume and read the sticks again. **B is not an emergency stop or a latched stop.** Use Driver Station Disable to stop normal robot operation.

### What you've now built

Run it:

1. Build, sim, enable in teleop.
2. Plug in an Xbox controller (or use the sim keyboard).
3. Drive around.

The driving should feel:

- **Calm in the middle.** Small stick motions produce small drive commands.
- **Strong at the edges.** Full stick produces about 10.2 V at the motors (85% of 12 V).
- **Dead at rest.** No creep when the stick is centred.

If any of these aren't true, suspect the `TELEOP_DEADBAND` and `MAX_DRIVE_PERCENT` values in `DriveConstants` first, then your stick negate signs.

<RulesBox title="Done when">

With the default command in its own class, enabling in teleop drives with no button pressed, disabling stops it, and no other command has to be scheduled for the robot to respond to the sticks. In autonomous with no drive routine selected, moving the sticks produces no drive request. Use the distance-reading check from R07 until the field display is added in R13.
