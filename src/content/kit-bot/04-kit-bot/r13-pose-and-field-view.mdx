A **pose** contains the robot's position and rotation on the field. **Odometry** updates that pose from measured wheel travel and heading. In this lesson, the field display is a way to check motion. The timed autonomous routine does not use this pose to steer.

**Refresher:** [R07 Part 2](/kit-bot/r07-drive-io-part-2). You will use left distance, right distance, and heading (the direction the robot faces).

### Step 1: add heading to the IO inputs

Add this field to `DriveIO.DriveInputs`:

```java
public Angle heading = Degrees.zero();
```

In `DriveIO.java`, import `edu.wpi.first.units.measure.Angle` and statically import `edu.wpi.first.units.Units.Degrees`. Also add the static `Degrees` import to `DriveIOSim.java`. In `DriveIOSim.updateInputs`, add:

```java
inputs.heading = Degrees.of(sim.getHeading().getDegrees());
```

The stock real Kit Bot has no gyro in this curriculum. Leave the real heading at zero until a real heading sensor is installed and checked.

### Step 2: update odometry

In `Drive.java`, import `edu.wpi.first.math.kinematics.DifferentialDriveOdometry` and `edu.wpi.first.math.geometry.Rotation2d`. Add static imports for `Meters` and `Degrees` from `edu.wpi.first.units.Units`. Add this field inside the class, outside its methods:

```java
private final DifferentialDriveOdometry odometry =
    new DifferentialDriveOdometry(Rotation2d.kZero, 0.0, 0.0);
```

After `io.updateInputs(inputs)` in `periodic()`, add:

```java
odometry.update(
    Rotation2d.fromDegrees(inputs.heading.in(Degrees)),
    inputs.leftPosition.in(Meters),
    inputs.rightPosition.in(Meters));
```

Build before adding the publisher.

### Step 3: publish the pose

In `Drive.java`, import `edu.wpi.first.math.geometry.Pose2d`, `edu.wpi.first.networktables.StructPublisher`, and `edu.wpi.first.networktables.NetworkTableInstance`. Add this publisher as a field:

```java
private final StructPublisher<Pose2d> posePublisher =
    NetworkTableInstance.getDefault()
        .getStructTopic("Drive/pose", Pose2d.struct)
        .publish();
```

At the end of `periodic()`, publish the current pose:

```java
posePublisher.set(odometry.getPoseMeters());
```

`Pose2d.struct` describes the binary data so AdvantageScope can decode it as a pose instead of a collection of unrelated numbers.

### Step 4: use the field view

1. Run simulation and connect AdvantageScope.
2. Add a 2D Field tab.
3. Drag `Drive/pose` into the field's pose list. If the icon starts at an edge, pan or zoom so the origin is visible.
4. Drive forward, reverse, and turn.

The icon should move and rotate with the simulated drivetrain.

### What the real robot still needs

Wheel distance can estimate forward motion. Rotation needs a trustworthy heading measurement. Until a gyro is connected through `DriveIOReal`, the real robot's published rotation remains zero and turns make its field pose incorrect. State this limitation whenever you show real-robot pose data.

In simulation, `Drive/pose` moves and rotates on AdvantageScope's 2D field. You can name the three measurements used by odometry and explain why the real Kit Bot needs a gyro for trustworthy rotation.
