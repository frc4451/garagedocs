Telemetry is data the robot sends out so you can inspect its behavior. The feeder and intake-launcher motor each publish RPM, current, and applied voltage. Seeing both sets of values is how you confirm that launch spins the roller before the feeder changes to its full launch output.

**NetworkTables** carries named values between robot code and tools on the driver-station computer. A name such as `Launcher/Feeder/velocityRPM` identifies one value. The code publishes a new number every robot tick.

### Step 1: start the log

Add these two lines near the start of `Robot.robotInit()`, before constructing `RobotContainer`:

```java
DataLogManager.start();
DriverStation.startDataLog(DataLogManager.getLog());
```

Add imports for `DataLogManager` and `DriverStation`.

`DataLogManager` saves a `.wpilog` file. In simulation, the file is stored on the computer. `DriverStation.startDataLog` adds controller and Driver Station information to the same log.

### Step 2: open publishers once

Add these fields to `Launcher`:

```java
private final NetworkTable table =
    NetworkTableInstance.getDefault().getTable("Launcher");

private final DoublePublisher feederVelocityPublisher =
    table.getDoubleTopic("Feeder/velocityRPM").publish();
private final DoublePublisher feederCurrentPublisher =
    table.getDoubleTopic("Feeder/currentAmps").publish();
private final DoublePublisher feederVoltagePublisher =
    table.getDoubleTopic("Feeder/appliedVolts").publish();

private final DoublePublisher launcherVelocityPublisher =
    table.getDoubleTopic("IntakeLauncher/velocityRPM").publish();
private final DoublePublisher launcherCurrentPublisher =
    table.getDoubleTopic("IntakeLauncher/currentAmps").publish();
private final DoublePublisher launcherVoltagePublisher =
    table.getDoubleTopic("IntakeLauncher/appliedVolts").publish();
```

Add imports for `NetworkTable`, `NetworkTableInstance`, and `DoublePublisher`.

The fields are created once with the subsystem. Do not call `publish()` inside `periodic()`.

The topic paths keep each motor's readings together. A student inspecting `Launcher/Feeder` knows those three values came from the feeder controller, while `Launcher/IntakeLauncher` came from the other controller.

### Step 3: set the values every tick

Add these lines at the end of `Launcher.periodic()`:

```java
feederVelocityPublisher.set(inputs.feederVelocity.in(RPM));
feederCurrentPublisher.set(inputs.feederCurrent.in(Amps));
feederVoltagePublisher.set(inputs.feederAppliedVoltage.in(Volts));

launcherVelocityPublisher.set(
    inputs.intakeLauncherVelocity.in(RPM));
launcherCurrentPublisher.set(
    inputs.intakeLauncherCurrent.in(Amps));
launcherVoltagePublisher.set(
    inputs.intakeLauncherAppliedVoltage.in(Volts));
```

`DoublePublisher` accepts a primitive `double`, so each measure is converted to the unit named by its topic with `.in(...)`.

### Step 4: graph the values

1. Open AdvantageScope with `WPILib: Start Tool`.
2. Select **File → Connect to Simulator → Default**.
3. Add a Line Graph tab.
4. Add all three values from `Launcher/Feeder`.
5. Add all three values from `Launcher/IntakeLauncher`.
6. Enable teleop. Hold the left bumper to intake, the right bumper to launch, and A to eject.

Look for these behaviors:

- Intake and eject move both motors and reverse the fuel path.
- The intake-launcher voltage changes immediately when launch starts.
- The feeder uses its spin-up voltage first, then changes to its full launch voltage.
- Releasing any button returns both applied-voltage topics to zero.

The two RPM traces do not need to match. The motors do different jobs and are not followers.

### Match the graph to video

On real hardware, record the mechanism from the side while AdvantageScope records the same run. Use the video to mark when fuel enters the feeder and touches the intake and launcher roller. Compare those moments with both RPM traces. A dip in one trace tells you which roller took on the load.

The [YETI Robotics 2026 build thread](https://www.chiefdelphi.com/t/frc-3506-yeti-robotics-2026-build-thread/511666) shows repeated-shot testing with motor-speed evidence on a Kit Bot. Use its graphs as an example of the question to ask, not as a target value for your robot.

### Open a saved log

Stop simulation and find the new `.wpilog` file. Open it in AdvantageScope. The same six values should be available for playback even though robot code is no longer running.

### Troubleshooting

- **The Launcher table is missing:** confirm simulation is running and AdvantageScope is connected to the simulator.
- **Only one motor changes:** confirm `Launcher.periodic()` sends both target voltages and publishes both input groups.
- **Feeder and launcher traces are identical:** check for an accidental `.follow(...)` configuration or a copied topic path.
- **No log file appears:** confirm `DataLogManager.start()` runs from `robotInit()`.
- **A graph has the wrong scale:** confirm the topic name and `.in(...)` conversion use the same unit.

AdvantageScope shows separate RPM, current, and applied-voltage topics for the feeder and intake-launcher motors. A launch graph shows the spin-up phase, the feeder transition, and both outputs returning to zero. The same topics open from a saved WPILOG.
