### What WPILib installs

The WPILib offline installer bundles everything you need in one package:

| Component | Purpose |
|-----------|---------|
| VS Code (WPILib edition) | The editor, pre-configured for FRC development |
| WPILib extension | Robot project templates, deploy tools, and IntelliSense for WPILib APIs |
| Java development kit (JDK) | The Java version bundled for the current WPILib release |
| GradleRIO | The build system that compiles and deploys robot code |
| Robot Simulation | Run and test robot code without physical hardware |
| AdvantageScope | The log and telemetry viewer this curriculum uses from R13 on |
| Elastic | The driver dashboard; not used in Kit Bot |

Both AdvantageScope and Elastic are installed by the WPILib installer. There is nothing separate to download. Launch AdvantageScope from WPILib VS Code with *WPILib: Start Tool* → *AdvantageScope*, or from the shortcut the installer places in `wpilib/2026/tools`. (Team 6328 also publishes newer builds on the [AdvantageScope releases page](https://github.com/Mechanical-Advantage/AdvantageScope/releases); the WPILib copy is enough for this curriculum.) We skip the older Shuffleboard and SmartDashboard entirely.

<RulesBox title="Always use the WPILib VS Code">

The WPILib installer creates its own copy of VS Code. Always open it from the **WPILib icon on your desktop** (not a regular VS Code shortcut). It has the correct Java version and extensions pre-configured.

</RulesBox>

### Step 1: Download and install WPILib

The installer steps below are for Windows. On macOS or Linux, follow your operating-system tab in the [WPILib installation guide](https://docs.wpilib.org/en/stable/docs/zero-to-robot/step-2/wpilib-setup.html), then continue at Step 2.

1. Go to the [WPILib GitHub releases page](https://github.com/wpilibsuite/allwpilib/releases)
2. Download the latest **2026** offline installer for your operating system (`WPILib_Windows-2026.x.x.iso` for Windows)
3. Mount the ISO (double-click on Windows 11) and run `WPILibInstaller.exe`
4. Select **Everything** when prompted for installation options
5. Click **Install for this User** (does not require admin rights)
6. When the installer asks about VS Code, choose **Download for this computer only**

Installation takes a few minutes. When it finishes, a WPILib icon will appear on your desktop.

---

### Step 2: Create a new robot project

1. Open **WPILib VS Code** (the desktop icon)
2. Press `Ctrl+Shift+P` to open the Command Palette
3. Type `WPILib: Create a new project` and select it
4. Fill in the project wizard:

| Field | KitBot value | What it means |
|-------|-------------|---------------|
| Project type | Template | Start from a template, not a blank file |
| Language | Java | |
| Template | **Command Robot** | Uses the command-based framework |
| Base folder | Your documents folder | Where the project folder will be created |
| Project name | `KitBot` | |
| Team number | Your team number | Used during deploy to find the RoboRIO |
| Enable desktop support | ✓ checked | Allows simulation without a RoboRIO |

5. Click **Generate Project**. VS Code opens the new project automatically.

---

### Project structure

```
KitBot/
├── src/main/java/frc/robot/
│   ├── Main.java           ← entry point (never edit this)
│   ├── Robot.java          ← robot lifecycle
│   ├── RobotContainer.java ← subsystems + button bindings
│   ├── Constants.java      ← all constants
│   ├── subsystems/         ← one class per mechanism
│   └── commands/           ← one class per action
├── vendordeps/             ← third-party library configs
├── build.gradle            ← GradleRIO build config
└── .wpilib/
    └── wpilib_preferences.json  ← team number
```

The `frc.robot` package is where all your code lives. The template may include `ExampleSubsystem` and `ExampleCommand`. Keep the generated project intact for the first build. R04 replaces the example bindings with your own subsystem.

---

### Step 3: Add REVLib for SparkMax support

The KitBot uses REV Robotics SparkMax motor controllers. WPILib does not include their library by default: you add it as a vendor dependency.

1. Click the **WPILib** logo in the Activity Bar to open the Dependency Manager
2. Find **REVLib** in the available libraries and click **Install**. WPILib copies `REVLib.json` into your `vendordeps/` folder
3. Click **Yes** when prompted to run a Gradle build

If REVLib is not listed, press `Ctrl+Shift+P` → `WPILib: Manage Vendor Libraries` → **Install new libraries (online)** and paste the REVLib vendordep URL from the [REV documentation](https://docs.revrobotics.com/revlib/).

After the build completes, `import com.revrobotics.*;` will resolve correctly in your code.

---

### Step 4: Build the project

Press `Ctrl+Shift+P` → `WPILib: Build Robot Code`. (`WPILib: Simulate Robot Code` also builds before it runs.)

You can also build from the terminal:

```
./gradlew build
```

On Windows PowerShell, use `.\gradlew.bat build` from the project folder. The command above is for macOS or Linux.

A successful build prints `BUILD SUCCESSFUL`. Errors appear in the **Problems** panel.

### Hardware deployment

Complete the simulation lessons first. For a physical robot, work with a mentor through [roboRIO imaging](/kit-bot/r00-roborio-imaging), [radio setup](/kit-bot/r00-radio-setup), and [first deploy](/kit-bot/r12-first-deploy).

### Step 5: Simulate the robot

Desktop simulation lets you test code without physical hardware. Run `WPILib: Simulate Robot Code` from the Command Palette. A simulation GUI opens alongside VS Code showing:

- Robot state (enabled/disabled, teleop/auto)
- Joystick inputs (connect a real controller or use the keyboard)
- SmartDashboard values

Simulation lets you check code without moving a physical robot. It cannot confirm wiring, motor direction, or whether a real launcher will score.

---

### The GradleRIO build system

**Building** checks and compiles your Java files into a program. **Deploying** copies that program to the roboRIO. GradleRIO connects these tasks to WPILib.

Keep the `build.gradle` generated by your installed WPILib version. Do not replace it with a fragment from another project. Use **WPILib: Manage Vendor Libraries** to add REVLib.

### Useful WPILib VS Code commands

| Command Palette entry | What it does |
|----------------------|-------------|
| `WPILib: Build Robot Code` | Compile without deploying |
| `WPILib: Deploy Robot Code` | Build and deploy to RoboRIO |
| `WPILib: Simulate Robot Code` | Build and run in simulation |
| `WPILib: Manage Vendor Libraries` | Add/update/remove third-party libraries |
| `WPILib: Create a new class` | Generate a new subsystem or command from a template |
All WPILib commands start with `WPILib:`, typing that in the Command Palette filters the list. If VS Code itself is new to you, the [Tools section](/tools/vscode-tour#the-command-palette) covers the editor: the window, hotkeys, the Java tooling, and the debugger.

### Try it

1. Install WPILib and create a new Command Robot project named `KitBot` with your team number.
2. Add REVLib using the vendor library manager.
3. Build the project and confirm `BUILD SUCCESSFUL`.
4. Run `WPILib: Simulate Robot Code` and enable the robot in teleop mode. No drivetrain or launcher is connected to your code yet. That is expected. R01 walks through what each generated file does and where you'll start filling it in.

---

<RulesBox title="Done when">

The project builds with `BUILD SUCCESSFUL`, `WPILib: Simulate Robot Code` launches, and the Sim GUI's Robot State switches to Teleoperated without an exception in the terminal. Nothing moves yet; the point is that the pipeline from source to a running simulated robot exists on your laptop.

</RulesBox>
