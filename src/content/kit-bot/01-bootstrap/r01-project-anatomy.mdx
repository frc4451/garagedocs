You generated a project in R00. Before you change anything, you need to know **what each file does** and **where your code goes**. This module is the map.

A Java package connects a folder path with the classes inside it. Review [Packages and project layout](/java/fundamentals/packages-and-project-layout#what-the-layout-looks-like) if that idea is new. WPILib's command-based template adds a few files with specific jobs.

## Before You Start

Complete [R00: WPILib Setup](/kit-bot/r00-wpilib-setup) and open the whole `KitBot` folder in WPILib VS Code. Review [Packages and Project Layout](/java/fundamentals/packages-and-project-layout#what-the-layout-looks-like) and [Create and Find a File](/tools/vscode-tour#create-save-and-find-a-file). This lesson only reads files and builds the simulation project.

## Four Core Files

Inside `src/main/java/frc/robot/` the template generates four Java files at the top level, plus three example files in `subsystems/` and `commands/`. You will spend most of the season editing the last two of the four.

```
src/main/java/frc/robot/
├── Main.java              ← never edit
├── Robot.java             ← rarely edit
├── RobotContainer.java    ← edit constantly
├── Constants.java         ← edit when adding hardware
├── subsystems/
│   └── ExampleSubsystem.java   ← template example; R04 removes it
└── commands/
    ├── Autos.java              ← template example; R04 removes it
    └── ExampleCommand.java     ← template example; R04 removes it
```

### `Main.java`: The JVM Entry Point

A short file that hands control to WPILib. Treat it as read-only. The reason it exists separately from `Robot.java` is purely about the JVM finding a `public static void main`, the same rule as any file you ran with `java Main` in [Setting Up](/java/fundamentals/setup#compiling-and-running).

### `Robot.java`: The Lifecycle

`extends TimedRobot`. Holds the methods WPILib calls every 20 ms (`robotPeriodic`, `autonomousPeriodic`, `teleopPeriodic`, etc.) and the once-per-transition init methods. The template version is short: it constructs your `RobotContainer`, schedules the auto command when autonomous starts, and asks the `CommandScheduler` to tick every cycle.

We cover the lifecycle in depth in [R02](/kit-bot/r02-robot-lifecycle).

### `RobotContainer.java`: The Wiring

This is where your team's specific robot gets assembled. Subsystems get constructed here. Controllers get plugged in here. Button bindings get set up here. The auto-routine chooser lives here.

`RobotContainer` creates the objects your program uses. It returns the selected autonomous command when `Robot.autonomousInit()` asks for it. During teleop, button bindings and the drivetrain default command handle driver input.

### `Constants.java`: Settings and IDs

CAN IDs, controller port numbers, PID gains, current limits, gear ratios. Anything that's set once at design time and read everywhere else. Covered in [R03](/kit-bot/r03-constants).

## Packages You Will Create

The template creates `subsystems/` and `commands/` with one example subsystem and two example commands inside. R04 removes the examples; these two packages are where the bulk of your code lives.

### `subsystems/`: One Folder per Mechanism

For the Kit Bot you'll end up with:

```
subsystems/
├── drive/
│   ├── Drive.java           ← the subsystem (state + control logic)
│   ├── DriveConstants.java  ← per-subsystem tuning
│   ├── DriveIO.java         ← the IO interface
│   ├── DriveIOReal.java     ← talks to SPARK MAX controllers
│   └── DriveIOSim.java      ← talks to DifferentialDrivetrainSim
└── launcher/
    ├── Launcher.java
    ├── LauncherConstants.java
    ├── LauncherIO.java
    ├── LauncherIOReal.java
    └── LauncherIOSim.java
```

R07 and R08 explain why each mechanism has an interface plus real and simulation implementations. [A17](/java/assignments/a17-io-interface) provides optional practice with the same file relationship.

### `commands/`: Separate Command Classes

Smaller files with clear ownership. A command for one mechanism usually comes from that subsystem, such as `Launcher.launchFuel()`. Controller-specific drive logic and commands that coordinate several subsystems use a separate command class or composition helper.

We cover commands in [R05](/kit-bot/r05-commands-and-triggers).

## Build System Files

Outside `src/main/java/` are the build-tool files. You rarely touch them, but you should know they exist.

| File | What it does | When you edit it |
|---|---|---|
| `build.gradle` | GradleRIO build config | Almost never; the WPILib tools edit it for you. |
| `vendordeps/*.json` | Vendor library declarations (REVLib, etc.) | Through the WPILib Dependency Manager ([R00, Step 3](/kit-bot/r00-wpilib-setup#step-3-add-revlib)), not by hand. |
| `.wpilib/wpilib_preferences.json` | Team number, language | Through the project-creation wizard, occasionally by hand to fix a wrong team number. |
| `.gitignore` | What git doesn't track | Once per project. The template's defaults are fine. |
| `simgui-window.json` | Sim GUI layout | Auto-saved when you arrange the sim windows. Safe to delete and let it regenerate. |

## Read the Four Files

When you first open the project, read the files in this order. At the end, you should be able to name each file's job without explaining every generated line.

1. **`Main.java`**: a short file. Confirm it calls only `RobotBase.startRobot(...)`.
2. **`Robot.java`**: look at the empty `*Periodic` methods. Notice `CommandScheduler.getInstance().run()` in `robotPeriodic`, that's the heartbeat.
3. **`RobotContainer.java`**: note the constructor, the `configureBindings()` method, the `getAutonomousCommand()` method. This is the file you'll modify most.
4. **`Constants.java`**: one nested `OperatorConstants` class for now. R03 replaces it.

If you want a more visual tour, WPILib's [Command-Based Programming overview](https://docs.wpilib.org/en/stable/docs/software/commandbased/index.html) has the same map with more diagrams.

## Practice

1. Open `Main.java`, `Robot.java`, `RobotContainer.java`, and `Constants.java`.
2. Write one sentence in your notes describing each file's job.
3. In `Robot.java`, find `CommandScheduler.getInstance().run()` inside `robotPeriodic()`.
4. Run **WPILib: Build Robot Code**. This lesson requires no code changes.

A **breakpoint** pauses a program at a chosen line. To inspect this loop in simulation, review [VS Code: Debugging](/tools/vscode-debugging). Use breakpoints only in the simulator during this course.
