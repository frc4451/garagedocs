Robot code does not power a motor directly. It sends a request to a **motor controller**. The controller switches battery power and, when configured, can limit current and report measurements. Breakers and correctly sized wiring provide separate protection in the power circuit.

This curriculum uses REV Robotics SPARK MAX controllers with NEO brushless motors. Focus on four ideas: CAN IDs, voltage commands, current limits, and encoder readings.

The snippets below explain API calls. Do not paste them into the project yet; R07 provides complete files with imports.

## Before You Start

Review [Voltage and Current](/hardware/electrical-basics-voltage-current), [Power Wiring and CAN](/hardware/power-wiring-and-can), [R03: Constants](/kit-bot/r03-constants), and the [R00 WPILib setup](/kit-bot/r00-wpilib-setup). You will read examples in this lesson. You will not edit the robot project or power hardware.

## CAN IDs Identify Devices

The **controller area network (CAN)** bus is a shared two-wire network. Each device needs its own numeric CAN ID so robot code can address the correct controller.

```java
SparkMax leftLeader = new SparkMax(40, MotorType.kBrushless);
```

The `40` must match the ID configured on that physical controller. If two devices share an ID, communication becomes unreliable. If the code uses the wrong ID, it may control a different device or find no device at all.

Store IDs in the mechanism's constants class. Name the device as well as its number:

```java
public static final int LEFT_LEADER_CAN_ID = 40;
```

## Voltage Controls Motor Effort

Two common `SparkMax` output methods are:

| Call | Meaning |
|---|---|
| `motor.set(0.5)` | Request half of the available bus voltage. |
| `motor.setVoltage(6.0)` | Request six volts. |

This curriculum uses `setVoltage` because the requested value stays in volts when battery voltage changes. The controller can only apply voltage available from the battery, and battery sag or a current limit can reduce the measured applied voltage. A voltage request describes motor effort. It does not guarantee a particular speed.

REVLib accepts a bare `double`:

```java
motor.setVoltage(voltage.in(Volts));
```

The subsystem uses a typed `Voltage`. The IO implementation converts it to the raw number REVLib expects.

## Current Limits Reduce Sustained Current

Current rises when a motor works hard or cannot turn. A current limit tells the controller to reduce output when the configured threshold is reached. The motor, wiring, and breaker still need ratings appropriate for the circuit.

```java
SparkMaxConfig config = new SparkMaxConfig();
config.smartCurrentLimit(60);
```

The correct limit depends on the motor, mechanism, wiring, breaker, and team rules. Use the value approved for the robot's hardware configuration. The later lessons provide simulation starter values. A mentor must approve the values for the physical robot before deployment.

## Encoders Measure Motion

The NEO includes a relative encoder. It reports motor-shaft position and velocity:

```java
double motorRotations = motor.getEncoder().getPosition();
double motorRpm = motor.getEncoder().getVelocity();
```

Position starts from a reference established by the program or controller. It does not tell you an absolute wheel or arm position after power-up.

The drivetrain needs wheel distance rather than motor rotations. The gearbox and wheel size provide the conversion:

```text
wheel rotations = motor rotations / gear ratio
distance = wheel rotations × π × wheel diameter
```

R07 keeps this conversion inside `DriveIOReal`, so the rest of the program reads meters and meters per second.

## Leaders and Followers

Each Kit Bot drivetrain side has two motors. Code commands the leader, and the follower mirrors it over CAN. This pattern applies to the drivetrain only. The feeder and intake-launcher motors in R08 perform different jobs and receive separate commands.

```java
SparkMaxConfig followerConfig = new SparkMaxConfig();
followerConfig.follow(leaderCanId);
```

The second argument to `follow(leaderCanId, invertRelativeToLeader)` selects whether a follower mirrors or opposes its leader. Motor mounting, leader inversion, and this follower relationship all affect wheel direction. R07 records the intended sign contract in simulation. Real direction remains unverified until the mentor-led First Deploy procedure.

## Configuration Happens Once

Create and apply motor configuration when the IO implementation is constructed. Do not reconfigure a controller every 20 ms.

```java
SparkMaxConfig config = new SparkMaxConfig();
config.idleMode(IdleMode.kBrake)
      .smartCurrentLimit(60)
      .inverted(false);

motor.configure(
    config,
    ResetMode.kResetSafeParameters,
    PersistMode.kPersistParameters);
```

`kBrake` makes a stopped drivetrain resist motion. `kCoast` lets a mechanism spin down more freely. Choose the mode for the mechanism's intended behavior.

## Check Your Understanding

For each observation, name the first fact you would check:

| Observation | Check |
|---|---|
| Code reports that CAN device 40 is missing. | Confirm the controller label and configured CAN ID. |
| A 6 V request produces a different speed as the mechanism load changes. | Compare requested voltage with speed; voltage is effort, not a speed command. |
| Current rises while the shaft stops turning. | Check for a stall or mechanical obstruction before running again. |
| A 10.71:1 reduction reports 10.71 motor rotations. | Calculate `10.71 / 10.71 = 1` wheel rotation. |

## Why the Next Lessons Use an IO Interface

REVLib types belong in the real IO implementation. Simulation types belong in the simulation implementation. The subsystem calls the small interface shared by both. This keeps motor configuration, unit conversion, and sensor reads in one place.
