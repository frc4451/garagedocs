A distance table chooses a launcher setting from a requested distance. **Interpolation** estimates a value between two known entries. Use simulation values until a mentor is present for real launcher testing.

For this first version, the table maps distance in meters to voltage. The values below are examples for simulation. They are not measurements from a real Kit Bot.

### Add the table

Add this field and helper to `Launcher`:

```java
private final InterpolatingDoubleTreeMap voltageByDistance =
    buildVoltageTable();

private static InterpolatingDoubleTreeMap buildVoltageTable() {
    InterpolatingDoubleTreeMap table = new InterpolatingDoubleTreeMap();
    table.put(1.0, 6.0);
    table.put(2.0, 8.0);
    table.put(3.0, 10.0);
    return table;
}
```

Import `edu.wpi.first.math.interpolation.InterpolatingDoubleTreeMap`.

Add this method:

```java
public Command launchAtDistance(Distance distance) {
    Voltage launcherVoltage = Volts.of(
        voltageByDistance.get(distance.in(Meters)));
    return launchAtVoltage(launcherVoltage);
}
```

Keep the existing `Command` and `Voltage` imports. Add `edu.wpi.first.units.measure.Distance` and static imports for `Meters` and `Volts` from `edu.wpi.first.units.Units`. This factory belongs on `Launcher` because the subsystem owns both fuel-path motors. It reuses the two-phase launch helper from Part 2, so the distance table changes the intake-launcher voltage while the feeder still waits through spin-up and then feeds.

The map sorts its distance keys. A request for `2.5` meters is halfway between `2.0` and `3.0`, so it returns halfway between 8 V and 10 V: 9 V. A request outside the table uses the nearest end value.

### Add two test bindings

Add these bindings inside `RobotContainer.configureBindings()` and statically import `Meters` there too. Keep the D-pad bindings for the capstone distance check:

```java
driver.povUp().whileTrue(
    launcher.launchAtDistance(Meters.of(1.0)));

driver.povDown().whileTrue(
    launcher.launchAtDistance(Meters.of(3.0)));
```

Run the simulator. Hold each D-pad direction and print RPM with the X binding from R08 Part 2. The longer-distance command should produce a higher simulated RPM because it requests a higher voltage. Releasing the D-pad stops the launcher.

### Limits of this table

Voltage is an input to the motor, not a measured launcher speed. A real battery and mechanism change during operation, so the same voltage may not produce the same RPM every time. [R09 Part 1](/kit-bot/r09-characterization) measures how the mechanism responds so later tuning can use robot data.
