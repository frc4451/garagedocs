During autonomous, the robot runs without joystick input. This lesson composes subsystem commands into a short sequence: drive forward, stop, then run the launcher.

The routine uses time instead of a measured distance. This keeps the lesson focused on command sequences and simulation testing. A real time-based routine can drift as the battery and floor change.

### Step 1: create the routines

Create `src/main/java/frc/robot/commands/AutoRoutines.java`. This is a **complete file**.

```java
package frc.robot.commands;

import edu.wpi.first.units.measure.Time;
import edu.wpi.first.wpilibj2.command.Command;
import frc.robot.subsystems.drive.Drive;
import frc.robot.subsystems.launcher.Launcher;
import static edu.wpi.first.units.Units.Seconds;

public final class AutoRoutines {
    public static Command driveForward(
            Drive drive, double speed, Time duration) {
        return drive.driveAt(speed, 0.0).withTimeout(duration);
    }

    public static Command shoot(Launcher launcher, Time duration) {
        return launcher.launchFuel().withTimeout(duration);
    }

    public static Command driveThenShoot(
            Drive drive, Launcher launcher) {
        return driveForward(drive, 0.4, Seconds.of(1.5))
            .andThen(shoot(launcher, Seconds.of(2.0)));
    }

    private AutoRoutines() {}
}
```

`driveForward` and `shoot` compose commands already defined by `Drive` and `Launcher`; they do not repeat either subsystem's output or stop logic. `withTimeout` interrupts each command after the given time, so the subsystem's end action stops the mechanism. `andThen` starts the next command after the first finishes.

Build before continuing.

### Step 2: create the chooser

In `RobotContainer.java`, add imports for `edu.wpi.first.wpilibj2.command.Commands`, `edu.wpi.first.wpilibj.smartdashboard.SendableChooser`, `edu.wpi.first.wpilibj.smartdashboard.SmartDashboard`, and `frc.robot.commands.AutoRoutines`. Statically import `Seconds` from `edu.wpi.first.units.Units`. Add this field inside the class, outside its methods:

```java
private final SendableChooser<Command> autoChooser =
    new SendableChooser<>();
```

Add these lines in the constructor after the subsystems are created and before `configureBindings()`:

```java
autoChooser.setDefaultOption("Do nothing", Commands.none());
autoChooser.addOption(
    "Drive forward",
    AutoRoutines.driveForward(drive, 0.4, Seconds.of(1.5)));
autoChooser.addOption(
    "Drive then shoot",
    AutoRoutines.driveThenShoot(drive, launcher));

SmartDashboard.putData("Auto Chooser", autoChooser);
```

`SmartDashboard.putData` publishes the chooser through NetworkTables. You do not need to open the SmartDashboard application. Glass displays the published chooser widget.

Replace the existing `getAutonomousCommand()` method with this partial snippet. Keep all driver bindings:

```java
public Command getAutonomousCommand() {
    return autoChooser.getSelected();
}
```

### Step 3: select and run an autonomous routine

1. Start robot simulation.
2. Open Glass with `WPILib: Start Tool`.
3. In Glass, open the NetworkTables menu and find the chooser under the `SmartDashboard` table.
4. Select **Drive forward**.
5. Set the simulated robot to Autonomous and enable it.

The drivetrain should receive a drive request for 1.5 seconds, then a zero request. Its simulated speed may take time to decay.

Disable the robot. Select **Drive then shoot** and enable autonomous again. The drive request ends before the launcher command starts.

Also select **Do nothing**, enable autonomous, and move both sticks: the robot should receive no drive request. R11's teleop mode check prevents its default command from reading the sticks during autonomous. Release the launcher buttons during autonomous testing.

### How `Robot` starts and stops the selection

The command-based template schedules the selected command in `autonomousInit()`. It cancels the command in `teleopInit()` so joystick control can take over. Confirm both methods still exist in `Robot.java`.

### Troubleshooting

- **The chooser is missing:** confirm `SmartDashboard.putData` runs once from the `RobotContainer` constructor and Glass is connected to simulation.
- **The wrong routine runs:** select the option before enabling autonomous, then confirm `getAutonomousCommand()` returns `autoChooser.getSelected()`.
- **The drivetrain never stops:** confirm `driveForward` calls `drive.driveAt(...)` with `withTimeout`. The timeout interrupts `driveAt`, which runs its stop action.
- **Teleop does not take control:** confirm `teleopInit()` cancels the autonomous command.

<RulesBox title="On the real robot">

Run autonomous only after [R12 Part 2: First Deploy](/kit-bot/r12-first-deploy) and the teleop direction checks pass. Start with the robot on blocks, then move to an open practice area with a mentor at Disable. Battery voltage, carpet, and wheel slip change the distance traveled during a timed command, so measure the real stopping point and adjust the timeout from evidence. Recheck that teleop cancels an autonomous command that is still running.

</RulesBox>

Glass shows the chooser. Each option runs the behavior named by the option in simulation. The drivetrain stops when its timeout ends, and switching to teleop interrupts an autonomous routine that is still running.
