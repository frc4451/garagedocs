The capstone is one working WPILib project. You will demonstrate its behavior in simulation and explain how its main pieces connect.

### Required behavior

| Check | Observable result |
|---|---|
| Build | `./gradlew build` finishes successfully. |
| Teleop drive | A controller drives forward, reverse, and turns. The robot stays still inside the deadband. |
| Launcher and intake | Left bumper intakes, right bumper launches, and A ejects. The independent feeder and intake-launcher motors follow the correct sequence and both stop on release. Two distance settings produce different launch speeds. |
| Characterization | The drivetrain and launcher print steady-state samples and calculated `kS` and `kV` values. One result is checked with a hand-written sample table. |
| Runtime selection | Simulation constructs the simulation IO implementations. The real-hardware branch is visible in `RobotContainer`. |
| Telemetry and pose | AdvantageScope graphs separate RPM, current, and applied voltage for the feeder and intake-launcher motors. Its field view shows the simulated robot pose moving and turning. |
| Autonomous | Glass shows the chooser, and each required option runs and stops. |
| Repository | The project has a README and is pushed to its own Kit Bot repository. A00 explains the GitHub workflow; the `<yourname>Badge01` assignments repository stays separate. |

Real-hardware operation is a later confirmation with a mentor. It is not required when a safe Kit Bot is unavailable.

### Required project organization

Your names may differ, but the project needs these responsibilities:

- `Robot.java` starts logging and runs the command scheduler.
- `RobotContainer.java` creates subsystems, chooses real or simulation IO, configures bindings, and publishes the autonomous chooser.
- Each mechanism has a subsystem, an IO interface, a real implementation, a simulation implementation, and its constants.
- A command that operates one mechanism is returned by that subsystem, such as `Launcher.launchFuel()`.
- `TeleopDrive` owns controller-specific drive logic because controllers do not belong inside `Drive`.
- `AutoRoutines` composes subsystem commands into autonomous routines.

Extra files are acceptable when you can explain their purpose. Remove abandoned experiments and unused classes before the demonstration.

### Code review checklist

#### Java and project basics

- [ ] Package declarations match folder paths.
- [ ] Fields are private unless they are constants or the public measurements in an IO inputs class.
- [ ] Overridden methods use `@Override`.
- [ ] Objects stored in fields, such as the IO implementation, are `private final` when the field is not reassigned.
- [ ] VS Code reports no unused imports.
- [ ] `.gitignore` excludes build output and local editor files.

#### IO boundary

- [ ] Real IO files contain the REVLib calls.
- [ ] Simulation IO files contain the WPILib simulation calls.
- [ ] Subsystems depend on their IO interfaces.
- [ ] `RobotContainer` is the place that selects real or simulation implementations.

#### Command ownership

- [ ] Left bumper binds to `launcher.intakeFuel()`, right bumper binds to `launcher.launchFuel()`, and A binds to `launcher.ejectFuel()`.
- [ ] Commands that operate one mechanism are created by that subsystem and automatically require it.
- [ ] `RobotContainer` chooses triggers but does not repeat mechanism voltage or stop logic.
- [ ] Commands that coordinate several mechanisms compose the subsystem commands outside those subsystems.

#### Behavior and evidence

- [ ] Teleop drive stops when disabled.
- [ ] The feeder and intake-launcher outputs both stop when each mechanism button is released.
- [ ] Autonomous drive stops when its timeout ends.
- [ ] Telemetry topics include their units in the name.
- [ ] A saved WPILOG opens after simulation ends.
- [ ] The drivetrain and launcher each produce at least two accepted steady-state samples.
- [ ] One `kS` and `kV` result is checked with the regression sums from R09 Part 2.
- [ ] Recorded gains name their mechanism, units, environment, voltage steps, settle time, and test date.
- [ ] The simulated pose moves and rotates in AdvantageScope's field view.

### Ten-minute demonstration

#### 1. Show the project map

Point to one subsystem, its IO interface, and its real and simulation implementations. Explain that the subsystem uses the same methods in either environment.

#### 2. Show runtime selection

Open `RobotContainer`. Show where the program chooses the IO implementation. Start simulation and show the console confirmation from R12.

#### 3. Drive, intake, and launch

Enable teleop. Drive forward, reverse, and turn. Hold and release the left bumper, right bumper, and A to demonstrate intake, launch, and eject. Explain why all three commands belong to the same `Launcher` subsystem. Demonstrate two launcher distance settings. Show the launcher graph and moving field pose in AdvantageScope.

#### 4. Show the characterization record

You may use notes, the R09 equations, and a calculator. Show the drivetrain and launcher voltage-and-velocity samples. For one mechanism, show the four regression sums and compare your hand-calculated `kS` and `kV` with the Java output. State the velocity unit and explain why real hardware needs its own test data.

#### 5. Run autonomous

Open Glass, select each required autonomous option, and run it. Show that the drivetrain and launcher stop at the end of their commands.

#### 6. Explain one failure check

Choose one example:

- A button does nothing.
- The robot turns when commanded forward.
- A telemetry topic stays at zero.
- An autonomous command does not stop.

Describe what you would observe, what you would check first, and what evidence would confirm the cause.
