The capstone produces a working simulated Kit Bot with distance-based launcher settings, checked `kS` and `kV` calculations, a field pose, and timed autonomous routines. This page is a follow-up catalog, not another requirement for the simulation capstone. Choose one change from a behavior you have observed.

### Project guide

| Need you observed | Project | Preparation | Start here |
|---|---|---|---|
| Autonomous distance changes between runs | Add encoder-based distance control and a gyro for heading | Encoders, feedback control, drivetrain safety | [WPILib differential-drive odometry](https://docs.wpilib.org/en/stable/docs/software/kinematics-and-odometry/differential-drive-odometry.html) |
| Launcher speed drops as fuel enters | Add a velocity target with feedforward and feedback | R09 results, launcher RPM telemetry | [WPILib feedforward and feedback](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/controllers/combining-feedforward-feedback.html) |
| You need complete replayable logs | Add AdvantageKit after the base robot is understood | IO interfaces, AdvantageScope | [AdvantageKit documentation](https://docs.advantagekit.org/) |
| The launcher needs settings for additional field locations | Add measured distance and speed pairs | [R08 Part 3](/kit-bot/r08-launcher-calibration) and the current test logs | [A10](/java/assignments/a10-shooter-lookup-table) |
| A mechanism needs its position after reboot | Add an absolute encoder or homing routine | Sensors, mechanism safety | [CTRE CANcoder](https://v6.docs.ctr-electronics.com/en/latest/docs/hardware-reference/cancoder/index.html) |
| The robot needs to detect fuel or a hard limit | Add a beam break or limit switch | Digital input wiring | [WPILib digital inputs](https://docs.wpilib.org/en/stable/docs/software/hardware-apis/sensors/digital-inputs-software.html) |
| Drivers need clear robot-state feedback | Add addressable LEDs | A small subsystem and state definitions | [WPILib addressable LEDs](https://docs.wpilib.org/en/stable/docs/software/hardware-apis/misc/addressable-leds.html) |
| You need to diagnose brownouts or high current | Add power-distribution telemetry | AdvantageScope graphs | [WPILib power distribution](https://docs.wpilib.org/en/stable/docs/software/can-devices/power-distribution-module.html) |

### Pick a project from evidence

Write down:

1. The behavior you observed.
2. The measurement that would show improvement.
3. The smallest change that can affect that measurement.
4. The simulation check and the later hardware check.

Example: "The time-based auto stops at different distances. We will graph wheel distance, add a heading sensor, and replace the timed drive command with a distance target. Simulation must stop within the chosen tolerance before hardware testing."

### Keep season-specific choices separate

Sensors, motor controllers, and game rules change. Record the season and library version when adding one. Keep the subsystem's general behavior separate from the configuration for a specific robot.

### Read other teams' code carefully

Public robot repositories can show how experienced teams organize similar features. Start with one file and trace its inputs and outputs. Recreate the idea in your own project only after you can explain each dependency and safety condition.
