A hands-on curriculum for writing FRC robot code. By the end you will have rebuilt the **2026 KitBot** end to end, differential drive plus the KOP launcher, with real-hardware and simulation implementations sharing the same subsystem code.

**Everything here is built and evaluated in simulation.** Each module ends with something you make the simulated robot do and show in the simulator or in AdvantageScope; that is what "done" means. A physical Kit Bot is the last confirmation, when there is one available. It is not where you find out whether the code works. This is FRC 4451's rule for every robot, stated in full in [Simulation First](/frc/simulation-first); Kit Bot is where you learn to work that way.

The 2026 KitBot is FRC 4451's standing training robot. It stays the reference build across seasons, so what you write here is what the next cohort reads.

This curriculum assumes you have completed [Java Training](/java) and the [Practice Assignments](/assignments) through at least Track 2. Every WPILib pattern below maps to something you've already built in plain Java.

Nothing here runs in the in-page editor: WPILib code needs the WPILib toolchain, which is what R00 installs. Every Java listing on these pages is meant to be typed into your own project.

---

### What you're building

```
2026 KitBot
├── Drive               4× SparkMax + NEO, DifferentialDrive
└── Launcher            2× SparkMax + NEO, simple roller mechanism
```

Driver controller (port 0): stick-based arcade drive.
Operator controller (port 1): triggers and buttons for intake / launch.

Both subsystems use the **IO interface pattern** from Practice Assignment [A17](/assignments/a17-io-interface). The same subsystem code drives both real SparkMax hardware and a WPILib physics simulation. Switching between the two is a one-line change in `RobotContainer`.

Telemetry uses **AdvantageScope** end-to-end. No SmartDashboard, no Shuffleboard, no `Field2d` widget. From R13 on, AdvantageScope connected to the simulator is how every module's result is shown; before that, the simulator's console and GUI are.

### How you are evaluated

Every module has an **Evaluate in simulation** box at the end. It names the one thing the simulated robot must visibly do, and where to look. Do it, and where the box says so, keep the evidence (a screenshot of the console or of the AdvantageScope tab), because the [capstone](/kit-bot/rc-capstone) is a ten-minute simulation demo built from exactly these.

| Module | Evidence, in simulation |
|---|---|
| R00–R02 | The project builds, simulates, enables; `teleopPeriodic` visibly runs at 50 Hz |
| R03–R05 | A subsystem's `periodic` ticks in the console; two controller bindings change what it prints |
| R07 | Launcher RPM rises under a held button and current is non-zero; the calibration table changes RPM with distance |
| R08 | Driving forward for two seconds accumulates roughly six metres; turning splits the sides |
| R09 | The characterization routine prints a small positive `kS` and a `kV` that lands near 12 V at top speed |
| R10–R11 | Deadband holds the robot still at small stick; the curve makes 30 % stick glide, not jolt |
| R12 | The console reports which IO it picked; sim and real branches differ in one place |
| R13 | AdvantageScope live: the pose tracks on the field, left/right velocity separate in a turn, launcher current spikes |
| R14 | The auto chooser lists every routine; each runs to completion on the field view; teleop interrupts it |
| RC | The whole demo, in simulation, in ten minutes |

Real hardware, when it is available, is checked after simulation passes. When the two disagree, the [sim-to-real checklist](/frc/sim-autos#the-hand-off-to-the-real-robot) says what to look at.
